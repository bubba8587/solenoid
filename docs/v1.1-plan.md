# v1.1 — Detailed execution plan

The post-1.0 cycle. **v1.0 is released** — the desktop spine shipped (Tauri +
native Polars + the full relational verb set + the HTML-in-Canvas renderer) and is
tagged/live. v1.1 is the **deferred tail** the milestone split (2026-06-24) parked
so 1.0 could ship: the Format Controller redesign + the units architecture (the
flagship), the pack/extensibility surface, canvas/interaction polish, and a handful
of integration nodes. **This is now the active milestone** — work can begin.

This expands the archived `roadmap.md` "v1.1 — post-v1 deferred tail" bullet list
into a sequenced, file-level plan the same way `v1.0-plan.md` did for the spine.
The backlog stays the fine-grained checklist; this is the build order, the
dependencies, and the exit criteria.

**Development continues on `develop`** (the standing rule); `main` is the released
1.0 and is author-gated. The **bug lane** below is the natural first pickup.

---

## Shape of the release

Five workstreams, one always-on bug lane. Unlike v1.0 (a linear spine A→B→C→D),
v1.1's streams are mostly **independent** and can be picked up in any order. The
sequencing that matters is *within* a stream and at two hard gates:

| Workstream | Theme | Weight |
|---|---|---|
| **WS-A — Format Controller & Units** | the flagship: FC function model + visual redesign + units-by-dimensionality | large (own sub-milestones) |
| **WS-B — Packs & extensibility** | dormant-pack persistence gate, new core nodes, Timesavers, domain packs | medium |
| **WS-C — Canvas & interaction** | grid system, cable collision avoidance, hideable chrome, pinch-zoom, small polish | medium |
| **WS-D — Data & integration** | Obsidian sync, image bundling, finance connection, cube-cell XLOOKUP | medium |
| **WS-E — Engine scale niceties** | lazy-plan fusion, direct CSV→Polars reader, formula re-audit | small/opportunistic |

**Two hard gates:**
1. **WS-A's units architecture depends on the FC function model landing first** —
   the function model defines how one FC resolves precision × style × unit × type;
   units-by-dimensionality then generalizes "unit" from per-value to per-cell /
   per-column. Build the function model, then the units model.
2. **No *code* pack ships before dormant-pack persistence** (WS-B first task).
   Deactivating a pack today silently severs saved wiring, so the placeholder-node
   + pack-provenance work gates every domain pack and every `[C]` Timesaver.

Suggested cut order: **bug lane → WS-A (function model, then redesign) → WS-B gate
+ first pack → WS-C polish in parallel → WS-D/WS-E opportunistic.** WS-A is the
headline; everything else is fill-in.

## Bug lane (the first pickup)

Two dated author-flagged regressions with the diagnosis already recorded. Small,
self-contained, verify on the running app.

- [ ] **Navigator group rows are blown out** (author 2026-07-01). `OutlinePanel.tsx:465`
  paints a group row `background: r.color` — the raw accent at full opacity as a solid
  bar, while on canvas a group body is a translucent tint (`GroupNode.tsx` `hexToRgba(color,
  fillAlpha)`) with only the thin header full-strength. Fix: tint the row like the canvas
  body (low-alpha `hexToRgba(color, fillAlpha)` over the panel bg; accent as border/label,
  not a solid fill). Also verify `colorOf` (`:44`) resolves the palette **slot** via
  `resolveColor` the way `GroupNode` does (`resolveColor(node.color)`), not `node.color`
  straight to `themeAccent`. **NOTE:** the recent `develop` commits (`10c9498`…`7dce600`)
  already touched group-row fill (0.16→0.24) and border/tint — reconcile against the
  current state of the file before editing; this bug may be partly addressed.
- [ ] **FCs mis-dock to a frontmatter Note on load/switch** (author 2026-06-25, random-repro).
  Leading hypothesis (investigation already ruled out ID collision, singleton
  contamination, and load-time re-docking): `findDockTarget`'s `DOCK_SNAP_PX=34` is in
  **screen px**, so zoomed out it covers a large canvas area and snaps an FC to a far-away
  Note's tall stack of output sockets during editing; that wrong dock persists and shows on
  reload. Fix: make the snap radius **zoom-aware / canvas-unit**, and prefer a host the FC
  is actually adjacent to. Also fix the ordering smell: `nodecreated` calls `dockSelf()`
  (`Canvas.tsx:2249`) before persistence remaps `hostNodeId` (`:395`) → guard with
  `!isGraphRebuilding()`. Diagnostic first: open an affected save, confirm the wrong FC's
  `init.hostNodeId` equals the Note's id (persisted-wrong vs load transient).

## WS-A — Format Controller & Units (the flagship)

Author: "unit carrying and data-type segregation are some of the biggest value adds
of this project." This is the headline workstream. Four sub-parts, in dependency
order. `formatAnnotationStore.ts` (`FormatAnnotation`, `FormatStyle`), the FC popup,
`unitFlow.ts`, and the value renderers are the touch surface throughout.

### A1 — The function model (spec FIRST, then code)

Pin down ONE coherent definition of how an FC decides what to render across every
axis it controls at once, replacing today's per-style ad-hoc logic on
`FormatAnnotation`. The axes that must compose:

- **precision** — `decimalDigits` × `decimalMode` (`"places"` fixed decimals vs
  `"sig"` significant figures): one resolution rule for how it interacts with each
  style (sig-figs on `percent` / `scientific` / `fraction`).
- **format style** — `FormatStyle` (`auto | decimal | integer | percent | fraction
  | fraction_adv | scientific`) + `customPattern`.
- **unit** — `unit` / `customUnit`, a SEPARATE axis applied after the numeric format
  (currency is a unit, not a format); must coexist with every style.
- **value type** — the same FC can sit on number / date / text / logical; the model
  defines which controls light up vs no-op per incoming type (sig-figs meaningless
  on a date; `textCase` meaningless on a number).

**Deliverable order (author-specified):**
1. [ ] **The spec** — a truth table: which controls apply per value-type, plus the
   precision×style resolution rule. Write it into `docs/` (a `format-model.md` or a
   subsystem-invariants section) before touching code.
2. [ ] **The code** — refactor `FormatAnnotation` resolution to the single model;
   the FC popup lights/no-ops controls per incoming type off it.

Gate: A2 (visual redesign) and A4 (units) both build on this. Do it first.

### A2 — Visual / layout redesign + SegToggle unification

The aesthetic half the 2026-06-24 split moved to v1.1 (architecture was v0.9/DONE).

- [ ] **Layout redesign** of the FC's places / sig-figs / units panel. **Read
  `DESIGN.md` before any pixel** (hard rules: no accent stripe, Quiet Accent, no
  faux-3D). Pairs with A1 — the redesigned panel renders the function model's
  control matrix.
- [ ] **SegToggle unification** — route the FC's places/sig-figs toggle (and any new
  toggles) through the shared `SegToggle` component so there's one segmented-button
  definition. Today the FC keeps its own inline variant (`.solenoid-fc__seg` /
  `__segbtn`); `SegToggle` (Get Column / Add Column read-as) is the full-width form
  with the same look. Unify onto one.

### A3 — FC movement-function pass (docked FCs)

- [ ] **Audit every movement op for docked-FC correctness** (author 2026-06-19). Push
  / expand / collapse / autofit / tidy / drag each reposition nodes, and a docked FC
  must ride along with its host and re-snap. Coverage is uneven (tidy reserves the
  docked footprint + re-snaps in a deferred rAF; other ops are less careful). Do the
  same rigor the standoff-cluster pass did for standoffs. Touch: `repositionDockedTo`,
  `dockedNodeStore`, `realHostSize` / footprint logic in `Canvas.tsx`. Ties into the
  bug-lane mis-dock fix (both are `findDockTarget` / docking correctness).

### A4 — Units by dimensionality (the big one, own milestone)

The flagship vision (author 2026-06-25). Keyed to the dimensional ladder:

- **Matrix → unit-AGNOSTIC, always** (pure numbers stripped of headers/formatting).
- **List → units PER ELEMENT.** A list is conceptually a ROW (`[3 km, 5 mi, 2 km]`);
  each element carries its own unit, the same way the array-semantics model already
  carries per-cell `null` + `SolError` (`valueKinds.ts`). A unit becomes a per-cell
  tag, not a per-value one.
- **Frame → units PER COLUMN** (already the direction of "FCs on frame columns").
  A frame row is a list, so per-column frame units == the per-element units of any
  extracted row.
- **FCs assign units to STRING-LIST elements used as HEADER KEYS** (can be later in
  the sub-milestone). An FC puts a unit on a header string; building a frame from
  that header list LOCKS each column to its header's unit.

**Worked target UX:** build an Orders header list `[id (none), Item (none), Revenue
($0.00)]` (a string list where "Revenue" carries `$0.00` via an FC), feed it to
Build Frame / Add Column with revenue values `[5, 6, 7]` → forcibly formatted to
`[$5.00, $6.00, $7.00]`, and the per-column FC inside the resulting Frame popup is
LOCKED by the header list's unit.

**Design-first task:** define the **per-cell / per-column unit representation** before
building (a parallel unit array? a tagged cell? matrices opt out). Then:
- [ ] value model — a list element / header gains an optional unit tag; matrices opt out.
- [ ] `unitFlow` — propagate per-element / per-column units; passthrough/transform
  rules apply per cell; Build Frame / Add Column pull the unit from the header.
- [ ] FC + display — render mixed unit suffixes; the FC popup edits a list/column's
  units; an FC can target a string-list header key.
- [ ] aggregators — SUM over mixed units → convert or `#TYPE!` (like element-family
  separation already does).
- [ ] socket lattice — units as the finer-grained sibling of the element-family
  separation it already enforces.

Independent of future dimensionality math (mph); carrying mixed units through
selection / filter / reshape / frame-build is valuable on its own. **Big — its own
milestone; design the representation first.**

**WS-A exit criteria:** one FC model resolves all four axes per value-type off a
written truth table; the FC panel is redesigned on `SegToggle`; docked FCs survive
every movement op; a unit rides per-element through a list and per-column through a
frame, and the header-list→locked-column worked example loads in a seed.

## WS-B — Packs & extensibility

The pack *framework* + the Geometry worked example are done. This stream ships the
persistence gate, then real packs. Design lives in `pack-architecture.md`.

### B1 — Dormant-pack persistence (THE GATE — do before any code pack)

- [ ] **Placeholder node + pack provenance** (gap found 2026-06-21). Saves don't
  record which packs/versions they need, and a missing node type is **dropped (cables
  lost), not placeholdered** (`persistence.ts`). Formula-data packs survive load
  (they serialize as core `ExpressionNode`), so this only bites **code packs** (the
  visual/input packs + `[C]` Timesavers). Build the placeholder-node + pack-provenance
  record before the first code pack, else deactivating a pack silently severs wiring.

### B2 — New core I/O / visual / control nodes

- [ ] From `io-visual-control-node-proposal.md`. Highest-value **core** gaps: KPI /
  stat card (with delta), Dropdown + Multi-select, a real Data Table grid view of the
  Frame type, Scatter / Bubble / Histogram, Bullet graph, range slider, date-range.
  Specialist charts (box / candlestick / sankey / choropleth / 3-D) → packs, most
  behind a single optional heavy renderer (ECharts / Plotly). The first *code* pack
  (recharts-native: Funnel / Treemap / Sunburst / Sankey / Radar) proves the
  custom-widget pack path — depends on B1.

### B3 — Excel Timesavers pack

- [ ] From `timesavers-pack-proposal.md`. ~35 "no single Excel function" idioms:
  ~25 cheap **formula-data** pre-set Expression nodes (one JSON file, first real
  exercise of the formula-pack path beyond Geometry), ~8 **custom-logic** (Spell
  Number, Reverse, duration trio, Split Name, list-reducers, multi-criteria lookup,
  last-non-blank, rank-in-group), ~3 **composites** (Pareto, Join-If, Lookup-all).
  Several list-reducers are general enough to build as **core** Lookup/Aggregation
  nodes and merely tag into Timesavers. The `[C]` custom-logic + composites depend on
  B1; the `[F]` formula-data presets do not.

### B4 — Additional domain packs

- [ ] Electromagnetics (from the flux seed), Finance-pro, etc. Post-v1 polish; the
  capability is proven by Geometry. Each code pack depends on B1.

### B5 — Pack infrastructure follow-ups

- [ ] **Variant switch reconciles the socket set** — a simple pack's variant dropdown
  switches formulas with different variables; switching must add/remove sockets and
  preserve cables on shared variables. Reuse the Expression node's socket
  re-derivation, not new machinery.
- [ ] **Aliasing — many internal ports → one shell parameter** (the stats "confidence
  level" case). Decide v1.1 vs fast-follow: clean vs cluttered advanced panel.
- [ ] **Error UX on restriction violation** — typed error out the socket vs the node
  flagging the offending input locally. Pending.

**WS-B exit criteria:** deactivating a pack placeholders its nodes (no cable loss) and
records provenance in the save; at least one code pack ships on that foundation; the
Timesavers formula-data presets load.

## WS-C — Canvas & interaction

Independent polish. Each item is self-contained; pick up in parallel with WS-A.

### C1 — Grid system

- [ ] Implement `docs/grid-system.md`: soft grid alignment (not forced snap) across
  node placement, alignment helpers, note/group corners; primary grid + sub-grid +
  modifier-to-bypass. NOTE: cable shapes shipped grid-free (the walk router keys off
  socket positions), so gridding cables is a separate design question (see the doc's
  banner) — don't fold it in.

### C2 — Cable collision avoidance

Deferred from the routing spec (`cable-routing.md` §2). The shape system (walk router
+ tangent-exact spline) shipped; these are the routing-quality extensions:
- [ ] **Avoid nodes** — cables route around node bounding boxes.
- [ ] **Avoid cables** — parallel runs + bridge hops at crossings.
- [ ] **Per-cable shape / avoidance overrides** (graph-wide today).

**Invariant guard:** anything here touches `cablePaths.ts` — LENGTH stays the primary
sort key of route selection (gating on turn count first causes visible jumps), and
`cablePaths.test.ts` continuity must stay green. See subsystem-invariants "Cable
routing". Also honor `feedback-never-degrade-cables-in-motion` — full curved fidelity
always, no straightening during drag/pan/zoom.

### C3 — Moveable / resizable / hideable UI chrome

- [ ] User-flagged high-value direction: minimap corner choice (TL/TR/BL/BR), resize
  panels (minimap, inspector, toolbar), hide individual chrome elements. The same
  principle applies to anything added later (command palette, sidebar, console).
  Probably warrants a dedicated `docs/customization.md` once this lands.
- [ ] **Palette override editor UI** — a surface to edit the open doc's per-slot
  overrides (and maybe author/save custom named palettes) from inside the app. The
  store + persistence already support it (`SavedGraph.palette`); this is just UI.

### C4 — Pinch-zoom on trackpad

- [ ] The canvas zooms on Ctrl+scroll (Figma convention); macOS trackpad pinch should
  also zoom (the OS sets `e.ctrlKey` on pinch wheel events). Verify on real Mac
  hardware; if the rete area plugin's handler doesn't honor it, intercept the wheel
  event manually. Deferred from v0.9.

### C5 — Small polish

- [ ] **Pop-up "+ more" actions** — Export, "go to node" (pan/select the host on the
  canvas), copy-as variants. Lower value than the shipped Pin button.
- [ ] **Collapsed mini-preview for pure-visual nodes** — Chart / Gauge / Slicer /
  Sparkline / Heatmap are `collapsible={false}` today (collapsing to "—" was
  pointless). A thumbnail or passed-through value would let them collapse meaningfully.

## WS-D — Data & integration

Node-level integrations, mostly desktop (need the Tauri fs / http layer).

- [ ] **Obsidian markdown import/export — bidirectional sync** (author 2026-06-23).
  Builds on the frontmatter→sockets work. (1) Import a `.md` file as a Note node so
  its YAML keys become typed output sockets; ideally watch/re-read so editing it in
  Obsidian flows into the graph. (2) A markdown EXPORT node — write a Note (or computed
  record) back out as `.md` with frontmatter. Needs a file-path / vault binding + the
  Tauri fs layer (`fileBridge`); the parse (`noteFrontmatter.ts`) + serialize already
  exist for the in-graph half. North-star: a vault of notes ↔ a frame of records.
- [ ] **Image bundling** — embed locally-attached images so they survive save/reload.
  Pure-JSON saves can't carry image bytes without bloat, so this needs a bundle format
  (a `.zip`/folder of graph JSON + assets, or a sidecar) with the local `dataUrl`
  plumbed in. Until then a local attach shows "not saved"; a URL persists.
- [ ] **Finance connection** (GOOGLEFINANCE-ish) — a thin Web Source preset over a
  chosen finance API (current quote + historical table). Brings API-key + rate-limit
  baggage; do only if wanted. Google's backend isn't reusable.
- [ ] **XLOOKUP cube-cell mode** — frame mode shipped (Frame Lookup); the cube-cell
  half looks up into a Cube returning a nested cell, plus approximate match + a typed
  read-as output (the `any` output is the v1 simplification). Also the cube-aware
  **Nest Join for multi-level** (Customer→Order→LineItem). See `cube-node-scope.md`.
  DECIDED and unchanged: flat verbs do NOT map over nested cells (Unnest → verb → Nest
  explicitly).

Not blockers; the eager Rust engine + JS CSV parse are the current ceiling. Pull in

- [ ] **Lazy-plan fusion** — the lazy-handle finish (2026-06-30) keeps a verb chain in

- [ ] **Formula engine periodic re-audit** (author 2026-06-25) — re-sweep node-vs-

## Cross-cutting

- **Read `DESIGN.md` before any UI/visual change** (WS-A redesign, WS-C chrome, new
  visual nodes). The Quiet Accent Rule and the no-accent-stripe rule are the ones you
  violate blind.
- **Subsystem invariants gate the risky touches** — WS-C cable work against
  `cable-routing`, WS-A movement pass against `standoffs` / group-push / tidy. Verify
  against `subsystem-invariants.md`, don't eyeball.
- **`tsc` + `vitest` green after every step; verify visuals on the running app** (the
  author eyeballs; no puppeteer). Web/desktop split stays load-bearing — protect the
  `FrameBackend` seam.
- **Pre-alpha still applies** — break old saves freely; no back-compat shims for
  renames/format changes (the units-representation change in A4 will touch the save
  format; just update seeds + tests).

## Suggested milestones

1. **v1.1-α — FC model + redesign.** WS-A1 (function model spec + code) + A2 (visual
   redesign / SegToggle) + A3 (movement pass). The bug lane lands alongside.
2. **v1.1-β — units.** WS-A4 (units by dimensionality) as its own milestone, plus the
   WS-B1 persistence gate + first code pack.
3. **v1.1 ship.** WS-C polish + WS-D integrations that made the cut; WS-E as pulled in.

WS-A is the release's reason to exist; B/C/D/E are the tail that rides along.
