## How this audit was run

Nine parallel review passes (security, Excel-compute semantics, frame-engine JS↔Rust
parity, persistence/data-loss, performance/memory, code-quality/architecture,
UX/a11y/i18n/release, docs-reconciliation, plus a dependency-advisory sweep), each
told to skip anything already tracked as **v1.1/v1.2 or a known-deferred item**
(FC visual redesign, node packs, grid/collision, image bundling, lazy-plan fusion,
direct CSV→Polars reader, the eager-Rust-engine ceiling, the ≤300-node render target).
Top findings were then adversarially re-verified against the code (and, for the
Excel-semantics items, against live `tsx` probes). Baseline at audit time: `tsc`
clean, **1527/1527 vitest pass**, `npm run build` exits 0.

**Verification legend:** `[CONFIRMED]` = reproduced via probe or exact code read by the
verifier; `[PLAUSIBLE]` = strong code-path reasoning, not executed end-to-end (usually
depends on Rust/Polars runtime or a timing window).

## Scope notes / what is NOT here

- Already-known deferred work (see list above) is excluded by construction.
- Pre-alpha policy honored: **no** finding asks for back-compat shims, migration maps,

- The dependency sweep found **no shipped-dependency CVE** that applies (details in
  §7). The only `npm audit` hits are dev-server-only (vite/esbuild on Windows).

## 1. Compute correctness & Excel semantics

### [P0] 1. Timezone-dependent date-text parsing — off-by-one day east of UTC  `[CONFIRMED]`
- **Where:** `src/graph/nodes/date.ts:21-26` `parseDateToSerial` — the documented "ONE
  canonical text→date parser" — does `new Date(t)` then `jsDateToSerial(d)`.
- **Consumers:** DATEVALUE (`date.ts:171`, floors at `:177`), Cast→date (`cast.ts:85`),
  Get Column read-as Date (`nodes/frame.ts:904`), CSV date columns (`frame.ts:377`; the
  ISO regex at `frame.ts:338` also admits zone-less datetimes), typed date-list literals
  (`coerceInputs.ts:33`), Note frontmatter (`noteFrontmatter.ts:74`).
- **Repro (verified):** `TZ=Australia/Sydney`, `parseDateToSerial("01-Jan-2026")` =
  46022.54 → DATEVALUE floors to **46022 = 31-Dec-2025** (UTC gives 46023). The app's
  **own default display format** `DD-MMM-YYYY` round-trips wrong. Non-floored consumers
  (Cast, datelist literals, Note frontmatter) emit **fractional serials in any non-UTC
  zone**, so `Cast("Jan 3 2026") === DATE(2026,1,3)` is FALSE even in the US.
- **Fix:** parse date-only / zone-less forms to UTC explicitly (extract Y/M/D with local
  getters, rebuild via `Date.UTC(...)`), mirroring the fix already applied to Formula.js
  date results (`excelFunctions.ts:551-556`, which rounds "green in UTC CI, red locally").
- Triple-corroborated (compute + UX passes both reproduced; verifier re-reproduced).

### [P0] 2. Formula range functions bypass the null/error aggregator policy  `[CONFIRMED probe]`
- **Where:** `excelFormula.ts:438` — a `RANGE_FUNCTIONS` name gets its list args passed
  **raw to Formula.js**; the SolError guard at `:436` only checks top-level args, and FX
  has no null-skip / error-propagate contract. Predicted in the 2026-06-22 blast-radius
  audit (dev-notes:2421) but never built.
- **Repro:** `SUM([1,#DIV/0!,3])` → **4** (must be `#DIV/0!`); `MEDIAN([1,null,3])` → **1**
  (FX treats null as 0; Excel skips blanks → 2); `MEDIAN([1,err,3])` → `#DOMAIN!` (garbage
  code); `TEXTJOIN(",",TRUE,[a,err,b])` → `"a,[object Object],b"`.
- **Fix:** in `evalAst`'s range branch, run each array arg through `forAggregate`-style
  prep (propagate first SolError, drop nulls) before dispatch; keep COUNT/COUNTA exempt.

### [P1] 8. IFERROR / IFNA / ISERROR in formulas cannot catch Solenoid-minted errors  `[CONFIRMED probe]`
- **Where:** `excelFormula.ts:434-437` — the call branch returns any SolError arg
  **before** dispatch, for *every* function including FX's IFERROR/IFNA/ISERROR/ISNA.
- **Repro:** `IFERROR(a/b,99)` with b=0 → `#DIV/0!` (Excel 99); `ISERROR(1/0)` → the error,
  not TRUE; `IFERROR(XLOOKUP(...),"default")` broken. Contradicts `errorValue.ts:56`
  "IFERROR catches every code".
- **Fix:** special-case IFERROR/IFNA/ISERROR/ISNA/ISERR/ERROR.TYPE in the call branch —
  evaluate args, apply the same catch semantics as `IFErrorNode`/`IsTestNode` (share
  `isSolError`/`isNaError`), skipping the propagate-first check for those names.

### [P1] 9. NOW()/TODAY() in formulas return raw JS Dates → garbage or #VALUE!  `[CONFIRMED probe]`
- **Where:** `excelFunctions.ts:557` wraps only DATE/EDATE/DATEVALUE/WORKDAY with
  `toSerialIfDate`; FX NOW/TODAY return `Date` objects.
- **Repro:** `YEAR(TODAY())` → `#VALUE!`; `NOW()+1` → a string; bare `NOW()` → null. (The
  TodayNow *node* is correct.)
- **Fix:** register NOW/TODAY through `toSerialIfDate` (TODAY rounds; NOW keeps fraction).

### [P1] 10. VLOOKUP/HLOOKUP/LOOKUP/MATCH/INDEX broadcast element-wise in formulas  `[CONFIRMED probe]`
- **Where:** `excelFormula.ts:312-335` — absent from `RANGE_FUNCTIONS`, so `broadcastCall`
  maps them per element. All autocompletable.
- **Repro:** `VLOOKUP(2,[1,2,3],1)` → `[#N/A,#N/A,#N/A]`. Excel users type VLOOKUP first.
- **Fix:** add them to `RANGE_FUNCTIONS` with 1-D-appropriate internal impls that mint
  `#N/A`/`#VALUE!` SolErrors like XLOOKUP already does.

### [P1] 11. EDATE node doesn't clamp month-end — Jan 31 + 1mo = Mar 3  `[CONFIRMED probe]`
- **Where:** `nodes/date.ts:417-419` `Date.UTC(y, mo, d.getUTCDate())` rolls Feb 31 → Mar 3.
  (Formula-path EDATE via FX is correct; EOMONTH is correct; no EDATE test exists.)
- **Fix:** clamp day to `Math.min(d.getUTCDate(), new Date(Date.UTC(y,mo+1,0)).getUTCDate())`.

### [P1] 12. TIMEVALUE is timezone-dependent  `[CONFIRMED probe]`
- **Where:** `nodes/date.ts:201` `new Date(\`1970-01-01T${text}\`)` (zone-less → local),
  then reads `getUTC*`. `TIMEVALUE("14:30:00")` = 13.5h in Berlin, 19.5h in NY (Excel 14.5).
- **Fix:** parse the time text directly (regex h:m:s) or append `Z`.

### [P1] 13. The "NA" nodes emit null/NaN, not #N/A — advertised IFERROR/IFNA catch never works  `[CONFIRMED]`
- **Where:** `nodeCatalog.ts:184` promises "Outputs #N/A … Catch it with IFERROR/IFNA",
  but the Add-menu entry builds `ConstantNode({op:"na"})` whose value is **NaN**
  (`nodes/input.ts:104`); the separate registered `NaNode` (`nodes/logic.ts:427`) returns
  **null**. Post-2026-06-23 ("NaN is not an error"), ISNA/ISERROR read FALSE and
  IFNA/IFERROR pass through — three different "N/A"s, none the tagged `#N/A`.
- **Fix:** make the NA producer return `solError("#N/A", …)`; delete the dead `NaNode`
  (see §4 quality item) and the NaN constant, or relabel it plainly.

### [P1] 14. RollingNode reduces blind — per-cell error becomes strings; null counts as 0  `[CONFIRMED probe]`
- **Where:** `nodes/list.ts:878-905` — `slice.reduce((a,b)=>a+b,0)` concatenates a SolError
  object; min/max/median/stdev similarly blind. Rolling SUM over `[1,#DIV/0!,3]` w=2 →
  `["1","1[object Object]",...]` (strings in a numeric list). Rolling AVG treats null as 0
  and divides by full window.
- **Fix:** per-window `forAggregate` (propagate error into that cell, skip nulls, divide
  by present count).

### [P2] 25. Ragged-list policy: code truncates-to-shortest but docs say pad-to-longest-with-null  `[CONFIRMED]` — **BUILT 2026-07-02**
- `excelFormula.ts:349-361/392`, `shared.ts:105-138`, `logic.ts:21-31`, SumProduct/SortBy/
  Interleave all truncate; a test even pins it (`excelFormula.test.ts:369`). But
  dev-notes:2398 + backlog say P3 "RESOLVED: pad to longest with null / BUILD LANDED".
  `[1,2,3]+[10,20]` → `[11,22]` (third element vanishes). **Decide:** implement pad, or
  amend the docs to "decided-but-unbuilt".
- **Resolution:** pad implemented (numeric broadcasters emit null at a padded position;
  the logic broadcaster feeds the padded null to Kleene; the paired family keeps its
  min-length zip deliberately — pad-then-pairwise-drop is equivalent). See dev-notes
  2026-07-02.

### [P2] 26. P6 operator parity (settled 2026-06-22) not implemented  `[CONFIRMED]`
- `excelFormula.ts:367-386` `applyOp`: `=` is strict `===` (`"a"="A"` → FALSE; policy +
  Excel: case-insensitive TRUE); cross-type `<` silently coerces (policy: `#TYPE!`); `&`
  renders `String(v)` (`TRUE&"x"` → `"truex"` not `"TRUEx"`; `null&"x"` → `"nullx"`);
  string `+` concatenates and flows out on a numeric socket. **Decide/implement** the
  settled P6 table, or re-document P6 as unbuilt.

### [P2] 27. Boolean formula results collapse to null in Expression + LAMBDA family  `[CONFIRMED probe]`
- `expression.ts:21-25` (`guard`: boolean→null), `tableLambda.ts:91-95` (`cell`). `a>b`
  in an Expression → null; `MAP(x, x>2)` → all-null matrix. P7 logical shipped for
  nodes, not for the formula hosts. **Fix:** pass booleans through (display already
  renders TRUE/FALSE); note this is arguably outside the "Expression capped" decision,
  which covers dimensionality/complex, not logicals — author call.

### [P2] 28. XLOOKUP / Frame Lookup / frame filter text matching is case-sensitive  `[CONFIRMED probe]`
- `excelFunctions.ts:534,540` (strict `===`), `frameVerbs.ts:746` (`keyMatches`),
  `frameVerbs.ts:145` (filter eq). Excel default match is case-INsensitive.
  `XLOOKUP("Apple",["apple",...])` → `#N/A`. **Fix:** case-insensitive string compare;
  keep EXACT as the case-sensitive escape hatch.

### [P2] 29. TEXT() can't format date serials  `[CONFIRMED probe]`
- Formula TEXT → FX, which date-formats JS Dates, not serials. `TEXT(46096,"yyyy-mm-dd")`
  → `"46096"`. **Fix:** internal TEXT that detects date/time codes and routes through
  `formatDateSerial`.

### [P2] 30. AggregateNode STDEV.S(single)=0; SUM([])=null — inconsistent with peers  `[CONFIRMED]`
- `nodes/list.ts:1040` (`<2 → 0`; Excel `#DIV/0!`; sibling `var_s` correctly blanks),
  `:1025/:1115` (empty/all-null SUM → null; formula path and `aggregateGroup` both say 0).
  **Fix:** stdev n<2 → `#DIV/0!` (or null to match var_s); sum/[] → 0, product/[] → 1.

## 2. Frame engine — JS↔Rust parity, handles, async

### [P0] 3. Desktop GroupBy returns all-null for 7 of 12 aggregation ops  `[CONFIRMED]`
- **Where:** the node UI offers `product/median/mode/stdev/stdevp/var/varp`
  (`components/FrameNodes.tsx:187-200`) and routes the op ungated to the backend
  (`nodes/frame.ts:304-306`). The JS oracle implements all (`frameVerbs.ts:199-215`).
  Rust `aggregate_group` implements only sum/avg/min/max/count; everything else is
  `_ => Cell::Null` (`engine.rs:689-693`, verified).
- **Impact:** Group By `median` → web shows medians, **desktop shows an all-null column**,
  silently, no error.
- **Fix:** implement the remaining ops in `aggregate_group` (~30 lines of pure `Vec<f64>`
  math mirroring the oracle) **or** gate the extended ops to the JS verb. Add a cargo
  parity test per op.

### [P0] 4. Desktop RIGHT JOIN can mislabel columns  `[PLAUSIBLE]`
- **Where:** `verb_join` rebuilds output names **by position**, assuming
  `left(coalesced-in-place) + right-non-key`, guarded only by a count check
  (`engine.rs:896-925`). Polars with `CoalesceColumns` emits a **different column order
  for `JoinType::Right`** (coalesced key lands after left non-key cols) — Polars issue
  #20911, same 0.46 era as `Cargo.toml:37`. Count still matches → positional rename swaps
  labels, so key values appear under a non-key column's name **and inherit its SolType**.
- **Impact:** `orders[id,qty] RIGHT JOIN customers[id,name]` → desktop has `qty` values
  under the `id` header; web correct; no error.
- **Fix:** reorder the joined frame **by name** before renaming (account for Polars'
  `_right` suffix); add right/outer-join cargo parity tests (currently only inner+left,
  `engine/tests.rs:189-224`).

### [P1] 15. Join row order not guaranteed on desktop — `maintain_order` never set  `[CONFIRMED code / PLAUSIBLE effect]`
- `JoinArgs::new(how).with_coalesce(...)` (`engine.rs:885`) leaves `maintain_order` =
  default `None`; Polars docs say join order must not be relied on unless set. Oracle is
  strict left-row order with grouped fan-out (`frameVerbs.ts:341-360`). The engine header
  claim "inner/left/right match" is unbacked. **Fix:** `.with_maintain_order(Left/Right/
  LeftRight)`; add a fan-out ordering parity test.

### [P1] 16. Filter value coercion drifts (empty value, "true"/"false", "1,234")  `[CONFIRMED]`
- The Filter value is always a string (`nodes/frame.ts:176`, default `""`). JS uses
  `Number(value)` + JS truthiness for logical cols (`frameVerbs.ts:150-151`); Rust
  trims/strips-commas/`parse::<f64>` (`engine.rs:589-602`).
  - `""` (**the default!**): JS `Number("")`=0 compares vs 0; Rust NaN → `gt` keeps
    nothing, `neq(NaN)` keeps everything.
  - `"1,234"`: JS NaN (never matches); Rust 1234 (matches).
  - logical col, `"false"`: JS truthy→1 (matches TRUE rows — itself an oracle bug); Rust
    NaN (matches nothing).
- **Fix:** coerce the filter value **once in JS** per column type (reuse `coerceLogical`/
  `cellToNumber`), send a typed value over the wire; logical branch uses `coerceLogical`.

### [P1] 17. Logical cells aggregate as 1/0 in Rust but are skipped by the JS oracle  `[CONFIRMED]`
- Rust maps `Cell::Bool → 1.0/0.0` into the numeric set (`engine.rs:677-684`); JS
  `forAggregate` → `Number.isFinite(true)` is false → booleans excluded (`frameVerbs.ts:197`).
  Group By SUM over a logical column: desktop = count of TRUEs, web = 0. **Fix:** decide
  once in the oracle (coerce logical→1/0), match Rust, parity-test.

### [P1] 18. JS backend source handles can never be freed — web-session memory grows unbounded  `[CONFIRMED]`
- `inputHandle` caches `be.source(input)` in `_sourceCache` (WeakMap) and relies on a
  `FinalizationRegistry` to `drop` when the FrameValue is GC'd (`frameBackend.ts:301-323`)
  — but `JsFrameBackend.source` stores **the same FrameValue strongly** in its handle map
  (`frameBackend.ts:147-167`). Circular: the store pins its own registry key, so the
  finalizer never fires. Every Frame Input edit / Web Source refresh leaks the previous
  frame for the whole web session, even after node delete / doc switch. **(Independently
  found by the performance pass too.)**
- **Fix:** hold sourced frames as `WeakRef` on the JS backend, or treat `source()` as
  identity (handle payload = the frame itself), or clear source-tagged handles in
  `forgetAllNodes`.

### [P1] 19. `emitFrame` has no pass-generation guard — a stale out-of-order compute drops the live handle  `[PLAUSIBLE]`
- `nodes/frame.ts:42-47`: a superseded pass's `data()` isn't aborted (rete only discards
  the result). If stale pass A resolves after fresh pass B, A sees `_ref(refB)!==refA`,
  **drops refB** (the handle B just published), installs stale `refA` + preview. Rapid
  edits upstream of a verb chain on desktop (IPC widens the window) → spurious
  `#REF! frame handle not found` + stale preview.
- **Fix:** per-node monotonic token: `const gen=++node._gen` at `data()` entry; in
  `emitFrame`, if `gen!==node._gen` drop `out` and return without touching `_ref`.

### [P2] 31. NaN cells silently become null at the IPC boundary  `[CONFIRMED code]`
- A typed number/date column can hold NaN in JS (`frame.ts:208-211`); `JSON.stringify(NaN)`
  → `null` before Rust sees it (`engine.rs:188-220`). Oracle treats NaN as **present**
  (count/distinct/sort/`neq` all differ). **Fix:** normalize NaN→null in the oracle too
  (preferred), or encode NaN on the wire; document + fixture.

### [P2] 32. GroupBy/Select can emit duplicate column names in JS but hard-error in Rust  `[CONFIRMED]`
- `groupByFrame` applies no `makeHeaders` (`frameVerbs.ts:240-251`) and names the agg
  after the source column, so "count of Region grouped by Region" → two `Region` columns
  in JS, `#ERROR!` in Rust (`engine.rs:284-292`). Same for `selectColumns(f,["a","a"])`.
  **Fix:** `makeHeaders` over groupBy/select output in the oracle; parity test.

### [P2] 33. One Rust panic permanently poisons the global store mutex  `[CONFIRMED code]`
- Every path does `store().lock().unwrap()` while holding the lock across the whole verb
  (`engine.rs:133-157` etc.); no `panic=abort`. A Polars panic poisons the `Mutex` →
  **every later engine call fails until app restart**, webview still running. **Fix:**
  `lock().unwrap_or_else(|p| p.into_inner())` (or `parking_lot`); ideally compute on a
  cloned `DataFrame` outside the lock (also de-serializes all engine calls).

### [P2] 34. `WireOp::Pivot` is a stale, incompatible shape vs the JS `FrameOp` pivot  `[CONFIRMED]`
- Rust `WireOp::Pivot{index,columns,values,agg}` (`engine.rs:405-412`) is the pre-PIVOTBY
  single-field shape; JS pivot is the full `PivotSpec`. Nothing routes pivot through the
  backend today (PivotNode is eager), but `runFrameUnary`'s docstring advertises pivot
  and `applyVerb` dispatches it — any future caller gets a serde error or wrong cross-tab.
  **Fix:** delete `WireOp::Pivot`+`verb_pivot` (dead) or fix the docstring + leave a
  comment pointing at the eager-Pivot decision.

### [P2] 35. Webview reload orphans every Rust-side handle for the process lifetime  `[CONFIRMED]`
- The Rust store is process-global; only per-handle `engine_drop` frees (JS-driven).
  Ctrl+R / HMR full reload discards JS state → every source + verb `_ref` leaks until
  process exit; `initFrameBackend` doesn't clear. **Fix:** add `engine_clear`, call it
  from `initFrameBackend` when selecting Polars.

*(Frame P3s — `\u{1}` multi-key separator collision, GC-timing source freeing, non-finite
aggregates → null over the wire — in §6.)*

**Parity-test gaps to add (Rust side, `engine/tests.rs`, currently 19 tests):** right/
outer join, null-key join rows, fan-out row order, key dtype mismatch; groupby null/multi
keys + logical agg + date min/max type preservation + all non-basic ops (finding 3);

## 3. Persistence & data-loss

### [P0] 5. Undo history is never cleared/suppressed across loads → corruption that autosave persists  `[CONFIRMED]`
- **Where:** `new HistoryPlugin<Schemes>()` with **no limit** (`Canvas.tsx:1178`); **no
  `history.clear()` anywhere** (verified). `rebuildGraph` tears down + rebuilds via
  editor add/remove (`persistence.ts:308-421`), each recorded by the classic preset
  (removes re-add the node instance on undo); `beginGraphRebuild()` gates only the app's
  own pipes, not the history plugin.
- **Scenario:** after a startup restore or a File-menu doc switch, Ctrl+Z (live whenever
  not typing, `Canvas.tsx:791`) unwinds the **load itself** — deleting freshly-loaded
  cables/nodes and re-adding the *previous* document's node objects into the current
  canvas — then autosave (700 ms) writes the Frankenstein graph into the current slot;
  two autosaves fill both rotation slots. Also a real memory leak (§5, finding 20).
- **Fix:** `history.clear()` at the end of every successful `loadGraph` (expose a
  `setClearHistory` hook from `process.ts` like `setPushHistory`), and/or a pipe ahead of
  the plugin dropping node/connection events while `isGraphRebuilding()`; pass a `limit`
  (e.g. 200) as a backstop.

### [P1] 20 (persistence). Load failure leaves `currentId` pointing at the wrong doc → next autosave overwrites it  `[CONFIRMED code]`
- `documentStore.open()` does `captureCurrent(); setCurrent(id); persist(); showCurrent()`
  and **ignores `loadGraph`'s boolean** (`documentStore.ts:206-213`, `:115-118`);
  `loadGraph` returns false on the version-ceiling refusal and rolls the canvas back on a

## 4. Security

*(Dependency posture: clean — see §7.)*

### [P0] 6. Stored XSS via unsanitized Note markdown → Tauri IPC/filesystem access  `[CONFIRMED]`
- **Where:** `NoteNode.tsx:216` `marked.parse(data.renderBody, …)` (marked **14**, no
  default sanitization, no DOMPurify present) → `NoteNode.tsx:358`
  `dangerouslySetInnerHTML`. A Note body is arbitrary user text that persists in the save
  and travels between users.
- **Amplifiers:** `tauri.conf.json:23` `csp:null`, `:13` `withGlobalTauri:true`, and
  `capabilities/default.json` grants `fs` read/write/read-dir over **`$HOME/**`**, `http`
  over all `http(s)://**`, plus `opener`.
- **Scenario:** a shared `.solenoid` file (the stated threat model) carries a Note whose
  body injects an `<img src=x onerror=...>` (event handlers on injected elements fire via
  innerHTML). The script has full `window.__TAURI__` → read/exfiltrate/overwrite any file
  under `$HOME`, open arbitrary URLs. No CSP blocks it.
- **Fix (two independent layers):** (1) sanitize note HTML (DOMPurify, or a marked
  post-step) — strip event-handler attrs + `<script>`; (2) set a restrictive `csp`
  (`default-src 'self'`) so an injection can't reach IPC even if it lands.

### [P1] 23 (security). No defense-in-depth around IPC: `withGlobalTauri` + `csp:null` + `$HOME/**` fs  `[CONFIRMED]`
- Same config as above, as a standing weakness independent of the Note sink: any future
  DOM-injection bug escalates straight to arbitrary `$HOME` I/O + network egress. **Fix:**
  set the CSP; drop `withGlobalTauri` (code already uses the `@tauri-apps/api` import
  path); narrow the `fs` scope (saves go through the `dialog` plugin's user-selected
  paths, so a blanket `$HOME/**` grant isn't needed).

### [P2] 39. CSV/clipboard export doesn't neutralize formula-injection prefixes  `[CONFIRMED]`
- `TablePopup.tsx:66-70` `csvField` RFC-4180-quotes but doesn't escape leading `= + - @`
  (or tab/CR). Copy a table containing a `=cmd|...`/`=HYPERLINK(...)` string cell → paste
  into Excel/Sheets → formula executes. Solenoid becomes an injection carrier. **Fix:**
  prefix a `'` (or wrap) when a string cell's first char is `= + - @`/tab/CR.

### [P3] (security) devtools reachable in release builds
- `Cargo.toml:24` builds the `devtools` feature unconditionally; `open_devtools` is
  wired to F12 (`lib.rs:60-72`). Intentional per comments; combined with XSS it lets an
  injected script pop devtools. **Decide:** gate behind `#[cfg(debug_assertions)]` or
  accept + document. Also drop `--enable-unsafe-webgpu` from `additionalBrowserArgs`
  (`tauri.conf.json:19`) — the WebGPU render path is superseded (verify no live
  `navigator.gpu` use first).

**Verified security non-issues:** the Expression/LAMBDA `new Function` codegen is **not**

## 5. Performance & memory

### [P1] 20. Undo history unbounded + records every doc switch — retains removed node instances (and their frames) forever  `[CONFIRMED]`
- Same root cause as the P0 (finding 5): no `limit`, no clear, records `rebuildGraph`'s
  ~2(N+E) add/remove actions **per doc switch/open/seed load**, each holding full node
  instances — `cachedResult` frames, Image base64 `dataUrl`s, Note text. Secondary: the
  retained FrameValues **pin their Rust-side Polars frames** (finalizer never fires).
  **Fix:** as finding 5 (`clear` on rebuild + `limit` backstop).

### [P1] 24. A lazy `FrameRef` is fully collected once **per consumer per pass** — no memoization  `[CONFIRMED code]`
- `coerceInputs.ts:186-196` runs `readFrame` (→ `engine_collect`, **all columns**) per
  input value; no cache by handle. A Filter fanned to 3 Get Columns + Display + Chart on
  500k rows = **5 full-frame JSON serializations per pass**, pure redundancy. Also
  `GetColumnNode` isn't in `LAZY_FRAME_NODES`, so it gets a full-frame collect despite the
  backend's `column(handle,name)` primitive existing for exactly this. **Fix:** memoize
  `collect` per handle for the pass (Map cleared in `processGraph` begin); route
  GetColumn through `backend.column()`.

### [P2] 40. Every cable connect/disconnect triggers a full recompute + render-all  `[CONFIRMED code]`
- `Canvas.tsx:2340-2349` calls bare `processGraph()` → `_engine.reset()` (wipe all caches)
  + fetch + `area.update` every node (`process.ts:457-542`). Wiring one unrelated scalar
  cable re-runs every Polars chain, re-collects every preview, re-renders all React roots
  (unmemoized recharts included). The targeted path exists but is wired only for value
  edits. **Fix:** reset/render only `downstreamClosure(target)` (∪ source on removal) —
  the machinery exists; only `_cachedLoop` needs recompute since topology changed. Memoize
  chart subtrees on their data props as an independent win.

### [P2] 41. `makeAnnotationResolver` rebuilt per render per value box, O(connections) per hop  `[CONFIRMED code]`
- `DisplayNode.tsx:32-37` + `nodeKit.tsx:439-451` construct the resolver in the component
  body every render; each `inAnnotation` hop does `for (const c of editor.getConnections())`
  (`unitFlow.ts:110-198`); the memo lives one render. Plus `formatAnnotationStore.getForNode`
  scans the whole map with `startsWith` per call. On a 300-node/400-cable graph → ~10⁵–10⁶
  connection touches per pass, growing quadratically. **Fix:** one resolver per graph
  version (memoize on `connectionVersionStore.get()`); index connections by target once.

### [P2] 42. Source-handle cache defeated by non-memoized frame producers (BuildFrame) → full re-upload per pass  `[CONFIRMED code]`
- `_sourceCache` is keyed by FrameValue identity; `FrameInputNode` is memoized to stay
  hot, but `BuildFrameNode.data()` builds a **fresh** FrameValue every call
  (`nodes/frame.ts:751-756`), so each pass re-serializes the whole matrix over
  `engine_source` (and, on web, leaks it — finding 18). **Fix:** give BuildFrame (and any
  per-pass producer) the identity-stable memoization FrameInput has.

### [P2] 43. HTML-in-Canvas layer: any single node change re-clones + re-captures + re-mips the ENTIRE graph  `[CONFIRMED code]` *(feature-gated: renderMode "html")*
- `HtmlCanvasLayer.tsx:262-286` `scheduleRebuild` (subscribed to 8 stores + the area
  render pipe) always calls `engine.setNodes(specs)`, a **full rebuild** — release every
  ImageBitmap, deep-clone every DOM node, re-capture, rebuild every mip pyramid (~8
  `createImageBitmap`/node) (`htmlCanvasRenderer.ts:204-286`). Editing values on 300 nodes
  → 300 clones + ~2400 bitmap creations per commit. The targeted `updateNodes` exists but
  is used only for selection deltas. **Fix:** diff changed ids (the render pipe carries
  them) and call `updateNodes`; reserve `setNodes` for topology/theme.
