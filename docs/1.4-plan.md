# Solenoid 1.4 — release plan (PROPOSAL, 2026-09-01)

> **STATUS: PROPOSAL — awaiting the author's cut.** 1.3 shipped (v1.3.0 on `main`). This is
> the planning pass the backlog's "Deferral review" item asked for: every parked, deferred and
> author-gated idea walked, scored, and either planned here, planned in [`2.0-plan.md`](2.0-plan.md)
> (the structural arcs), or left in [`deferrals.md`](deferrals.md) (parked, no plan). Nothing here
> is scheduled until the author promotes it: a promoted item becomes a line in
> [`backlog.md`](backlog.md) (the task truth) and its plan section here is the spec. When an
> item lands, delete its section; when the release ships, this file archives.

**How to read a plan.** Each item carries a score (rubric below), the grounding (where it
lives in code, what already exists), the build steps, the tests that pin it, the gate (an
author call, a license, a design pass) and a done-definition. Line numbers are deliberately
absent — grep the symbol. **No time estimates anywhere, by order.**

## Theme

1.3 finished the engine body (parity, the analytics shelf, Script, computed columns, the
React Flow port). **1.4 is the workbench release: the canvas becomes a place you *operate* a
model, not only build one.** Four ideas carry it:

1. **What-if surgery** — pin, mute, peek, and a hover brush that shows a node's cone, plus an
   Optimize run mode so "min/max this subject to that" stops being the one Solver-shaped hole.
2. **Records and tables, finished** — the Record node's view family and the table popup get
   the display lifts the competitor sweep found, and categorical columns get their 1.4 look.
3. **Everyday sources** — the widget nodes (Weather / Geocode / Holidays / FX / TZ / QR) that
   make a document worth leaving open, behind a per-document network permission.
4. **Surface hardening** — the formula surface becomes declared-only (allowlist), the rules
   get their ARR pass, node-combining round 2 lands, and the AI palette comes back on.

Not 1.4, by design: anything that changes what a *document* is (pages, cloud, multiplayer),
the Excel transpiler, conditional formatting, the canvas-at-scale rework — `2.0-plan.md`.

## The rubric (used here and in `2.0-plan.md`)

| Axis | Values | What it measures |
|---|---|---|
| **Strength** | Strong / Solid / Weak | How much the idea improves the product on its own terms — would a user go find it and play with it (the release-notes bar) or does it close a real hole |
| **Relevance** | Core / Adjacent / Peripheral | Fit to the identity sentence — *inspectable, typed computation over data, in a file the user owns* — and to this release's theme |
| **Complexity** | Low / Medium / High / Very high | Design plus build difficulty. NOT time |
| **Blast radius** | Contained / Moderate / Wide / Structural | Contained = one module and its test. Moderate = one subsystem, a few docs. Wide = several subsystems, or the save format, socket lattice, or value model. Structural = touches identity, `decisions.md`, or an architecture seam |
| **Call** | IN / PULLABLE / AUTHOR / HOLD / DROP / 2.0 | IN = recommended for 1.4. PULLABLE = fits 1.4 if capacity allows. AUTHOR = cannot be placed without a decision. HOLD = stays parked with its trigger. DROP = recommend ruling it out. 2.0 = planned in `2.0-plan.md` |

## Track A — What-if surgery on the canvas

The competitor dive (2026-08-18) found four canvas verbs every mature node tool has and
Solenoid lacks: pin (n8n / KNIME), mute (Blender / n8n), peek (Blender viewer), hover-cone
(marimo). Together they make the canvas a what-if bench. They share one design surface (a
node-state badge) and one engine hook (a node whose `data()` is replaced by a held value or
a pass-through), so they ship as a track, badge pass first.

### A0 — Node-state badge design pass (new; prerequisite)

**Why.** Pinned, muted, stale (`compositeStaleStore`), held-after-Solve, and disarmed-sink
are all "this card is not computing what it looks like it computes" states. Today the card
has a corner badge and lock glyph (`NodeCard.tsx`, `nodeCard.css`) and the composite status
dot. Four new states without one design read as four inventions.
**Do.** One DESIGN.md § Cards addition: a single badge slot with a fixed vocabulary (pin,
mute, stale, held, disarmed), Quiet Accent Rule (state is a glyph and a border treatment,
never a fill), the tooltip copy per state (§7 Voice), and how a muted/pinned card's value
box reads (pinned shows the held value with the pin glyph; muted shows the passed-through
input). Also settle whether the badge is a click target (pin/unpin, mute/unmute) — recommend
yes, mirrored in the node context menu and a single-key shortcut.
**Gate.** Author eyeball on the dev server. **Done.** DESIGN.md section + `nodeCard.css`
vocabulary in place; A1/A2 build on it.

### A1 — Pin a node's output

**Score.** Strong · Core · Medium · Moderate.
**Grounding.** The compute pass is `graphCompute.ts` (`computeAll`, `invalidate`); every
`data()` is wrapped at `nodecreated` by `coerceInputs` then `installErrorGuards`. A held
value is a third wrapper layer, or a guard-level short-circuit: if the node is pinned,
return the held result and skip `data()`. Live connections already hold `cachedResult`
serving synchronously; volatile nodes freeze per recalc generation
(rules freezeVolatilePerCalc). Provenance: a pinned value IS a labeled literal — the origin
stamp (`errorsKeepOrigin`) should say "pinned at <time>".
**Design calls (recommend).** (1) Pin captures the CURRENT output value(s) and persists them
in the save: a pinned FrameRef must be collected to a `FrameValue` at pin time (a lazy
handle does not survive a session) — cap it (head-N with a "pin collected N rows" badge
tooltip, or refuse to pin a frame past a row budget). (2) Upstream edits do not recompute
the pinned node or its downstream cone (`invalidate` stops at pinned nodes — the one real
engine change; targetedEqualsFull must still hold: pin state is part of the graph state
both passes read). (3) Unpin recomputes. (4) A pinned node reads visually per A0.
**Steps.** Pin state in a node-keyed store (`registerNodeForget`, rules storesRegisterForget)
persisted through the text-form sidecar (rules saveViaTextForm — add to BOTH `writeTextForm`
and `readTextForm`) → guard short-circuit → `invalidate` stops at pins → card badge +
context-menu verb + shortcut → Problems panel ignores pinned errors? (no: a pinned error is
still an error). Composite internals: pins inside a drill-in persist with the composite.
**Tests.** `graphCompute` targeted-vs-full parity with a pin in the cone; text-form
round-trip of a pinned scalar / list / frame; unpin recomputes; seeds unaffected.
**Interacts with.** Calc modes (manual mode + pins are orthogonal), the parked #23 compute
cache (a pin is a user-chosen cache entry; #23 would be the automatic one — design pin's
storage so #23 can reuse it), provenance Tier 2.
**Done.** Pin/unpin from badge, menu and key; survives save/load; downstream holds; tests.

### A2 — Mute / bypass a node

**Score.** Solid · Core · Medium · Moderate.
**Grounding.** Blender's M-mute passes the first compatible input to the output. Solenoid's
socket lattice (`sockets.ts` `accepts`) decides what "compatible" means, and rules
`widenNeverNarrow` / `noAutoCross` bound it: a mute may only pass a value whose type the
output socket accepts.
**Design (the real work).** Per node, the pass-through rule: for each output, the first input
whose declared type is accepted by that output (same family, rank ≤). Nodes with no such pair
(sources, sinks, most frame verbs with a frame in and frame out DO qualify; Aggregate list→
number does NOT) show mute as unavailable — the badge tooltip says why. Multi-output nodes
map per output. Under mute the node's `data()` is skipped (guard-level, same layer as A1);
the card shows the pass-through per A0; the value box shows the passed value.
**Steps.** `mutePassthrough(node): Record<outputKey, inputKey> | null` as a pure function
over the node's sockets (testable without an editor) → guard short-circuit → badge/menu/key
→ sidecar persistence (same discipline as A1) → drill-in parity.
**Tests.** The pass-through table over every catalog leaf (a shape guard: count of mutable
nodes pinned, so a new node with a surprising rule is a deliberate change); targeted-vs-full;
round-trip.
**Done.** Mute/unmute on any eligible node; ineligible nodes explain; persists; tests.

### A3 — Peek any socket — PROMOTED (author 2026-09-04c), reshaped

The line is in `backlog.md`; the earlier menu-verb design is superseded.

### A4 — Dependency-cone hover brush

**Score.** Solid · Core · Low · Contained.
**Grounding.** Isolate already computes upstream/downstream cones (`isolate.ts`,
`isolateBoundary.ts`); where-used highlight shipped; cable hover state lives in
`cableState.ts`; `FlowCableEdge` styles from it.
**Do.** On card hover (desktop pointer only; touch has no hover) with a short dwell, soft-
highlight the node's upstream cone one way and downstream the other (two treatments, DESIGN.md

Setting-gated (Settings ▸ Canvas), default on. Must not fight the HIC gesture layer (brush
only when the DOM surface is idle).
**Tests.** Cone membership is already pinned by the isolate tests; add the dwell store's
pure state transitions. **Done.** Hover shows the cone; no jank at 200 nodes (probe script).

### A5 — Fusion indicator

**Score.** Weak · Adjacent · Low · Contained. The lazy-handle engine work landed; the seam
knows which chain flushed as one `applyMany` (`frameBackend.ts` `flushRef`) and which
consumer forced a materialization. Show it in the `CableInspector` (a "fused with N upstream
verbs / materialized here" line) and as a tiny glyph on verb cards in a debug Setting. Value

### A6 — Optimize run mode (new; replaces "constrained optimizer node")

**Score.** Strong · Core · High · Moderate.
**Why this shape.** The deferral framed Solver parity as a sibling node of Equation. The
Solenoid-native shape is already in the codebase: **Goal Seek is a composite RUN MODE** (as
are Scenarios, Data Table, Monte Carlo, Simulation). Excel's Solver is Goal Seek generalized:
N decision inputs, one objective output (min / max / target), constraints as logical outputs
that must hold. So: a sixth run mode, **Optimize**, on the composite, with the same arm-and-
run status dot and `compositeStaleStore` semantics. No new node, no acausal machinery.
**Design.** Decision variables = the composite's chosen numeric inputs with bounds; objective
= one numeric output + min/max/target; constraints = any logical outputs (must be TRUE) and
optionally numeric outputs with ≤/≥ bounds. Method: derivative-free (Nelder–Mead with a
penalty for constraints, or COBYLA) — the subgraph is a black box, so gradient methods are
finite-difference anyway; Excel's GRG/Evolutionary are the parity reference, exact
algorithm match is not (consistencyOverQuirks). Integer/binary constraints: v1 no (say so).
Outputs: the optimum, the decision values, iterations, a converged flag, and a Problems
entry when infeasible.
**Steps.** Pure optimizer kernel in a rete-free module (rules implReteFree) pinned against
scipy on the classic test functions → the run-mode driver reusing Goal Seek's parameter
surface (`maxIterations` / `tolerance` / bounds) → run controls UI in the drill-in panel →
a seed ("Production plan" — the textbook LP-ish example, solved by penalty).
**Gate.** Author call on scope (constraint forms, integer no). **Done.** The composite
answers "max profit subject to capacity" without a Solver node; seed + kernel tests.

### B2 — Select / categorical columns

## Track H — Allocator-family analytical nodes (PROPOSAL 2026-09-04)

Same DNA as the **Allocator** (renamed from Budget Allocator this session): a small closed-form
linear problem, exact and solver-free, tedious to wire by hand. From a domain sweep the author
promoted three; parked two to `deferrals.md` (blend/mix, loan-term solver); ruled break-even a
composite run mode (A6 territory), not a node. **Each ships WITH a seed** (bake it via
`scripts/tune-seeds.mjs`, per the 2026-09-03 authoring rule).

### H1 — Payoff Planner

Nearest neighbour to the Allocator — the same "spread a fixed pot by a rule, cascade the freed
slack" mechanic, over time instead of across ranges.
**Design.** Rows are debts (Balance, APR, Min payment) + an `extra` monthly literal. Order by
**Avalanche** (highest APR) or **Snowball** (smallest balance) via ArgSelect; pay every minimum,
throw `extra` + each freed payment at the head debt, roll month by month. Closed-form
amortization, no solver. Output mode-selected: a schedule frame (Month · per-debt balance) or a
summary (Debt · Months · Interest · Payoff date). Carry the Balance column's currency unit.
**Seed.** "Debt payoff" — 3–4 debts where avalanche vs snowball visibly reorder and differ in total interest.
**Gate.** Schedule-frame vs summary as the default output (author).

### H2 — Apportionment (AUTHOR: mode vs node)

Split N indivisible units across groups by weight so they sum **exactly** to N — the integer
sibling the Allocator deliberately isn't (continuous, range-bound).
**Recommendation: a NEW node, not an Allocator mode.** The Allocator requires min/max price
columns and emits fractional money; apportionment takes a single total N + weights, no ranges,
integer output, exact-sum. Folding it in would fork the card's socket set and validation — here
noDuplicateNodes points the other way (different inputs, different invariant). Reuse the
water-filling intuition, not the node.
**Design.** Weights column (or wired list) + total N literal; method ArgSelect — **Largest
remainder (Hamilton)** / **D'Hondt** / **Sainte-Laguë**. Output: Group · Quota · Seats, integer
and exact-sum.
**Seed.** "Seats by population" — the classic Hamilton vs D'Hondt divergence on one dataset.
**Gate.** Confirm new-node over mode; which methods v1.

### H3 — Group Cost Settle

Rows are people (Paid, optional Share weight); output the minimum set of transfers that settles
everyone up. Net each balance, greedily match the biggest creditor to the biggest debtor.
Linear, greedy-exact, a real pain by hand.
**Design.** People frame in; net = Paid − Share·(ΣPaid / ΣShare); emit a transfers frame
(From · To · Amount) + a per-person Net column. Currency unit carried.
**Seed.** "Trip split" — four people, uneven payments, settled in three transfers.
**Gate.** Equal-split vs Share-weighted default (both supported; pick the default).

### Scheduling slice — calendar-shaped, solver-free (PROPOSALS 2026-09-04b, AUTHOR-GATED)

The first pass (Hours Balancer as an Allocator mode, Shift Assignment via Hungarian, a
round-robin Rotation generator, an Erlang staffing requirement) was judged decent but not
calendar/schedule-shaped enough. Reworked here for a **simplistic user** — someone with a
roster, a date range and a total to spread — keeping only what has an exact, explainable answer
with **no solver**. Each ships with a seed. Nothing below starts until the author picks.

**Not a node — hours balancing IS the Allocator.** "Spread 160 shift-hours across a team with
contract min/max and a weight" is Fit budget with an hours unit. Propose a **seed** ("Balance a
team's hours": people rows Min · Max · Weight, the Allocator with `h` on the Min column, a Display
of Share as %) and loosening the Allocator's socket copy from "price range" to "range" so hours
read naturally. Zero code beyond copy.

#### H4 — Rota (shift fill-in)
The direct answer to "who covers which shift". **In:** a Shifts frame (Date · Shift · Needed,
optional Hours) and a People frame (Name, optional Max hours, optional Off — a text cell of days
or dates the person can't work). **Mode (ArgSelect):** *Round robin* — everyone in turn in roster
order, skipping the unavailable, resuming where it left off; *Fewest hours first* — each slot goes
to the available person with the least assigned hours so far (ties by roster order). **Out:** an
Assignments frame (Date · Shift · Person) and a Load frame (Person · Shifts · Hours); a slot no
one can take stays as an explicit `Unfilled` row rather than silently vanishing. Greedy,
deterministic, explainable — not optimal, and says so. A "no back-to-back" or skills constraint
tips into the Optimize run mode (A6); v1 stays pure.
**Seed.** "Weekend cover" — 6 people, 4 weekends, two slots a day, two people with days off; the
Load table shows the fairness.  **Gate.** Confirm the two modes; whether Off is days-of-week,
dates, or both.

#### H5 — Spread over dates (phasing)
The Allocator's proportional DNA over a calendar: one total, one date range, one rule. **In:**
Total, Start, End (or Days), a Holidays date list. **Rule (ArgSelect):** *Every day* / *Working
days* (skip weekends + holidays) / *By weekday weights* (a Mon..Sun weights row) / *Ramp* (front-
or back-loaded, linear) / *By month length*. **Out:** Date · Amount · Cumulative, unit carried
from Total. What Excel users build from WORKDAY/NETWORKDAYS by hand. Simple user: phase a
quarterly budget, a savings plan, planned hours per day.
**Seed.** "Phase a budget across Q4" — even vs working-days vs ramp side by side, one chart.
**Gate.** Which rules v1; whether a wired per-date weights frame replaces the weekday row.

#### H6 — Schedule (task timeline, CPM forward/backward pass)
**In:** a Tasks frame (Task · Duration in days · Predecessors as a text cell "A, B"), a project
Start date, Working days on/off + a Holidays list. **Out:** Task · Start · Finish · Float ·
Critical (logical), best-first order kept. Topological order + earliest/latest passes — exact
arithmetic, not a solver; a cycle or an unknown predecessor is a `#VALUE!`. The data half of
the 2.0 Gantt figure. Simple user: "when will these be done, and which task can't slip?"
**Seed.** "Kitchen remodel" — 8 tasks, the critical path filtered out beside a Display.
**Gate.** Working-day arithmetic by default (yes?); whether Float ships in v1 or later.

#### H7 — Common free time
**In:** an Availability frame (Person · Day-or-Date · From · To, times as serials or "9:00"),
optional At least N people, Minimum minutes. **Out:** Day · From · To · Who (count or names) —
the windows the whole group (or any N) is free for at least the minimum. A sorted interval
sweep, exact. Simple user: "when can the four of us meet?"
**Seed.** "Find a meeting slot" — four calendars, one 45-minute window pops out.
**Gate.** Whether it takes busy windows (calendar exports) as well as free ones.

**Parked from the first pass** (`deferrals.md`): Shift Assignment (people × shifts score matrix
→ best one-to-one matching; Hungarian is exact but reads as a solver and answers a question a
simple user rarely asks) and Staffing requirement (Erlang C; call-centre specific).

## Track I — Fold the Format Controller into the Display (AUTHOR PROPOSAL 2026-09-04, LATER)

**The idea (author).** Instead of a docked FC that pushes format/unit BACKWARD onto the box
feeding it and forward through the resolver, the Display node IS the format point: a value is
formatted and unit-tagged where it is shown, and that flows DOWNSTREAM only until another
Display overrides. One direction, no docking.

**For.** Deletes the two-direction machinery — `fcDocking.ts`, `dockedNodeStore`, dock
reconcile, host-socket hiding, reposition-after-layout, the upstream resolver walk — and the
"a chip on a socket formats the box behind it" rule users must learn. The FC popup becomes the
Display's popup. Unit lock states (forwarding / lockedByConvert / dictation) stay as they are,
in fewer places.

**Against, and the answer.** The FC's one irreplaceable job is authoring a unit on a LITERAL at
its source (unit-flow lane A: an FC on a Number input). So the fold needs its second half:
**source nodes (Number, Date, Text, list inputs) carry the same control** — format and unit are
set at sources and at displays, never pushed backward; everything between inherits downstream
(the 2026-09-04 formatFlowsDownstream rule is this model's first half, already landing). Smaller
losses, accepted: formatting a compute node's OWN box means inheriting or adding a Display; a
multi-output node wants one Display per formatted output; charts / lambdas / documents keep
their view-as options on the Display.

**Scope.** Delete: the FC node, docking (`fcDocking.ts`, `dockedNodeStore.ts`, `fcReconcile.ts`'s
dock half, `FormatControllerNode.tsx`/`.css`, the socket-hiding + reposition paths, the
`downstreamAnnotation` walk). Move: the format popup onto Display + the source nodes;
`formatAnnotationStore` keyed per node. Migrate: every seed with an FC (19 in unit-flow alone —
re-author as source units / Display formats, re-tune), the unit-flow seed's captions (A–J),
`format-model.md`, `subsystem-invariants.md` § Unit flow, `rules.md` (`unitOnValue`,
`relaysTransparent`, `formatFlowsDownstream`), the node-coverage FC entry, the Reference copy.
**Sequence.** After the downstream-flow + surfaces work has been lived with; then a 1.4 item
with its seed migration in the same commit series. **Gate.** The author's go, and the source-node
control design (a compact unit/format chip on the input cards — DESIGN.md pass).
