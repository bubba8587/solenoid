# Solenoid 2.0 — release plan (PROPOSAL, 2026-09-01)

> **STATUS: PROPOSAL — awaiting the author's ratification.** Supersedes the 2026-07-08
> release view. 2.0 collects the arcs that change what a *document* is or how the canvas
> scales; each is built WITH the author in a dedicated session. The 1.4 workbench release is
> [`1.4-plan.md`](1.4-plan.md) (the rubric lives there); bundle-level detail lives in
> [`v2.0/`](v2.0/README.md). **New surface by author order (2026-09-01): accounts, cloud saves,
> multiplayer editing** — `v2.0/21-collaboration.md`. No time estimates, by order.

## Theme — what 2.0 changes about a document

1.x made a document a single canvas in a single file that one person computes with. 2.0
changes three of those words:

- **single canvas → pages** (Arc 1): one file, many canvases, references across them.
- **one person → people** (Arc 2): an identity, a place the file also lives, others editing
  it with you. This is the identity fork the out-of-scope draft argued against; the plan is
  built to keep the exits open (the file is still yours, exportable, self-hostable).
- **a canvas you built → a canvas you imported** (Arc 3): a workbook opens as a graph.

Around those: conditional formatting (the last big table-display flagship), the canvas-at-
scale rework (virtualization, worker painting), the value-model extensions, and packs as a
real program. 2.0 is the release where **`noBackCompat` flips** — the first external user is
the first cloud user — so a save-format freeze and a migration seam are prerequisites, not
features.

## Arc 1 — Pages (`v2.0/20-pages.md`)

The author's ruling (2026-08-30): tabs are **pages in one document** — one save file, tabs
are canvas pages of it, pages reference each other's nodes; explicitly NOT concurrently-
loaded library documents with cross-doc links. The bundle recommends **one editor and one
engine serving all pages** (pages as view scopes) and settles the cross-page reference
rendering (portals at the page edge — the archived Portal idea, finally with a job). It is
the prerequisite for the transpiler's sheets → pages mapping and makes multiplayer's "who is
on which page" natural. Blast radius is Wide because everything positional (Tidy, minimap,
lasso, standoffs, groups, fly-to, isolate) becomes page-scoped — one filter at the RF
projection (`flowModel.ts` `toFlowNodes`) does most of it if the model carries `page` on the
node.

## Arc 2 — Collaboration: accounts, cloud saves, multiplayer (`v2.0/21-collaboration.md`)

**The framing.** `out-of-scope.md`'s test 3, §3 and §11 said no — but that doc is a DRAFT
with no ARR (rules `authorRuled`: nothing outside `rules.md` is author-ruled), so the "no"
was the agent's inference and the author's order is the FIRST ruling on this ground. Those
sections and decisions R5 are rewritten to the order (2026-09-01). What the inference got
right survives as design constraints, not objections: **the cloud holds the
same file** (the text form + sidecar), the client is local-first (offline works, sync catches
up), every hosted piece has an exit (export everything; a self-hostable relay), and the
staging lets the author stop at any stage with a coherent product:

- **Stage 0 — your own sync folder** (no server): file watch + reload + conflict copy. Cloud
  saves for one person across devices via Dropbox/OneDrive/iCloud. Pullable into 1.4.
- **Stage 1 — accounts + cloud library**: sign-in, a hosted document list, versions (P5),
  share links with viewer/commenter/editor roles, the AI palette's key becomes account-held.
- **Stage 2 — asynchronous collaboration**: comments with real identity (the shipped node-
  anchored comments + `commentAuthorStore` grow an account), presence ("3 people have this
  open"), last-writer-wins with a conflict copy — the posture out-of-scope §3 always allowed.
- **Stage 3 — real-time multiplayer**: a CRDT document keyed by the addressable model's
  stable NAMES, the rete editor as its view, per-user undo, awareness (cursors, selection,
  viewport follow). Every client computes (purity makes results agree; volatile and live
  nodes are the documented exception).

The bundle carries what it costs (a service: auth, storage, abuse, privacy/deletion, uptime,
support, billing) and the security work that stops being optional the day one person opens
another's document: **trust on open** (Script's sandbox is containment, not a boundary;
sources fetch on load; Write sinks already load disarmed — P2), and CSP closure of the
worker's `import()` door.

## Arc 3 — The Excel transpiler (`v2.0/08-excel-transpiler.md`)

The bundle is current on the parser machinery (`excelFormula.ts` AST, `NODE_EXCEL`,
`EXCEL_GAP`, the redirect table, the 70% strategy). Three updates from this pass:
1. **Sheets → PAGES, not Groups** (Arc 1 lands first). Cross-sheet references become
   cross-page connections rendered as portals — exactly the thing pages exist for.
2. **Excel Tables (ListObjects) → Frame Inputs with computed columns.** Structured references
   (`[@Price] * [@Qty]`) map almost 1:1 onto tableRefSemantics (`@name` = this row, bare name
   = the column). This is the transpiler's best-fidelity path and should be the SECOND thing
   built after the arithmetic spike — it is where real workbooks keep their logic.
3. **A fidelity report is a deliverable**, not a nice-to-have: per formula — mapped / redirected
   / fallback Expression / dropped — as a frame the user can filter, and as Problems entries.
   Named ranges → node names (the addressable model makes this free). Data-validation lists →
   B2's categorical columns. Parser dependency: an xlsx reader (SheetJS community edition or
   exceljs; the license and bundle size are the gate — desktop-only import is acceptable for
   v1). Score: Strong · Core · High · Moderate (an importer touches no live subsystem).

## Arc 4 — Conditional formatting (`v2.0/23-conditional-formatting.md`)

The author's bar: must clear Excel's version by a lot; Display-side only; must not step on
FC format/units territory. The bundle proposes the Solenoid-native reading of "by a lot":
**a rule is a graph value, not a hidden dialog** — a wired or computed logical/number
column drives color scales, data bars, icon sets and chips as per-column DISPLAY annotations
in `frameFormatStore` (never the unit), inspectable and wireable like everything else, with
1.4's chip mechanism (B2) as the first primitive. Design pass first; the open questions are
listed there. Score: Solid · Core · Medium · Moderate.

## Arc 5 — Canvas at scale (`v2.0/22-canvas-at-scale.md`)

Headless card metrics (Pretext), RF `onlyRenderVisibleElements` (virtualization — the memory
lever), HIC painted from a worker, figure rasterize-at-rest, and the parked high-memory bug —
one arc because they share a precondition: **a card's size must be computable without
mounting it.** Sequence: 1.4's heap snapshot (F5) → headless metrics → virtualization →
worker HIC. Score: Solid · Core · High · Wide (every layout consumer reads mounted geometry).

## Arc 6 — Value-model extensions and decision sensitivity

- **Uncertain values app-wide** (`v2.0/12` #21): the composite-scoped `UncertainNumber`
  (mean ± sd) exists; going app-wide means a propagation rule in `forAggregate` and every
  element-wise op, display as a unit-like suffix, a `±` field on Number Input, and the Monte
  Carlo bridge. Wide. AUTHOR representation call stands (symmetric ± vs interval) — the
  composite precedent argues for ± . Sequenced last.
- **Money mode** (`v2.0/12` #43): recommend **per-unit scope** — currency is already a unit
  (firstClassUnits, noMixCurrencies), so exact-decimal arithmetic can key off "this value
  carries a currency unit" rather than a per-document mode: a decimal path in the JS oracle
  plus Polars' `decimal` dtype, and a rounding-policy setting on the `RoundNOp` pattern.
  Still Wide; AUTHOR.
- **Decision sensitivity** (`v2.0/10`): the Monte Carlo shape (wire `DecisionMatrixNode`'s
  weights through the composite MC run mode) is 2.0; the minimal ±N% affordance is
  1.4-pullable (D13).

## Arc 7 — Packs as a program

The composite pack-node shape (packs declaring a subgraph + boundary ports; the queue is
`pack-composite-plans.md`) and the B1 distribution + dependency system (`archive/v1.1-plan.md`:
bundled / downloadable / local tiers, a manifest with `version` and `dependencies[]`, the
load-time PROMPT, `SavedGraph.packs` finally consumed, the absent-pack formula diagnosis).
Rides P1: a pack manifest is the second versioned artifact after the save. 1.4's E1 (general
port aliasing) is the model half it needs. Score: Solid · Adjacent · High · Wide.

## Arc 8 — Timeline / Gantt

The author's "loves Gantt, not now; probably a MUST eventually for the all-in-one feel."
The decomposition from the 2026-08-18 review stands and is the plan: (a) a display figure in
the Waterfall class (bars from Task / Start / End; dependency arrows optional; zoom by day /
week / month), (b) a **Schedule** computation as a frame verb — forward pass over Task /
Duration / Depends with a Holidays input (WORKDAY math in `date.ts`; on both backends per
oneVerbCorpus), (c) no bar editing ever (edits happen in the table). The calendar figure is
the sibling and ships after, on the same date-keyed layout code. Score: Strong · Adjacent ·
High · Moderate.

## Prerequisites that cut across arcs (the gaps this plan fills)

- **P1 — Save-format freeze + migration seam.** `noBackCompat` says it flips the day the first
  external user exists; cloud saves and shareable packs create that user. Before Arc 2 Stage 1:
  bump `CURRENT_SAVE_VERSION`, define the migration seam (a per-version pure `SavedGraph →
  SavedGraph` step list run by the load gate, tested on frozen fixtures of every prior
  version from the freeze on), and decide what "forward refusal" means for a cloud document
  edited by a newer client (the server stores the version; older clients open read-only).
  The text form is the migration's friend: name-addressed, canonical, diffable.
- **P2 — Trust on open** (`v2.0/21` § Trust). 1.4's C2 (network permission on foreign
  documents) grows into: Script disabled until allowed on documents you did not author,
  sources quiet, sinks disarmed (already), a visible "restricted" banner, and the worker's
  `import()` door closed by CSP on web and desktop.
- **P3 — Desktop updater + release channel.** A portable exe on GitHub Releases is fine for
  one user. Cloud users on an old client are a support cost and a save-format hazard: Tauri's
  updater plugin, a signed manifest published by `windows-portable.yml`, a stable/beta channel
  Setting. Contained.
- **P4 — The web-target decision.** Multiplayer on the web makes web a real target, which
  reopens polarsEngine ("web = look and try"). Options: (a) collaboration is desktop-first,
  web is a read/comment client; (b) the JS oracle IS the web engine — semantically identical
  by corpus, slower, fine for the documents people share; (c) a WASM engine (Polars-WASM if
  production-ready, else DuckDB-WASM behind the seam — the recorded alternative). Recommend
  (b) for Stages 1–2 and decide (c) only if a real workload forces it. AUTHOR.
- **P5 — Version history + in-app diff.** Cloud saves keep versions; the text form is the
  unit and `textDiff.ts` (the AI apply-approval view) already renders a line diff. A version
  panel that restores or diffs any two versions revives the deferred snapshots idea (#6) in
  its natural home. Ships with Stage 1.
- **P6 — Accessibility baseline.** A shared product gets users you did not pick: keyboard-
  only canvas operation (the command palette and single-key map exist; the gap is focus
  order across cards and sockets), names on every control, reduced-motion respect (the HIC
  layer and cable flow already have toggles). Pullable; do a pass before Stage 1 goes public.

## Verdict pending → placed

- **#23 persistent compute cache** — HOLD, but 1.4's pin store (A1) is designed as its seam:
  a pin is a user-chosen cache entry; #23 is the automatic, hash-keyed one, verb tier first,
  desktop only, advisory. Revisit when a real workload makes reopen-recompute painful.
- **#35 MCP port** — HOLD. The 2026-07-03 verdict stands (the CLI covers "read structure, set
  inputs, run, get outputs"); the one gap — driving the SAME live session — is exactly what
  Stage 3's sync model provides for free (an agent is another client of the CRDT document).
  Revisit after Arc 2; do not build a second op layer before then (aiWholeDocRewrite).

## Sequencing (dependency order, not dates)

1. **P1 save-format freeze** and **Arc 1 pages** (independent; pages changes the format, so
   pages lands before the freeze is declared).
2. **Arc 2 Stage 0** (no server) any time; **Arc 3 transpiler** after pages; **Arc 4 CF** after
   1.4's chip primitive; **Arc 5** after 1.4's memory findings.
3. **Arc 2 Stage 1–2** after P1 + P2 + P3 (+ P6 pass); **Arc 7 packs** with P1.
4. **Arc 2 Stage 3 multiplayer** last among the collaboration stages; **Arc 6** last overall.

## Not happening

The ruled-OUT list in `v2.0/README.md` stands (named dimensions, model linter, synthetic
data, data slots, formula lens, PDF/OCR, guided tutorials, history scrubber, shared-
definitions library, structured templates, the trust-machinery cluster, publish-as-form,
transform-by-example, sealed models, list-of-frames…). Arc 2 does NOT revive publish-as-form
or the embeddable-engine identity: sharing a document is not shipping it as an app.
