# Solenoid — Node coverage

`nodeCatalog.ts` is the source of truth — the Add menu AND the in-app Function
Reference (Ctrl+/) are generated from it, so a node's catalog `description` is its
Reference entry. This file is a human-readable inventory by category plus the
non-obvious per-node notes. (Moved out of CLAUDE.md to keep the always-loaded doc
lean; update it when the catalog changes meaningfully.)

**Add-menu pane ROW BUDGET** — the rule behind every catalog regrouping: a category
pane holds about **12 rows** before it needs a scrollbar, so a pane growing past ~12
gets its tail folded into subcategories rather than left flat (the 2026-07-16 sweep
applied this across charts, statistics, hyperbolics, bitwise, and the frame verbs;
control widgets folded into Input 2026-07-09, freeing the top-level row Packs uses).
A future node addition that flattens a pane back past the budget reintroduces the
scrollbar that sweep removed.

**Scalar**: Input, Constant, Arithmetic (all ops), Math functions, Rounding, Trig (a `Math` node's trig ops carry a **deg/rad/Auto** SegToggle — Auto (default) reads the incoming unit so a °-tagged value computes in degrees, else radians = Excel parity; Rad/Deg pin it; forward trig converts the input, inverse trig converts the result and tags the `deg` unit; resolved at recompute time by `trigMode.ts` — the one place compute reads units), Hyperbolic, Logarithms, Combinatorics, Bitwise, Engineering, **Comparison + Boolean logic** (emit the first-class **logical** type — purple, TRUE/FALSE, coerces ↔ 1/0; AND/OR/NOT are Kleene 3-valued on `null`. **Restructured 2026-06-23:** the old multi-op `LogicalNode` was split into **`BooleanOpNode`** — AND/OR/XOR/NAND/NOR/XNOR as **N-ary reducers** over extensible operand rows, all emitting logical so the op switch never swaps the socket — plus a standalone **`NotNode`** (unary element-wise flip). **Operand inputs are `logicalcombo` (purple), not `numlist` (2026-07-15)** — a boolean op takes booleans; a number still bridges in (0/1 ⟷ FALSE/TRUE). Rows are WIRE-ONLY like IfNode's condition (you wire a comparison/test) and a standalone **`IfNode`** (value passthrough, `util`-colored like its Choose/Switch/Ifs siblings, NOT logical)), **IF / IFS / SWITCH / CHOOSE** (the value selectors — all **variadic now**: CHOOSE has add/remove value rows over a fixed `index`; IFS takes any number of condition/value pairs **plus an "Otherwise" fallback**; SWITCH takes any number of when/then pairs between a fixed `expr`/`default`; see `docs/archive/node-arity-audit.md` + the **Labeled-slots vs list-input rule** below for why these are labeled per-slot inputs, not list sockets), IFError, NA, **IS.TEST** (`IsTestNode` — labeled "IS.TEST"; op dropdown ISNUMBER/**ISNULL**/ISBLANK/ISERROR/ISNA/ISBOOLEAN/ISTEXT/ISNONTEXT, where ISBOOLEAN is our name for Excel's ISLOGICAL — the `islogical` op value is unchanged for save compat. ISNULL is the per-cell missing test (≠ unwired); every check tests per-cell to any depth incl. a frame. Doubles as the error-inspection surface, see Error values), **ISEVEN/ISODD** (`IsEvenOddNode` — a single parity-test node with an even/odd toggle; emits the **logical** type TRUE/FALSE (not 1/0) and broadcasts over a list — extracted from the Math op-dropdown 2026-06-23 so it could carry a logical socket; lives in the Logic menu), **Alert** (watch a value — fires a toast + logs to the Alerts HUD on a changed trigger; see subsystem-invariants "Alert node + Alerts HUD"). *(Removed 2026-06-23: the **T / N / TYPE** coercion-info nodes — their input socket was never rendered so they were unwireable, and Cast + the socket type system + Test supersede them; and the multi-op **`LogicalNode`**, split as above. Old saves load these as Placeholders — wiring/data kept, re-saved as the original type.)*

**Lists**: Literal, Range, LinSpace, Geometric, Fibonacci, Aggregate (a fixed-op 1-D list reducer — 19 ops: sum/avg/min/max/count/median/product/stdev/var/geomean/…; class `AggregateNode`, header title "Aggregate". Renamed from "Reduce" so it isn't confused with the table-taking REDUCE lambda), List Filter (D16: 1-D ONLY; label renamed from FILTER 2026-07-09 with its Frame sibling, the list against its own values — the frame Filter's condition engine, extensible AND/OR op+value rows, text ops + Match case, `anylist`; the old mask and table acceptance are GONE — tables go to Frame Filter, which a matrix enters as auto-named Col1..N; permanent `Dropped` = the exhaustive complement), Coalesce/Fill (a bundled missing-value node — `FillNode`, op selector: constant/ffill/bfill/mean/median/mode/interpolate/drop/coalesce; per-cell errors pass through, statistics impute from present values), List Sort, Reverse, Slice, Take, Drop (Reverse/Slice/Take/Drop/Shuffle/NthElement/Interleave/Pad are element-agnostic `anylist` — position-only ops, the D15 coherence sweep; the single-input ones — Reverse/Slice/Take/Drop/Shuffle/NthElement/Pad, + matrix TRANSPOSE/CHOOSEROWS/COLS/TAKE-DROP/EXPAND — are PASSTHROUGH nodes (2026-07-15): adoptive in+out + a `passthrough()` decl, so a reversed/transposed date list keeps its type + date formatting downstream instead of decaying to a neutral `anylist`. The multi-input rungs of the append ladder — Concat Lists, Interleave, VSTACK/HSTACK — and the rank-changing TOCOL/WRAP are opted in too, via `agree` over their rows and a rank projection respectively; see passthrough.ts / subsystem-invariants "Passthrough"), Unique, Set (two-list set ops — `SetOpNode`, op selector: union/intersection/difference (A∖B)/symmetric difference; compares by value, dedupes + preserves first-seen order like UNIQUE, ignores nulls, errors survive except in intersection; Solenoid-native — Excel ships only UNIQUE), Set relation (two-list set PREDICATES → logical TRUE/FALSE — `SetRelationNode`, op selector: equal/subset (A⊆B)/superset (A⊇B)/disjoint; same value-set semantics as Set; both unwired → null; the companion to Set), Diff, **Concat Lists** (the 1-D rung of the APPEND LADDER, D15: N extensible element-agnostic `anylist` rows joined in row order; a scalar widens to a 1-element list), Interleave, Pad, Repeat, Shuffle, NthElement, Index, Length, Contains, NthValue, ArgMin/Max, SumProduct, Cumulative, Percentile, Quartile, Percentrank, Rank, Normalize, Standardize, Correl, Covariance, Fisher, Rolling aggregates.

**Stats**: NormDist, NormInv, NormSDist, NormSInv, TDist, TInv, ChisqDist, ChisqInv, FDist, FInv, BetaDist, BetaInv, GammaDist, GammaInv, BinomDist, BinomInv, LognormDist, PoissonDist, and more.

**Finance**: TVM — ONE acausal Equation node covering PMT/PV/FV/NPER/RATE (wire four of {rate, nper, pmt, pv, fv}, the fifth solves; payment-timing dropdown swaps the locked relation; rate = 0 uses the exact limit form), Compound Growth (fv = pv·(1+rate)^nper; covers PDURATION/RRI) and Effective Rate (EFFECT/NOMINAL) as locked Equation presets, IPMT/PPMT, CumPmt, NPV, IRR, MIRR, depreciation (SLN/DB/DDB/SYD/VDB), bond pricing (PRICE/YIELD, odd coupons, accrued interest), XIRR/XNPV.

**Distributions**: normal/t/chi-sq/F + inverses, beta, gamma, lognormal, Weibull, exponential, binomial, Poisson, hypergeometric, negative binomial; Z/T/F/Chisq tests.

**Text**: Text Input, case/trim transforms, CONCAT, TEXTJOIN/SPLIT, LEN, FIND/SEARCH, SUBSTITUTE/REPLACE, TEXTAFTER/BEFORE, **REGEX** (REGEXTEST/EXTRACT/REPLACE), VALUE/NUMBERVALUE, TEXT/DOLLAR/FIXED, ROMAN/ARABIC, CHAR/CODE, ENCODEURL, list-wise Text Filter. **Every element-wise text node broadcasts (2026-07-25):** operands are `strcombo`/`numlist` and a wired list spills element-wise, Excel-array-formula style (`=UPPER(A1:A10)`) — see the Element-wise operand rule below. *(Removed 2026-07-25: **Text Map** ("UPPER (list)") — Text Transform with a list wired in IS it now; old saves load it as a Placeholder.)* The exceptions are deliberate: CONCAT/TEXTJOIN REDUCE a set to one string (Excel's CONCAT flattens an array rather than spilling), TEXTSPLIT and Text Filter are already 1-D → 1-D (broadcasting would need a rank-2 result the lattice has no 1-D→2-D edge for), and Regex stays on the wildcard ladder because its element type depends on the op — though it now emits `anycombo` rather than `any` (2026-07-25), so its dot no longer draws a scalar circle on a port that can spill a list.

**Date & Time**: TODAY/NOW, DATE/TIME construct, date parts, WEEKNUM/WEEKDAY, DATEDIF, workdays/networkdays, date formatting.

**Complex numbers**: COMPLEX build/unpack, 16 unary ops, 4 binary ops, IMPOWER.

**Build Frame** / **Frame from Lists** — the matrix⇄frame constructors, both TYPE-BY-ADOPTION (2026-07-15). "Slap headers on a table → Frame" (Build Frame) and "N typed lists → a mixed Frame" (Frame from Lists); adding columns is other nodes' job. Their value inputs are **adoptive** sockets (`adoptiveTableIn`/`adoptiveListIn` — an `AdoptiveSocket` with an `anytable`/`anylist` BASE instead of `trueany`): they accept any element family AND adopt the wired cable's concrete type via `settleWildcardTypes`, so a `datetable`/`datelist` → **date columns**. This is the only way `date` survives — a serial is indistinguishable from a number at the value level (`colTypeForSocket` maps the adopted socket → `FrameColType`; `null` for a not-yet-adopted `anytable`/`anylist` or `complex` falls back to value inference). `typedColumn`/`buildFrameTyped` (core `frame.ts`) do the typing; a numeric matrix still routes through the unchanged `buildFrame` (byte-identical). Headless (`run-graph.ts`, no settle pass) degrades to value inference (date→number). The old `columnFromCells` + Frame-from-Lists' "dates arrive as numbers, retype downstream" limitation are GONE.

**Split Frame** (`SplitFrameNode`): Frame → Matrix + Headers, with a **column-type filter** SegToggle (All / Num / Date / Bool / Text). Filtering to a type pulls just those columns out of a MIXED frame (which plain "All" can't — any text column makes the number matrix null); both Matrix and Headers are filtered. **The Matrix output socket type tracks the filter** (`splitMatrixOutput` + in-place swap via `applySplitColType`, like Get Column's read-as): number/all → `table`, date → `datetable` (serials), bool → `logicaltable` (1/0), text → `strtable` (a real string matrix, not null). `colType` persists via extractInit.

**Frames / Table verbs** (`nodes/frame.ts` + `frameVerbs.ts`; the relational family): Get Column (read-as retype incl. Boolean), Get Row, Add Column, Frame Filter, Frame Sort, Join (incl. as-of + semi/anti modes), Group By (Frame), Append, Distinct, Head, Sample, PIVOTBY, Unpivot, Nest, Unnest, the cleanup verbs (Fill Down, Replace Values, Drop Blank Rows, Select/Drop Columns, Rename, Split Column, Merge Columns, Add Index (incl. the TWO-WAY option, author 2026-07-16: the same data indexed on BOTH axes as a coordinate-bordered matrix — exactly the grid Surface / Contour / Grid Interpolate read; a wired matrix widens to Col1…N and gets row + column indices counting from Start), Headers), Reconcile, and the cube family (Nest Join, Build Cube, Cube Columns, Cube Rollup). **Frame XLOOKUP `search_mode`** decides which row wins on DUPLICATE keys: "first" (default, Excel's mode 1) scans top-to-bottom, "last" (mode −1) bottom-up; Excel's binary modes (2 / −2) are deliberately omitted — on a materialized column a binary search over sorted data finds the SAME row a linear scan does, a pure speed knob with no distinct result here, and we always scan linearly for correctness. **Reconcile** classifies each key as added (right-only) / removed (left-only) / changed (a shared column differs) / unchanged with before/after/Δ per shared numeric column; when both a price and a quantity column are named (numeric on both sides) it decomposes the total (price×qty) change into the textbook three-term PRICE/VOLUME/MIX variance — price = (P1−P0)·Q0, volume = (Q1−Q0)·P0, mix = (P1−P0)·(Q1−Q0) — which sums EXACTLY to P1·Q1 − P0·Q0. **Computed Column** (`ComputedColumnNode`, D24/D25): adds ONE defined column mid-pipeline — an inline formula or a wired λ; a bare name (or `[Name]`) is the WHOLE column as a list, `@name` / `@[Name]` is this row's cell; λ params stay row-bound; free names grow `anydata` SIDE-INPUT sockets (`sideVars`, persisted) with per-variable column-binding pickers; `addAs` types the result, `After` places it; one definition per column, never per cell. This node is WHY frames stay out of formulas (D23): the row iteration lives here and the formula only ever sees scalars (author direction 2026-07-29 — the frame stays pure data, the computation is a graph citizen). Per-row contract mirrors the broadcast rules: an error cell in any BOUND column propagates to that row's output (first in binding order); a null flows INTO the formula (ISBLANK/IF can see it — a formula is not an element-wise op); the output column's type is inferred from the computed cells, and a `Name (unit)` header tags the unit like Add Column. The same definition model lives on Frame Input's per-column source picker (**Data | Formula | λ**) — both surfaces run `computedColumnCore.ts`, so they cannot disagree. **Query** = a Composite pre-shaped for data transformation (verb chain inside, Manual-refresh mode — the Power Query shape, D22).

**2D Tables / Matrix**: Table Input grid (a LITERAL source on Frame Input's model: raw text is the stored truth, bad cells derive to NaN with the quiet affordance, the grid editor edits Source text; ONE element type per table via a Num/Text/Date/Bool SegToggle that retypes the output socket in place — header accent tracks it), MMULT, MDETERM, MINVERSE, MUNIT, TRANSPOSE, **VSTACK/HSTACK** (the 2-D rungs of the append ladder, D15: N extensible `anytable` rows stacked in row order; a list counts as ONE ROW; ragged inputs pad with #N/A cells like Excel), WRAPROWS/COLS (leftover cells pad with #N/A, Excel's default pad_with), TOCOL/ROW, CHOOSEROWS/COLS, **TAKE/DROP (table)** (2-D edge cuts, rows+cols in one node, negative = from the end, 0 = omitted arg), **EXPAND** (grow to R×C; wired Fill or #N/A; shrink is #VALUE!), ROWS/COLUMNS. (Node kind `table` — vermilion accent matching the table socket; see `kind.ts`.)

**Input/Control**: ScalarInput, BooleanInput, Slider (its ◄/► step buttons are the "stepper"), AngleDial, **DatePicker** (native calendar → date serial), **XYPad** (drag a 2D handle → X/Y in [0,1]), **ColorPicker** (RGB / HSV sliders with gradient-painted tracks, or a Hex text field — a third mode; output-format dropdown hex/rgb — CSS-valid only, no `hsv()`/`hsl()`; output socket sits on the swatch row below the dropdown; conversions via the `colord` lib; feeds Chart Builder's Color), **ColorBlend** (two CSS color-string inputs — typeable or wired — × a blend-mode dropdown: mix/multiply/screen/overlay/soft·hard-light/darken/lighten/difference/exclusion/dodge/burn, W3C separable formulas per RGB channel, A = backdrop; hex out on a ColorPicker-style swatch row; unparseable input → `#VALUE!`; `colord` gained the `names` plugin globally so "tomato" parses; kind `string`), Slicer, RandBetween, RandArray, Sequence.

**Formula**: **Expression** node — type `a * b + 1`, named variables auto-become input sockets; full math-function scope + list broadcasting. **Per-variable explanations (2026-07-09):** each variable can carry a prose description (`varDescriptions` map, kept OUT of the formula string so KaTeX never renders it) — a hover tooltip on the card + an editable legend under the KaTeX in the formula popup; shared with **Equation and LAMBDA** (all three use the same formula popup), seeded on some pack presets (Ohm's Law, ideal gas…). A **LAMBDA wired into a Report renders its formula as KaTeX with a muted "where:" legend beneath** (the value carries the descriptions) — the math-renders/prose-explains split. The **lambda-helper family** is MAP / BYROW / BYCOL / REDUCE / **SCAN** / MAKEARRAY (each runs an inline formula or a wired LAMBDA value): **SCAN** (2026-07-10) is REDUCE's running-intermediate twin — the same row-major fold from Initial but it emits the accumulator after every cell, keeping the input's shape (a running total is `acc + value`, a running max is `MAX(acc, value)`); the fixed-op Cumulative covers CumSum/CumMax and REDUCE gives only the final value. **Polyform** (2026-06-19): a Number/Text/Date/Auto result-type selector lets it (and MAP/BYROW/BYCOL/REDUCE/SCAN/MAKEARRAY/LAMBDA) loop ANY Excel function over arrays of any element type — `UPPER(name)`, `first & " " & last`, `DATE(y,m,d)` — swapping the output socket to match; Expression variable inputs are `anydata` (scalar / 1-D list / 2-D matrix — the D23 lift; frames and cubes stay out permanently, the verb engine is their surface, and a Computed Column carries row formulas). LAMBDA's capture sockets stay `anylist`. See the "Polyform" dev-notes entry. The names `pi`/`tau`/`e`/`phi` resolve to constants (`FORMULA_CONSTANTS` in `excelFormula.ts`), not variables — they're skipped by `extractVariables` and inlined by codegen + `evaluateSteps`, so the whole formula engine (Expression, LAMBDA, MAP/BYROW/REDUCE…) sees them.

**Equation** (`EquationNode`, `equationSolve.ts`, decision D14): the acausal sibling of Expression. Type a relation (`V = I * R`); every variable gets an input AND an output socket, plus a fixed logical **Check** (output key `holds`) output. Exactly one unknown (unwired, empty literal) -> solved: symbolic AST isolation when the unknown appears once (`+-*/^`, POWER/LOG, EXP/LN, SQRT, trig/hyperbolic, DEGREES/RADIANS, unary minus, %) -- the isolated form unparses to a formula and recompiles, so list broadcasting is free; otherwise a QUADRATIC-in-the-unknown residual (numerically probed, any arrangement) solves via the quadratic formula and yields EVERY real root as an ascending list (x² = 36 -> [-6, 6]; double root scalar; negative discriminant #SOLVE!), and anything else falls to a numeric log-grid + bisection fallback on the LHS-RHS residual (scalar-only, `#SOLVE!` when no real root). All variables known -> Check is a relative-tolerance (1e-9) truth check, broadcasting per-element. Principal branches on inversion (sqrt, ASIN). Wired variables pass through to their outputs, so the node doubles as a labeled junction.

**Decision support**: **Decision Matrix** (`DecisionMatrixNode`, frame kind, in the Table-verbs menu) — a port of the jortscity Decision Matrix Bases View. Scores + ranks a Frame of options (rows) by criteria (number/logical columns — NOT date; an optional leading text column names them): weighted average `Σ(score × weight) / Σ|weight|` (a NEGATIVE weight penalises a lower-is-better criterion), then competition rank. Each detected criterion gets a row: a **labeled, default-1 weight box** (`node.weightMap`) **and a per-column normalize override dropdown** (`node.normMap`) — the latter is DMBV's per-column "Rank Raws" (rank just the $-scale columns). The global `normalize` SegToggle is the default each column inherits; `none`/`÷max`/`rank` where **÷max and rank both land in [0,1]** so mixed-mode columns stay comparable (the point of normalizing: weights, not scale, decide influence). The `weights` socket is an optional positional override for computed weights. `detail` SegToggle (Summary / Breakdown) optionally inserts each criterion's effective 0–1 value behind the score. **Decision Sensitivity** (`DecisionSensitivityNode`) is the companion: feed the same Scores + a Scenarios frame (each row = a weight scenario, columns named after criteria) and it emits a **Cube** — Scenario · Winner · Margin · Ranking, where Ranking is the full ranking frame nested per cell (drill in). Margin = top − runner-up (decisiveness). Verbs `decisionMatrix` / `decisionSensitivity` in `frameVerbs.ts`; seed `decision-matrix.json` shows both. Output frame `Option · [criteria?] · Score · Rank`, best first; the podium/rankings visual is just Get Column "Score" → Chart. Math in `frameVerbs.decisionMatrix` (`decisionMatrix.test.ts`); worked-example seed `decision-matrix.json`. See dev-notes 2026-06-30.

**Aggregation**: **GroupBy** — 1D parallel-list group + aggregate (keys + values outputs). **Group By (Frame)** — group a frame's rows by key columns + aggregate. **SUMIFS** (D16, amended 2026-07-09) — conditional aggregate over ONE FRAME: op selector (SUMIFS/COUNTIFS/AVERAGEIFS/MINIFS/MAXIFS), a Values-column field (hidden for COUNTIFS), extensible criteria rows (column + test + value, AND like Excel's *IFS); empty-match parity (AVERAGEIFS #DIV/0!, MINIFS/MAXIFS 0); missing column → #REF!; parallel lists route through Frame from Lists (the 2026-07-06 aligned-columns rule). **Pivot** = full Excel `=PIVOTBY` (2026-06-29): multi row/col/value fields (composite `"East | A"` headers), per-value function from the expanded set (SUM/AVERAGE/COUNT/MIN/MAX/PRODUCT/MEDIAN/MODE/STDEV.S-P/VAR.S-P/PERCENTOF), grand+subtotals (row/col depth, top/bottom) that **re-aggregate the source**, value/field sort, filter mask, and % running totals (`relativeTo`). Engine = `pivotFrame(f, PivotSpec)` in `frameVerbs.ts`. See dev-notes "PIVOTBY — full Excel parity".

**Annotation**: **Note** (free-floating sticky note — markdown title/body, drag, tint. Hover/selection highlight = an imperative `filter: drop-shadow` glow in the adjustable color (not per-move React state). Persistence: the markup lives in `stringLiterals.source` (Mermaid pattern — text, no bundling, unlike Image); `url`/`hoverColor`/`selectedLayer` round-trip via `INIT_FIELD_ORDER`. **Caveat:** cross-origin URL fetch can be CORS-blocked (local-file attach is the always-works path); a failed fetch leaves an inline hint. `svgLayer.test.ts` + `svgPicker.test.ts`.
- **Image persistence (`nodes/annotation.ts`):** a web `url` round-trips through the JSON save (and copy/paste) via `extractInit`; a LOCAL file is read to a base64 `dataUrl` that is deliberately NOT persisted (the save is plain JSON — no embedded image bytes yet; bundling comes later), so it's session-only and `dataUrl` is kept out of the extractInit whitelist. `src` getter = `dataUrl || url` (a fresh local attach wins; setting one source clears the other). The height field uses `useDraftCommit` (commit on Enter/blur), not live onChange — a live-clamped number input can't be cleared to retype.

**Conduit**: block bundler (up to 8 lanes, one rotation angle) whose outputs travel as a single Ribbon cable. (The old two-arm "Manifold" bundler it replaced was removed 2026-06-19.)

**Composability rule**: scalars → fine-grained one-op nodes. Lists/tables → bundled task-shaped nodes (e.g. one Aggregate with op selector, not five separate sum/avg/etc. nodes).

**Labeled-slots vs list-input rule** (the variadic-node design call — see `docs/archive/node-arity-audit.md`): a variadic node uses **individually-labeled, individually-wireable scalar input rows** (the `ExtensibleInputs` / `PairedExtensibleInputs` pattern) — NOT a single list/table socket — when each input plays a **distinct role**: positional (CHOOSE's value-per-index) or **paired** (IFS/SWITCH's condition↔result). The label IS the affordance — it tells the user what each slot does and what their edit affects; a raw list of paired/role-distinct values hides the cond↔result relationship and makes edits opaque. Per-slot sockets also let each input come from a **different** upstream node. Use a single **list socket** only when the elements are **interchangeable** — all the same role, where order may matter but identity/pairing does not (SUM/AVERAGE/AGGREGATE, List literal). Litmus test: if you'd have to write "the 2nd element means X, the 3rd means Y" to explain the list, it should be labeled slots instead.

**Input-dimensionality rule** (audited end-to-end 2026-06-19 — every node input checked against its `data()`; the socket type both gates connections via `canConnect` AND drives engine-boundary coercion in `coerceInputs.ts`, so it must match what `data()` actually consumes). Pick an input socket by the input's ROLE, not by what "feels related":

- **Element-wise operand** (paired with each element through a broadcaster) → the family's COMBO: `numlist` / `strcombo` / `datecombo` / `logicalcombo` / `complexcombo`. This is an *operand*, so per-element vectors are valid and intended (Excel array-formula parity, e.g. `=ROUND(A1:A10, B1:B10)`, `=LEFT(A1:A10, B1:B10)`). Covers ArithmeticNode's `a`/`b`, the secondary operands `RoundN.digits`, `Clamp.min`/`max`, `MRound.multiple`, `Gcd.b`, every date operand (DatePart/DateAdd/DateDiff/DATEDIF/WORKDAY/NETWORKDAYS/DATE/TIME), every text operand (UPPER/LEN/LEFT-MID-RIGHT/FIND/SUBSTITUTE/REPLACE/REPT/CHAR-CODE/TEXTAFTER-BEFORE/EXACT/NUMBERVALUE/ROMAN-ARABIC/FIXED/DOLLAR/ENCODEURL/Reverse Text/Spell Number), and every complex operand (COMPLEX/IM Unpack/the IM unary + binary ops/IMPOWER/Quadratic Roots). **All five families are swept as of 2026-07-25** — a combo rung with no node uses is now a bug, not a gap. Do NOT narrow these to the scalar rung — that would break list-broadcasting and make them inconsistent with the rest of their family. The combo is a pure WIDENING: it accepts everything the scalar accepted and feeds everything the scalar fed (combo→scalar is an explicit lattice edge), so switching one breaks no existing cable.
- **Structural control param** (a count, index, window size, polynomial/Bessel order, numeric base, MODE/type flag) → `number` (or scalar `string`). It has no per-element meaning, so a list there is a genuine mistake the socket should block. The test is whether the value describes ONE operation over the whole input or varies per element: `Take.count`, `Rolling.window`, `Combinatorics.n`/`k`, `BaseConvert.from`/`to`, `Slice.start`/`end`, distribution evaluation points/parameters, all finance scalars (rate/nper/pmt/pv/fv/basis…), WEEKDAY's `return_type`, YEARFRAC's `basis`, WORKDAY's `weekend_code`, NUMBERVALUE's decimal/group separators, Text Filter's `pattern`. A per-element numeric operand is NOT this — `LEFT.n`, `MID.start`/`len`, `REPLACE.start`/`num_chars`, `REPT.times`, `FIXED.decimals` are combos.
- **1-D list / sample data** → `list` (`strlist` / `datelist`). Stats samples, cashflow arrays (NPV/IRR/XIRR…), Filter's `mask` include-vector.
- **2-D matrix** → `table` (numeric), `strtable` (text), `datetable` (date), `complextable` (complex); **named-column data table** → `frame`. Matrix ops take `table`; frame ops take `frame`. Any 2-D OUTPUT is blocked from narrowing into a 1-D/0-D input. A lower-rank value WIDENS UP: a list → a matrix/frame, a matrix → a frame (a list → a single ROW). **Element-agnostic 2-D inputs use the GRID socket `anyTableIn`** (TRANSPOSE, HSTACK, CHOOSEROWS/COLS, reshape-flatten, MAP/BYROW/REDUCE-values) — they render as a grid and a 1-D list widens in. TableInfo (ROWS/COLUMNS) is `frame`-typed (a matrix/list/scalar widens in). See subsystem-invariants "Socket lattice". **Frame edges (2026-06-24):** Get Column gains a **read-as Boolean** (a logical column exits as a real logical list; 0/1 + true/false coerce); **Frame Input** is a LITERAL source for Data columns — stores the raw text you typed, derives the typed frame at compute, and the popup's **Source checkbox** shows that raw text on every frame node (`FrameColumn.raw`) — and since the column-source model (2026-07-29/31) each column also has a SOURCE: **Data** (typed cells) | **Formula** (an inline row-wise expr; `expr?` on `FrameSourceColumn`) | **λ** (a wired lambda; `lambda?`, which wins when both are set). Computed columns evaluate in topo order with cycle refusal, may carry a per-column UNIT from the popup's unit picker, and the chip's **ƒ** marks a defined table. See subsystem-invariants "Frame Input is a LITERAL source".
- **Recursive nested table** → `cube` (the lattice supremum: a frame whose cells hold ANY value, incl. a nested frame/cube). Producers: **Nest Join** (nest two frames on a shared key -> a cube of sub-frames; tidyr nest_join, the dual of a flat Join) and **Build Cube** (extensible `trueany` cells -> one column, each cell any value). Accessor: **INDEX** is `trueany`-in/`trueany`-out and reads a cell out of a list/matrix/frame/cube (a nested frame/cube comes out whole). **Whole-axis form (2026-07-15):** a blank/0 Row = the whole COLUMN and a blank/0 Column = the whole ROW (Excel's `INDEX(range, 0, col)`); both blank passes the container through. Slice shapes follow the existing accessor conventions — frame row → a ONE-ROW FRAME (Get Row), frame column → the values LIST (Get Column), cube slices stay CUBES (nested cells whole), matrix slices → 1-D lists. The Row/Column fields default empty with an `[all]` placeholder. **Cube Rollup** (`CubeRollupNode`, 2026-07-03) is the reverse direction: aggregate a column INSIDE each row's nested sub-frame (sum/avg/min/max/count, reusing Group By's `aggregateGroup`), flattening the cube back to a Frame with the roll-up appended — the BOM/nested-costing shape ("cost of an assembly = SUM of its nested parts"); see the rollup row in the `cubes` seed (the dedicated bom-costing seed was retired 2026-07-08). Display: `CubeDisplay` + the drill-in `CubePopup` (depth shown; every nested cell — cube/frame/list — drills in place via one breadcrumb). Cached `depth` counts cube-in-cube only (a nested frame is a leaf). Full detail: `docs/cube-node-scope.md`.
- **Genuinely type-agnostic** → the WILDCARD LADDER (D17, 2026-07-09): `any` is an element-agnostic SCALAR (gray circle — one value of any family), `anylist`/`anytable` its 1-D/2-D siblings, and **`trueany`** (a HOLLOW gray circle, border only) is the supremum that accepts anything — Cast, Display, the Test inspector, Input Switch, unwired Conduit lanes, selectors, Report refs, Placeholder/composite ports. **Expression's variable INPUTS are `anydata`** (D23, 2026-07-28 — the rank-≤2 rung: scalar / list / matrix in, frames/cubes never; the ladder also holds `anydata` between `anylist` and `anytable`), while **LAMBDA's capture sockets stay `anylist`**; the polyform producers declare their OUTPUT element type with a Number/Text/Date/Auto result-type selector that swaps the output socket at the node's dimensionality (Auto = `any` at scalar/combo, `anytable` at matrix), and a MATRIX result swaps the family's matrix rung in place (SOCK-7 reconcile). (REDUCE's iterable `values` and the MAP/BYROW table inputs are `anyTableIn` grids; the scalar seed is `anylist`.) See D17 + the "Polyform" dev-notes entry.

Governing principle: **enforce TYPE separation (Cast to cross element families; `logical↔number` is the one bridge), allow DIMENSIONAL flow** (lower ranks widen into `anytable`/`frame`). See subsystem-invariants "Socket lattice"; machine-checked by the full-sweep `socketConnect.test.ts`.

## Packs (add-on node bundles — `src/graph/packs/`, 2026-07-09 wave)

Pack nodes live in per-pack files (`packs/electricity.ts`, …), NOT `nodeCatalog.ts` —
each pack file IS its inventory (formula entries + custom-node placements + FC
units/formats), and every pack has a vitest file asserting its formulas against
reference values. Registry/activation: `packs.ts`; authoring shapes: `packs/packShared.ts`.
The current built-in set — Geometry + Common Excel Timesavers ship ON; the rest ship OFF:

- **Geometry** (ON): 27 formula presets (areas/volumes, circles & arcs, solids) + HYPOTENUSE + **Triangle Solver** (the current EQUATION card: dual-socket hero rows per part + a logical Valid check + the triangle drawn to scale; the angle outputs carry the real `deg` unit per-output (`annotationFor`), so they read as degrees downstream (and a trig node in Auto mode picks them up) while the sides stay bare; `numlist` sockets like the rest of the Equation family — parallel lists broadcast to a triangle per index (Valid becomes a logical list, the figure draws index 0); any three parts incl. one side → all sides/angles/area/perimeter, over-given parts are consistency-CHECKED like Equation's all-known mode; SSS/SAS/ASA/AAS, ambiguous SSA is an honest #SOLVE!); DMS format, turn/px units.
