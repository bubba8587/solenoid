# Solenoid — Node coverage

`nodeCatalog.ts` is the source of truth — the Add menu AND the in-app Function
Reference (Ctrl+/) are generated from it, so a node's catalog `description` is its
Reference entry. This file is a human-readable inventory by category plus the
non-obvious per-node notes. (Moved out of CLAUDE.md to keep the always-loaded doc
lean; update it when the catalog changes meaningfully.)

**Multi-op declarations (`nodeOps.ts`)** — one declaration per op-selector node class, two independent axes. `expose` is the MENU axis: `"collapsed"` (default) gives one Add-menu leaf with every op reachable from SEARCH ("Chart: Column"); `"leaves"` generates a leaf per op — a family earns per-op leaves deliberately, the default keeps dropdowns from spraying the tree. The `{ }` marker is DERIVED, never declared (shown iff the node has ops with no leaf of their own; `mark: false` suppresses it for labels that already enumerate, e.g. "GCD / LCM"). `kind` is the SEMANTIC axis and does NOT affect the menu: `"operation"` = the op stands alone as a name (SETUNION, ISODD) and earns its own formula name under formulaNaming 2(a); `"argument"` = meaningless without its host (aggregatorsAreArguments) — the family takes ONE formula name, the op rides as an argument. Kind-only declarations (no `ops`/`create`) are for families already listed op-by-op, or whose variants are DATA rather than operations (element symbol, pipe material, resistor band count). The coverage test fails the build until every op-selector family is classified.

**Add-menu pane ROW BUDGET** — the rule behind every catalog regrouping: a category
pane holds about **12 rows** before it needs a scrollbar, so a pane growing past ~12
gets its tail folded into subcategories rather than left flat (the 2026-07-16 sweep
applied this across charts, statistics, hyperbolics, bitwise, and the frame verbs;
control widgets folded into Input 2026-07-09, freeing the top-level row Packs uses).
A future node addition that flattens a pane back past the budget reintroduces the
scrollbar that sweep removed.

**Scalar**: Input, Constant, Arithmetic (all ops), Math functions, Rounding, Trig (a `Math` node's trig ops carry a **deg/rad/Auto** SegToggle — Auto (default) reads the incoming unit so a °-tagged value computes in degrees, else radians = Excel parity; Rad/Deg pin it; forward trig converts the input, inverse trig converts the result and tags the `deg` unit; resolved at recompute time by `trigMode.ts` — the one place compute reads units), Hyperbolic, Logarithms, Combinatorics, Bitwise, Engineering, **Comparison + Boolean logic** (emit the first-class **logical** type — purple, TRUE/FALSE, coerces ↔ 1/0; AND/OR/NOT are Kleene 3-valued on `null`. **Restructured 2026-06-23:** the old multi-op `LogicalNode` was split into **`BooleanOpNode`** — AND/OR/XOR/NAND/NOR/XNOR as **N-ary reducers** over extensible operand rows, all emitting logical so the op switch never swaps the socket — plus a standalone **`NotNode`** (unary element-wise flip). **Operand inputs are `logicalcombo` (purple), not `numlist` (2026-07-15)** — a boolean op takes booleans; a number still bridges in (0/1 ⟷ FALSE/TRUE). Rows are WIRE-ONLY like IfNode's condition (you wire a comparison/test) and a standalone **`IfNode`** (value passthrough, `util`-colored like its Choose/Switch/Ifs siblings, NOT logical)), **IF / IFS / SWITCH / CHOOSE** (the value selectors — all **variadic now**: CHOOSE has add/remove value rows over a fixed `index`; IFS takes any number of condition/value pairs **plus an "Otherwise" fallback**; SWITCH takes any number of when/then pairs between a fixed `expr`/`default`; see `docs/archive/node-arity-audit.md` + the **Labeled-slots vs list-input rule** below for why these are labeled per-slot inputs, not list sockets), IFError, NA, **IS.TEST** (`IsTestNode` — labeled "IS.TEST"; op dropdown ISNUMBER/**ISNULL**/ISBLANK/ISERROR/ISNA/ISBOOLEAN/ISTEXT/ISNONTEXT, where ISBOOLEAN is our name for Excel's ISLOGICAL — the `islogical` op value is unchanged for save compat. ISNULL is the per-cell missing test (≠ unwired); every check tests per-cell to any depth incl. a frame. Doubles as the error-inspection surface, see Error values), **ISEVEN/ISODD** (`IsEvenOddNode` — a single parity-test node with an even/odd toggle; emits the **logical** type TRUE/FALSE (not 1/0) and broadcasts over a list — extracted from the Math op-dropdown 2026-06-23 so it could carry a logical socket; lives in the Logic menu), **Alert** (watch a value — fires a toast + logs to the Alerts HUD on a changed trigger; see subsystem-invariants "Alert node + Alerts HUD"). **Between** (inclusive Low ≤ Value ≤ High) and **Is Close** (|A−B| ≤ tolerance) — numListIn predicates broadcasting like Comparison, logicalcombo out (2026-08-23). *(Removed 2026-06-23: the **T / N / TYPE** coercion-info nodes — their input socket was never rendered so they were unwireable, and Cast + the socket type system + Test supersede them; and the multi-op **`LogicalNode`**, split as above. Old saves load these as Placeholders — wiring/data kept, re-saved as the original type.)*

**Stats**: the ONE Distribution node (oneDistributionNode, below) covers the distribution families; **Hypothesis Test** is likewise ONE node (nodeCombiningRound1): Z.TEST / T.TEST (paired, equal var, Welch) / F.TEST / CHISQ.TEST as ops — every op emits a p-value, the two-sample ops share the a/b keys so switches keep cables.

**Finance**: TVM — ONE acausal Equation node covering PMT/PV/FV/NPER/RATE (wire four of {rate, nper, pmt, pv, fv}, the fifth solves; payment-timing dropdown swaps the locked relation; rate = 0 uses the exact limit form), Compound Growth (fv = pv·(1+rate)^nper; covers PDURATION/RRI) and Effective Rate (EFFECT/NOMINAL) as locked Equation presets, IPMT/PPMT, CumPmt, NPV and IRR (each with a Periodic/Dated SegToggle — Dated reveals a Dates input and IS XNPV/XIRR, nodeCombiningRound1), MIRR, depreciation (ONE node since nodeCombiningRound1: SLN/DB/DDB/SYD/VDB, per-op input rows), bond pricing (PRICE/YIELD, odd coupons, accrued interest).

**Distributions**: ONE Distribution node (oneDistributionNode, 2026-08-09): a distribution dropdown (normal, standard normal, t, chi-squared, F, beta, gamma, lognormal, Weibull, exponential, binomial, Poisson, hypergeometric, negative binomial) plus a form dropdown (CDF / PDF / PMF / tails / inverse); the inverse trades the x input for a probability, a distribution switch swaps the parameter inputs. `DIST_SPECS` in `nodes/distribution.ts` is the SSOT. Binomial Range stays its own node. Z/T/F/Chisq tests unchanged.

**Text**: Text Input, case/trim transforms, CONCAT, TEXTJOIN/SPLIT, LEN, FIND/SEARCH, SUBSTITUTE/REPLACE, TEXTAFTER/BEFORE, **REGEX** (REGEXTEST/EXTRACT/REPLACE), VALUE/NUMBERVALUE, TEXT/DOLLAR/FIXED, ROMAN/ARABIC, CHAR/CODE, ENCODEURL, list-wise Text Filter. **Every element-wise text node broadcasts (2026-07-25):** operands are `strcombo`/`numlist` and a wired list spills element-wise, Excel-array-formula style (`=UPPER(A1:A10)`) — see the Element-wise operand rule below. *(Removed 2026-07-25: **Text Map** ("UPPER (list)") — Text Transform with a list wired in IS it now; old saves load it as a Placeholder.)* The exceptions are deliberate: CONCAT/TEXTJOIN REDUCE a set to one string (Excel's CONCAT flattens an array rather than spilling), TEXTSPLIT and Text Filter are already 1-D → 1-D (broadcasting would need a rank-2 result the lattice has no 1-D→2-D edge for), and Regex stays on the wildcard ladder because its element type depends on the op — though it now emits `anycombo` rather than `any` (2026-07-25), so its dot no longer draws a scalar circle on a port that can spill a list.

**Date & Time**: TODAY/NOW, DATE/TIME construct, date parts, WEEKNUM/WEEKDAY, DATEDIF, **Workdays** (ONE node, nodeCombiningRound1: WORKDAY/NETWORKDAYS as inverse forms — the op swaps Days↔End date and retypes the output date↔number via `retypeOutputCables`), date formatting.

**Complex numbers**: COMPLEX build/unpack, 16 unary ops, 4 binary ops, IMPOWER.

**Build Frame** / **Frame from Lists** — the matrix⇄frame constructors, both TYPE-BY-ADOPTION (2026-07-15). "Slap headers on a table → Frame" (Build Frame) and "N typed lists → a mixed Frame" (Frame from Lists); adding columns is other nodes' job. Their value inputs are **adoptive** sockets (`adoptiveTableIn`/`adoptiveListIn` — an `AdoptiveSocket` with an `anytable`/`anylist` BASE instead of `trueany`): they accept any element family AND adopt the wired cable's concrete type via `settleWildcardTypes`, so a `datetable`/`datelist` → **date columns**. This is the only way `date` survives — a serial is indistinguishable from a number at the value level (`colTypeForSocket` maps the adopted socket → `FrameColType`; `null` for a not-yet-adopted `anytable`/`anylist` or `complex` falls back to value inference). `typedColumn`/`buildFrameTyped` (core `frame.ts`) do the typing; a numeric matrix still routes through the unchanged `buildFrame` (byte-identical). Headless (`run-graph.ts`, no settle pass) degrades to value inference (date→number). The old `columnFromCells` + Frame-from-Lists' "dates arrive as numbers, retype downstream" limitation are GONE.

**Split Frame** (`SplitFrameNode`): Frame → Matrix + Headers, with a **column-type filter** SegToggle (All / Num / Date / Bool / Text). Filtering to a type pulls just those columns out of a MIXED frame (which plain "All" can't — any text column makes the number matrix null); both Matrix and Headers are filtered. **The Matrix output socket type tracks the filter** (`splitMatrixOutput` + in-place swap via `applySplitColType`, like Get Column's read-as): number/all → `table`, date → `datetable` (serials), bool → `logicaltable` (1/0), text → `strtable` (a real string matrix, not null). `colType` persists via extractInit.

**Frames / Table verbs** (`nodes/frame.ts` + `frameVerbs.ts`; the relational family): Get Column (read-as retype incl. Boolean), Get Row, Add Column, Frame Filter, Frame Sort, Join (incl. as-of + semi/anti modes), Group By (Frame), Append, Distinct, Head, PIVOTBY, Unpivot, Nest, Unnest, the cleanup verbs (Fill Down, Replace Values, Drop Blank Rows, Columns (Keep / Drop), Rename, Split Column, Merge Columns, Add Index (incl. the TWO-WAY option, author 2026-07-16: the same data indexed on BOTH axes as a coordinate-bordered matrix — exactly the grid Surface / Contour / Grid Interpolate read; a wired matrix widens to Col1…N and gets row + column indices counting from Start), Headers), Reconcile, and the cube family (Nest Join, Build Cube, Cube Columns, Cube Rollup). **Frame XLOOKUP `search_mode`** decides which row wins on DUPLICATE keys: "first" (default, Excel's mode 1) scans top-to-bottom, "last" (mode −1) bottom-up; Excel's binary modes (2 / −2) are deliberately omitted — on a materialized column a binary search over sorted data finds the SAME row a linear scan does, a pure speed knob with no distinct result here, and we always scan linearly for correctness. **Reconcile** classifies each key as added (right-only) / removed (left-only) / changed (a shared column differs) / unchanged with before/after/Δ per shared numeric column; when both a price and a quantity column are named (numeric on both sides) it decomposes the total (price×qty) change into the textbook three-term PRICE/VOLUME/MIX variance — price = (P1−P0)·Q0, volume = (Q1−Q0)·P0, mix = (P1−P0)·(Q1−Q0) — which sums EXACTLY to P1·Q1 − P0·Q0. **Computed Column** (`ComputedColumnNode`, tableRefSemantics/noPerCellFormulas): adds ONE defined column mid-pipeline — an inline formula or a wired λ; a bare name (or `[Name]`) is the WHOLE column as a list, `@name` / `@[Name]` is this row's cell; λ params stay row-bound; free names grow `anydata` SIDE-INPUT sockets (`sideVars`, persisted) with per-variable column-binding pickers; `addAs` types the result, `After` places it; one definition per column, never per cell. This node is WHY frames stay out of formulas (matricesInFormulas): the row iteration lives here and the formula only ever sees scalars (author direction 2026-07-29 — the frame stays pure data, the computation is a graph citizen). Per-row contract mirrors the broadcast rules: an error cell in any BOUND column propagates to that row's output (first in binding order); a null flows INTO the formula (ISBLANK/IF can see it — a formula is not an element-wise op); the output column's type is inferred from the computed cells, and a `Name (unit)` header tags the unit like Add Column. The same definition model lives on Frame Input's per-column source picker (**Data | Formula | λ**) — both surfaces run `computedColumnCore.ts`, so they cannot disagree. **Query** = a Composite pre-shaped for data transformation (verb chain inside, Manual-refresh mode — the Power Query shape, queryIsCompositePreset).

**2D Tables / Matrix**: Table Input grid (a LITERAL source on Frame Input's model: raw text is the stored truth, bad cells derive to NaN with the quiet affordance, the grid editor edits Source text; ONE element type per table via a Num/Text/Date/Bool SegToggle that retypes the output socket in place — header accent tracks it), MMULT, MDETERM, MINVERSE, MUNIT, TRANSPOSE, **VSTACK/HSTACK** (the 2-D rungs of the append ladder, appendLadder: N extensible `anytable` rows stacked in row order; a list counts as ONE ROW; ragged inputs pad with #N/A cells like Excel), WRAPROWS/COLS (leftover cells pad with #N/A, Excel's default pad_with), TOCOL/ROW, CHOOSEROWS/COLS, **TAKE/DROP (table)** (2-D edge cuts, rows+cols in one node, negative = from the end, 0 = omitted arg), **EXPAND** (grow to R×C; wired Fill or #N/A; shrink is #VALUE!), ROWS/COLUMNS, DIAGONAL (numpy.diag; off-diagonal 0 or blank, MUNIT's toggle), OUTER, Cross Product (3-vectors), TRACE / MATRIXRANK / NORM (MDETERM card ops; its op switch now retypes the output number ↔ table), Solve A·x = b, Eigen (symmetric, Jacobi). (Node kind `table` — vermilion accent matching the table socket; see `kind.ts`.)

**Formula**: **Expression** node — type `a * b + 1`, named variables auto-become input sockets; full math-function scope + list broadcasting. **Per-variable explanations (2026-07-09):** each variable can carry a prose description (`varDescriptions` map, kept OUT of the formula string so KaTeX never renders it) — a hover tooltip on the card + an editable legend under the KaTeX in the formula popup; shared with **Equation and LAMBDA** (all three use the same formula popup), seeded on some pack presets (Ohm's Law, ideal gas…). A **LAMBDA wired into a Report renders its formula as KaTeX with a muted "where:" legend beneath** (the value carries the descriptions) — the math-renders/prose-explains split. The **lambda-helper family** is MAP / BYROW / BYCOL / REDUCE / **SCAN** / MAKEARRAY (each runs an inline formula or a wired LAMBDA value): **SCAN** (2026-07-10) is REDUCE's running-intermediate twin — the same row-major fold from Initial but it emits the accumulator after every cell, keeping the input's shape (a running total is `acc + value`, a running max is `MAX(acc, value)`); the fixed-op Running covers the common aggregates and REDUCE gives only the final value. **Polyform** (2026-06-19): a Number/Text/Date/Auto result-type selector lets it (and MAP/BYROW/BYCOL/REDUCE/SCAN/MAKEARRAY/LAMBDA) loop ANY Excel function over arrays of any element type — `UPPER(name)`, `first & " " & last`, `DATE(y,m,d)` — swapping the output socket to match; Expression variable inputs are `anydata` (scalar / 1-D list / 2-D matrix — the matricesInFormulas lift; frames and cubes stay out permanently, the verb engine is their surface, and a Computed Column carries row formulas). LAMBDA's capture sockets stay `anylist`. See the "Polyform" dev-notes entry. The names `pi`/`tau`/`e`/`phi` resolve to constants (`FORMULA_CONSTANTS` in `excelFormula.ts`), not variables — they're skipped by `extractVariables` and inlined by codegen + `evaluateSteps`, so the whole formula engine (Expression, LAMBDA, MAP/BYROW/REDUCE…) sees them.

**Equation** (`EquationNode`, `equationSolve.ts`, decision equationNode): the acausal sibling of Expression. Type a relation (`V = I * R`); every variable gets an input AND an output socket, plus a fixed logical **Check** (output key `holds`) output. Exactly one unknown (unwired, empty literal) -> solved: symbolic AST isolation when the unknown appears once (`+-*/^`, POWER/LOG, EXP/LN, SQRT, trig/hyperbolic, DEGREES/RADIANS, unary minus, %) -- the isolated form unparses to a formula and recompiles, so list broadcasting is free; otherwise a QUADRATIC-in-the-unknown residual (numerically probed, any arrangement) solves via the quadratic formula and yields EVERY real root as an ascending list (x² = 36 -> [-6, 6]; double root scalar; negative discriminant #SOLVE!), and anything else falls to a numeric log-grid + bisection fallback on the LHS-RHS residual (scalar-only, `#SOLVE!` when no real root). All variables known -> Check is a relative-tolerance (1e-9) truth check, broadcasting per-element. Principal branches on inversion (sqrt, ASIN). Wired variables pass through to their outputs, so the node doubles as a labeled junction.

**Decision support**: **Decision Matrix** (`DecisionMatrixNode`, frame kind, in the Table-verbs menu) — a port of the jortscity Decision Matrix Bases View. Scores + ranks a Frame of options (rows) by criteria (number/logical columns — NOT date; an optional leading text column names them): weighted average `Σ(value × weight) / Σ|weight|` (a NEGATIVE weight penalizes a lower-is-better criterion), then competition rank ON THE ROUNDED (4dp) score — display and rank can never disagree (decisionMatrixFamily). Each detected criterion gets a row: a **labeled, default-1 weight box** (`node.weightMap`) **and a per-column normalize override dropdown** (`node.normMap`). The global `normalize` SegToggle is the default each column inherits — **÷max is the node default** (decisionMatrixFamily: raw silently degenerates the moment criteria mix scales); `none`/`÷max`/`rank` where **÷max and rank both land in [0,1]** so mixed-mode columns stay comparable (the point of normalizing: weights, not scale, decide influence). The `weights` socket is an optional positional override for computed weights; while wired the card renders the wired list read-only per row (`node.wiredWeights`, transient). `detail` SegToggle (Summary / Breakdown): Breakdown inserts each criterion's **signed contribution** — effective × weight / Σ|weight|, so the columns sum to the Score and a negative-weight column reads as the penalty it is (decisionMatrixFamily; never the bare post-normalize value). **Decision Sensitivity** (`DecisionSensitivityNode`) is the companion: feed the same Scores + a Scenarios frame (each row = a weight scenario, columns named after criteria; missing column → weight 1, but NO matching column at all → `#VALUE!`, the renamed-criteria trap) and it emits a **Cube** — Scenario · Winner · Margin · Ranking, where Ranking is the full ranking frame nested per cell (drill in). Margin = top − runner-up (decisiveness); a dead tie for first lists every tied option in Winner ("A = B"). Verbs `decisionMatrix` / `decisionSensitivity` in `frameVerbs.ts` (`decisionMatrix.test.ts`); worked-example seed `decision-matrix.json`, held to the engine by `decisionSeed.test.ts` (winner order, the flip, the exact tie, the report wiring); the seed feeds one criterion from a Note's frontmatter list (prose = the judgment, list = the data) through Add Column, draws the podium via Select Columns [Option, Score] → Chart (labeled bars), and ends in a Report memo pulling `=winner` (INDEX 1,1), the podium figure, and the contributions table. See dev-notes 2026-06-30, 2026-08-19b.

**python-r-gap Tier 2 (2026-08-23g, see `python-r-gap.md`):** Lists gained Smooth (Savitzky–Golay / LOWESS / Gaussian, op-owned parameter sockets), Find Peaks, ARGMAX ops ARGSORT / ARGSORT DESC / WHICH (sockets retype with the op), Polynomial Roots (Complex); Finance gained Returns (log / simple / cumulative, drawdown, max drawdown, CAGR, volatility, Sharpe, Sortino — op owns rf / periods); Regression gained Decompose (classical seasonal); Text gained Pad Text, Truncate Text, Template ({name} grows a socket), Hash, UUID, UNACCENT / SLUGIFY on Text Transform and Base64 on the url-encode card; Tables gained K-Means, PCA, Logistic Regression (Analyze), Bind Columns (Append's positional sibling — a backend verb on both engines) and Join `how = cross`.

**Describe / Correlation Matrix / Window** (Table verbs, 2026-08-23f): pandas describe (one row per column), df.corr / df.cov (Pearson / Spearman / Kendall / covariance, pairwise-complete), and **Window** — the per-group transform column (running / rank / lag / lead / diff / pct_change / rolling / group total / share / first / last, partition + order, original row order kept); a lazy FrameOp — Polars `.over()` on desktop, oracle on web, `window.json` parity fixture. Engine = `pivotFrame(f, PivotSpec)` in `frameVerbs.ts`. See dev-notes "PIVOTBY — full Excel parity".

**Annotation**: **Note** (free-floating sticky note — markdown title/body, drag, tint. Sockets-less BY DEFAULT, but if its body opens with an Obsidian-style `---`-fenced YAML frontmatter block, each key becomes a typed OUTPUT socket — guessed type persisted/overridable per-key — so the Note doubles as a typed-record / constants source; `noteFrontmatter.ts`, dev-notes 2026-06-23). **Image** (free-floating picture, in the Add menu's "Other" category — attach a local file or paste a web URL, height field, no socket; sockets-less, no data). **SVG** (interactive picture / visual slicer, also in "Other" — `SvgPickerNode`, kind `input`; see below). **Format Controller** (catalog label "Format") — docked node setting a socket's number format, and AUTHORING a unit only onto a unit-less value; fed an already-united value it MIRRORS the unit and LOCKS (firstClassUnits — only Convert changes a unit). `formatModel.ts` is the control truth table.
- **SVG Picker (`nodes/annotation.ts` `SvgPickerNode`, `components/SvgPickerNode.tsx`, 2026-07-08):** load an SVG (local `.svg` read as TEXT, or a web URL fetched to text — inlined into the well so its inner shapes are hoverable/clickable). **Click a shape/layer → the `Layer` string output emits its NAME** (element `inkscape:label`/`data-name`/`aria-label`/`id`, human-label-first, walking up to the nearest named ancestor — pure `svgLayer.ts`, `resolveLayer`); wire that into a Filter to slice a dataset by the clicked region (a clickable map/floorplan as a data selector). **Conduit**: block bundler (up to 8 lanes, one rotation angle) whose outputs travel as a single Ribbon cable. (The old two-arm "Manifold" bundler it replaced was removed 2026-06-19.)

**Composability rule**: scalars → fine-grained one-op nodes. Lists/tables → bundled task-shaped nodes (e.g. one Aggregate with op selector, not five separate sum/avg/etc. nodes).

**Labeled-slots vs list-input rule** (the variadic-node design call — see `docs/archive/node-arity-audit.md`): a variadic node uses **individually-labeled, individually-wireable scalar input rows** (the `ExtensibleInputs` / `PairedExtensibleInputs` pattern) — NOT a single list/table socket — when each input plays a **distinct role**: positional (CHOOSE's value-per-index) or **paired** (IFS/SWITCH's condition↔result). The label IS the affordance — it tells the user what each slot does and what their edit affects; a raw list of paired/role-distinct values hides the cond↔result relationship and makes edits opaque. Per-slot sockets also let each input come from a **different** upstream node. Use a single **list socket** only when the elements are **interchangeable** — all the same role, where order may matter but identity/pairing does not (SUM/AVERAGE/AGGREGATE, List literal). Litmus test: if you'd have to write "the 2nd element means X, the 3rd means Y" to explain the list, it should be labeled slots instead.

**Input-dimensionality rule** (audited end-to-end 2026-06-19 — every node input checked against its `data()`; the socket type both gates connections via `canConnect` AND drives engine-boundary coercion in `coerceInputs.ts`, so it must match what `data()` actually consumes). Pick an input socket by the input's ROLE, not by what "feels related":

- **Element-wise operand** (paired with each element through a broadcaster) → the family's COMBO: `numlist` / `strcombo` / `datecombo` / `logicalcombo` / `complexcombo`. This is an *operand*, so per-element vectors are valid and intended (Excel array-formula parity, e.g. `=ROUND(A1:A10, B1:B10)`, `=LEFT(A1:A10, B1:B10)`). Covers ArithmeticNode's `a`/`b`, the secondary operands `RoundN.digits`, `Clamp.min`/`max`, `MRound.multiple`, `Gcd.b`, every date operand (DatePart/DateAdd/DateDiff/DATEDIF/WORKDAY/NETWORKDAYS/DATE/TIME), every text operand (UPPER/LEN/LEFT-MID-RIGHT/FIND/SUBSTITUTE/REPLACE/REPT/CHAR-CODE/TEXTAFTER-BEFORE/EXACT/NUMBERVALUE/ROMAN-ARABIC/FIXED/DOLLAR/ENCODEURL/Reverse Text/Spell Number), and every complex operand (COMPLEX/IM Unpack/the IM unary + binary ops/IMPOWER/Quadratic Roots). **All five families are swept as of 2026-07-25** — a combo rung with no node uses is now a bug, not a gap. Do NOT narrow these to the scalar rung — that would break list-broadcasting and make them inconsistent with the rest of their family. The combo is a pure WIDENING: it accepts everything the scalar accepted and feeds everything the scalar fed (combo→scalar is an explicit lattice edge), so switching one breaks no existing cable.
- **Structural control param** (a count, index, window size, polynomial/Bessel order, numeric base, MODE/type flag) → `number` (or scalar `string`). It has no per-element meaning, so a list there is a genuine mistake the socket should block. The test is whether the value describes ONE operation over the whole input or varies per element: `Take.count`, `Running.window`, `Combinatorics.n`/`k`, `BaseConvert.from`/`to`, `Slice.start`/`end`, distribution evaluation points/parameters, all finance scalars (rate/nper/pmt/pv/fv/basis…), WEEKDAY's `return_type`, YEARFRAC's `basis`, WORKDAY's `weekend_code`, NUMBERVALUE's decimal/group separators, Text Filter's `pattern`. A per-element numeric operand is NOT this — `LEFT.n`, `MID.start`/`len`, `REPLACE.start`/`num_chars`, `REPT.times`, `FIXED.decimals` are combos.
- **1-D list / sample data** → `list` (`strlist` / `datelist`). Stats samples, cashflow arrays (NPV/IRR/XIRR…), Filter's `mask` include-vector.
- **2-D matrix** → `table` (numeric), `strtable` (text), `datetable` (date), `complextable` (complex); **named-column data table** → `frame`. Matrix ops take `table`; frame ops take `frame`. Any 2-D OUTPUT is blocked from narrowing into a 1-D/0-D input. A lower-rank value WIDENS UP: a list → a matrix/frame, a matrix → a frame (a list → a single ROW). **Element-agnostic 2-D inputs use the GRID socket `anyTableIn`** (TRANSPOSE, HSTACK, CHOOSEROWS/COLS, reshape-flatten, MAP/BYROW/REDUCE-values) — they render as a grid and a 1-D list widens in. TableInfo (ROWS/COLUMNS) is `frame`-typed (a matrix/list/scalar widens in). See subsystem-invariants "Socket lattice". **Frame edges (2026-06-24):** Get Column gains a **read-as Boolean** (a logical column exits as a real logical list; 0/1 + true/false coerce); **Frame Input** is a LITERAL source for Data columns — stores the raw text you typed, derives the typed frame at compute, and the popup's **Source checkbox** shows that raw text on every frame node (`FrameColumn.raw`) — and since the column-source model (2026-07-29/31) each column also has a SOURCE: **Data** (typed cells) | **Formula** (an inline row-wise expr; `expr?` on `FrameSourceColumn`) | **λ** (a wired lambda; `lambda?`, which wins when both are set). Computed columns evaluate in topo order with cycle refusal, may carry a per-column UNIT from the popup's unit picker, and the chip's **ƒ** marks a defined table. The popup's **Form view** (frame-source editors only, 2026-08-18) edits ONE record as labeled fields — pager, + Record / − Record — riding the same raw-text grid truth and edit-draft path as the grid cells, so its cursor reaches rows past the grid's 1000-row render cap; computed columns render read-only there. Field placement is the SAME Record layout text (`parseRecordLayout`; empty = stacked, unmatched names keep inert boxes, columns off the layout are hidden), and the form renders as the record-card look made editable (touching square boxes, label in-box). The layout is authored on the Frame Input CARD (the Record card's textarea pattern — never in the popup) and persists as `FrameInputNode.stringLiterals.layout` (the declaration is the load gate). See subsystem-invariants "Frame Input is a LITERAL source".
- **Recursive nested table** → `cube` (the lattice supremum: a frame whose cells hold ANY value, incl. a nested frame/cube). Producers: **Nest Join** (nest two frames on a shared key -> a cube of sub-frames; tidyr nest_join, the dual of a flat Join) and **Build Cube** (extensible `trueany` cells -> one column, each cell any value). Accessor: **INDEX** is `trueany`-in/`trueany`-out and reads a cell out of a list/matrix/frame/cube (a nested frame/cube comes out whole). **Whole-axis form (2026-07-15):** a blank/0 Row = the whole COLUMN and a blank/0 Column = the whole ROW (Excel's `INDEX(range, 0, col)`); both blank passes the container through. Slice shapes follow the existing accessor conventions — frame row → a ONE-ROW FRAME (Get Row), frame column → the values LIST (Get Column), cube slices stay CUBES (nested cells whole), matrix slices → 1-D lists. The Row/Column fields default empty with an `[all]` placeholder. **Cube Rollup** (`CubeRollupNode`, 2026-07-03) is the reverse direction: aggregate a column INSIDE each row's nested sub-frame (the full 12-op AggOp set, reusing Group By's `aggregateGroup`), flattening the cube back to a Frame with the roll-up appended — the BOM/nested-costing shape ("cost of an assembly = SUM of its nested parts"); see the rollup row in the `cubes` seed (the dedicated bom-costing seed was retired 2026-07-08). Display: `CubeDisplay` + the drill-in `CubePopup` (depth shown; every nested cell — cube/frame/list — drills in place via one breadcrumb). Cached `depth` counts cube-in-cube only (a nested frame is a leaf). Full detail: `docs/archive/cube-node-scope.md`.
- **Genuinely type-agnostic** → the WILDCARD LADDER (wildcardLadder, 2026-07-09): `any` is an element-agnostic SCALAR (gray circle — one value of any family), `anylist`/`anytable` its 1-D/2-D siblings, and **`trueany`** (a HOLLOW gray circle, border only) is the supremum that accepts anything — Cast, Display, the Test inspector, Input Switch, unwired Conduit lanes, selectors, Report refs, Placeholder/composite ports. **Expression's variable INPUTS are `anydata`** (matricesInFormulas, 2026-07-28 — the rank-≤2 rung: scalar / list / matrix in, frames/cubes never; the ladder also holds `anydata` between `anylist` and `anytable`), while **LAMBDA's capture sockets stay `anylist`**; the polyform producers declare their OUTPUT element type with a Number/Text/Date/Auto result-type selector that swaps the output socket at the node's dimensionality (Auto = `any` at scalar/combo, `anytable` at matrix), and a MATRIX result swaps the family's matrix rung in place (retypeReconciles reconcile). (REDUCE's iterable `values` and the MAP/BYROW table inputs are `anyTableIn` grids; the scalar seed is `anylist`.) See wildcardLadder + the "Polyform" dev-notes entry.

Governing principle: **enforce TYPE separation (Cast to cross element families; `logical↔number` is the one bridge), allow DIMENSIONAL flow** (lower ranks widen into `anytable`/`frame`). See subsystem-invariants "Socket lattice"; machine-checked by the full-sweep `socketConnect.test.ts`.
