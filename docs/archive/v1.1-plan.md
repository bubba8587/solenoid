## B1 — Pack distribution + dependency system (remaining, unbuilt)

The no-cable-loss safety already shipped: an unknown-pack node loads as a **placeholder**
(wiring + data intact, round-trip lossless), and `SavedGraph.packs?: string[]` records the
active pack-id set as a breadcrumb — **not yet consumed on load** to auto-activate dormant
packs. Consuming it grew (author 2026-07-01) into a full distribution + dependency system,
bigger than the original "consume `packs` on load."

**Priority: LAST for 1.1, and a "maybe"** — it must land in tandem with subgraphs
(composite/subgraph nodes), themselves only a maybe; if subgraphs slip, this slips with them.
Load-time behavior is a **PROMPT, not silent auto-activate**, because not every pack is
bundled. Governing idea: **modularity.** The pieces:

- **Distribution tiers:** a pack is **bundled** (builtin), **downloadable**, or **local-file**
  (loaded from the user's computer). A save can reference a pack that isn't installed.
- **Pack dependencies:** external packs (downloadable + local) can **declare they need other
  packs**. The manifest carries a dependency list; the load-time resolver walks it
  **recursively**.
- **Packs can bundle full SUBGRAPHS** (composite/subgraph nodes), not just formula-data or
  code nodes — ties to `pack-architecture.md` "Composite pack node".
- **Manifest fields implied:** id, **version**, distribution type (+ download URL / local
  path), `dependencies[]`, and payload (formula-data / code / subgraphs).
- **Load flow:** read `SavedGraph.packs` → for each not-installed pack, **prompt** (offer
  download if downloadable, file-pick if local) → recursively resolve declared deps →
  activate → affected nodes un-placeholder. Missing/declined stays **placeholdered** (the safe
  fallback, already built). `loadCustomPacks()` (`packs.ts`, currently returns `[]`) is where
  local/downloadable packs get wired in.
