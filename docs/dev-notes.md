### SESSION DIGEST (2026-11-03: Write Properties types with Solenoid Properties; cloud session)
- **New keys register Solenoid Properties types** ([[D116]] writeSolenoidTypes, new): `obsidianTypeName` maps a Cube cell to `solenoid-cube`, a Frame cell to `solenoid-frame`, a matrix or list to its family's `solenoid-*table` / `solenoid-*list`, complex text to `solenoid-complex`; plain scalars keep Obsidian's types, and `tags` / `aliases` / `cssclasses` are never registered.
- **The YAML writer now writes matrices and nested rows**: a matrix was written as a list of `"1,2"` strings and a table inside a row as `[object Object]`; both now spell as the plugin and Obsidian do (`frontmatterPatch.test.ts` round-trips the demo vault's `Property types.md`).
- **Keys is a normal input row** on Write to Obsidian (Properties) and Write Tasks: a String List socket, `ColumnListField` suggesting the wired rows' columns, placeholder `all`; it replaced the one-off monospace box. The `annotations` fixture was spliced for `vault-as-a-table` only: re-freezing it whole also moves power-features, computed-columns and null-and-logical (MAP/Display families), drift from elsewhere left for its owner.
- **Cable beads are the canvas's biggest idle cost** (backlogged, low priority: § Canvas frame cost): every bead frame makes Blink rebuild the whole page's paint artifact and layerize it, so the cost grows with the page, not the bead count. personal-finance idle with beads on: 826 ms/s of main thread, 1577 ms/s raster (`scripts/cable-flow-probe.mjs`). Ruled out: promoting the edge layer (raster ÷4, main unchanged, 12 → 33 layers), CSS motion-path dots (more layout and layerize), the dash math (no-dash repaint costs the same). The toolbar's bead icon now slides on the compositor (≈50 ms/s of header paint gone).
- **Write to Obsidian's `rows` socket has an example hint** (`path`, `property1`, `property2`) on hover and in the Inspector. The hint mechanism was never socket-type gated; the node just had none.

### SESSION DIGEST (2026-11-03: dates are a value kind; InlineCast; cloud session, continued)
- **A date is its own kind** ([[D114]] dateIsAKind, [[D115]] datesArePoints, new): `V::Date` in the core, `{__date}` on the wire, `SolDate` in TypeScript (`dateValue.ts`); the spec is `tree/specs/values/date-values.md`. Operators shift a date by days and take a span between dates; anything else with a date is `#TYPE!`. Every function is classed once (`date_values.rs` `class_of`), readied after its arguments evaluate (`Eval::call`); an unlisted function refuses a date. The formula-text date guess (`date_typing.rs`) is gone: results are typed by their values.
- **Still relaying, listed in the spec:** date-typed inputs read as dates on the way into formulas, computed columns and the LAMBDA helpers; card bodies outside `SEES_DATES` read a date as its serial; the source-type relays (`from_in`, `produced`, Cast's and Script's sniffing, the display hand-offs) stand until each source sends a date itself.
- **Never a serial outside Cast** ([[C137]] datesNeverSerials): Slicer chips, peeks, exports, template and Cube lists; SUMIFS MIN/MAX/AVERAGE of dates are dates and SUMIFS of dates `#TYPE!`; Coupon's COUPNCD/COUPPCD output dates; Split Frame All leaves no matrix over a date column; Script takes dates as JS `Date`s; a chart refuses dates as heights ([[D112]] chartDatesHeld, held); a sum, product or share of dates is `#TYPE!` in Group By, Pivot, Window and Rollup (`dates_plan`).
- **InlineCast** ([[D113]] inlineCast): the Formula card and LAMBDA helpers' result-type toggle became a Cast section (∅ first, the default); a pick runs Cast's own conversion. A mixed answer is untyped.
- **Tests**: the node re-freezer rewrites a shown field that moved on its own and drops one the core stopped showing; many date tests now pass dates (`solDate`) and expect dates.
- **Linear again** ([[C120]] linearWork): a range function over a whole date column per row (COUNTIF, XLOOKUP, XMATCH, RANK, MAXIFS, a kept SORT re-stamped as dates) copied the column every row and missed the memo; `date_values.rs` now keeps one copy per list (`COPIES`). Also: MIN/MAX of a column beside a row value (`column_extreme`, `eval.rs`), one-comparison MINIFS/MAXIFS/whole-number SUMIFS off a sorted run (`Rolled`), connection lookups indexed (`connectionsInto`/`connectionsOutOf`), and `Call::again` reads dates as serials for unconverted cards as `Call::from_json` does. `examples/colbench.rs` has a Date column to measure these.
- **Every card takes dates** ([[D114]] dateIsAKind, `../tree/specs/values/date-values.md` § Cards): one date step for every call (`date_values::call`: formulas, card bodies through `core_call`, a node's `engine_call`); the sources send dates (Value and List Input, Get Column, a date socket's literal); tables built from values type Date columns (`infer_column`); planners never read a Date column as an amount. Every relay is gone: per-card date stripping, the formula and LAMBDA re-wrapping, `from_in`, Cast's and Script's sniffing, the display hand-offs by source socket. `tests/date_fuzz.rs` hands every card dates wherever one can be wired (no panics, no serial leaks). Card fixtures' date-fed inputs migrated to dates and refrozen; the TS tests send `solDate`s.
- **Exact sums** (the author 2026-11-03, `../tree/specs/computation/formula-language.md` § Sums): every total of a list is its exact sum rounded once (`exact_sum.rs`), snapped to 0 only where the numbers as written cancel (`Written`); SUM no longer snaps each addition. It made one-comparison SUMIFS/AVERAGEIFS of any values a sorted-run read (6 s to 70 ms at 20k rows) and rolling sums, mins and maxes a slide (the backlog's rows × window item). 78 frozen answers moved, all in the last digit or two but one fuzz mean over ±1E308, which is now the true mean.

### SESSION DIGEST (2026-11-02: lookups, dates through wildcards, Record and Cards, popups; cloud session)
- **Once calculated, nothing is untyped** ([[C136]] typesKnownAfterCalc, new, unratified): the Type Settle (the glossary's name for `settle.rs`) reads each card's run-time facts where the wiring leaves a wildcard: the branch IF, IFS, SWITCH, CHOOSE and IFERROR took (`selected`), and the column family XLookup and INDEX extracted (`produced`, `Call::produced`).
