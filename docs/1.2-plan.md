## Tier 1 — known-issue fixes (the release's backbone; all shipped in 1.1's Known Issues list)

- [x] **Tidy / Cleanup around expanded groups is wonky** — DONE 2026-07-16 (movement
  pass): root cause was STALE expand-push restore records — a Tidy/Cleanup/align move
  fires no `nodedragged`, so the record survived with its ancient preX/preY and a second
  group's push merged into (re-armed) it; collapse then restored to a dead layout's
  coordinate. The merge path now applies the restore path's staleness test. Plus the
  measuredBox() sizing unification + frozen-member-card / anchor-skew fixes
  (`groupPushRecords.test.ts`, `tidyArrangeGroups.test.ts`).
- [x] **Node-label edits aren't undoable** — RESOLVED IN CODE (stale item, 2026-07-10
  audit). The premise "it never went through pushHistory" is no longer true: the node
  title is the only label-edit surface (no other rename UI exists), it commits via
  `useDraftCommit`, and `useDraftCommit.onBlur` gained `pushHistory(() => apply(committed),
  () => apply(next))` on 2026-07-08 (after the 2026-07-07 note) — routed through
  `getActiveHistory`, so it undoes on the main canvas AND inside a drill-in. Author
  eyeballed + confirmed working (2026-07-16 release eyeball); the Known Issues entry was
  already pruned in the 1.2 release-notes rewrite. CLOSED.
- [x] **Private-browsing reload loop** on a stale deploy during an outage — DONE
  2026-07-10. (Corrected the plan: an in-memory fallback can't work — a reload wipes
  memory. The `vite:preloadError` guard now FAILS SAFE: it reloads only when the
  sessionStorage timestamp can actually be persisted, else surfaces the error. Logic
  extracted to `chunkReloadGuard.ts` + unit-tested.)
- [x] **Set nodes compare complex numbers by identity** — DONE 2026-07-10: a shared
  `setKey()` canonicalizes a complex `[re, im]` tuple to a string across SetOp / Is In /
  Tally / Set relation (primitives unchanged). (Tally's frame Value column still
  stringifies complex — frames have no complex type — but the count groups by value.)
- [x] **Problems panel + model fuzzer miss per-cell errors** — DONE 2026-07-12 (Stream D):
  a BOUNDED head-plus-stride scan (`findCellError` + `sampledCellIndices` in `errorValue.ts`;
  `CELL_SCAN_HEAD`=64 + 32 tail samples per container) wired into `reportOut` and
  `modelFuzz.badValue` (now frame-aware). A systematic whole-column error is always caught;
  a lone cell buried past the head between strides is the accepted cap cost.
