# Solenoid — Subsystem invariants

Detailed mechanics and hard-won invariants for the trickier subsystems. CLAUDE.md
carries a one-line "don't break this" index pointing here; read the relevant
section in full before touching that subsystem. (Moved out of CLAUDE.md so the
always-loaded doc stays lean.)

## Cable rendering knobs

- Per-socket cable exit-angle overrides live in `cableAngleStore` (keyed by `${nodeId}::${socketKey}`). The Conduit registers a per-lane exit angle from its rotation (perpendicular to the socket's face). External `ConnectionComponent` reads from the store and passes `sourceAngleDeg` / `targetAngleDeg` to `getCablePath`.
- **NAMING**: **Conduit** = the block bundler node (`ConduitNode`, formerly "Ribbon"). **Ribbon** = the bundled cable entity (formerly "bundle"). The old two-arm bundler **Manifold** (briefly "Conduit" before that) was removed 2026-06-19; old saves referencing `ManifoldNode` load it as a Placeholder (wiring kept, re-saves as the original type; no backward migration — pre-alpha).
- **Ribbons** (`ribbonCable.ts`): 2+ cables from one visible Conduit's outputs to the same entity (another visible Conduit, or one collapsed group) render as ONE wide neutral trunk with flat caps that fans into per-lane slots near each Conduit face (or lands whole on the group's combined pill). The lowest-lane connection draws the trunk; every member draws its own fan branches to its own measured sockets (slots spread across the trunk width, ranked by lane order per side ⇒ fans can't cross; no cross-lane position lookups). The flow-bead overlay must keep `strokeLinecap="round"` — the beads are 0.01-length dashes that butt caps flatten into slivers. Hover/selection/delete treat the ribbon as one entity (`ribbonHoverStore`, select = repId, Canvas delete removes all members). Membership is derived fresh per render — never stored. Selecting a Conduit separates its ribbons; selecting a separated lane PINS the separation open (`pinRibbonSeparation`, keyed by the selected cable id so it self-expires). See dev-notes "Conduit output ribbons". **Inverse case (`kind: "groupSource"`):** a Conduit *hidden* inside a collapsed group whose 2+ outputs leave the group bundle out of the group's combined OUTPUT pill — the mirror of the combined-input pill. `recomputeGroupCollapse` collapses all of a hidden Conduit's crossing `out_*` sockets into one combined readout row + pill (`RetainedTerminal.lanes`); `groupSourceRibbon` detects it; `ConnectionComponent` renders a short trunk leaving the pill that fans out to each external target (no source fan — the pill IS the bundling point). v1 omits the flow-bead animation and a wide output stadium.
- **Conduit RUNS — a cable is a segment, not the whole wire** (`conduitPath` in `conduitTrace.ts`, unit-tested). A Conduit is wiring, not computation, so the user-meaningful entity is the RUN: walk upstream along lanes (a chain — an input lane takes one cable) to the node that really produces the value, then downstream FROM THAT ORIGIN (a tree — one output lane can feed many cables) to every input that really consumes it. **The downstream walk MUST start at the origin, not at the clicked cable** — otherwise clicking one branch of a fan-out hides its siblings and two segments of the same run resolve to different runs, which breaks the inspector's "is this selection exactly one run?" test. Cycles are broken by a `seen` set plus a hop cap (a `#CIRC!` conduit loop). Two consumers: the **Cable inspector** reports the run's ends (From = origin, one To row per terminal, a quiet Via row naming the Conduits crossed) and reads the value/annotation/frame-shape from the ORIGIN, and **double-click on a cable** selects every segment of the run (`selectRun` in `ConnectionComponent`), so the whole path highlights and Delete takes all of it.
- **Double-click on a cable is detected via `e.detail >= 2` in `onClick`, NOT `onDoubleClick`** — the canvas swallows native `dblclick` in CAPTURE phase (`stopImmediatePropagation`, to kill rete's zoom-on-dblclick; `Canvas.tsx` + `areaPresets.installSurfacePointer`), so React never dispatches a synthetic double-click on anything inside the canvas. The `detail` guard must come BEFORE the single-click select/deselect branches or the second click toggles the selection off first.
- **Diagonal and straight modes share one walk-enumeration router** (`routeWalk` in `cablePaths.ts`, parametrised by compass division: `div=8` → 45° segments/turns, `div=4` → 90° segments/turns rendered with rounded `Q` corners). ALL cables in those modes route through it, plain and angle-hinted; the old `getDiagonalPath`/`getSmoothStepPath`/`withAngleLeads` heuristics are gone. Constraints hold **by construction**, there is no sharper-turn fallback: rigid exit/entry stubs along the exact socket direction, every other segment on a compass heading, every turn exactly one compass step. A route is a *walk* of compass headings (±1 step between legs); the canonical family is back `b` / forward `b+r+e` / back `e` steps over both rotation directions. Selection = **globally shortest solvable walk** (sort order — fewest turns, preferred rotation — only settles exact ties). Length MUST stay the primary criterion: a walk entering feasibility does so at exactly the length of its own wider extension, which was already competing, so handoffs are seamless; gating by turn count first turns those handoffs into visible jumps (a bug we hit). Leg lengths are a closed-form solve (`solveWalk`): legs between same-direction turns keep a minimum (collapsing one would fuse two turns into a sharper corner), legs between opposite turns may collapse to zero (merges same-heading neighbors into a straight run), legs adjoining an **off-grid stub** (rotated arm between compass headings) stay pinned open — collapsing one would merge the snap offset into the next turn (up to 135° in straight mode). Residual displacement decomposes on the unique adjacent fan-heading pair bracketing it, spread evenly per heading (centers Z diagonals). Stub scales `min(14, dist/4)`, staircase minimum `min(14, dist/8)` — the minimum must shrink faster at close range or every walk becomes unsolvable; a halve-and-retry loop guarantees termination. Renderer dedup epsilon must stay well under a pixel (0.01): a coarser one deletes real tiny vertices and skews neighboring headings off-grid. Remaining discontinuities, all inherent: straight-line collapse for near-touching sockets (Euclidean `dist < 15`, deliberately NOT per-axis), and equal-length route swaps (incl. the head-on mirror flip). Property tests in `cablePaths.test.ts` machine-check the invariants AND continuity under simulated 0.5px drags (large jumps allowed only between equal-length routes) — keep them passing when touching the router.
- **Spline is a single tangent-exact cubic** (`getAngleBezierPath`): control arms (`max(40, dist·0.4)`) sit along the exit/entry directions (angle hint or cardinal side), so the curve leaves the socket exactly along its direction and may bend immediately after — no rigid straight lead. Its collapse test is the same Euclidean `dist < 15`: a target merely *axis-aligned* with the source (e.g. directly below an east-facing Conduit) must NOT fall back to a point-to-point line.

## Group expand push (`groupPush.ts` + `groupPushCore.ts`)

Expanding a collapsed group displaces its neighbourhood via the pure, unit-tested core in `groupPushCore.ts` (plain boxes, no rete/DOM — see `groupPushCore.test.ts`). Rules, in order: (1) **rails** — a loose node wired to the group's members that the expansion would displace lands on its dataflow side (feeders left, consumers right, y-aligned to its connected members; a consumer already right of the group just gets cleared, not re-placed); (2) **clear** — minimal disturbance: ONLY boxes the expanded footprint would cover move, and only just past the expanded edge + `PUSH_GAP`. Direction: a box with connection ANCHORS (cables to other entities — the other end resolved to its push entity: member → its group, docked FC → its host) picks whichever of the four clears keeps mean anchor distance + a displacement penalty smallest, so a node wired to a group on the left hops LEFT out of the way; unconnected boxes use the axis matching their position vs the collapsed card (right → right, below → down, beyond both edges → dominant axis). Free area is expanded into without anything moving; (3) residual clear (belt-and-braces); (4) **cascade** — a mover pushes what it lands on just clear of itself along its direction of travel, and only boxes that started AHEAD of it on that axis (movers process in original-position order), so a band of cleared boxes re-stacks in original order instead of flattening or inverting. Boxes the user parked ON the collapsed card are exempt, and pre-existing overlaps are never "fixed". Displacements are recorded as ABSOLUTE before/after pairs with a `dueTo` SET of contributing groups (a second expansion shoving the same node merges into one record — but ONLY if the node is still within EPS of where the last push left it: a programmatic move between pushes — Tidy, Cleanup, align/distribute — voids the old record and the merge replaces it with a FRESH one anchored at the current position, the 2026-07-16 fix for "Tidy around expanded groups is wonky", pinned by `groupPushRecords.test.ts`); restore fires when ALL contributors are collapsed or deleted, and only if the node is still where the push left it — manual moves win, and only real drags invalidate (NOT clicks: rete fires `nodedragged` on every pointerup after a pick, which once wiped records on plain clicks and broke snap-back). `setGroupsCollapsed` is the ONE toggle entry point — chevron, outline panel, and Ctrl+Shift+E all route through it; it measures collapsed-card sizes BEFORE flipping (they're the stretch seam origins). Deliberately no ELK in this path: rails+stretch are deterministic, preserve deliberate placement, and invert exactly; ELK re-derives positions globally and can't snap back. `setGroupsCollapsed` is the only *toggle* caller of `runExpandPushes`, but not the only caller — `pushForGrownGroups` reuses the same engine (non-toggle) when a within-group Tidy grows the box (see Auto-arrange / Tidy below).

**Group membership changes ONLY on an explicit gesture** — dragging a NODE in/out (`reconcileGroupMembership` on `nodedragged`), a select→group action, or a MANUAL box resize over a node (`reconcileGroupBox` from the grip drag). **Autofit must NOT** re-derive membership: it wraps the box around the EXISTING members, so running `reconcileGroupBox` after it would silently absorb any bystander whose center the shrunk box covers (the bug fixed 2026-06-15). `autofitGroupWithHistory` therefore omits the reconcile; `rebuildGroupMembership` (refreshing the color markers from the unchanged list) is fine. **A COLLAPSED group never gains members (2026-07-07):** it renders as a small card with members hidden, so a node dropped/created over the card silently joined and was hidden by the next `syncGroupCollapse` (it visibly vanished). All three editors guard it — `reconcileGroupMembership` skips collapsed join targets, `absorbIntoContainingGroup` skips collapsed groups, `reconcileGroupBox` no-ops while collapsed (reconciling against the card-box would also dump every member). Membership edits require the group expanded.

## Standoffs (`standoffs.ts`, `standoffSolver.ts`, `StandoffLayer.tsx`)

User-declared arrangement constraints: a pale thick bar UNDER everything (own React root in the area plane at z -3 — the area-plane stacking order is standoffs -3 < expanded groups -2 < conduits -1 < nodes 0; a Conduit inside a group was unselectable until groups dropped from -1 to -2) linking two top-level items (nodes/groups; no conduits/FCs/group-members) side↔side (cardinal) or corner↔corner (diagonal). Semantics are AXIS-BAND: `min ≤ dot(P_b − P_a, axis from a.anchor) ≤ max`; the perpendicular offset is left free (the bar slants to show slack) UNLESS the standoff is LOCKED — the rigid 45° mode (default-ON for new standoffs), which also pulls the perpendicular to 0 so the two ends align exactly along one of the 8 anchor directions (the toolbar angle dial cycles which one; `setAxis` rotates `a.anchor`, `b` takes the opposite). `solveStandoffs({ forceLock })` forces that rigidity for a single solve WITHOUT touching saved `locked` — used so every layout op treats a standoff-connected cluster (`standoffClusters()` = connected components) as one rigid block. Created via right-click on one of exactly-two selected items → "Link with Standoff" (anchors auto-face along the dominant of 8 directions; band defaults to [PUSH_GAP, current distance], min hard-floored at `STANDOFF_MIN` = 30). The pure solver (`solveStandoffs`, unit-tested) is iterative projection with pinning; it runs as the LAST word after every layout-affecting pass: live drag chain-pull (keyed off the pointer-driven node only — programmatic translates never trigger it; deliberately band-only, NOT forceLock, so an unlocked slant survives a drag), group expand (inside `runExpandPushes`, corrections folded into the push records so collapse restores; a CLUSTER moves as one block — after the heuristic push every member gets the cluster's largest displacement, so a lone push isn't pulled partway back), collapse (post-restore re-settle), autofit, and tidy. **Tidy lays each loose cluster out as a SINGLE ELK super-node** (`Canvas.tsx` arrange): the leader (prefer a non-group member) is sized to the cluster bbox so ELK reserves room for the block, follower edges remap to the leader (node-level, like the gbridge), members are re-placed at their stored offsets after layout, and the leader's REAL size is restored (the applier resizes proxy nodes to their reported size — same gotcha as `realHostSize`). All of it is a strict no-op without qualifying clusters (graphs with no standoffs tidy identically). Selection is mutually exclusive with nodes/cables; selected standoff shows a docked toolbar (min/max band committing on Enter/blur via `useDraftCommit`, a 45° Lock toggle, an angle dial); Delete removes it. Persisted additively as `SavedGraph.standoffs` (incl. `locked`). Known v1 edges: a standoff endpoint hidden in a collapsed group goes dormant (bar hidden, constraint skipped); a cluster whose members aren't ALL in the loose layout (e.g. spans a group interior) falls back to the forceLock post-settle instead of the super-node path; no undo entries; Tidy/Cleanup edge-cases on heavy overlap not fully swept.

## Auto-arrange / Tidy (ELK, `rete-auto-arrange-plugin`)

- **Every movement-stack size read routes through `measuredBox()` (`nodeSize.ts`)** — live DOM → the ResizeObserver mirror → a non-zero collapse-aware fallback (2026-07-16 unification; align/autofit adopted it first, then tidy/push/standoffs/splice/focus). Do NOT reintroduce ad-hoc `offsetWidth || node.width || 100` reads — the variants disagreed pre-paint and on collapsed groups (OutlinePanel's reversed read centered the camera on a collapsed group's stored EXPANDED box). `hostFootprint`/`realHostSize` restores are restricted to LAYOUT TARGETS (a docked-FC host that is a group member isn't laid out, and stamping it left a height pin nothing cleared — frozen card); ELK-footprint restores run BEFORE the post-layout anchor measurement (measuring while hosts/leaders were still inflated skewed the preserved center); the within-group autogrow rounds `group.width/height` to integers (the 8622a72 rule). Harness: `tidyArrangeGroups.test.ts` drives the REAL arrange/cleanup with real elkjs over a fake area modeling the DOM contract.

The "tidy" button / Ctrl+Shift+K runs an ELK layered layout. Two non-obvious things:
- **Do NOT use the plugin's `classic` port preset.** It puts OUTPUT ports at the node TOP and INPUT ports at the BOTTOM, so ELK lines up a source's top-output with a target's bottom-input and every link staircases the target UPWARD — the whole graph reads as floating high. We register a custom preset whose ports are placed SYMMETRICALLY (same vertical offset for in & out) so two connected nodes line up. The preset reads the `tidyAlign` setting per layout: **"center"** (default) → ports at the node's vertical center → node CENTERS align (cables may slant slightly because our real output socket sits lower than the input rows); **"top"** → ports near the node top → node TOP edges align. The setting lives in `settingsStore` and renders as a Center/Top segmented control (a `"segment"` field type) in Settings ▸ Canvas.
- **The post-layout anchor preserves LEFT + vertical CENTER, not top-left.** ELK lays out from origin; we shift the result back. Horizontal keeps the cluster's left edge; vertical keeps its CENTER (selection: the members' old center; within-group: the box interior's center, clamped so centering never lifts members above the header). Anchoring by the top dropped a flattened row to the top of the old footprint (another "nodes float up" symptom). Both references are deterministic, so the Cleanup tidy→autofit cycle stays a fixed point. FC hosts are reserved as inflated bounding boxes during layout (so neighbors don't pack into the FC's area) and resized back after.
- **The applier leaves a FIXED inline `height` on every arranged card — `arrangeFn` now DROPS it.** `area.resize` (the applier's per-node sizing + the host/leader restores) writes an inline `height` on the `.solenoid-node` card; post-layout it just equals content height but FROZE the card (collapse couldn't shrink, a grown value clipped — the bug that read as "old/tidied saves don't collapse"). After the size-restores, `arrangeFn` clears the height pin on every arranged node (`card.style.removeProperty("height")`), so nodes stay content-driven. **Groups are skipped** (GroupNode sets `height` via its React `style` prop, so React clears the pin itself on collapse); regular nodes never set inline height, so theirs lingered. Width pins are harmless (fixed/React-managed). `NodeCard` also clears it on collapse and `clearPinnedHeight` on a formula edit — both now belt-and-suspenders. The **group Tidy button** follows its within-group arrange with an autofit (wrap-to-members), waiting two frames for the deferred docked-FC snap-back first.
- **A within-group Tidy that GROWS the box triggers the expand push — PERMANENTLY.** After laying out members, the within-group path autogrows `group.width/height` (`Math.max`) to wrap them. If it grew, Canvas calls `pushForGrownGroups` (groupPush.ts) — the SAME `runExpandPushes` engine as expand-on-uncollapse, fed the pre-grow size as `preSizes` — so neighbors are shoved off the grown edges. But it passes `record:false`: a Tidy is a deliberate manual action, so the displacement is PERMANENT (no restore record) — the pushed neighbors stay put when the group later collapses instead of rushing back. (A neighbor that *did* have an expand-push record from earlier goes stale and is treated as manually moved, so it won't snap back either.) Gated by the `groupPush` setting. **Cleanup passes `skipPush:true`** to the per-group `arrangeFn`: it runs its own autofit-shrink → collapse (restore) → top-level re-tidy, so a transient per-group push there is just noise. Selection / whole-canvas Tidy doesn't push (it rearranges groups as whole units, not their interiors).

## Conduit perpendicular-face sign

The Conduit rotates, so picking which face carries the input vs output lane sockets has to flip *somewhere* — there's no continuous rule. Old `cos r − sin r > 0` flipped at 45° / 225°, which is right in the middle of useful angles. Rule: choose the perpendicular whose x-component leans east (output) / west (input), flipping at `sin r = 0` (0° / 180°). That moves the flip to horizontal orientations, which users rarely park on. Tiebreaker at the boundary uses the y-component to keep cables flowing top-to-bottom.

## Resizable-content nodes (the Conduit pattern)

When a node renders content whose size depends on live user input (slider, drag, growing list), keep the **node body (hit area + offsetParent) a constant size** and let the visible content overflow. Float the inspector toolbar at a body-relative offset — that offset is then canvas-invariant, so the toolbar doesn't jiggle while the user is sliding/dragging.

The Conduit applies this with `CONDUIT_BODY_SIZE`, pivot at body center, the housing + sockets drawn from the pivot with `overflow: visible` (sockets absolutely positioned, can extend outside the body), toolbar at a body-relative offset. Trade-off: click-to-select hit area is the small body, not the visible silhouette — acceptable.

What NOT to do:
- ❌ Size the body to fit the variable content. Body grows → toolbar position shifts → jiggle.
- ❌ Try to "pin" the visible center by translating the node in `useLayoutEffect`. `area.translate` is async (awaits a guard pipe), so its DOM update doesn't ride the same paint as React's commit — you get a one-frame flash.

## Pointer gestures — pinch priority by listener PHASE (`pointerGesture.ts`, `areaPresets.ts`, 2026-07-27)

**The rule: pinch listens in CAPTURE and cannot be vetoed; pan and node-drag listen in BUBBLE and can be.** Both halves matter — do not move either.

**Why it exists.** rete's stock `Zoom` counts fingers from a **bubble-phase** `pointerdown` on the area container, and `Zoom.move` is a `.map` over the pointers it already holds — never an upsert. So a finger whose pointerdown is swallowed anywhere below the container is invisible to the zoom handler for the *whole gesture*, with no recovery: two fingers down, one counted, `isTranslating()` false, no zoom. That made every `onPointerDown={(e) => e.stopPropagation()}` inside a node a pinch-blocker — ~180 of them, so a pinch died over most of the FC node, the connection nodes, and every inline field. It also made the bug look random, because whether pinch worked depended on which pixel your first finger happened to land on.

This was diagnosed once before, on 2026-07-04, and fixed *only* for the lasso (see the archive). The general class survived because the fix was per-call-site. `CappedZoom` now re-seats the finger count into capture phase, which fixes it positionally: no call site can break a pinch, and none has to remember not to.

The bubble half is not an oversight — it's the other half of the rule. A control that wants the pointer for itself (a slider, a dial, a text field) *should* be able to suppress the pan and the node drag by stopping the event. Only the zoom is unstoppable.

**Consequences for `CappedZoom`:**
- `initialize` must re-register `down` in capture *after* `super.initialize` binds it in bubble, and remove the bubble one. Registering both double-pushes every contact, which makes `isTranslating()` true on ONE finger.
- `destroy` must be overridden. Stock `destroy` removes `pointerdown` without the capture flag, which doesn't match a capture registration — the base teardown leaks the listener, and every composite drill-in open/close stacks another.

**What counts as a finger.** Only `pointerType === "touch"`. Stock rete pushes every pointer type; that was harmless behind a hundred `stopPropagation`s but is not in capture phase, where every contact really does arrive — a stylus resting on the glass plus one finger would read as two pointers and zoom. `isPinching()` (`pointerGesture.ts`) is the single definition — **≥2 touch contacts** — and everything that yields to a pinch reads it from there rather than counting raw pointers.

**No palm rejection, deliberately.** Solenoid is a precise editor, not an inking surface: nobody rests a palm on a node graph, so there is no palm to reject and the state that would take isn't earned (author call, 2026-07-27). A pen is handled only as what it is — a *precise* pointer: it never counts toward a pinch, and it keeps select-and-drag in one motion like a mouse. If a drawing-style surface ever lands in the app, this is the decision to revisit; it would want contact geometry (`width`/`height`/`pressure`), not a pen-active flag.

**The census (`pointerGesture.ts`)** is a module singleton on **window capture** — the only listener position that is both global and un-swallowable, so three unrelated consumers (rete's Zoom instance, the Canvas area pipe, the lasso installer) can answer "is a pinch in flight" without threading a ref. `resetPointerCensus()` is the backstop for a `pointerup` the browser never delivers (long-press contextmenu, a pointer that leaves the window); Canvas calls it when its own tracker goes empty.

**A finger never selects on pointerdown.** rete picks a node synchronously on pointerdown (the drag depends on it), so the first finger of a pinch would select whatever it landed on — at that instant the gesture is genuinely unclassifiable, since no second finger exists yet. The fix is to defer, not to correct: an unselected node is **drag-transparent to touch** (`patchDragGuard`), so the press falls through to a pan, and selection happens on `pointerup` only if the gesture stayed one finger (`!gestureMultiRef`) and didn't move. A pinch therefore *never* selects, rather than selecting and being rolled back.

Rollback was considered and rejected — snapshot the selection on the first finger, restore it when the second lands. It works, but it leaves a visible flash for however long the two fingers are apart, and correcting a wrong state reads as a glitch where never entering it reads as nothing happening.

This model already existed for phones; it is now keyed on **pointer type, not device class** (`tapTouchRef`, set from `e.pointerType === "touch"`). The reason is that the model exists to handle "this press might become a pinch", which is true of any touchscreen — tablet, touchscreen laptop — not just a phone. A mouse or pen can't pinch and keeps select-and-drag in one motion; a *selected* node still drags on the first touch, so moving a selection stays one motion too. The cost is that a tablet now needs tap-then-drag to move an unselected node, exactly as a phone always has.

**Tablet.** `IS_MOBILE` is false on a tablet (iPadOS ships a desktop UA by default — deliberate, see `coarse.ts`), so a tablet runs the desktop interaction model: nodes are not drag-transparent, and `stopDragStart` swallows exactly like desktop. That is correct, not a gap — panning on a tablet is the two-finger gesture, and the capture fix is what makes it work over every part of every node. Before it, a tablet could only pan over empty canvas.

**`stopDragStart` (`coarse.ts`) is no longer about pinch at all.** It decides the ONE-finger question only: does a drag starting on this element pan the canvas, or belong to the element? Node chrome and single-line fields use it. Two things keep an unconditional `stopPropagation` for reasons that are actually established: drag-interactive controls (sliders, dials, the Conduit, group bodies, resize handles) genuinely own the pointer, and `<textarea>`/contenteditable own their own scroll and text selection, so a bubbled press there would pan instead of letting the user scroll inside the field.

A third group — native-popup controls (`<select>`/`LazySelect`, `<input>` of type color/date/file) — also keeps the hard swallow, but **on precaution, not on a verified mechanism**. The stated reason is CLAUDE.md's OS-dropdown rule (node pointerdown → selection → re-render → the open dropdown closes mid-pick). That rule is cited around the codebase but no originating incident is recorded, and on the mobile path it looks like it may not apply: `nodeAndControl` already excludes form controls from tap-to-select, `patchDragGuard` returns false for an unselected node before any pick happens, and mobile browsers open the native picker on tap-completion rather than on pointerdown — so there may be no open dropdown for a pointerdown-time re-render to interrupt. **Unverified either way** (needs a real device or a mobile-emulated CDP run; the vitest env is node). Left as-is because the delta is worth almost nothing — it only decides whether a one-finger pan can *start* on top of a small tap target — while a broken pick would be a real regression. Pinch is unaffected regardless: the capture-phase count doesn't care what these swallow. If someone wants to settle it, that's a browser-automation task, not a reading task.

## Socket lattice (`sockets.ts`)

**GOVERNING RULE (author, 2026-06-22): enforce TYPE separation, allow DIMENSIONAL flow.** Element families (number / string / date / complex / logical) NEVER auto-cross — crossing requires an explicit **Cast** (so a `date` won't wire into a `number` socket even though a date IS a serial; same for complex/string). The ONE deliberate exception is `logical ↔ number` (0/1 ⟷ TRUE/FALSE, the spreadsheet multiply-by-a-condition idiom; `coerceInputs` does the runtime bool↔number conversion). A value flows freely UP in dimensionality within the lattice: scalar → list/combo → matrix → frame.

- The regular types are an `(element × dimension)` grid — `FAMILIES` in sockets.ts. `SOCKET_ACCEPTS` is DERIVED from ONE predicate, **`dimFlows(dOut, dIn)`**: `DIM_RANK[dOut] ≤ DIM_RANK[dIn]` (widening up; narrowing blocked) **OR** the one exception the rank model can't express — a **combo may narrow into its element scalar** (a combo IS scalar-or-list, so it can be a scalar). `dimFlows` drives BOTH the within-family accept-sets and the `logical↔number` bridge, so the exception can't drift out of one of them (it was bolted onto the within-family case only until 2026-07-25, which left `logicalcombo → number` blocked while `logical → number` flowed — a real gap once EXACT/Comparison started emitting the combo rung).
- **The COMBO rung collapses a one-element list (runtime, `coerceInputs.collapseSingleton`).** A value arriving at a combo — or any scalar rung — as a 1-element list IS that scalar, so `List Input [Date]` with one entry into YEAR yields the year, not a list of one. This is what makes the `combo→scalar` edge above TRUE rather than merely permitted; `toScalar` had always done it for the numeric scalar rung, which left the combo (the rung that generalizes it) stricter than its own scalar. A **strict** list socket (`list`/`strlist`/`datelist`/`logicallist`/`anylist`) keeps its list — that IS the difference between the two rungs — and re-widens a scalar on the way in, so the round trip is lossless. A complex is a tagged object (VAL-15), so it collapses like any other scalar — no outer-shape special case.
- The pure rank-derivation CANNOT express the cross-TYPE *dimensional* edges, so they're explicit in `accepts()` — and they're exactly what kept getting "lost" on each rework (the recurring failure mode). They are: `combo→scalar`; `logical↔number` (dim-mirrored, `dimFlows` on both sides); **`anytable` as an INPUT** accepts any rank≤2 family value (a list/scalar/matrix WIDENS into the 2-D wildcard) while as an OUTPUT it stays strictly 2-D (→ a concrete matrix, never narrows); **`frame` as an INPUT** accepts any rank≤2 value OR `anytable` (a matrix → rows×cols, a 1-D list → a single ROW, a scalar → 1×1 — `coerceInputs` builds it via `frameFromRows`), while a `frame` OUTPUT only flows into another frame (it'd lose its headers otherwise).
- **Element-agnostic 2-D inputs use the GRID socket** (`anyTableIn`), not the scalar-circle `any`: TRANSPOSE, HSTACK, CHOOSEROWS/COLS, reshape-flatten, MAP/BYROW/REDUCE-values. They render as a grid (matching their `anytable` outputs) and a 1-D list still widens in. `any` stays for true wildcards (Cast / Display / IS.TEST / formula+LAMBDA vars / TableInfo — TableInfo is `frame`-typed now, so a matrix/list/scalar widens in and it reports R×C).
- **Machine-checked by `socketConnect.test.ts`** — a full sweep of the entire family×dimension cross product asserts the rule; the sweep applies the SAME `dimFlows` predicate within a family and across the bridge (within-family widening + `combo→scalar`; cross-family blocked except `logical↔number`; every rank≤2 value reaches `anytable`/`frame`; outputs stay 2-D / frame-only; `any` bridges both ways). The **"Dimensional Flow" seed** demonstrates it visually (list/scalar/matrix → frame; list → TRANSPOSE → column; + the type wall via required Casts).

## Type propagation on in-place socket retype (`fcReconcile.ts`)

A Format Controller doesn't carry a fixed type — it ADOPTS the concrete type flowing into it (`adaptTypeFromConnections` → `concreteTypeOfOutput`, which walks upstream through passthrough WILDCARD sockets — both rungs, via `isWildcardType` — and reads the live socket `dataType`), and auto-picks a date format for a date type. That re-adaptation runs from the Canvas `connectioncreated`/`connectionremoved` pipe. **The trap:** several nodes change an OUTPUT socket's type IN PLACE via a UI control — **Cast** target, **LAMBDA/Expression** result type (`ResultTypeToggle`), **Get Column** read-as, and a **Note**'s frontmatter retype — and a pure in-place retype fires NO connection event, so without help the downstream FCs keep formatting by the stale type (the reported "date serial retyped to a number still renders as a date" — a broken core promise).

- **The rule: any code that mutates a socket's `dataType` in place MUST re-drive FC adaptation.** Use `fcReconcile.ts`:
  - `reconcileFcTypes(editor, area)` — the shared sweep (re-adapt every FC's type + re-project annotations + refresh Convert unit-arrows + re-render). The Canvas connection pipe calls it; so does anything doing a manual retype. Does NOT recompute — the caller owns `processGraph`.
  - `retypeOutputCables(editor, area, nodeId, outKey)` — call after swapping an OUTPUT socket: reads the new type off the (already-swapped) socket, KEEPS each outgoing cable the new type can still feed (an `any` input always survives; same-family widening too), drops only the now-incompatible ones, then `reconcileFcTypes`. This replaced the old "drop EVERY cable" behavior in Cast / ResultTypeToggle / Get Column (which needlessly severed `any`-input cables). The Note's `commitFields` does the equivalent per retyped key.
- **`concreteTypeOfOutput` walks through wildcard passthroughs** (a Display fed by a date reads as date) but STOPS at a node with its own concrete output type — so a retype legitimately ends at the first node that re-types the value (e.g. a math node that always outputs a number). That's correct, not a propagation gap.
- **Passthrough is ONE declaration (`nodes/passthrough.ts`, 2026-07-15).** A node that forwards a value to an output (a selector, a pure passthrough, an element-agnostic reshape) declares it ONCE via `passthrough(): PassthroughSpec[]` — `{output, inputs (value branches), combine: single|agree|active, selected?() (data-aware branch), pure?}`. FOUR consumers read this one source: trueany TYPE adoption (`trueAnyAdopt` `reconcileOnce` — `resolvePassthroughType` with the `agree` rule), UNIT flow (`unitFlow` — `selected()` first, else combine over the inputs; `pure` drives the downstream FC-segment walk), the type-default DISPLAY walk (`valueDisplayFormat` `displayedType`), and coerceInputs' keep-tags boundary (`unitAware || isPassthroughNode`). This REPLACED the old split where type used a hardcoded `instanceof` chain and units used `passesUnitThrough`/`unitPassInputs`/`selectedUnitInput` duck markers — the two sets drifted (Expect/CableSwitch/IFERROR passed type but not units). Declarers: Display/Expect (pure single), IF/IFERROR/CHOOSE/SWITCH/IFS (agree over value branches), CableSwitch One-mode (active), and the element-preserving same-rank ops (Reverse/Slice/Take/Drop/Shuffle/NthElement/Pad + TRANSPOSE/CHOOSEROWS/COLS/table-TAKE-DROP/EXPAND — single, with adoptive in+out so their output forwards the input's type). The append ladder declares `agree` over its EXTENSIBLE rows, re-read each pass so a grown row is a value branch immediately (Concat Lists 1-D; VSTACK/HSTACK 2-D), and the rank-CROSSING reshapes (WRAPROWS/WRAPCOLS/TOCOL/TOROW) declare `single` — `projectTypeToBase` lands the element family on the output's own rank. An EXTRACTION (INDEX — it forwards a value out of its container, not the container) declares `single` plus a `project(t, ctx)` that drops the RANK and keeps the element FAMILY: the COMBO rung means exactly "one cell or a whole axis, decided at runtime". `ctx` (`ProjectContext`) is what the projection may consult BEYOND the socket type — the static frame `Shape` arriving on an input (`frameShapeResolver`, supplied by the adoption pass) and whether an input is wired — because a FRAME carries no family in its socket but its named COLUMNS each do (2026-07-27): blank/0 Column → the whole row, still a `frame`; Column = c → that column's family at the combo rung; `trueany` only where genuinely unknown (a WIRED Column, an unresolvable upstream shape, a `dynamic` shape, an out-of-range index, a cube cell). A generative output (XLOOKUP value-dependent, MAP formula-typed, sources) declares nothing → static. **Passthrough alone is the wrong lever when the forwarded value crosses a unit GRANULARITY (D20).** Keeping tags would ride per-element `UnitCell`s INTO a matrix, which the model forbids — so the rank-crossing nodes (WRAPROWS/WRAPCOLS and the stackers, whose `anytable` rows accept a list) are `unitAware = true` and reduce each input themselves (`matrixCellsFromList` → bare magnitudes + the one shared unit, tagged with `withMatrixUnit`); `unitAware` wins over the passthrough keep-tags branch in coerceInputs, so the two compose. Machine-checked: `passthroughSystem.test.ts` + `trueAnyAdopt.test.ts` + `matrixUnitPolicy.test.ts`.
- **THREE derived-socket-type systems, one settle point (D17, 2026-07-09).** Conduit lanes (`conduitTrace.ts`), FC adoption (above), and **trueany adoption** (`trueAnyAdopt.ts`): every `AdoptiveSocket` — the marker subclass `trueAnyIn`/`trueAnyOut` mint per port — adopts the wired cable's type and reverts to its declared `base` on disconnect (default `trueany`; a narrower `anytable`/`anylist` base — `adoptiveTableIn`/`adoptiveListIn`, used by Build Frame / Frame from Lists to learn a matrix/list's element family incl. `date` — keeps the port RESTRICTED to that rung while still adopting the concrete wired type). INPUTS adopt universally; OUTPUTS only where honest (Display/Expect/Input-Switch-One pass through; IF/IFERROR/CHOOSE/SWITCH/IFS results adopt when every WIRED branch agrees; INDEX projects its container's family onto its own rank, reading a frame's per-column family off the static shape; XLOOKUP's result is `staticTrueAnyIn/Out` — the shared never-mutated singleton — because a cube cell's type varies per row). `settleWildcardTypes(editor)` alternates the Conduit and trueany passes to a joint fixpoint and is THE entry point — `reconcileFcTypes` and the load path (`persistence.ts`) both route through it, so the connection pipe, Note retypes, paste, and load all settle identically. Since 2026-07-27 a socket type can also be derived from static CONFIG (INDEX's Column literal + the frame shape every verb's literal config feeds), so the LITERAL commit paths — `InlineInputs` set/setStr, `useNodeField`, the Frame Input source editor — call `reconcileTypesAfterEdit` (fcReconcile), which runs the settle and pays the full FC reconcile ONLY when a type actually moved. **Invariants:** adoption NEVER drops cables (it is derived state; the mismatch scan flags an ill-typed cable — only explicit user retypes go through `retypeOutputCables`); adopted types are NEVER persisted (re-derived from wiring on load); an adopting port must own its socket instance (a shared singleton would leak adoption across cards — the Input Switch's old shared `valueSocket` was exactly this trap). Runs on the MAIN editor only — drill-in composites don't adopt yet (backlog). Machine-checked: `trueAnyAdopt.test.ts`.
- Machine-checked: `noteFcPropagation.test.ts` (Note date→number re-adapts a direct + a through-passthrough FC) and `fcReconcile.test.ts` (`retypeOutputCables` keeps an `any`-input cable, drops an incompatible typed one).

## Unit flow — the FC is VALUE-MUTATING; format is a display annotation (`unitFlow.ts`)

Two layers since FC A4 (2026-07-13). **The UNIT is a property of the VALUE.** A value carries its dimension + display unit AS DATA — a base-SI `UnitCell` (`unitValue.ts`) with an optional `display` id. An FC (`applyFcUnit` in `FormatControllerNode.data()`) or Convert (`data()`) AUTHORS it — the ONLY two authors; the Number node is a plain literal source (a "Number picker" author appeared in earlier revisions of this doc and was stale — CLAUDE.md's "authored ONLY by the FC / Convert" is the truth); it then rides the value through anything that passes the value along and BREAKS at anything that transforms it, ON ITS OWN — every algebra result funnels through `tagDim`, which carries NO display, so a transformed value reverts to its derived-symbol form. **There is no graph unit-walk** (`makeUnitResolver` was deleted 2026-07-13). **The number FORMAT** (style / precision / negatives / K-M-B) is a separate DISPLAY annotation an FC locks onto the box behind it; `makeAnnotationResolver` (pure, duck-typed, memoized + cycle-guarded) resolves THAT forward/back. The one-line "don't break this":

- **`applyFcUnit(value, fcUnitId)`** (`unitBridge.ts`) is the value-side author: a dimensionless number + a real unit → base-SI `UnitCell` (interpret the magnitude AS that unit — `5` + km ⇒ 5000 m, display km); an already-dimensioned cell + a COMMENSURABLE unit → re-display (base kept, `display` swapped); dimensioned + INcommensurable → `#UNIT!` (a true dimension clash is honest-wrong, not silently re-asserted); `none`/`custom`/text/matrix/frame → pass through (any existing tag rides on). Convert authors likewise (base-SI + toUnit display; a clash between an already-dimensioned input and the target is `#UNIT!`). `guardCell` (`shared.ts`) preserves `display` through the broadcaster.
- **The FORMAT annotation resolver — per-node rule** (`makeAnnotationResolver.compute`): **Convert** → drops the inherited format (a value transform); **per-output producer** (`hasAnnotationFor` — `annotationFor(outKey)`) → each output carries its OWN lock or nothing (Triangle Solver: `deg` on the angles, sides bare; Element: g/mol on mass, Z bare); **FC / node-level producer** (`hasAnnotation`) → locks its own format; **pure passthrough** (`passesUnitThrough === true`, Display) → carries its input's; **selector** (`unitPassInputs()` — IF/CHOOSE/SWITCH/IFS) → carries the value branches', **DATA-AWARE** (`selectedUnitInput()` = the branch it actually computed), so `IF(true,km,mi)` follows `then`; indeterminate pick → COMBINE (conflict → none); **anything else** → nothing.
- **The FORMAT reaches a box in BOTH directions, bounded by transforms:** DOWNSTREAM — a box AFTER the FC inherits via `inAnnotation` walking back through passthroughs; UPSTREAM — a box BEFORE a trailing FC (even multi-hop) inherits via `downstreamAnnotation` walking FORWARD through pure passthroughs to an FC ahead. Read-side derivation, so a box's OWN direct FC (`getForNode`) always wins → two FCs in one segment don't clobber.
- **Who writes vs. who derives:** an FC `refreshAnnotation` WRITES its format annotation onto its immediate input-source box (single hop) into `formatAnnotationStore` — keyed `nodeId::socketKey`, `findDockTarget` snaps to the NEAREST socket. The unit LOCK states are live, derived from the VALUE in `data()` (plus `refreshAnnotation`'s do-I-feed-a-Convert walk): `lockedByConvert` (← ← the Convert ahead dictates its fromUnit) and `forwarding` (→ → the incoming value already carries a unit — the dropdown MIRRORS it and LOCKS; author ruling 2026-07-31: an inherited unit is the value's, set elsewhere in the chain, and the FC never re-authors over it — Convert is the re-display tool). Only an FC on an unit-less value authors freely (← →). The READ side: a hero row's `ValueDisplay` names its `socketKey` and reads only that socket's annotation; `DisplayNode` reads `getForNode ?? inAnnotation("in") ?? downstreamAnnotation("out")`. An UNannotated `UnitCell` renders in its own `display` unit (`formatCellWithDisplay` in `valueDisplayFormat.ts`); an annotated one unwraps to the annotation's unit (kept in sync with `display` by the FC).
- **The one compute-time unit read (`trigMode.ts`):** a `Math` node's trig op in **Auto** angle mode computes in degrees when the value feeding it carries a `deg` FORMAT annotation (a bare-degree producer — Triangle Solver, inverse-trig-in-degrees), read via `makeAnnotationResolver.inAnnotation`. A genuinely dimensioned angle is already stored base-RADIANS, so `MathFnNode`'s unit-aware path computes on its magnitude directly and never needs this. `resolveTrigModes(editor)` runs from `processGraph` before the engine pull, stamping a transient `_resolvedAngleMode`. Machine-checked: `trigMode.test.ts`.
- **Currency has no FX — the display CODE is the unit identity (`unitValue.ts` `currencyMismatch`).** Every currency collapses onto the single `currency` base axis at scale 1 (unitBridge's DIRECT — exchange rates are out of scope), so `$5` and `5€` store the SAME base magnitude. A plain magnitude compare/add/aggregate would therefore call them equal, which is wrong. So two currency cells with DIFFERENT, explicit `display` codes are **incommensurable**: `compareUnits` (drives `ComparisonNode`, which is `unitAware`) returns `#UNIT!` → equality answers FALSE (`=`)/TRUE (`≠`), ordering (`<`/`>`) propagates the `#UNIT!`; `addUnits`/`subUnits` and `forAggregateUnits` return `#UNIT!`. A currency cell with NO code (a computed `currency` result) is lenient (adopts). Every OTHER dimension is fine on plain magnitudes — km vs m carry differing SCALES, so base magnitudes already encode the relationship. `ComparisonNode` being `unitAware` also fixes `5 km = 5000 m` (base-SI compare, not the display magnitude the unit-blind boundary used to hand it). A dimensionless operand ADOPTS the other's unit in a compare (`$5 > 1000` compares 5 vs 1000), matching the additive rule. Machine-checked: `unitValue.test.ts` (currency block), `logic.test.ts` ("ComparisonNode is unit-aware").
- **LAMBDA hosts carry units over a 1-D list:** REDUCE / BYROW / BYCOL strip tagged cells to base-SI magnitudes for the numeric fold, run `dimEval` (`unitDimExpr.ts`) with the fold/aggregate vars bound to the element dim to get the result dim, and re-tag (preserving `display` when the dim is unchanged); mixed units / a formula clash → `#UNIT!`; a dimensionless-yielding formula (COUNT) strips to a plain number. MAP/MAKEARRAY/SCAN stay matrix-agnostic (`tableLambda.ts`).
- **ONE concept, a carrier per RANK — and the matrix-op guard (D20).** "This value has unit X" is carried differently at each rank because units attach at the granularity of homogeneity: **scalar** = a value-level `UnitCell` (base-SI); **list** = per-cell `UnitCell`s (base-SI, mixed allowed); **frame** = a `ColumnUnit` on `FrameColumn.unit` over AS-TYPED cells; **matrix** = ONE `ColumnUnit` for the whole grid as a non-enumerable Symbol tag over AS-TYPED cells (`unitValue.ts`); **cube** = PER-CELL like a list (heterogeneous per cell) — a dimensioned cell is a base-SI `UnitCell` (`CubeCell` includes it); `cubeCellsFromColumn` tags a frame column into the cube, `inferColumn` recovers a uniform column unit on the way back (`cellToNumber`/`cellKeyId` read the display magnitude). NOTE the storage split: scalar/list `UnitCell.value` is BASE-SI, but frame/matrix CELLS are AS-TYPED — so crossing between them CONVERTS (`tagFrameCellUnit` as-typed→base `UnitCell`; `displayMagnitudeOf`/`matrixCellsFromList` base→as-typed). The matrix Symbol is LOSSY (any array rebuild drops it), so every matrix op declares a POLICY — **carry** (structural reshape) / **carry-if-uniform** (VSTACK/HSTACK, `sharedMatrixUnit`) / **convert** (rank change crosses carriers: TOCOL/TOROW→list `taggedListFromMatrix`, WRAPROWS/WRAPCOLS←list `matrixCellsFromList`) / **strip** (MMULT/MDETERM/MINVERSE) / **na** / **author** (Table Input). A new algebra op = add `unitAware = true`; a new numeric-matrix INPUT is re-carried across `toMatrix` in `coerceValue`'s `table` case (the trueany-adopts-`table` fix). **`matrixUnitPolicy.test.ts` is the anti-recurrence guard:** it tests each policy AND runs a completeness sweep that fails the build if a `matrix.ts` node takes a matrix without a declared policy — so "did you carry the unit?" is a red test, not a silent drop. A `MatrixValue` wrapper was rejected (D20): the fragility is localized to rebuild sites, so the discipline+guard is the right fix, not churning the universal `toMatrix`/`toScalar` coercers.
- **Machine-checked:** `unitFlowAnnotation.test.ts` (format directional rules + `applyFcUnit` value-mutating cases), `unitFlowSeed.test.ts` (the **Unit Flow** seed's five captioned behaviors, re-authored to the value model), `convert.test.ts` (Convert tags its output), `tableLambda.test.ts` (LAMBDA-host unit carry).
- **What the annotation RENDERS is a separate model** (v1.1 A1, 2026-07-05): `docs/format-model.md` + `formatModel.ts` — the per-family control truth table (which FC controls exist per socket type; hidden-and-inert, never disabled-but-visible), the ONE precision×style rule, and the advanced tier (grouping / negative styles / K/M/B scale). `formatModel.test.ts` machine-checks the whole SocketDataType union against it. `resolveValueOrigin` (same file as the resolvers) is the popup "Go to source" upstream walk — same duck-typed per-node rule, different payload.

## Error values (`errorValue.ts`)

Failures flow as tagged `SolError` values (Excel-style `#CODE!`, but a more specific set borrowed from SQLSTATE class 22 and OpenFormula Err:5xx — `#DIV/0!`, `#N/A`, `#DOMAIN!`, `#CONV!`, `#OVERFLOW!`, `#SYNTAX!`, `#VALUE!`, `#TYPE!`, `#SHAPE!`, `#UNIT!`, `#NAME?`, `#REF!`, `#CIRC!`, `#SOLVE!`, `#ERROR!` — the `SolErrorCode` union + full mapping table in the module header). `installErrorGuards(node)` wraps every node's `data()` at `nodecreated`: error in → error out without running the node, a throwing `data()` degrades to a local `#ERROR!` (one bad node can't half-kill a recompute pass), and `cachedResult` mirrors the error so the value box renders the red code badge (ValueDisplay, tooltip = structural message). IFERROR/IS-checks and the lane routers (Conduit/CableSwitch) are registered to see raw errors instead. Producers return `solError(...)` instead of `null` where the failure is a real error — `null` stays the legitimate "blank".
- **The old scalar-level invariant is RELAXED — array-semantics value model (Inc 1–8, 2026-06-22).** Lists, matrices, and frames now carry, as DISTINCT kinds: a first-class `null` (missing — rendered `null`, **skipped** by aggregators, dropped by Filter's predicate, propagated by element-wise math), per-cell `SolError`s (propagated), and a first-class **logical** boolean (purple socket family, TRUE/FALSE, coerces ↔ 1/0). `valueKinds.ts` is the core (`isMissing`, `forAggregate` = skip-null/propagate-error, Kleene `kleeneAnd/Or/Not`). `FrameColumn` carries a `logical` column type + per-cell errors; the table popup edits number/text/date/**logical** columns. `IS.TEST` (ISNULL + the numeric checks) tests per-cell to any depth incl. frames. The **Coalesce/Fill** node (`FillNode`) is the opt-in to treat `null` as something (constant/ffill/bfill/mean/median/mode/interpolate/drop/coalesce). Persistence needs NO new format (computed values regenerate; a Frame Input's logical/null cells round-trip via `frameText`). Display/popup branch on boolean + null + `isSolError`. **Element-wise math nodes tag per-cell errors UNIFORMLY (2026-06-24):** a condition that's a tagged error at scalar level (`÷0`→`#DIV/0!`, domain miss→`#DOMAIN!`, cross-family Convert→`#N/A`, overflow→`#OVERFLOW!`) is the SAME tag inside a list, per cell — no node may collapse a per-element error to NaN/null. The mechanism is `broadcastErr` (sibling of `broadcast` in `nodes/shared.ts`): its element fn may return a `SolError`, and the call-site maps the producer's domain-`null` sentinel via `?? errFactory()`. Whole-NODE errors (Convert's cross-family unit pick — not a per-cell condition) stay a single value at every dimensionality. Converted nodes: Arithmetic, Math (MathFn), TwoInputMath (LOG), Standardize, Fisher, Convert. (`broadcast` itself still NaN-collapses; use it only where a bad element is genuinely a blank, not an error.) Coalesce is full N-ary (2026-07-05): FillNode's Else rows are extensible (`e0, e1, …`, CHOOSE-style valueKeys round-trip); first present of List-then-each-Else wins per position; a typed literal on an unwired Else row is a broadcast last-resort constant. (The popup-grid error red-badge was SCRAPPED 2026-06-24 — code-as-text is acceptable.) See the dev-notes archive "Build progress (array-semantics)".
- **The null/error handling family is a 2×2 with ONE notion of "error" (aligned 2026-06-23).** Detect × recover, over missing(`null`) vs error(`SolError`): **detect** = Test `ISNULL` (per-cell missing, deep — uses `isMissing`) / `ISERROR` (`isSolError`) / `ISNA` (`isNaError`); **recover** = `FillNode` (missing → constant/ffill/…/coalesce) / `IFERROR`·`IFNA` (error → fallback, per-cell). Invariants that MUST hold across these: (1) a tagged `SolError` is the SINGLE definition of "error" — `ISERROR` and `IFERROR` agree exactly (`isSolError`); a bare `NaN` is NOT an error (ops classify non-finite RESULTS via `guardFinite` → `#DOMAIN!`/`#OVERFLOW!`, so untagged NaN never reaches these nodes — see the per-cell/non-finite bullet below). (2) A `null` (missing) is NOT an error in any of them — it passes through `IFERROR`/`IFNA` and is the thing `Fill` targets; a real "not found" is a tagged `#N/A` (e.g. XLOOKUP), not `null`. (3) The `#N/A` test lives in ONE place, `isNaError` (errorValue.ts), shared by `ISNA` + `IFNA` so they can't drift. (4) An error consumer reading a possibly-`null` WIRED input must test connection-PRESENCE (`inputs.x && inputs.x.length`), not `inputs.x?.[0] ?? literal` — `??` treats a delivered `null` as absent and substitutes the literal, hiding the missing cell. `Fill` and `IFERROR` partition cleanly (Fill never touches errors, IFERROR never touches null); `Fill`'s `coalesce` op is `IFERROR`'s shape applied to `null`.
- **Frame Input is a LITERAL source; coercion happens at the value boundary (2026-06-24).** An input node must NOT rewrite what you type (the `1`→`TRUE` bug). The model SEPARATES the edit/storage representation from the computed value: Frame Input stores a raw `FrameSource` (`{name, type, cells: string[]}`, in `frameText`) — exactly the text typed — and `deriveFrame` produces the typed `FrameValue` (booleans, date serials) at COMPUTE time via `coerceFrameCell` (sharing `coerceLogical`). `parseFrameSource`/`frameSourceToText` load/store; `frameFromInputText = deriveFrame ∘ parseFrameSource`; old typed-`values` JSON + legacy CSV still parse (cells kept raw), no migration. **`FrameColumn.raw?: string[]`** carries the INPUTTED text per cell (pre-inference) for SOURCE frames: `inferColumn` populates it (so every CSV/Web/Import frame has it), `deriveFrame` carries the Frame Input's cells. The popup's **Source checkbox** (always shown on a frame popup) renders `raw` verbatim; a purely-computed column with no `raw` falls back to the underlying form (a date's serial, a logical's 1/0). **INVARIANT — keep `raw` row-aligned:** a transform that changes a column's rows/values MUST drop or REMAP `raw` (Filter + Get Row remap to surviving/picked rows; Add Column's replace drops it) — a stale `raw` misaligns the Source view. (v1.1 will reuse the same checkbox for per-column FC styling, e.g. numbers→percentages.) **Table Input joined the model (2026-07-09):** `tableText` is raw text, `tableRawCells`/`deriveTable` (matrix.ts) derive the typed matrix through the SAME `coerceFrameCell` (blank → null, bad number/date → NaN, bad logical → null), the grid popup edits raw cells via the lean `onSaveRaw` mode (never a parse→serialize round trip), and ONE `dataType` SegToggle (number/string/date/logical) retypes the output socket in place (`retypeOutputCables`).
- **Shape errors are part of this system, not a parallel one.** The central input coercion (`coerceInputs.ts`) wraps every node's `data()` INSIDE the error guard (Canvas installs coercion first, guard second); a narrowing failure throws `ShapeError`, which propagates to the guard's catch where `fromThrown` (matched by `e.name`, no import coupling) maps it to a tagged `#SHAPE!`. So a dimension mismatch renders the badge and propagates like every other error — there is no separate `#DIM!`/`cachedError`-string path (removed 2026-06-15). The shared **result displays all tolerate a `SolError` in `cachedResult`** (render the badge, not crash): `ValueDisplay`, `TableDisplay`, `FrameDisplay`, and the GroupNode collapsed readout. When adding a NEW custom result display, give it an `isSolError(v)` branch up front.
- **A formula node keeps BOTH signals.** Expression / LAMBDA / MAP·BYROW·BYCOL·MAKEARRAY·REDUCE / Filter set the rich inline `cachedError` string (in-node authoring hint, e.g. `Shape mismatch (3×2 vs 2×2)`) AND return a propagating `SolError` whose code matches the failure (`#SYNTAX!` bad formula, `#VALUE!` arity/eval, `#NAME?` bad param, `#SHAPE!` dimension, `#OVERFLOW!` too-large). `cachedResult` stays `null` on these so the box shows the richer inline message; the returned value carries the code (tooltip = its message) for downstream. A blank/empty formula stays `null` (legitimate no-value), never an error.
- **Producer sweep done (2026-06-15).** Genuine-error sites across finance (IRR/RATE/XIRR non-convergence → `#CONV!`, MIRR same-sign cashflows → `#DIV/0!`, MIRR overflow → `#OVERFLOW!`), scalar (Combinatorics out-of-domain → `#DOMAIN!`, overflow → `#OVERFLOW!`), Convert (cross-family units → `#N/A`, overflow → `#OVERFLOW!`), stats (zero-variance Correl/Standardize/Forecast/Regression → `#DIV/0!`, Fisher/Percentile domain → `#DOMAIN!`, Rank/PercentRank/FIND miss → `#N/A`), cast/text (parse failures → `#VALUE!`), date (DATEVALUE/TIMEVALUE unparseable non-empty text → `#VALUE!`; blank still → blank), matrix (singular → `#DIV/0!`, non-conformable/non-square → `#SHAPE!`), and list (INDEX out of range → `#REF!`). The only deliberate null-on-failure sentinels left are the discrete-distribution pmf/cdf helpers (`dist-discrete.ts`), where an out-of-support argument is a blank/N-A by design, not a computation failure. The SCALAR-LEVEL invariant governs every one: a `broadcast`/`.map` over a list keeps per-element `null`s (blanks); only a scalar result becomes a `SolError`. `Displayable` (standardNode.tsx) includes `SolError`, so a converted producer using `makeNodeComponent((n) => n.cachedResult)` renders the badge with no extra work.
- **Per-cell error/null contract + non-finite guard (2026-07-04).** ONE rule, per output cell, decided BEFORE the op, factored into every element-wise broadcaster (`shared.ts` broadcast/broadcastErr, `excelFormula.ts` broadcastCall + operators/unary, `logic.ts` broadcastEl): a `SolError` operand → that error UNMORPHED (first in arg order); else a missing (`null`) operand → `null`; else compute. Shared helpers `cellShortCircuit` (full) / `cellError` (error-only, for the Kleene logic family which feeds `null` to its own fn) in `valueKinds.ts`. So an in-range list cell behaves identically to a scalar and a ragged-pad — `[1,#DIV/0!,3]+10` keeps the error, `[1,null,3]+10` → `[11,null,13]`. broadcastCall's null short-circuit is skipped for a `NULL_INSPECTING` predicate set (ISBLANK/ISNUMBER/…) that must SEE the blank. **Non-finite guard (`guardFinite`, valueKinds.ts):** a computation never yields a bare NaN/Infinity — per RESULT, with input awareness: NaN → `#DOMAIN!`; ±Inf from all-FINITE inputs → `#OVERFLOW!` (renamed from `#RANGE!` — descriptive, not Excel-#NUM!-mimicry; one code, still splits Excel #NUM!, ERROR.TYPE 6); ±Inf when an INPUT was already infinite PASSES (the Constant node's ∞ is first-class: ∞+5=∞, 2×∞=∞, 5/∞=0). Runs at the producing op (broadcasters + applyOp + broadcastCall), so Expression's `tagResult` trusts it and just passes a surviving ∞ (nets a stray NaN → `#DOMAIN!`). `0^0 = 1` (JS/Polars; Excel #NUM! — parity:false on the pow leaf). **Scalar reads:** `readInput(wired, literal)` (shared.ts) replaces `inputs.x?.[0] ?? literal` for DATA inputs so a WIRED `null` propagates instead of being swallowed to the literal; CONFIG inputs (base/digits/order/counts) keep defaulting. (Supersedes the 2×2 bullet's point (4) `??`-warning for swept nodes.) Applied across scalar.ts; the remaining data() files are a follow-up (backlog). Machine-checked by `broadcastContract.test.ts`.
- **`#CIRC!` is engine-level, not a producer.** The pull-based DataflowEngine resolves a node's inputs (recursively) *before* calling its `data()`, so a dependency loop makes `engine.fetch` **deadlock forever** (NOT throw). `processGraph` (process.ts) finds the loops' TRUE members up front via Tarjan SCC (`loopMembers` — nodes in a 2+ node strongly-connected component, or a self-loop) and **pre-seeds the engine's result cache** (`engine.cache.add(id, …)`, a documented public field) for each with a `#CIRC!` value. A downstream node then resolves a member straight from the cache instead of recursing in, so it computes normally and shows the *propagated* `#CIRC!` (a Display badge, an ISERROR explanation) — only the actual members dead-end. Seed ONLY the SCC members, never their descendants (Kahn-leftover lumps both together; marking descendants would blank their own computation). The connection guard already blocks self-loops on creation; multi-node loops are caught here.
- **`DisplayNode` SEES errors (`SEES_ERRORS`).** Display is a pass-through whose value box reads `cachedValue`, not the `cachedResult` the generic error short-circuit mirrors to — so without this it stayed blank when an error reached it. Letting its `data()` run on the raw error lets it both SHOW the badge (via the SolError-aware `ValueDisplay`) and FORWARD the error on `out` so the chain keeps propagating. (Nodes that render `cachedResult` — the large majority — already show propagated errors; the gap was the `cachedValue`/`cachedList`/`cachedText` minority, and Display was the one that mattered for the showcase chain.)
- **Per-cell errors surface via a BOUNDED scan (2026-07-12).** `reportOut` (the error-sink → Problems panel) and `modelFuzz.badValue` no longer see only a TOP-LEVEL `SolError` — `findCellError` (errorValue.ts) also finds a per-cell error inside a list/matrix/frame. A full O(rows×cols) scan every node every pass was rejected on perf, so the scan is CAPPED: `sampledCellIndices(len)` examines the head (`CELL_SCAN_HEAD`=64) plus a stride sample (`CELL_SCAN_STRIDE_SAMPLES`=32) of the tail — a constant per container (matrix rows recurse under the same per-row bound). A systematic whole-column error (a bad transform on every row — the common case) is always caught by the head; a lone bad cell buried past the head between two strides can be missed — the accepted cost of an O(1)-per-output hot path. `modelFuzz` reuses the same bound (`badValue` → `collectFinite`/`sampledCellIndices`); nulls are NOT flagged (a missing is first-class-legitimate, not a defect). See `cellErrorScan.test.ts`.
- **the error-codes tour** (merged into `seedGraphs/null-and-logical.json`, the "Errors, Null & Logic" seed) is the showcase: one row per code of the set current at its build (`#ERROR!` is the unreachable internal catch-all, noted in the seed; the later `#TYPE!`/`#UNIT!`/`#SOLVE!` codes aren't toured), each wired **producer → Display → ISERROR** so the error shows its badge, propagates, and the ISERROR check explains it. The `#CIRC!` row loops back through an upside-down Conduit. `errorSeed.test.ts` loads the actual JSON, runs it through a real editor+engine (coercion + guards + the cycle cache-seeding) and asserts every ISERROR reports its row's code — so a wrong socket key or a silently-null producer fails CI instead of showing blank in-app. `seeds.test.ts` validates structure; `errorIntegration.test.ts` locks the engine paths (coercion `#SHAPE!`, lambda→MAP `#NAME?`, Display show+forward, cycle cache-seeding).

## Alert node + Alerts HUD (`nodes/display.ts` AlertNode, `alertStore.ts`, `components/AlertLayer.tsx`, `HudStack.tsx`)

The **Alert** node watches a value and fires a notification when its condition is met. The `mode` dropdown (persisted via the shared `mode` init key) picks BOTH the trigger condition AND which input sockets are live — `ALERT_MODE_KEYS`: `range` → value/low/high (outside [low,high]); `equals` → value/target (exact match, socket labeled "Match"); `boolean` → value (is TRUE — `=== 1`, NOT any nonzero: this app encodes booleans as 1/0); `text` → text/match (contains). The node carries the full superset of sockets and the component shows only the active mode's keys, dropping cables to now-hidden sockets on a mode change (the TVM pattern). The status output is 0=calm, 1/2 for range LOW/HIGH, 1=triggered otherwise.

- **Edge detection is on the STATUS, not a boolean** (`statusKey`): it re-fires whenever the alerting status changes to a *different* alerting value — so range OK→LOW, OK→HIGH and LOW↔HIGH all fire, but LOW→LOW / HIGH→HIGH don't, and returning to calm is silent. `lastStatusKey` starts at the `NO_STATUS` sentinel so a node born alerting (or freshly switched into an already-met condition) fires once; a MODE CHANGE compares against `NO_STATUS` (the old mode's status is meaningless), so switching into a met condition surfaces it. `null` result = unknown (missing input) — neither fires nor disturbs the baseline. Firing is gated by `isGraphRebuilding()` so load/seed don't spam (the post-rebuild `processGraph` runs inside the rebuild scope).
- **`fireAlert(...)` (alertStore.ts) is the single entry point:** it logs an event to `alertStore` (a capped, transient, NOT-persisted log) AND raises a toast via `pushNotice` (noticeStore). Messages are neutral observations ("150 above 100", "equals 7", "is true", `contains "error"`) — an Alert is a watch/notify, not a pass/fail, so the value box dropped ✓/⚠ for a neutral state dot.
- **`HudStack.tsx`** is the right-side fixed HUD column (one portal, `top:124px right:12px`, below the nav pill): it owns positioning and stacks `PinLayer` (pinned values, top) above `AlertLayer` (fired alerts, below) — so the alerts button always lands below all pins regardless of pin count. Each section renders nothing when empty. `PinLayer` lost its own portal/fixed wrapper (moved up to the stack). **Not a generic panel API** — each child (`PinLayer`, `AlertLayer`, and any future panel) is a fully bespoke component with its own `useState`, own trigger button, own `registerChrome` call; a new panel is a new component added as a sibling child, not a plug-in to a shared base.

## Addressable model (`nodeNameStore.ts`, `nodeNaming.ts`, `textForm.ts`)

Every node has a **stable, user-editable name**, separate from the rete-internal `id`
(which stays random/regenerated-on-load, per `rebuildGraph`'s `idMap` — names never
assume id stability). Default: a type-scoped counter (`Filter_2`), editable, validated
unique per document. (`label` is a per-class constant, not per-instance — not the name.)

The **text projection** (graph ↔ one-node-per-line text, name-addressed rather than
id-addressed) is a second view of the same document, alongside the canvas and the JSON
save. Grammar invariants:
- **Line order is topological (dependency order), ties broken alphabetically by
  name** — NOT canvas position and NOT plain alphabetical. Canvas-position order would
  reshuffle the whole file on every drag (constant, logic-unrelated churn — the worst
  option for the git-diffability this whole bet exists for); topological order only
  perturbs the region actually touched by a real edit.
- **Canonicalization on write:** numbers via JS's default shortest round-trippable
  `String(n)` (no locale formatting, no fixed padding); each node line's fields in one
  fixed schema order (type, name, literals in a stable declared order, then
  connections) — never alphabetical-by-key or insertion-order. Two writes of an
  unmodified graph must be byte-identical.
- **Visual state (position, size, collapsed, etc.) lives in a separate trailing
  block/sidecar, not inline in the per-node lines** — keeps the readable lines looking
  like code (type, name, wiring), not a scene graph.
- **The sidecar ALSO carries every non-node top-level SavedGraph field**: `positions`,
  `standoffs`, `pins`, `comments`, `seedId`, `palette`, `reportPalette`, `meta` (doc
  author/tags, F-2), `packs` (+ `v`). A NEW top-level field MUST be added to BOTH
  `writeTextForm` and `readTextForm` — `serializeGraph` round-trips through the text form,
  so anything the sidecar omits is **silently dropped on every save** (the per-doc autosave
  goes through `serializeGraph` via `captureCurrent`). `comments` + `reportPalette` were lost
  this way from their ship date until 2026-07-06 — a real data-loss bug; don't reintroduce the
  gap. Node references inside the sidecar (pins/standoffs/comments `nodeId`) are name-addressed.
- The JSON save is *generated* from the text form, not hand-maintained in parallel —
  contain the two-formats-to-sync risk by making JSON strictly derived.
- Round-trip losslessness (text → graph → text is idempotent) is machine-checked the
  same way `seeds.test.ts` checks structural invariants today — load every seed, write
  text, re-read, re-write, assert the second write is byte-identical. Keep it green
  permanently, same discipline as `cablePaths.test.ts`'s continuity gate.

## Per-doc autosave persistence (`documentStore.ts`, 2026-07-05)

Each document persists to its OWN two-slot localStorage pair
(`solenoid.docs.doc.<id>.a/.b`) plus one light two-slot INDEX pair
(`solenoid.docs.index.a/.b` — currentId + `[{id, name, updatedAt, filePath}]`, no
graphs). `persist()` writes the index always (tiny) and only the documents whose
object CHANGED. The invariants that make this correct:

- **Change detection is OBJECT IDENTITY, so `documentStoreCore.ts`'s transforms must
  stay immutable.** A changed doc must be a NEW object (`{...d, …}`); mutating a
  `SolDoc` in place means `persist()` sees the same reference and silently NEVER
  writes it. (Mutating a doc you just created, before its first persist, is fine —
  `importAsDocument` does this.) If a future transform needs to touch a doc, copy it.
- **Slot seq is a strictly-monotonic in-session counter** (seeded from `Date.now()`),
  not raw `Date.now()` — two same-millisecond writes tie, making the "newer slot"
  read ambiguous (the read could resurrect the older write). Seq is read via a
  `^\{"seq":(\d+)` prefix regex so choosing the write slot never re-parses a large
  graph blob.
- **The index is metadata only; a doc's own slot is the truth** on any field
  disagreement (the index is rewritten wholesale from memory on every persist). A
  missing/corrupt doc slot is SKIPPED on restore — the rest of the library loads.
- **Deleting a doc must remove its slots** (`removeDocSlots`) — that's the quota-frees
  half of the feature; `persist()` does it by diffing `_lastPersisted`'s keys against
  the live library.
- No migration path exists (D3): the pre-2026-07-05 whole-library keys
  (`solenoid.docs.lib.a/b`) are deleted on startup. Guard tests:
  `documentStorePersist.test.ts`.

## Inline literal maps — declaration gates restore (2026-07-19)

`literals` / `stringLiterals` are the per-node inline-typed values (number rows,
CSV-typeable lists, column pickers). The governing convention: **a node class
DECLARES the map field iff its card edits it inline.** Everything hangs off that:

- **Load restores a saved literal map ONLY onto a declaring class**
  (`persistence.ts` load, `typeof anyNode.literals === "object"` gate). A
  wire-driven card — the Equation family (Equation, TVM, Triangle Solver) —
  declares neither, so a hand-authored save/seed cannot plant a hardcoded known
  the user can't see or edit on the card (the PF "TVM fv: 0" bug). Equation
  variables are known ONLY through cables; the literal fallback was deleted from
  `EquationNode.data()` outright.
- **Seeds are checked at authoring time**: `seeds.test.ts` rejects any seed
  node whose `literals`/`stringLiterals` target a non-declaring class — fail
  loud there instead of silently dropping on load. Wire a visible input node
  (Number Input etc.) instead.
- **A typeable-list input implies the declaration**: any node with a
  `strlist`/`datelist`/`logicallist` input must declare `stringLiterals`
  (the CSV editor stores raw text there; `coerceInputs` injects the parsed
  list when unwired) — machine-checked by the `FLAT_CATALOG` sweep in
  `coerceInputs.test.ts`, so a new verb-style node can't silently lose the
  user's typed CSV on reload.
- Node-specific DEFAULTS stay legitimate: a class initializing
  `literals = { rate: 0.05, … }` is declaring editable-with-a-default, which is
  exactly what the convention permits.

## Composite drill-in mount lifecycle (`CompositeEditorOverlay.tsx`, 2026-07-05)

A composite's drill-in rete stack (AreaPlugin + ReactPlugin + ConnectionPlugin +
HistoryPlugin) is created ONCE per composite instance and cached on the node
(`__drillMount`) — rete has no `unuse`, so a fresh AreaPlugin per open would
accumulate dead pipes on the long-lived `internalEditor`. The lifecycle invariants:

- **Close must REMOVE every internal node/connection VIEW** (`area.removeNodeView` /
  `removeConnectionView`), not just detach the container. A detached container keeps
  the per-view React roots MOUNTED — their effects keep running, which is how a
  Connection node's auto-refresh interval inside a closed (or deleted) composite kept
  firing full `processGraph()`s forever (audit 2026-07-05). Unmounting the views runs
  the component effect cleanups; `removeNodeView` on an id with no view is a safe
  no-op (rete guards it), so the sweep is idempotent and race-proof against a
  close-during-hydrate.
- **Open must BACKFILL views idempotently** (skip ids already in
  `area.nodeViews`/`connectionViews`): first open because the internal graph predates
  the area (nodes hydrate at collapse/load, before any `nodecreated` the plugins could
  see), every reopen because close removed them.
- **The undo/redo HistoryPlugin lives on the mount**, so its stack survives
  close/reopen by design — don't move it into the per-open effect.
- **`compositeEditorStore.close()` is part of `rebuildGraph`'s bulk-reset** (with
  reportStore/presentationStore): a drill-in open across a document switch would
  render a CompositeNode belonging to the dead graph.
