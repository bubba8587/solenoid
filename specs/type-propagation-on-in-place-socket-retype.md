# Spec: Type propagation on in-place socket retype

Serves [[D16]] retypeReconciles; the static shape walk serves [[D17]] relaysTransparent (passthroughs forward the shape) and [[C8]] declareOnce (`frameShape()` and `columnPickers()` are each a node's one declaration). The mechanics a builder implements: what the system does and blocks, with the decision each behaviour serves. Lifted from `docs/subsystem-invariants.md` § Type propagation on in-place socket retype; a WHY that is not in a node belongs in one.

A Format Controller doesn't carry a fixed type — it ADOPTS the concrete type flowing into it (`adaptTypeFromConnections` → `concreteTypeOfOutput`, which walks upstream through passthrough WILDCARD sockets — ALL SIX family-less rungs, via `isWildcardRung`, since a rank with no family is no answer — and reads the live socket `dataType`), and auto-picks a date format for a date type. That re-adaptation runs from the Canvas `connectioncreated`/`connectionremoved` pipe. **The trap:** several nodes change an OUTPUT socket's type IN PLACE via a UI control — **Cast** target, **LAMBDA/Expression** result type (`ResultTypeToggle`), **Get Column** read-as, and a **Note**'s frontmatter retype — and a pure in-place retype fires NO connection event, so without help the downstream FCs keep formatting by the stale type (the reported "date serial retyped to a number still renders as a date" — a broken core promise).

- **YES, a node's own op/mode/arg field DOES swap that node's sockets in place — this is an established, first-class pattern, not a thing to "discover" as absent (it has been mis-reported as absent more than once; it is not).** A control-driven swap changes an INPUT socket, an OUTPUT socket, or both, and adds/removes whole input rows. This is DISTINCT from wildcard/adoption retyping (`trueAnyAdopt`, above), which is wiring-driven and never touched by a field. **The mechanics (all one recipe):** the class exposes `setOp`/`setMode` that mutates `this.inputs`/`this.outputs` (`addInput`/`removeInput`, or `out.socket = spec.socket`); the class exposes `keysDroppedBySwitch(next)` naming the input keys the swap removes; the COMPONENT, on the toggle, (1) `dropInputCables(id, departing)` FIRST — **onePrunePath**, or a removed socket leaves an invisible live cable — then (2) calls `setOp`/`setMode`, then (3) `rerenderNode`, then (4) after an OUTPUT swap only, `retypeOutputCables` (an in-place swap fires no connection event, per the trap). Exemplars, so this is never doubted again: **`WorkdaysNode`** (Days↔End-date input + date↔number output), **`SettleNode`** (people-frame↔ledger-cube INPUT on its `mode`), **`RecordNode`** (Row/Group-by sockets per op), **`WorkdaysNode`/`ReturnsNode`/finance + `date.ts`** (output family), **`CableSwitchNode`** (One↔Many output), **`Expression`/`composite`/`formatController`** (`setType`). Grep `setOp`/`setMode`/`keysDroppedBySwitch` before ever claiming a node can't retype on a mode.

- **The rule: any code that mutates a socket's `dataType` in place MUST re-drive FC adaptation.** Use `fcReconcile.ts`:
  - `reconcileFcTypes(editor, area)` — the shared sweep (re-adapt every FC's type + re-project annotations + refresh Convert unit-arrows + re-render). The Canvas connection pipe calls it; so does anything doing a manual retype. Does NOT recompute — the caller owns `processGraph`.
  - `retypeOutputCables(editor, area, nodeId, outKey)` — call after swapping an OUTPUT socket: reads the new type off the (already-swapped) socket, KEEPS each outgoing cable the new type can still feed (an `any` input always survives; same-family widening too), drops only the now-incompatible ones, then `reconcileFcTypes`. This replaced the old "drop EVERY cable" behavior in Cast / ResultTypeToggle / Get Column (which needlessly severed `any`-input cables). The Note's `commitFields` does the equivalent per retyped key.
- **`concreteTypeOfOutput` walks through wildcard passthroughs** (a Display fed by a date reads as date) but STOPS at a node with its own concrete output type — so a retype legitimately ends at the first node that re-types the value (e.g. a math node that always outputs a number). That's correct, not a propagation gap.
- **Passthrough is ONE declaration (`nodes/passthrough.ts`, 2026-07-15).** A node that forwards a value to an output (a selector, a pure passthrough, an element-agnostic reshape) declares it ONCE via `passthrough(): PassthroughSpec[]` — `{output, inputs (value branches), combine: single|agree|active, selected?() (data-aware branch), pure?}`. The consumers of this one source: trueany TYPE adoption (`trueAnyAdopt` `reconcileOnce` — `resolvePassthroughType` with the `agree` rule), UNIT flow (`unitFlow` — `selected()` first, else combine over the inputs; `pure` drives the downstream FC-segment walk), the frame-SHAPE resolver (`frameShapeResolver` `passthroughForOutput` — load-bearing for column pickers and INDEX's frame projection), coerceInputs' keep-tags boundary (`unitAware || isPassthroughNode`), `ValueDisplay`'s carried-annotation branch (`isPassthroughNode`), and the FC's `refreshAnnotation` do-I-feed-a-Convert walk (`isPurePassthroughNode`). The FC's TYPE adapt walk does NOT read it — `concreteTypeOfOutput` walks upstream on socket `dataType` via `isWildcardRung`. This REPLACED the old split where type used a hardcoded `instanceof` chain and units used `passesUnitThrough`/`unitPassInputs`/`selectedUnitInput` duck markers — the two sets drifted (Expect/CableSwitch/IFERROR passed type but not units). Declarers: Display/Expect (pure single), IF/IFERROR/CHOOSE/SWITCH/IFS (agree over value branches), CableSwitch One-mode (active), and the element-preserving same-rank ops (Reverse/Slice/Take/Drop/Shuffle/NthElement/Pad + TRANSPOSE/CHOOSEROWS/COLS/table-TAKE-DROP/EXPAND — single, with adoptive in+out so their output forwards the input's type). The append ladder declares `agree` over its EXTENSIBLE rows, re-read each pass so a grown row is a value branch immediately (Concat Lists 1-D; VSTACK/HSTACK 2-D), and the rank-CROSSING reshapes (WRAPROWS/WRAPCOLS/TOCOL/TOROW) declare `single` — `projectTypeToBase` lands the element family on the output's own rank. An EXTRACTION (INDEX — it forwards a value out of its container, not the container) declares `single` plus a `project(t, ctx)` that drops the RANK and keeps the element FAMILY: the COMBO rung means exactly "one cell or a whole axis, decided at runtime". `ctx` (`ProjectContext`) is what the projection may consult BEYOND the socket type — the static frame `Shape` arriving on an input (`frameShapeResolver`, supplied by the adoption pass) and whether an input is wired — because a FRAME carries no family in its socket but its named COLUMNS each do (2026-07-27): blank/0 Column → the whole row, still a `frame`; Column = c → that column's family at the combo rung; `trueany` only where genuinely unknown (a WIRED Column, an unresolvable upstream shape, a `dynamic` shape, an out-of-range index, a cube cell). A generative output (XLOOKUP value-dependent, MAP formula-typed, sources) declares nothing → static. **Passthrough alone is the wrong lever when the forwarded value crosses a unit GRANULARITY (unitGranularity).** Keeping tags would ride per-element `UnitCell`s INTO a matrix, which the model forbids — so the rank-crossing nodes (WRAPROWS/WRAPCOLS and the stackers, whose `anytable` rows accept a list) are `unitAware = true` and reduce each input themselves (`matrixCellsFromList` → bare magnitudes + the one shared unit, tagged with `withMatrixUnit`); `unitAware` wins over the passthrough keep-tags branch in coerceInputs, so the two compose. Machine-checked: `passthroughSystem.test.ts` + `trueAnyAdopt.test.ts` + `matrixUnitPolicy.test.ts`.
- **Frame SHAPE is declared per PRODUCER (`nodes/frameShapeHook.ts`, 2026-09-04).** A node that emits a frame states its output columns once via `frameShape(outKey, ctx)` — computed from the wired input shapes (`ctx.inputShape`) and its own literals on UNWIRED sockets (`ctx.wired`) — or returns `null` where only the data can settle the column set (a fetched document, a type inferred from cells, a matrix's width); a misconfigured verb throws the same `#REF!`/`#VALUE!` its run would and the resolver swallows it to `null`. `frameShapeResolver.ts` is the WALK alone (memo + cycle guard, the Conduit lane case, `passthrough()` forwarding, then the hook) and knows no node classes. A rule that can't mirror its verb exactly declares nothing rather than a wrong name. Machine-checked: `frameShapeCoverage.test.ts` (every catalog frame output has a rule, forwards one, or is a NAMED data-dependent producer) + `frameShapeRules.test.ts` (one case per rule). **A node whose string LITERAL names a column of an incoming frame declares that once too, via `columnPickers()` (`nodes/columnPickerHook.ts`): the literal key + the frame input it's a column of.** The shared `ColumnPickerField` (rendered by `InlineInputs` for those keys) offers that frame's static column names (`frameShapeResolver` → `columnNamesOf`) with a free-text fallback, committing the same string literal (socket/literal model unchanged) — declare it beside `frameShape()`. Customers: Sort/Join/Get Column.
- **THREE derived-socket-type systems, one settle point (wildcardLadder, 2026-07-09).** Conduit lanes (`conduitTrace.ts`), FC adoption (above), and **trueany adoption** (`trueAnyAdopt.ts`): every `AdoptiveSocket` — the marker subclass `trueAnyIn`/`trueAnyOut` mint per port — adopts the wired cable's type and reverts to its declared `base` on disconnect (default `trueany`; a narrower `anytable`/`anylist` base — `adoptiveTableIn`/`adoptiveListIn`, used by Build Frame / Frame from Lists to learn a matrix/list's element family incl. `date` — keeps the port RESTRICTED to that rung while still adopting the concrete wired type). INPUTS adopt universally; OUTPUTS only where honest (Display/Expect/Input-Switch-One pass through; IF/IFERROR/CHOOSE/SWITCH/IFS results adopt when every WIRED branch agrees; INDEX projects its container's family onto its own rank, reading a frame's per-column family off the static shape; XLOOKUP's result is `staticTrueAnyOut` — the shared never-mutated singleton — because a cube cell's type varies per row). `settleWildcardTypes(editor)` alternates the Conduit and trueany passes to a joint fixpoint and is THE entry point — `reconcileFcTypes` and the load path (`persistence.ts`) both route through it, so the connection pipe, Note retypes, paste, and load all settle identically. **ORDER (waitForTypeSettle):** any one-shot consumer that CACHES a resolved type — the FC dock loop is the load-path instance — runs AFTER the settle; `persistence.ts`'s rebuild tail is hydrate → settle → dock, pinned by `fcDockReload.test.ts` (the "false Frame type on reload" bug). Since 2026-07-27 a socket type can also be derived from static CONFIG (INDEX's Column literal + the frame shape every verb's literal config feeds), so the LITERAL commit paths — `InlineInputs` set/setStr, `useNodeField`, the Frame Input source editor — call `reconcileTypesAfterEdit` (fcReconcile), which runs the settle and pays the full FC reconcile ONLY when a type actually moved. **Invariants:** adoption NEVER drops cables (it is derived state; the mismatch scan flags an ill-typed cable — only explicit user retypes go through `retypeOutputCables`); adopted types are NEVER persisted (re-derived from wiring on load); an adopting port must own its socket instance (a shared singleton would leak adoption across cards — the Input Switch's old shared `valueSocket` was exactly this trap). A drill-in composite settles its INTERNAL editor itself (`composite.ts` `settleInternalTypes` — the same joint fixpoint plus boundary adoption; the main canvas pipe never touches the internal editor). Machine-checked: `trueAnyAdopt.test.ts`.
