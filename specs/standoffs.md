# Spec: Standoffs

Serves [[C65]] domOrderStacking. The mechanics a builder implements: what the system does and blocks, with the decision each behaviour serves. Lifted from `docs/subsystem-invariants.md` § Standoffs; a WHY that is not in a node belongs in one.

User-declared arrangement constraints: a pale thick bar UNDER everything (`StandoffLayer` inside RF's `<ViewportPortal>` at z -3 — the area-plane stacking order is standoffs -3 < expanded groups -2 < conduits -1 < nodes 0, stamped per node by `nodeZIndex`; a Conduit inside a group was unselectable until groups dropped from -1 to -2) linking two top-level items (nodes/groups; no conduits/FCs/group-members) side↔side (cardinal) or corner↔corner (diagonal).

- **Semantics are AXIS-BAND:** `min ≤ dot(P_b − P_a, axis from a.anchor) ≤ max`; the perpendicular offset is left free (the bar slants to show slack) UNLESS the standoff is LOCKED — the rigid 45° mode (default-ON for new standoffs), which also pulls the perpendicular to 0 so the two ends align exactly along one of the 8 anchor directions (the toolbar angle dial cycles which one; `setAxis` rotates `a.anchor`, `b` takes the opposite). `solveStandoffs({ forceLock })` forces that rigidity for a single solve WITHOUT touching saved `locked` — used so every layout op treats a standoff-connected cluster (`standoffClusters()` = connected components) as one rigid block.
- **Creation:** right-click on one of exactly-two selected items → "Link with Standoff" (anchors auto-face along the dominant of 8 directions; band defaults to [PUSH_GAP, current distance], min hard-floored at `STANDOFF_MIN` = 30).
- **The solver runs LAST.** The pure solver (`solveStandoffs`, unit-tested) is iterative projection with pinning; it runs as the last word after every layout-affecting pass: live drag chain-pull (keyed off the pointer-driven node only — programmatic translates never trigger it; deliberately band-only, NOT forceLock, so an unlocked slant survives a drag), group expand (inside `runExpandPushes`, corrections folded into the push records so collapse restores; a CLUSTER moves as one block — after the heuristic push every member gets the cluster's largest displacement, so a lone push isn't pulled partway back), collapse (post-restore re-settle), autofit, and tidy.
- **Tidy lays each loose cluster out as a SINGLE ELK super-node** (`tidyArrange.ts` `makeArrangeFn`; FlowCanvas only wires it): the leader (prefer a non-group member) is sized to the cluster bbox so ELK reserves room for the block, follower edges remap to the leader (node-level, like the gbridge), members are re-placed at their stored offsets after layout, and the leader's REAL size is restored (the applier resizes proxy nodes to their reported size — same gotcha as `realHostSize`). All of it is a strict no-op without qualifying clusters (graphs with no standoffs tidy identically).
- **Selection & persistence:** selection is mutually exclusive with nodes/cables; a selected standoff shows a docked toolbar (min/max band committing on Enter/blur via `useDraftCommit`, a 45° Lock toggle, an angle dial); Delete removes it. Persisted additively as `SavedGraph.standoffs` (incl. `locked`).
- **Known v1 edges:** an endpoint hidden in a collapsed group goes dormant (bar hidden, constraint skipped); a cluster whose members aren't ALL in the loose layout (e.g. spans a group interior) falls back to the forceLock post-settle instead of the super-node path; no undo entries; Tidy/Cleanup edge-cases on heavy overlap not fully swept.
- **In seeds (author's rule, 2026-09-04):** groups liberally, standoffs sparingly. A seed standoff ONLY pins an unwired explanatory Note to what it explains; a Note wired through its frontmatter exports gets none, and a data node never standoffs to its consumer — an exhibit and its Note go in one group (a Note can be a member). Re-bake with `scripts/tune-seeds.mjs` after editing; exemplars `decision-matrix.json`, `table-verbs.json`.
