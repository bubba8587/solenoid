# Spec: React Flow surface contract

Serves [[C43]] oneFlowSurface. The mechanics a builder implements: what the system does and blocks, with the decision each behaviour serves. Lifted from `docs/subsystem-invariants.md` § React Flow surface contract; a WHY that is not in a node belongs in one.

The view is React Flow over a headless rete model ([[B10]] reactFlowView). What RF owns, what the model owns, and the conversions at the seam — every item below was a shipped bug when it was violated.

- **ONE surface component for both canvases** ([[C43]] oneFlowSurface). The main canvas (`FlowCanvas`) and the composite drill-in (`FlowCompositeOverlay`) render the SAME `FlowSurface` over a `SurfaceStack`; hosts differ only through `SurfaceHooks` (what settles a move, which history answers undo, what Delete removes). Anything surface-level — a gesture, a menu, a key, a layer, an installer — goes in FlowSurface, never in one host: a behavior installed in a host is one the other silently lacks (the rete-era dead drill-in finger pan; the RF-port dead drill-in lasso / hotkeys / group collapse). Command slots the chrome calls through `canvasCommands.ts` (select, Tidy/Cleanup, the keyboard-less delete button) are swapped PER SURFACE by the drill-in while it is open and restored on unmount (`swapSelectionSlots`, `swapArrangeSlots`, `swapDeleteSlot`); a new slot that a drill-in should own needs its own `swap*` here, or the verb silently hits MAIN. Node-scoped code resolves its graph with `getOwningEditor/View`, chrome with `getActiveEditor/View`; bare `getEditor()/getView()` are for persistence and the main-only lifecycle ([[C33]] saveBindsMain). Two mounted flows MUST carry different RF `id`s (`hooks.rfId`) — every internal pattern/marker/aria id derives from it.
- **`process.ts` refs + the `View` seam.** `_editor/_engine/_view`; `processGraph()` recomputes (the model pass itself is `graphCompute.ts`, shared with the composite engine, the CLI and the tests). `_view` is `flow/flowView.ts`, the one implementation of `view.ts` `View` — `position(id)`/`nodeElement(id)`/`connectionElement(id)`/`hasNode(id)`, the camera (`transform`/`zoom`/`pan`), `moveNode`, `rerenderNode`/`rerenderCables`, `onRender`, `viewport`. A node's absolute position lives ON the node (`node.position`, stamped by the model layer on every add path) — there is no side map and nothing reconciled; `nodeElement` is a per-call live-DOM resolve, so cache it locally inside per-frame loops. Chrome verbs (select, Tidy, delete…) reach the surface through `canvasCommands.ts` slots. `view.moveNode(nodeId, …)` is async and will not share a paint with a React commit: if a size change would need a paired position change, restructure so it doesn't (§ Resizable-content nodes). `SolenoidConnection` takes `ClassicPreset.Node` as its type parameter (variance).
- **Groups are RF sub-flows** (`parentId`). The MODEL keeps absolute positions (`node.position`); RF holds a member's position RELATIVE to its group and tows members itself. Convert ONLY at the boundary (`flowModel.toFlowPosition/fromFlowPosition`, `handlers.moveNode`, `onNodesChange`) — never write a member's RF position from absolute coordinates. Details: § Group expand push.
- **An OPEN group's interior is working canvas, not a drag handle.** The wrapper is pointer-transparent (`sol-group-open` from `flowModel.nodeClassName` + flow.css `!important`, the Conduit pattern); the header, the 14px `solenoid-group__band` divs along the dashed edge and the grip claim their own pointers (GroupNode.css), and the whole body re-arms only while the group is SELECTED, so a selected group drags by its face. Interior presses fall through to the pane (pan, lasso, cable hits, the canvas context menu). Collapsed groups carry no class and stay fully draggable. Restored 2026-08-28; the rete surface enforced the same rule as a `dragHandler.guards.down` patch.
- **RF owns Delete/Backspace, selection and right-click routing** (`deleteKeyCode` + `onBeforeDelete`, `useOnSelectionChange`, `onNode/Edge/PaneContextMenu`): the app's verbs run FROM those callbacks. Don't add a second window listener for any of them. RF's own arrow move is off (`disableKeyboardA11y`) because the canvas keyboard nudges the selection on the dot grid; RF box-select is off (`selectionKeyCode={null}`) because shift-drag is the lasso's; `zoomOnDoubleClick={false}` (see `touch-gestures.md`).
- **Cables render as `<g>` inside RF's shared edge svg** (`FlowCableEdge.tsx`): visible strokes are `pointer-events:none`; the named `.solenoid-cable-hit` path (with `data-conn-id`) is the ONE hit target — RF's own interaction path stays disabled (`interactionWidth: 0`) or it eats `closest()` targeting. Routing and ribbons: § Cable rendering knobs.
- **The socket box is a deterministic 12×12** ([[C11]] socketBox12): `display:block; line-height:0` (global rule in `nodeCard.css`); the RF Handle wraps the glyph (`FlowSocketHandle.tsx`, reset by `.sol-rf-handle-reset`) and RF measures the HANDLE's box for cable endpoints (its outer edge, mid-height); every cable drawer then pulls that end `SOCKET_OVERLAP` (2px, `intoSocket` in `cablePaths.ts`) INTO the glyph, because a stroke that merely abuts the half-pixel handle edge leaves a lighter seam (edges paint under nodes, so the overlap is hidden; collapsed pills and Conduit lanes use their own points and are exempt). All sockets anchor to `.solenoid-node__content` (excludes the header) so positions are header-independent; vertical placement is measured per row (`MeasuredSocketRow`), never a fixed constant; the dot straddles the card edge via `left/right:-5` anchored to `__content` — do NOT make the io-row or `__body` a positioning context. A Conduit's tips come from `conduitLaneOffset`, not the measured handle (§ Resizable-content nodes).
- **A node can FLIP its sockets left↔right** (`socketFlipStore`, a per-node Set mirroring `collapseStore`; persisted per-node as `SavedNode.flipped` through the text form's `positions`, restored in `rebuildGraph`). Node-agnostic: a type opts in via `flippableNodes.ts` (`isFlippableNode`, tested by constructor name) and the right-click menu shows Flip / Unflip; Display is the first adopter. Three places read the flip, all swapping only the VISUAL side — never a Handle's `type` (target/source stays semantic, so connection legality and cable direction are untouched): `NodeSocket` (the CSS `left`/`right`), `FlowSocketHandle` (the RF `Position`), and `FlowCableEdge` (each endpoint's `CablePosition` into `getCablePath`, so the outward stub projects from the correct edge — a flipped output exits Left, a flipped input enters Right). `data-socket-side` stays semantic; DOM lookups resolve by the measured dot, so they follow for free. The toggle calls `rerenderNode` so RF re-measures the moved handles.
- **RF owns a node wrapper's inline `visibility`** (it stamps `visible` after measuring), so imperative visibility writes on `.react-flow__node` are silently overwritten. Per-node hide/show state rides RF's `className` (`flowModel.nodeClassName` + an `!important` rule in flow.css); collapsed-group member hiding is the standing example (§ Group collapse). Stacking is per-node `zIndex` ([[C65]] domOrderStacking).
- **World-coordinate overlays render inside RF's `<ViewportPortal>`** (StandoffLayer) — a sibling of `<ReactFlow>` paints in screen space and detaches from the camera.
- **A cable drag blurs the focused field first** (`onConnectStart`), so a mid-edit value commits before it is wired — rely on this, don't re-implement it.
- **Two ghost-cable mechanisms, by whether a real connection survives.** *Option A* (`cableGhostStore`, keyed by a live connection id — a node spliced out of a chain, or an in-place socket RETYPE that stays wired: Group Cost Settle, `archive/dev-notes-history.md` 2026-09-08d): the rete connection is REAL, just drawn dashed until it's valid/adopted. *Option B* — the **Input Switch pending-reconnect** (`cablePendingStore` + `cablePendingReconnect.ts`): the One↔Many toggle retypes `out`, and `retypeOutputCables` DROPS the downstream cables the new type can't feed, so there is no connection left to ghost. Each drop is remembered as a NON-connection ghost keyed by source·output·target·input, and re-materialised as a real cable when the output type fits that socket again — the same key if it's back, else the same label (`trueany` in One mode fits every socket, so a flip back reattaches all of them). `PendingCableLayer` (a ViewportPortal layer, like drawn cables) draws each one dashed in the Option A stroke from RF's measured handle bounds, since no edge exists to carry it. Persist nothing: `registerNodeForget`/`registerNodeForgetAll` clear a ghost when either node is removed and on every load. Machine-checked by `cablePendingReconnect.test.ts`.
- **Native form popups inside a node keep their pointer/mouse-down `stopPropagation`** — it doubles as drag prevention (§ Pointer gestures, `stopDragStart`). **A controlled `<select>` is driven from `useState`** and mirrored to the node in the change handler — never refreshed through a `useReducer` forceUpdate.
- **Every render is boundaried** (`components/ErrorBoundary.tsx`): the app root and EACH card (`SolNodeAdapter`). A throw prints the message + component stack with a Copy button at the app level, and a single bad card degrades to a small red box while the canvas keeps working. When a black screen IS reported, ask for the copied text first.
- **Load performance rides two mechanisms** (§ Graph load / teardown performance): the topology pipe coalesces a rebuild into ONE commit, and `syncTopology` preserves survivors' object identity so RF's memo skips unchanged cards.
- **A `chart`-socket figure carries DATA, not geometry, and lays out at its measured width** (25-gantt.md § 6.3, the Gantt is the first non-`<svg>` one). The value on the cable is flat JSON (a `ChartPayload`); the SAME figure draws at four sizes — the card's [Chart] chip, the resizable Display (capped), the popup (`virtualize` windows its rows), a Report embed — never a pre-baked pixel frame. `ChartFigure` (`chartView.tsx`) is the one dispatcher; the popup threads `virtualize`. **Export SVG seam:** a figure whose drawn form is NOT a single `<svg>` (the Gantt's HTML tree grid beside per-row banded SVGs) registers its own serializer via `registerChartSvgProvider` (`canvasCapture.ts`), keyed by the host node it draws in — the on-canvas Display registers, the transient popup does not. The webpage export (`captureChartSvgs`) and the Write-to-Obsidian raster ask the provider (`nodeChartSvgProvided`) for a whole-chart SVG string (`ganttSvg`) before falling back to scraping the largest DOM `<svg>`; every other chart keeps the largest-SVG path unchanged.
