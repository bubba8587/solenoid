# Spec: Auto-arrange / Tidy

Serves [[B10]] reactFlowView. The mechanics a builder implements: what the system does and blocks, with the decision each behaviour serves. Lifted from `docs/subsystem-invariants.md` § Auto-arrange / Tidy; a WHY that is not in a node belongs in one.

- **Every movement-stack size read routes through `measuredBox()` (`nodeSize.ts`)** — live DOM → the ResizeObserver mirror → a non-zero collapse-aware fallback (2026-07-16 unification; align/autofit adopted it first, then tidy/push/standoffs/splice/focus). Do NOT reintroduce ad-hoc `offsetWidth || node.width || 100` reads — the variants disagreed pre-paint and on collapsed groups (OutlinePanel's reversed read centered the camera on a collapsed group's stored EXPANDED box). `hostFootprint`/`realHostSize` restores are restricted to LAYOUT TARGETS (a docked-FC host that is a group member isn't laid out, and stamping it left a height pin nothing cleared — frozen card); ELK-footprint restores run BEFORE the post-layout anchor measurement (measuring while hosts/leaders were still inflated skewed the preserved center); the within-group autogrow rounds `group.width/height` to integers (the 8622a72 rule). Harness: `tidyArrangeGroups.test.ts` drives the REAL arrange/cleanup with real elkjs over a fake area modeling the DOM contract.

The "tidy" button / Ctrl+Shift+K runs an ELK layered layout via `elkTidyLayout` — elkjs loaded lazily (`makeEnsureElk`) and called directly; the function builds the exact ELK graph rete-auto-arrange used to (root layered / INCLUDE_CHILDREN / POLYLINE, sorted FIXED_POS ports, port-id edges) and applies positions through `translate`. Two non-obvious things:
- **Ports MUST be placed SYMMETRICALLY (same vertical offset for in & out)** so two connected nodes line up — `symmetricPortPreset`. (rete-auto-arrange's `classic` preset put outputs at the node TOP and inputs at the BOTTOM, so every link staircased the target UPWARD and the whole graph read as floating high — the reason the custom preset exists; don't rebuild that shape.) The preset reads the `tidyAlign` setting per layout: **"center"** (default) → ports at the node's vertical center → node CENTERS align (cables may slant slightly because our real output socket sits lower than the input rows); **"top"** → ports near the node top → node TOP edges align. The setting lives in `settingsStore` and renders as a Center/Top segmented control (a `"segment"` field type) in Settings ▸ Canvas. `symmetricPortPreset(direction)` is a factory over the layout DIRECTION: **RIGHT** puts inputs WEST / outputs EAST spaced down the card's height; **DOWN** transposes to NORTH / SOUTH spaced across the width. `elkTidyLayout` invokes the factory per layout reading `tidyDirection`, so a setting change is picked up with no re-registering.
- **The post-layout anchor preserves the FLOW's leading edge + cross-axis CENTER, not top-left.** ELK lays out from origin; we shift the result back. Under RIGHT it keeps the cluster's LEFT edge + vertical center; under DOWN it transposes to the TOP edge + horizontal center (within-group: the box interior's leading edge, clamped so centering never pushes members past the header under RIGHT / the left pad under DOWN). Anchoring by the top dropped a flattened row to the top of the old footprint (another "nodes float up" symptom). Both references are deterministic in either direction, so the Cleanup tidy→autofit cycle stays a fixed point (pinned under DOWN and cap 3 in `tidyArrangeGroups.test.ts`). FC hosts are reserved as inflated bounding boxes during layout (so neighbors don't pack into the FC's area) and resized back after.
- **Three Tidy knobs → ELK options (`tidyLayoutOptions`, read at layout time by BOTH call sites via `tidyOptionsFromSettings`).** `tidyDirection` → `elk.direction` RIGHT/DOWN (+ the port/anchor transpose above); `tidyDensity` → the spacing pair `elk.layered.spacing.nodeNodeBetweenLayers`/`elk.spacing.nodeNode` (compact 36/24, normal 55/38 = today's, airy 80/56); `tidyWidthCap` → ELK layerUnzipping: `tidyLayoutOptions` sets the GLOBAL switch `elk.layered.layerUnzipping.strategy = ALTERNATING` (omitted when "off"), and the port preset's per-node `options` hook stamps `elk.layered.layerUnzipping.layerSplit` = the sublayer count (`tidyLayerSplitFor(nodeCount, cap) = ceil(count/cap)`, floored at 1). layerSplit is per-NODE — set on the root it's ignored. count is the whole layout's node count (per-layer widths aren't known pre-layout), so it over-splits a graph with nodes outside the fat layer; that errs SAFE (widest layer W ≤ count ⟹ W/split ≤ cap, never exceeds). Needs elkjs ≥ 0.11 (layerUnzipping landed 0.11; we're on 0.12). The composite drill-in reads these too. `elk.algorithm`/`hierarchyHandling`/`edgeRouting` come from `elkTidyLayout`'s root options. Popover off the top-bar Tidy button (`.solenoid-tidy-options`) mirrors the Settings rows.
- **Nodes stay content-driven — no layout pass may leave a fixed inline `height` on a card.** A pinned height FREEZES the card (collapse can't shrink, a grown value clips — the old "tidied saves don't collapse" bug from rete-auto-arrange's applier). `area.resize` is a no-op on the flow Surface and `elkTidyLayout` only translates, so nothing stamps sizes today; `arrangeFn`'s post-layout pin-drop loop stays as the guard (`card.style.removeProperty("height")`, `.solenoid-node` roots only — other roots set inline size from React's `style` prop, which removeProperty would strip with no re-stamp) and re-applies a manually-sized width from `nodeSizeStore`. The **group Tidy button** follows its within-group arrange with an autofit (wrap-to-members), waiting two frames for the deferred docked-FC snap-back first.
- **A flipped node lays out as a PREDECESSOR.** A node in `socketFlipStore` reads from its right and emits to its left, so `subsetConns` reverses the ELK edge direction whenever either endpoint is flipped and drops the ports (node-level edge, so the mirrored side never fights the symmetric port preset). Net effect in a RIGHT layout: a flipped sink lands to the LEFT of its source (it "acts as one farther up the chain"). It also lands BELOW its layer-mates rather than above: when (and only when) an ELK-visible node is flipped, `elkTidyLayout` emits the flipped nodes LAST in the children array and adds `FLIPPED_MODEL_ORDER_OPTIONS` (`elk.layered.considerModelOrder.strategy=NODES_AND_EDGES` + `elk.layered.crossingMinimization.forceNodeModelOrder`) to the root options, so forced model order sorts them to the trailing edge of their layer — scoped, so a layout with no flipped node is byte-identical to before. Pinned by `tidyArrangeGroups.test.ts` (placement + the unflipped options/children snapshot).
- **A position-locked group sits out global Tidy / Cleanup as a FIXED OBSTACLE.** `GroupNode.lockedPosition` (persisted via `INIT_FIELD_ORDER`) drops the group from `layoutTargets` (so global Tidy never re-places it or carries its members) and skips it in Cleanup's member-tidy / autofit / collapse loops — it stays exactly where pinned. But the fresh arrangement can land on top of it, so a post-layout pass (global tidy only) feeds every locked box as a **pinned obstacle** to `separateOverlaps` (groupPushCore.ts, `pinned` set — a pinned box never moves, its partner yields; monotonic +x/+y so it terminates and, once clear, is a fixed point on re-run) and shifts any overlapping tidied node off it (a pushed group carries its members). Its own header Tidy button (a within-group arrange) still works; the lock is only about the box's corner. Toggled from the group's right-click menu ("Lock position" / "Unlock position") or the header lock icon (left of the Tidy icon, shown only while locked); `setGroupLocked` (groupLogic.ts) is the one entry point. The lock also wins over a Standoff band: every `solveStandoffs` call site pins locked groups (`withLockedGroupsPinned`), so a locked standoff endpoint holds and the correction falls entirely on the other end.
- **A within-group Tidy that GROWS the box triggers the expand push — PERMANENTLY.** After laying out members, the within-group path autogrows `group.width/height` (`Math.max`) to wrap them. If it grew, `tidyArrange.ts` calls `pushForGrownGroups` (groupPush.ts) — the SAME `runExpandPushes` engine as expand-on-uncollapse, fed the pre-grow size as `preSizes` — so neighbors are shoved off the grown edges. But it passes `record:false`: a Tidy is a deliberate manual action, so the displacement is PERMANENT (no restore record) — the pushed neighbors stay put when the group later collapses instead of rushing back. (A neighbor that *did* have an expand-push record from earlier goes stale and is treated as manually moved, so it won't snap back either.) Gated by the `groupPush` setting. **Cleanup passes `skipPush:true`** to the per-group `arrangeFn`: it runs its own autofit-shrink → collapse (restore) → top-level re-tidy, so a transient per-group push there is just noise. Selection / whole-canvas Tidy doesn't push (it rearranges groups as whole units, not their interiors).
