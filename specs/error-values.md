# Spec: Error values

Serves [[C24]] arraySemantics. The mechanics a builder implements: what the system does and blocks, with the decision each behaviour serves. Lifted from `docs/subsystem-invariants.md` § Error values; a WHY that is not in a node belongs in one.

Failures flow as tagged `SolError` values (Excel-style `#CODE!`, but a more specific set borrowed from SQLSTATE class 22 and OpenFormula Err:5xx — `#DIV/0!`, `#N/A`, `#DOMAIN!`, `#CONV!`, `#OVERFLOW!`, `#SYNTAX!`, `#VALUE!`, `#TYPE!`, `#SHAPE!`, `#UNIT!`, `#NAME?`, `#REF!`, `#CIRC!`, `#SOLVE!`, `#ERROR!` — the `SolErrorCode` union + full mapping table in the module header). `installErrorGuards(node)` wraps every node's `data()` at `nodecreated`: error in → error out without running the node, a throwing `data()` degrades to a local `#ERROR!` (one bad node can't half-kill a recompute pass), and `cachedResult` mirrors the error so the value box renders the red code badge (ValueDisplay, tooltip = structural message). IFERROR/IS-checks and the lane routers (Conduit/CableSwitch) are registered to see raw errors instead. Producers return `solError(...)` instead of `null` where the failure is a real error — `null` stays the legitimate "blank".
- **The old scalar-level invariant is RELAXED — array-semantics value model (Inc 1–8, 2026-06-22).** Lists, matrices, and frames now carry, as DISTINCT kinds: a first-class `null` (missing — rendered `null`, **skipped** by aggregators, dropped by Filter's predicate, propagated by element-wise math), per-cell `SolError`s (propagated), and a first-class **logical** boolean (purple socket family, TRUE/FALSE, coerces ↔ 1/0). `valueKinds.ts` is the core (`isMissing`, `forAggregate` = skip-null/propagate-error, Kleene `kleeneAnd/Or/Not`). `FrameColumn` carries a `logical` column type + per-cell errors; the table popup edits number/text/date/**logical** columns. `IS.TEST` (ISNULL + the numeric checks) tests per-cell to any depth incl. frames. The **Coalesce/Fill** node (`FillNode`) is the opt-in to treat `null` as something (constant/ffill/bfill/mean/median/mode/interpolate/drop/coalesce). Persistence needs NO new format (computed values regenerate; a Frame Input's logical/null cells round-trip via `frameText`). Display/popup branch on boolean + null + `isSolError`. **Element-wise math nodes tag per-cell errors UNIFORMLY (2026-06-24):** a condition that's a tagged error at scalar level (`÷0`→`#DIV/0!`, domain miss→`#DOMAIN!`, cross-family Convert→`#N/A`, overflow→`#OVERFLOW!`) is the SAME tag inside a list, per cell — no node may collapse a per-element error to NaN/null. The mechanism is `broadcastErr` (sibling of `broadcast` in `nodes/shared.ts`): its element fn may return a `SolError`, and the call-site maps the producer's domain-`null` sentinel via `?? errFactory()`. Whole-NODE errors (Convert's cross-family unit pick — not a per-cell condition) stay a single value at every dimensionality. Converted nodes: Arithmetic, Math (MathFn), TwoInputMath (LOG), Standardize, Fisher (via `broadcastErr`); Convert reaches the same behavior through `broadcastUnit`. (`broadcast` no longer NaN-collapses either — every result passes `guardFinite`, so a NaN result is `#DOMAIN!` per cell; only an explicit fn → null stays a blank.) Coalesce is full N-ary (2026-07-05): FillNode's Else rows are extensible (`e0, e1, …`, CHOOSE-style valueKeys round-trip); first present of List-then-each-Else wins per position; a typed literal on an unwired Else row is a broadcast last-resort constant. (The popup-grid error red-badge was SCRAPPED 2026-06-24 — code-as-text is acceptable.) See the dev-notes archive "Build progress (array-semantics)".
- **The null/error handling family is a 2×2 with ONE notion of "error" (aligned 2026-06-23).** Detect × recover, over missing(`null`) vs error(`SolError`): **detect** = Test `ISNULL` (per-cell missing, deep — uses `isMissing`) / `ISERROR` (`isSolError`) / `ISNA` (`isNaError`); **recover** = `FillNode` (missing → constant/ffill/…/coalesce) / `IFERROR`·`IFNA` (error → fallback, per-cell). Invariants that MUST hold across these: (1) a tagged `SolError` is the SINGLE definition of "error" — `ISERROR` and `IFERROR` agree exactly (`isSolError`); a bare `NaN` is NOT an error (ops classify non-finite RESULTS via `guardFinite` → `#DOMAIN!`/`#OVERFLOW!`, so untagged NaN never reaches these nodes — see the per-cell/non-finite bullet below). (2) A `null` (missing) is NOT an error in any of them — it passes through `IFERROR`/`IFNA` and is the thing `Fill` targets; a real "not found" is a tagged `#N/A` (e.g. XLOOKUP), not `null`. (3) The `#N/A` test lives in ONE place, `isNaError` (errorValue.ts), shared by `ISNA` + `IFNA` so they can't drift. (4) An error consumer reading a possibly-`null` WIRED input must test connection-PRESENCE (`inputs.x && inputs.x.length`), not `inputs.x?.[0] ?? literal` — `??` treats a delivered `null` as absent and substitutes the literal, hiding the missing cell. `Fill` and `IFERROR` partition cleanly (Fill never touches errors, IFERROR never touches null); `Fill`'s `coalesce` op is `IFERROR`'s shape applied to `null`.
- **Frame Input is a LITERAL source; coercion happens at the value boundary (2026-06-24).** An input node must NOT rewrite what you type (the `1`→`TRUE` bug). The model SEPARATES the edit/storage representation from the computed value: Frame Input stores a raw `FrameSource` (per column `{name, type, cells: string[]}` plus the column-source fields `unit?`/`expr?`, in `frameText`) — exactly the text typed — and `deriveFrame` produces the typed `FrameValue` (booleans, date serials) at COMPUTE time via `coerceFrameCell` (sharing `coerceLogical`). **Since the column-source model (2026-07-29/31) a column may be COMPUTED** — an inline `expr`, which reaches a wired λ by its socket name (`specs/literal-input-editors.md`): `FrameInputNode.data()` derives computed columns in dependency order with cycle refusal (`#REF!` "Circular computed columns"), identity-stable caching (`_computedFrom`), and the source unit riding onto the derived column. The row-eval rules (bare name = whole column, `@` = this row, bracket refs — tableRefSemantics/rowFormulaRefs) live in the SHARED `computedColumnCore.ts`, so this surface and the Computed Column verb cannot disagree. The popup edits definitions through the LIVE-COMMIT seam (`tablePopupStore` `SourceCommitRefresh`/`onCommitSource` — a blur/pick recomputes through the real engine and refreshes the open popup). `parseFrameSource`/`frameSourceToText` load/store; `frameFromInputText = deriveFrame ∘ parseFrameSource`; old typed-`values` JSON + legacy CSV still parse (cells kept raw), no migration. **`FrameColumn.raw?: string[]`** carries the INPUTTED text per cell (pre-inference) for SOURCE frames: `inferColumn` populates it (so every CSV/Web/Import frame has it), `deriveFrame` carries the Frame Input's cells. The popup's **Formatted/Source toggle** (always shown on a frame popup — Grid, CSV AND Form) renders `raw` verbatim in Source mode; a purely-computed column with no `raw` falls back to the underlying form (a date's serial, a logical's 1/0). **The Form view edits in BOTH modes, like the grid** (author, 2026-09-19): Source OFF shows each field's formatted value, and an image cell's picture (`recordImageSrc`, the Record figure's `.sol-record__img`), until the field is focused, then the raw text; Source ON shows raw text throughout. A Date field is a text input (a draft, committed on Enter / blur) with the calendar beside it, never a native date input controlled per keystroke (that wiped a half-typed year); in the grid the same calendar, and a Boolean's checkbox, appear on the right edge of the ONE cell being edited (`CellEditAffix.tsx`). A Text cell's existing values use the same edge (`CellSuggest.tsx`, replacing the native `<datalist>`, whose opener and OS-drawn list can't be styled): a bulleted-list opener shows every value, typing filters them in a list hung under the cell above the popup layer, ↑ ↓ select and Enter / Tab accept; it never opens on focus alone, and anything new still types. **A COMPUTED column is marked in every view**: tinted read-only cells in the grid, an accent dot beside the field's label in the Form, and in the CSV view its values are highlighted in place (`CsvEditor.tsx`: a mirror behind a transparent textarea, fields located by `csvFieldSpans`). A textarea can't lock part of its text, so marked text stays typeable and is IGNORED (a computed column has no cells); leaving the block rebuilds the text, putting the computed values back. With Source off the CSV VIEW's text is what the grid shows, a column's FC picks included (Copy and Export stay on the type's default format), and the Source toggle rebuilds the block. In Formatted mode the block edits like a grid cell: the WHOLE text shows its source while focused and the formatted text again on the way out. Because computed columns bind by index, CSV text whose rows don't each hold one value per column is REFUSED while the table has one: an error line under the block says so, Save is disabled, and the table keeps its last valid state. The Form's dot is an SVG circle, never a rounded CSS box: a centered popup sits at a fractional position, where a small box's edges snap per axis and the dot reads as an oval. **INVARIANT — keep `raw` row-aligned:** a transform that changes a column's rows/values MUST drop or REMAP `raw` (Filter + Get Row remap to surviving/picked rows; Add Column's replace drops it) — a stale `raw` misaligns the Source view. (The per-column format+unit row shipped — it works on computed columns too.) **Table Input joined the model (2026-07-09):** `tableText` is raw text, `tableRawCells`/`deriveTable` (matrix.ts) derive the typed matrix through the SAME `coerceFrameCell` (blank → null, bad number/date → NaN, bad logical → null), the grid popup edits raw cells via the lean `onSaveRaw` mode (never a parse→serialize round trip), and ONE `dataType` SegToggle (number/string/date/logical) retypes the output socket in place (`retypeOutputCables`).
- **Shape errors are part of this system, not a parallel one.** The central input coercion (`coerceInputs.ts`) wraps every node's `data()` INSIDE the error guard (Canvas installs coercion first, guard second); a narrowing failure throws `ShapeError`, which propagates to the guard's catch where `fromThrown` (matched by `e.name`, no import coupling) maps it to a tagged `#SHAPE!`. So a dimension mismatch renders the badge and propagates like every other error — there is no separate `#DIM!`/`cachedError`-string path (removed 2026-06-15). The shared **result displays all tolerate a `SolError` in `cachedResult`** (render the badge, not crash): `ValueDisplay`, `TableDisplay`, `FrameDisplay`, and the GroupNode collapsed readout. When adding a NEW custom result display, give it an `isSolError(v)` branch up front.
- **A formula node keeps BOTH signals.** Expression / LAMBDA / MAP·BYROW·BYCOL·MAKEARRAY·REDUCE / Filter set the rich inline `cachedError` string (in-node authoring hint, e.g. `Shape mismatch (3×2 vs 2×2)`) AND return a propagating `SolError` whose code matches the failure (`#SYNTAX!` bad formula, `#VALUE!` arity/eval, `#NAME?` bad param, `#SHAPE!` dimension, `#OVERFLOW!` too-large). `cachedResult` stays `null` on these so the box shows the richer inline message; the returned value carries the code (tooltip = its message) for downstream. A blank/empty formula stays `null` (legitimate no-value), never an error.
- **Producer sweep done (2026-06-15).** Genuine-error sites across finance (IRR/RATE/XIRR non-convergence → `#CONV!`, MIRR same-sign cashflows → `#DIV/0!`, MIRR overflow → `#OVERFLOW!`), scalar (Combinatorics out-of-domain → `#DOMAIN!`, overflow → `#OVERFLOW!`), Convert (cross-family units → `#N/A`, overflow → `#OVERFLOW!`), stats (zero-variance Correl/Standardize/Forecast/Regression → `#DIV/0!`, Fisher/Percentile domain → `#DOMAIN!`, Rank/PercentRank/FIND miss → `#N/A`), cast/text (parse failures → `#VALUE!`), date (DATEVALUE/TIMEVALUE unparseable non-empty text → `#VALUE!`; blank still → blank), matrix (singular → `#DIV/0!`, non-conformable/non-square → `#SHAPE!`), and list (INDEX out of range → `#REF!`). The only deliberate null-on-failure sentinels left are the discrete-distribution pmf/cdf helpers (`dist-discrete.ts`), where an out-of-support argument is a blank/N-A by design, not a computation failure. The SCALAR-LEVEL invariant governs every one: a `broadcast`/`.map` over a list keeps per-element `null`s (blanks); only a scalar result becomes a `SolError`. `Displayable` (standardNode.tsx) includes `SolError`, so a converted producer using `makeNodeComponent((n) => n.cachedResult)` renders the badge with no extra work.
- **Per-cell error/null contract + non-finite guard (2026-07-04).** ONE rule, per output cell, decided BEFORE the op, factored into every element-wise broadcaster (`shared.ts` broadcast/broadcastErr, `excelFormula.ts` broadcastCall + operators/unary, `logic.ts` broadcastEl): a `SolError` operand → that error UNMORPHED (first in arg order); else a missing (`null`) operand → `null`; else compute. Shared helpers `cellShortCircuit` (full) / `cellError` (error-only, for the Kleene logic family which feeds `null` to its own fn) in `valueKinds.ts`. So an in-range list cell behaves identically to a scalar and a ragged-pad — `[1,#DIV/0!,3]+10` keeps the error, `[1,null,3]+10` → `[11,null,13]`. broadcastCall's null short-circuit is skipped for a `NULL_INSPECTING` predicate set (ISBLANK/ISNUMBER/…) that must SEE the blank. **Non-finite guard (`guardFinite`, valueKinds.ts):** a computation never yields a bare NaN/Infinity — per RESULT, with input awareness: NaN → `#DOMAIN!`; ±Inf from all-FINITE inputs → `#OVERFLOW!` (renamed from `#RANGE!` — descriptive, not Excel-#NUM!-mimicry; one code, still splits Excel #NUM!, ERROR.TYPE 6); ±Inf when an INPUT was already infinite PASSES (the Constant node's ∞ is first-class: ∞+5=∞, 2×∞=∞, 5/∞=0). Runs at the producing op (broadcasters + applyOp + broadcastCall), so Expression's `tagResult` trusts it and just passes a surviving ∞ (nets a stray NaN → `#DOMAIN!`). `0^0 = 1` (JS/Polars; Excel #NUM! — parity:false on the pow leaf). **Scalar reads:** `readInput(wired, literal)` (shared.ts) replaces `inputs.x?.[0] ?? literal` for DATA inputs so a WIRED `null` propagates instead of being swallowed to the literal; CONFIG inputs (base/digits/order/counts) keep defaulting. (Supersedes the 2×2 bullet's point (4) `??`-warning for swept nodes.) Applied across every `nodes/*.ts` file — `readInputSweep.test.ts` is the zero-floor ratchet; the spec is `value-semantics.md` "Reading an input". Machine-checked by `broadcastContract.test.ts`.
- **`#CIRC!` is engine-level, not a producer.** The pull-based DataflowEngine resolves a node's inputs (recursively) *before* calling its `data()`, so a dependency loop makes `engine.fetch` **deadlock forever** (NOT throw). `processGraph` finds the loops' TRUE members up front via Tarjan SCC (`graphCompute.ts` `loopMembers` — nodes in a 2+ node strongly-connected component, or a self-loop) and **pre-seeds the engine's result cache** (`engine.cache.add(id, …)`, a documented public field) for each with a `#CIRC!` value. A downstream node then resolves a member straight from the cache instead of recursing in, so it computes normally and shows the *propagated* `#CIRC!` (a Display badge, an ISERROR explanation) — only the actual members dead-end. Seed ONLY the SCC members, never their descendants (Kahn-leftover lumps both together; marking descendants would blank their own computation). The connection guard already blocks self-loops on creation; multi-node loops are caught here.
- **`DisplayNode` SEES errors (`SEES_ERRORS`).** Display is a pass-through whose value box reads `cachedValue`, not the `cachedResult` the generic error short-circuit mirrors to — so without this it stayed blank when an error reached it. Letting its `data()` run on the raw error lets it both SHOW the badge (via the SolError-aware `ValueDisplay`) and FORWARD the error on `out` so the chain keeps propagating. (Nodes that render `cachedResult` — the large majority — already show propagated errors; the gap was the `cachedValue`/`cachedList`/`cachedText` minority, and Display was the one that mattered for the showcase chain.)
- **Per-cell errors surface via a BOUNDED scan (2026-07-12).** `reportOut` (the error-sink → Problems panel) and `modelFuzz.badValue` no longer see only a TOP-LEVEL `SolError` — `findCellError` (errorValue.ts) also finds a per-cell error inside a list/matrix/frame. A full O(rows×cols) scan every node every pass was rejected on perf, so the scan is CAPPED: `sampledCellIndices(len)` examines the head (`CELL_SCAN_HEAD`=64) plus a stride sample (`CELL_SCAN_STRIDE_SAMPLES`=32) of the tail — a constant per container (matrix rows recurse under the same per-row bound). A systematic whole-column error (a bad transform on every row — the common case) is always caught by the head; a lone bad cell buried past the head between two strides can be missed — the accepted cost of an O(1)-per-output hot path. `modelFuzz` reuses the same bound (`badValue` → `collectFinite`/`sampledCellIndices`); nulls are NOT flagged (a missing is first-class-legitimate, not a defect). See `cellErrorScan.test.ts`.
- **the error-codes tour** (merged into `seedGraphs/null-and-logical.json`, the "Errors, Null & Logic" seed) is the showcase: one row per code of the set current at its build (`#ERROR!` is the unreachable internal catch-all, noted in the seed; the later `#TYPE!`/`#UNIT!`/`#SOLVE!` codes aren't toured), each wired **producer → Display → ISERROR** so the error shows its badge, propagates, and the ISERROR check explains it. The `#CIRC!` row loops back through an upside-down Conduit. `errorSeed.test.ts` loads the actual JSON, runs it through a real editor+engine (coercion + guards + the cycle cache-seeding) and asserts every ISERROR reports its row's code — so a wrong socket key or a silently-null producer fails CI instead of showing blank in-app. `seeds.test.ts` validates structure; `errorIntegration.test.ts` locks the engine paths (coercion `#SHAPE!`, lambda→MAP `#NAME?`, Display show+forward, cycle cache-seeding).
