# Spec: Group collapse

Serves [[C88]] collapseIsVisual. The mechanics a builder implements: what the system does and blocks, with the decision each behaviour serves. Lifted from `docs/subsystem-invariants.md` § Group collapse; a WHY that is not in a node belongs in one.

Collapse is visual-only: members stay wired and computing. Collapsing hides the member nodes and every cable touching them, and re-presents the group's "terminal" readouts compactly in its header box. **Hiding rides RF node `className`** (`flowModel.nodeClassName` → `.sol-member-hidden`, an `!important` visibility rule in flow.css; FlowSurface re-stamps off the store notify): React Flow owns the wrapper's inline `visibility` — it writes `visible` after measuring — so an imperative element sweep silently loses (the "seed loads with members exposed" bug). Kept as `visibility`, never `display` — a hidden member must stay laid out or its measured size and socket positions collapse to 0. **Retain rule** (which member readouts survive): any member whose output leaves the group becomes a readout row, in two flavors. (1) **Display members** are the special-cased *visible* readout — a Display is retained iff its *effective output* has no connection or that connection leaves the group. "Effective output" follows a single Display→FC hop: if a Display feeds a member FC, the FC's output is what's tested and exposed (the Display stays the visible readout; the FC is hidden). So Display → FC → outside: retained (shown as the Display); Display → FC → inside: hidden; Display → nothing: retained. (2) Any *other* member with an output connection that leaves the group gets a generic readout row (label + live value from `cableValueStore`), and so does a LEAF member — one with an output socket and no outgoing connection at all (`groupReadouts` Pass 2b): a dead-end value is a terminal too. Only a member whose output feeds strictly INSIDE the group is hidden without a readout. Nodes already exposed as a Display (or a Display's FC hop) are not double-counted. `groupReadouts()` and `recomputeGroupCollapse()` must keep this contract identical.

**Camera targets across collapsed groups (`flyToNode.ts` — binds the "go to node" callers: pins/alerts HUD, cable inspector, Presentation; the RF minimap draws from RF's own node set with colors from `minimapFillForNode`, and `collapsedAwareNodesRect` serves the fit-all math in `NavMenu`):** a node hidden in a collapsed group has no visible element, so `zoomAt(area, [node])` targets a stale ~(0,0) and the view jumps off-screen — any "go to this node" path must first resolve the nearest VISIBLE ancestor (walking up through nested collapsed groups). Separately, `zoomAt`'s `getNodesRect` frames `node.width/height` whenever defined, but a collapsed group still carries its EXPANDED dimensions — pass a SIZELESS ref for a collapsed group so it falls back to the rendered element size (the minimap's `collapsedAwareNodesRect` sizing); plain nodes pass the real node.
