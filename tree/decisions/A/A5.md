## Decision

Solenoid does not reinvent the spreadsheet function vocabulary. Excel functions keep their Excel name and return Excel's answer. We also use other libraries' functions and behavior verbatim where possible (`pandas`, `scipy`, etc.).

1. Deprecated Excel functions are omitted (and re-routed to the superseding function).
2. Cell-grid-only functions (ADDRESS, INDIRECT and their kind) are omitted.
3. Where Solenoid adds its own custom functions, we consider Excel's syntax and behavior.
## Why

The project author, and the target customer base, are Excel users. We want to build a product that is more powerful and flexible than Excel for many workflows, but without making users learn an entire new syntax if we can help it.

## Consequences

- Any remaining difference from Excel is documented where the function is catalogued (parity false, with a note), never silent.
- Which functions count as deprecated, and how the current form replaces them on every surface, is [[C14]] currentExcelParity's.
- The rule families under this leaf (shared implementation, naming, arguments, comparisons, calc modes) refine how parity is kept, never whether.
