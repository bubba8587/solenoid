## Decision

The Rust core is the one implementation of formulas, functions and Frame verbs. The browser and the desktop app both run it as WebAssembly, and its tests run it natively. A change in behavior is made in the Rust, and each TypeScript implementation is deleted once the core covers it. **MUST:** every function, verb and formula path is pinned by conformance fixtures: answers frozen from the TypeScript before it was deleted, plus Excel's documented examples. A fixture changes only on purpose, in the commit that changes the behavior.

## Why

Two implementations make every change in behavior twice, and a check between them only says they agree, not that either is right. One core is fast everywhere, and fixtures that change only on purpose keep its answers from drifting.

## Consequences

- How it's built: [[rust-core]].
- The app waits for the core before its first calculation.
- A pack's formula functions are the core's too, so a saved formula computes with its pack off.
- Nothing falls back to the TypeScript: when the core declines to read a value, that refusal is the answer ([[rust-core]] § Nothing falls back).
- **Reopen if:** Solenoid needs a web build that runs without WebAssembly, or the core fails to load for a meaningful share of people.
