## Decision

The Rust core is the one implementation of formulas, functions and table verbs: the browser runs it as WebAssembly and the desktop links the same code natively, beside Polars for table verbs. A change in behaviour is made in the Rust. Each TypeScript implementation is deleted once the core covers it. **MUST:** every function, verb and formula path is pinned by conformance fixtures: answers frozen from the TypeScript before it is deleted, plus Excel's documented examples. A fixture changes only on purpose, in the commit that changes the behaviour.

## Why

Two implementations make every change in behaviour twice, and a check between them only says they agree, not that either is right. One core is fast everywhere, and fixtures that change only on purpose keep its answers from drifting.

## Consequences

- How it's built: [[rust-core]].
- The app waits for the core before its first calculation.
- A pack's JavaScript function is called back from the core.
- [[D98]] wholeColumnFallback retires when nothing falls back to the TypeScript.
- **Reopen if:** Solenoid needs a web build that runs without WebAssembly, or the core fails to load for a meaningful share of people.
