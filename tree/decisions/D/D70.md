## Decision

A function answers a blank when its result is undefined but nothing is wrong (fewer points than the statistic needs, a reversed DATEDIF range, a solver that stalled), and an error only when the input is actually wrong for it. Excel answers `#DIV/0!` or `#NUM!` for both, and this is a deliberate departure.

## Why

[[C24]] arraySemantics separates a missing value from an error. "Not enough data yet" is the normal state of a growing table, not a mistake; making it an error turns every partial column red and hides the one cell that is actually wrong. A blank is a real value that everything downstream skips ([[D36]] nullSkippedNotZero), so the quiet answer fits in.

## Consequences

- Each function's documentation says which of its answers are the quiet blank, and where Excel would error the difference is recorded per name in [[formulajs-divergences]].
- **Reopen if:** a user needs Excel's exact error for a formula that mixes the two (an `IFERROR` guard that must fire on short data).
