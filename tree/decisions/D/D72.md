## Decision

In the Solenoid Properties editor in Obsidian, Save writes each cell as it was typed, never a value converted to a picked type. A cell nobody edited keeps the value it came in with. A type is only a lens: switching it changes how cells show, never what the note holds, and a cell the type can't read is shown as unreadable instead of refused. One exception: the Complex field has no editor of its own, so it refuses text it can't read and writes nothing. It never writes a converted value either.

## Why

The author's ruling: switching a table's date column to Number showed NaN, as it should, but Save then wiped the dates from the note. [[C58]] tableInputRawText is the app's rule for the same boundary (what was typed is the stored truth, editors never convert it), and [[C107]] obsidianPlugin bundles the same editors, so the note is treated the way the app treats its own typed values. Writing a converted value would make picking a type destructive; a lens can't lose data.

## Consequences

- Solenoid treats what the plugin wrote the same way: a picked type that can't read a cell shows NaN over the text, never a silent blank, and the note is untouched.
- **Reopen if:** a plugin editor gains a per-cell error value that can be stored in the note (then an unreadable cell could carry that instead of its text), or the app's own editors stop keeping what was typed ([[C58]]).
- How it's built: the obsidian-plugin spec. No test pins it: the plugin tests were dropped on the author's call.
