## Decision

*Exception* to [[C24]] arraySemantics, under which an error input is the card's answer: the IF, IFS, SWITCH and CHOOSE cards receive their errors and answer one only when it is in a test (the condition, the index, the value matched or a case reached before the match) or in the branch they take. An error wired into a branch not taken is not the answer, as in the formulas.

## Why

A formula like IF(x = 0, 0, 1/x) guards its own division, as it does in Excel ([[A5]] excelParity), and the card spelling the same IF has to guard it too: a card that fails where its formula answers is a wrong answer, not a safer one.

## Consequences

- **Removed by:** the formulas IF, IFS, SWITCH and CHOOSE answering an error in any argument, branch not taken included; the cards would follow them back under the rule.
- IFS reads its tests in order: an error in a test before the first TRUE is the answer, one after it is not, as its formula does.
- How it's built: [[compute-pass#The error guard]], [[error-values#Nodes that see raw errors]]; the formula side is [[formula-language#The dispatch ladder]].
