## Decision

Each item typed on List Input is read the way a Frame Input cell of the same type is read: an item the type can't read is NaN, never a silent blank. The typed text is kept beside each value, so the list popup's Source view shows what was typed. A wired value is still converted, as before.

## Why

[[C58]] tableInputRawText makes what was typed the stored truth. List Input already keeps its typed rows untouched, so its popup has to show that same text in Source, and a Date list typed as 2024, 2025 must read as it would in a Frame column, not as two blanks with the typed text lost from view. One reading for typed cells across Frame Input and List Input means one rule to learn.

## Consequences

- The card itself stays view-only for the popup: it hands the popup only the typed text, never a save callback ([[literal-input-editors]] § List Input is not one of them).
- A bare year typed into a Date list reads as a day serial, as a Frame's Date column reads it (2024 is 16-Jul-1905).
- **Reopen if:** Frame Input's cell reading changes; this follows it.
