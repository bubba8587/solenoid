## Decision

**MUST:** within a family, a value may flow up in rank (scalar → list → matrix → frame → cube) and never down. A list widens into a 2-D input as one row.

## Why

Widening loses nothing, since a scalar is a one-item list. Narrowing has to pick or drop items, and doing that silently at a socket would change a value's meaning with no node on the canvas to show it ([[A6]]).

## Consequences

*Exceptions:* a combo (scalar-or-list) narrows into its element scalar; a plain list does not. That is what makes a combo a combo. **Removed by:** nothing.

A Cube never enters a Frame socket, because a Cube can hold nested tables a Frame verb was never built for. When a Frame verb should take a Cube, that node gets a wider input of its own; the lattice itself is never widened to spare one node the work. The author's ruling: "if you have to upgrade something, upgrade the sockets on each node, not vice versa." How such a node reads a Cube is in the socket-lattice spec.
