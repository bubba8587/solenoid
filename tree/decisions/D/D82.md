## Decision

The formula `SPARKLINE(range, [type])` answers a small SVG picture as `data:image/svg+xml` text: a line, columns or a win/loss strip, the Sparkline node's three types. A range longer than 40 points is averaged down to 40 buckets, and the picture is one or two paths in three palette colors: gold for a line and columns, green and red (vermilion) for win/loss. The text carries the Default palette's hexes, and wherever the picture shows, it's painted in the active palette's gold, green and red, as the Sparkline node is.

## Why

A computed column's cell holds a number, text, TRUE/FALSE, a blank or (in a Cube) a list, never a chart value ([[C54]] noPerCellFormulas keeps the one definition on the header), so a chart per row has to travel as text. [[C100]] chartIsAValue still holds for the Sparkline node, whose output is the full chart. A sparkline column runs once per row over a whole table, so the picture's size must not grow with the data: a fixed point cap and a fixed shape keep each cell a few hundred bytes, the same spirit as [[C21]] matchNodeLimits.

## Consequences

- The value doesn't change with the palette, so a save, a copy or an export gives the same text on every palette; only the display repaints. A picture that isn't a sparkline (it lacks the sparkline mark) is shown as it is.
- Any text cell holding a `data:image` picture shows as the picture ([[D83]] imageTextCells).

## Contest

### Contest 2026-09-29 by Claude Opus 5.5: keep wins

Fixed colors vs palette-following. Baking the active palette into the value would make saves and exports change with the palette and would go stale until a recompute; fixed colors clash on non-Default palettes. Verdict: keep the Default hexes in the value and repaint at display, on the author's word (2026-09-29).
