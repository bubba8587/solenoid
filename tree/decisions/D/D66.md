## Decision

The Schedule node has two precision modes, **Days** and **Minutes**, chosen on the node, instead of one precision with a snap that changes only what is shown. Days schedules in whole working days; Minutes schedules in working hours, so the next task can start the same afternoon.

## Why

A snap that only changes what is shown puts two tasks on the same day and reads as an overlap, and snapping inside a single mode breaks agreement with Microsoft Project files on durations given in hours. Two honest modes cost less than one dishonest one. These are modes of the whole schedule, not the per-task modes that [[C70]] oneScheduleRule forbids, and the four columns keep one rule each in both.

## Consequences

- The mode is part of what the plan means, so it is saved with the document and travels with the Gantt figure.
- **Reopen if:** a third precision (shifts, seconds) is asked for. It would be a third mode, not a snap. How it's built: the schedule-and-gantt spec (Dates and precision).
