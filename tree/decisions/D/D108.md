## Decision

**What counts as an aggregate here:** a function or card that reduces numbers to one number. By name: SUM, PRODUCT, AVERAGE, MIN, MAX, COUNT, MEDIAN, MODE.SNGL, the STDEV and VAR families, SUMSQ, GEOMEAN, HARMEAN, AVEDEV, DEVSQ, SKEW, KURT, LARGE, SMALL, the PERCENTILE and QUARTILE families, SUMPRODUCT, and the Aggregate card's operations.

**The rule:** inside an aggregate, TRUE reads as the number 1 and FALSE as the number 0. This holds in both places a logical can sit:

- typed or passed straight in as an argument: `SUM(TRUE, 1)` is 2;
- inside a list, at any depth of nesting: `SUM(x > 5)` is the number of items above 5.

Worked example, with `x = 1, 6, 7` (so `x > 5` is FALSE, TRUE, TRUE):

| Formula | Answer | Why |
|---|---|---|
| `SUM(x > 5)` | 2 | 0 + 1 + 1: the number of matches |
| `COUNT(x > 5)` | 3 | all three are now numbers (count the matches with `SUM(x > 5)` or `COUNTIF(x, ">5")`) |
| `AVERAGE(x > 5)` | 0.67 | 2 ÷ 3: the share that match |
| `MIN(x > 5)` / `MAX(x > 5)` | 0 / 1 | |
| `SUMPRODUCT(x > 5, x)` | 13 | 0×1 + 1×6 + 1×7 |

**Unchanged by this leaf:**

- Text is never a number ([[C10]]): text inside a list is still skipped by an aggregate.
- A blank is still skipped, and an error is still the answer.
- COUNTA still counts every non-blank item, logicals included, as before.
- AND, OR and XOR read logicals as logicals, not numbers; they are not aggregates here.
- The criteria family (SUMIFS, COUNTIFS, AVERAGEIFS, MINIFS, MAXIFS and the rest) is not decided here.

**Where this differs from Excel, on purpose:** Excel agrees for a logical typed straight in (its `SUM(TRUE, 1)` is 2). Inside a range Excel skips logicals instead: there its `SUM` of TRUEs is 0, `COUNT` is 0, `AVERAGE` is `#DIV/0!`, and `SUMPRODUCT` treats them as 0. Solenoid counts them.

## Why

Before this leaf, half the aggregates skipped logicals and half counted them, so one list gave answers that didn't fit together: `SUM(x > 5)` was 0 while `AVERAGE(x > 5)` was 0.67. One rule had to win. It follows from [[C133]] logicalIsZeroOrOne: a logical is the number 0 or 1, so an aggregate of numbers counts it. Counting also won on its own merits: Solenoid's lists are typed ([[A6]]): a list of logicals is never a stray mix inside a range of numbers, it is a deliberate list of yes/no answers, and counting those (`SUM(x > 5)`) is the common need. TRUE and FALSE already act as 1 and 0 elsewhere: in arithmetic (`TRUE + 1` is 2) and when a Frame column of logicals is aggregated.
