## Decision

**MUST:**
- Solenoid has no exchange rates, so a currency's code (USD, EUR) is what tells two amounts apart.
- Every operation that combines two values with units (the seven arithmetic operators, comparisons and totals) refuses two different currencies with `#UNIT!` ("no exchange rate"). Multiply and divide refuse too: dividing dollars by euros would give a plain ratio, and that number is a made-up exchange rate.
- A currency value with no code, such as a computed result, takes the other side's code.

## Why

When only some operations checked, `$5 + 5€` answered `$10` and `$10 ÷ 5€` answered 2, while the careful versions of the operators sat unused. One check, made before every operation, means no operation can miss it ([[C8]] declareOnce). How it's built: the unit-flow spec (Currency).
