## Decision

In a computed column over a Cube, `@name` on a column of list cells reads this row's list, and the formula may answer a list, which becomes that row's list cell. A bare name of a list column is its rows stacked, one list per row, padded with blanks to the longest list, so `SUM(prices)` totals every row's items. A nested table cell stays out of formulas as `#SHAPE!`.

## Why

[[C22]] rowFormulaRefs makes `@name` this row's cell, and in a Cube a cell can be a list, which [[C15]] matricesInFormulas already lets into a formula. Refusing it would make a Cube's list columns unreachable from the one place per-row math lives. A Cube can hold a list per row, so the answer can be one too; a Frame can't, so a Frame's computed column still answers one value per row.

## Consequences

- `SPARKLINE(@history)` in a Cube Input Fx column or a Computed Column over a Cube draws each row's own list.
- A list is one row ([[D85]] columnsStayColumns), so a column of them is a table. The padding is blank, not the `#N/A` that VSTACK pads with: a short list's missing positions don't exist, and a blank is no value, which totals and averages skip. `ROWS(prices)` is the row count and `INDEX(prices, ROW(), 2)` this row's second item.
- A list column that holds a grid in some row has no single table to stack, so read whole it stays `#SHAPE!` pointing at `@`.
- How it's built: [[computed-columns]].

## Contest

### Contest 2026-09-29 by Claude Opus 5.5: keep wins

Keep wins against C22 and C15: @name reading this row's list is C22's @ on a cell that holds a list, which C15 lets into a formula. Opposite (no list cells in formulas) makes a Cube's list columns unreachable. Deletion leaves the Cube surface unspecified. The whole-column clause is amended on the author's word: a column of list cells reads as its rows stacked, padded with blanks.
