## Decision

In a computed column over a Cube, `@name` on a column of list cells reads this row's list, and the formula may answer a list, which becomes that row's list cell. A bare name of a list column is `#SHAPE!` pointing at `@`, since a column of lists is no single list. A nested table cell stays out of formulas as `#SHAPE!`.

## Why

[[C22]] rowFormulaRefs makes `@name` this row's cell, and in a Cube a cell can be a list, which [[C15]] matricesInFormulas already lets into a formula. Refusing it would make a Cube's list columns unreachable from the one place per-row math lives. A Cube can hold a list per row, so the answer can be one too; a Frame can't, so a Frame's computed column still answers one value per row.

## Consequences

- `SPARKLINE(@history)` in a Cube Input Fx column or a Computed Column over a Cube draws each row's own list.
- The whole-column reading of a list column has no value to give: a list of lists is not a value a formula takes.
- How it's built: [[computed-columns]].
