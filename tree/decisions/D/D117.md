## Decision

Once the calculation has run, a wildcard output takes the type of the value it carried ([[C136]] typesKnownAfterCalc). An answer with no value to read (empty, all blank or all errors) keeps the type the output last carried. Before it has carried any, it takes what its source declares: the column a lookup or Get Column reads, the Values column a SUMIFS reads. With neither, it stays untyped.

## Why

Read off the value alone, an empty answer says nothing, and an output flickering to untyped every time a filter empties would retype the cables downstream for no change in the data. The column's declared type is what the value would have been, so it is the honest reading before any value has passed.

## Consequences

- The Type Settle reads every wildcard output's type off the value it last carried, for every card alike, in place of each card declaring the family it extracted ([[socket-lattice]] req. 9, run-time types).
- Measured against the declarations it replaces (2026-11-03, the card fixtures): the value's own family agrees in 393 cases; the 80 that differ are 77 empty answers this leaf settles and 3 where List Index declared nothing and the value says date or table.
- **Reopen if:** keeping a stale type through an empty answer misleads more than an untyped socket would (a filter that empties and then fills with another kind).
