## Decision

**MUST:** when a node receives an error, it doesn't compute. It passes that same error out, unchanged, on every output. If a node fails while computing, its output is an error saying so.

## Why

An error is a value in its own right ([[C24]] arraySemantics), so it travels on as itself. A node that computed on it would give a believable wrong number or an unrelated message, and the original cause would be lost.

## Consequences

- *Exception:* a few nodes exist to look at errors, so they receive them instead: nodes that catch or test errors (IFERROR, Type Check); nodes that carry separate lanes (Conduit, Cable Switch), where one lane's error mustn't spoil the others; nodes that show whatever arrives (Display, Note, Report); a composite, which hands the error to the nodes inside it exactly as if it were unpacked ([[C77]] compositeIsSubgraph); and Chart, which draws an empty figure for an error. **Removed by:** nothing; a node that catches errors has to be able to see them.
- How it's built: [[compute-pass]] (The error guard) and [[error-values]].
