## Decision

**MUST:** every `data()` is wrapped by `installErrorGuards`. An error on any input goes out on every output without the node running, and a `data()` that throws becomes a local `#ERROR!`.

**MUST (ordering):** the error guard wraps outside the input coercion. Coercion installs first, innermost, and the guard second, so a `ShapeError` thrown while narrowing an input lands in the guard as `#SHAPE!` instead of escaping both wrappers into the engine.

## Why

A node that ran on an error input would compute a plausible value from garbage, or throw an unrelated message. Passing the original error through keeps its cause visible downstream ([[C24]] arraySemantics).

## Consequences

- *Exceptions:* the classes that must see an error are declared in one place, `SEES_ERRORS` (`errorValue.ts`): error consumers (IFERROR, Type Check), lane relays (Conduit, Cable Switch, where "any error poisons every output" would poison sibling lanes), raw readers (Display, Note, Report), the subgraph boundary (Composite and its output marker, so an error crosses into the members, whose own guards apply there, exactly as it would unpacked, [[C77]] compositeIsSubgraph) and the figure sink (Chart, which draws an error input as an empty figure and never sends an error out its `chart` socket). The formula side's set is `ERROR_HANDLER_FUNCTIONS` (IFERROR, IFNA, ISERROR, ISERR, ISNA, ERROR.TYPE). **Removed by:** nothing; a catcher that can't see the error can't catch it.
- Where an error came from is [[E9]] errorsKeepOrigin.
