## Decision

**MUST:** when a node receives an error, it doesn't compute. It passes that same error out, unchanged, on every output. If a node fails while computing, its output is an error saying so.

A few nodes exist to look at errors, so they receive them instead:

- nodes that catch or test errors (IFERROR, Type Check);
- nodes that carry several separate lanes (Conduit, Cable Switch), where one lane's error mustn't spoil the others;
- nodes that show whatever arrives (Display, Note, Report);
- a composite, which hands the error to the nodes inside it, exactly as if it were unpacked ([[C77]] compositeIsSubgraph);
- Chart, which draws an empty figure for an error.

**Removed by:** nothing; a node that catches errors has to be able to see them.

## Why

A node that computed on an error would produce a believable wrong number or an unrelated message. Passing the original error along keeps its cause visible downstream ([[C24]] arraySemantics). Where an error started is [[E9]] errorsKeepOrigin. How this is built (the guard around every node, the order it runs in, the full exception list) is in the compute-pass and error-values specs.
