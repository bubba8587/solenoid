## Decision

A node that receives an error doesn't compute: it passes that same error out, unchanged, on every output. A node that fails while computing answers an error saying so.

## Why

An error is a value, so it travels on as itself. Computing on it would give a believable wrong answer and lose the original cause.

## Consequences

- *Exception:* nodes that exist to look at errors receive them: the ones that catch or test errors, carry separate lanes, show or draw whatever arrives, and composites, which hand the error to the nodes inside. **Removed by:** nothing; a node that catches errors has to see them.
- How it's built: [[compute-pass#The error guard (`installErrorGuards`, `errorValue.ts`)]] and [[error-values]].
