## Decision

A function that reduces a range to one answer skips blanks, as Excel's range functions do, while work done cell by cell treats a blank as unknown. So `SUM` and `AND(range)` over a list with gaps skip the gaps, while `+`, IF, the Boolean Op node and the Filter's conditions give an unknown answer for an unknown input. This is the one place blanks are read two ways, and it splits by kind of work, never by surface: a node and its formula agree.

## Why

A function is the same as a node or a formula, so any difference has to come from the work itself. A total over a column with gaps should still total, as in Excel, but one unknown cell compared or added should give an unknown answer rather than a guess.

## Consequences

- Any other disagreement between a node and its formula is a bug.
- How it's built: [[formula-language#Range functions]] and [[value-semantics]].
- **Reopen if:** Excel's range functions stop skipping blanks.
