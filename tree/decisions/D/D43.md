## Decision

**MUST:** a List carries a `UnitCell` per item, a Frame a `ColumnUnit` per column, and a matrix one unit for the whole grid.

## Why

A unit attaches where values are guaranteed to match: a Frame column holds one kind of thing, a matrix is one quantity, and a List's items don't have to agree. A finer attachment wastes; a coarser one lies.

## Consequences

- **Matrix:** one unit, as a symbol-keyed tag on the outer array. This is lossy by design, so code that rebuilds a matrix re-tags it. Every matrix op declares a unit policy, and `matrixUnitPolicy.test.ts` fails the build on an op that doesn't.
- **List:** per item on purpose, since a List is the one rank with no guarantee its items match, and a Frame row really can be mixed. Cube cells carry a `UnitCell` each, like a List.
- **Rejected:** a `MatrixValue` wrapper. It would churn every coercion primitive for a small payoff, while the fragility it fixes is confined to the places that rebuild arrays.
- **Reopen if:** per-column units on unnamed matrices are wanted. That is what a Frame is for.
