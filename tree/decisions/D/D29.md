## Decision

**MUST:**
- Every frame verb both engines speak is specified by cases in `fixtures/frame-verbs/`: recorded wire payloads (frames plus the op in serde's own tagged shape) that both runners deserialize with production code (`frameVerbCorpus.test.ts` through the oracle, `corpus_cases` in `engine/tests.rs` through Polars).
- A verb without corpus cases doesn't ship. The completeness guard requires a fixture file per verb in `FRAME_OP_KINDS` and `BINARY_VERBS`, plus the `pipeline` fixture (sequential vs fused parity), and a new `FrameOp` kind fails to compile before it fails the guard.
- A verb only one side runs is declared, not skipped: an `ORACLE_ONLY_VERBS` entry (pivot) makes cargo assert that the engine still does not parse the op, so the exemption removes itself if the engine ever learns it.
- **MUST NOT** re-encode a case per side. The corpus format is the wire format, so a fixture that parses on one side and not the other is itself the parity failure, surfacing at load.

## Why

The two engines used to be kept in agreement by hand-mirrored test pairs tied together by comments, and nothing failed when a verb, option or edge case landed on one side only. The corpus's first three runs each caught a real divergence the pairs had missed: a silent null column for an unknown aggregate op (now `#NAME?` on both sides), NaN passing gt and gte under Polars' total float order, and outer-join row order, which the engine side never pinned.

## Contest

### Contest 2026-09-24 by Claude Opus 5.5: keep wins

Keep: extending the corpus fuzzer to window, fillBlanks, replaceValues, sliceRows, bindColumns and cross join surfaced eight oracle/Polars divergences in one run, each pinned as a shared wire case; hand-mirrored per-side tests (opposite) are what missed such cases before. Deletion leaves C16 with no mechanism that forces the two engines to agree on edge cells.
