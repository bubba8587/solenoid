## Decision

A list is one row everywhere: for its shape, for broadcasting and for every row and column position (`INDEX(x, 2, 1)` is `#REF!`, as `CHOOSEROWS(x, 2)` is `#VALUE!`). A function whose answer is a column in Excel because of what it does keeps that shape as a one-column table: TOCOL, MAKEARRAY with one column, and BYROW. SEQUENCE(n) stays a list.

## Why

[[C15]] matricesInFormulas counts a list as one row, and [[A5]] excelParity wants Excel's answer. When a column-shaped answer collapsed into a list it turned into a row, so the answers that depend on the shape came out wrong without an error: `m / BYROW(m, SUM)` divided each column by the wrong totals, and `HSTACK(m, BYROW(m, SUM))` spilled the totals across one row. Keeping the column makes those formulas right, and it leaves a list with one reading, so a position past row 1 is an error rather than a guess. SEQUENCE(n) is a series of values whose orientation carries no meaning, and the Sequence card answers a list, so it stays one.

## Consequences

- TOROW flattens to a list reading row by row, as Excel's does; it is the way to turn a table or a column into a list.
- The Table Reshape card's TOCOL op and the By Axis card's BYROW op answer one-column tables, and switching op retypes the output.
- `INDEX(SEQUENCE(5), 3)` is item 3; `INDEX(SEQUENCE(5), 3, 1)` is `#REF!`.
- **Reopen if:** SEQUENCE's orientation starts to matter to a formula people write.
