## Decision

A List is one row (like one line of a CSV file) everywhere, and a Frame column read whole in a formula is a column, as an Excel table column is. A function whose Excel answer is a column (TOCOL, BYROW) answers a column, while SEQUENCE(n) stays a list. Functions that don't care about direction read a row or a column alike and answer in the shape they were given; functions that work along rows and columns (SORT, TAKE, VSTACK) follow Excel strictly, and a different behavior on a list gets its own toggle or function rather than an exception.

## Why

We want Excel's answers, and in Excel many of them depend on shape: `m / BYROW(m, SUM)` is only right if the totals come back as a column. Giving each shape one reading keeps those answers right, and makes a position past a list's first row an error rather than a guess.

## Consequences

- Frame from Lists turns lists into columns and Get Column turns a column back into a list; nothing else turns one shape into the other silently.
- How it's built, function by function: [[formula-language]] (*Lists, columns and tables*).
- **Reopen if:** SEQUENCE's orientation starts to matter to a formula people write, or a function needs direction for one argument and not another.
