## Decision

A list is one row for its shape (ROWS is 1, it broadcasts and stacks as a row). A function that takes a row and a column position reads a list along whichever axis names more than one position: `INDEX(x, 1, k)` and `INDEX(x, k, 1)` are both item k, and only a row and a column both past 1 is `#REF!`.

## Why

[[C15]] matricesInFormulas counts a list as one row, but SEQUENCE(n), TOCOL, MAKEARRAY(n, 1) and BYROW over a column all answer a list too, because the value model has no one-column matrix separate from a list. Reading a list only as a row would break every Excel formula that indexes such a column, and reading it only as a column breaks every one that indexes a row. Accepting either axis gives Excel's answer in both cases and never picks a wrong item: the one index both readings share, (1, 1), is item 1 either way.

## Consequences

- `INDEX(x, 1, 0)` is the whole list (the row); `INDEX(x, k, 0)` past 1 is item k (the column).
- Functions that take a row count and a column count (TAKE, DROP, CHOOSEROWS, CHOOSECOLS) are to follow the same rule; until they do, each is a finding against this leaf.
- **Reopen if:** the value model gains a one-column matrix distinct from a list.
