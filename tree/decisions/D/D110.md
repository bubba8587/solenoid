## Decision

**Text given to AND, OR or XOR is `#VALUE!`, wherever it sits.** These three never skip text. Text is `#VALUE!` in all three places it can reach them:

1. typed into the formula: `AND(TRUE, "a")`;
2. coming from a name or a wired card: `AND(TRUE, x)` with `x` = `"a"`;
3. as an item inside a list, at any depth: `AND(xs)` with `xs` = TRUE, `"a"`.

This holds for text that looks like a logical or a number too: `"TRUE"` and `"2"` are text, not logicals or numbers ([[C10]] socketLattice), so `AND(TRUE, "TRUE")` is `#VALUE!`, not TRUE.

**Why `#VALUE!`:** each of the three is arithmetic once a logical is read as 0 or 1 ([[C133]] logicalIsZeroOrOne), and arithmetic on text is `#VALUE!` ([[C134]] functionsFollowAlgebra):

- **AND** is multiplication: `AND(a, b)` is TRUE when `a * b` is 1. `TRUE * "a"` is `#VALUE!`.
- **OR** is "any is 1": `OR(a, b)` is TRUE when `a + b` is above 0 (the largest of them is 1). `FALSE + "a"` is `#VALUE!`.
- **XOR** is "the count of 1s is odd": `XOR(a, b)` is TRUE when `MOD(a + b, 2)` is 1. `TRUE + "a"` is `#VALUE!`.

NOT already answers `#VALUE!` for text, so the four logic functions now agree.

**An error still wins:** an error anywhere among the values, before or after the text, is the answer: `AND(NA(), x)` and `AND(x, NA())` are both `#N/A`, as `NA() * x` and `x * NA()` are.

Worked example, with `x` = `"a"`, `xs` = TRUE, `"a"`, and `ys` = FALSE, `"a"`:

| Formula | Solenoid | Before this leaf | Excel (a cell or range holding the same) |
|---|---|---|---|
| `AND(TRUE, "a")` | `#VALUE!` | TRUE | `#VALUE!` |
| `AND(TRUE, x)` | `#VALUE!` | TRUE | TRUE (the text is skipped) |
| `AND(xs)` | `#VALUE!` | TRUE | TRUE |
| `AND(TRUE, "TRUE")` | `#VALUE!` | TRUE | TRUE (typed `"TRUE"` read as TRUE) |
| `OR(FALSE, "a")` | `#VALUE!` | FALSE | `#VALUE!` |
| `OR(FALSE, x)` | `#VALUE!` | FALSE | FALSE |
| `OR(ys)` | `#VALUE!` | FALSE | FALSE |
| `OR(FALSE, "2")` | `#VALUE!` | FALSE | `#VALUE!` |
| `XOR(TRUE, "a")` | `#VALUE!` | TRUE | `#VALUE!` |
| `XOR(TRUE, x)` | `#VALUE!` | TRUE | TRUE |
| `XOR(xs)` | `#VALUE!` | TRUE | TRUE |

**The Boolean Op card follows:** its AND, OR and XOR answer text as the formulas do, with the same `#VALUE!` and message, item by item over lists ([[C17]] shareImpl); its NAND, NOR and XNOR answer the formulas' `#TYPE!`. Text on its inputs reaches the card instead of the input's own `#TYPE!`. Its own reading of a blank (unknown) is unchanged.

**Unchanged by this leaf:**

- A number still reads as TRUE when it is not 0: `AND(TRUE, 2)` is TRUE, `OR(0, 0)` is FALSE, `XOR(TRUE, 3)` is FALSE.
- Logicals answer as before: `XOR(TRUE, TRUE)` is FALSE.
- An error is still the answer, wherever it sits among the values: `AND(NA(), x)` and `AND(x, NA())` are `#N/A`.
- NOT is unchanged: `NOT("a")` is `#VALUE!`.
- NAND, NOR and XNOR are not decided here; they answer `#TYPE!` for text, as before.
- Empty text (`""`), a blank (an unwired input or a null) and NaN are not decided here, as [[D109]] aggregatesRefuseText leaves them: `""` is still skipped, `AND(TRUE, "")` is TRUE, and each keeps what it does today.

**Where this differs from Excel, on purpose:** Excel errors only for text typed straight into the formula, and even there it reads typed `"TRUE"` and `"FALSE"` as the logicals (`AND(TRUE, "TRUE")` is TRUE). Text from a cell or inside a range it skips. Solenoid answers `#VALUE!` in all three places, `"TRUE"` included.

## Why

AND, OR and XOR are shorthands for arithmetic on 0 and 1, so they should answer what that arithmetic answers ([[C134]] functionsFollowAlgebra), and arithmetic on text is an error wherever the text came from. A skipped text item turns a test into a quiet pass: `AND(checks)` reads TRUE though one check is the label `"n/a"`.

## Consequences

- Text in a list of conditions stops being left out. To leave it out on purpose, filter it first.
- **Reopen if:** people need AND or OR to skip text inside a list, or Excel's own answer is wanted back.
