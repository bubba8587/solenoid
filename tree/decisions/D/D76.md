## Decision

Min and max over a text column in GROUPBY, PIVOTBY and Cube Rollup give the group's alphabetically first and last text, instead of a blank as Excel's MIN and MAX would give by ignoring text. The order is the one Sort uses ([[C59]] byteStringOrder), and the result column stays text. The list MIN and MAX functions keep Excel's answer.

## Why

Excel's blank answer for the min and max of text carries no information, and [[C24]] arraySemantics keeps a blank for a missing value, not for a question the function declined to answer. The first and last text in alphabetical order is a useful answer instead. Using the order Sort uses ([[C59]] byteStringOrder) means both engines give the same answer. The author's call.

## Consequences

- **Reopen if:** a blank result for text is wanted back for Excel parity, or a locale-aware order is adopted for data sorts ([[C59]] byteStringOrder reopens first).
- The running and window min and max stay numeric; extending them is an addition under this leaf.
- How it's built: the frame-verbs spec (aggregates).
