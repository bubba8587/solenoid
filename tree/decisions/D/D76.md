## Decision

A min or max aggregate over a text column returns the group's smallest or largest non-blank text, in code-unit order ([[C59]] byteStringOrder), and the result column stays text. A blank (null) and an empty string are skipped; a group with neither is blank. A mixed column is already a text column with its numbers stored as text, so it orders the way Sort orders it ("10" before "9"). An error cell in the group makes the result that error, as every aggregate does. This holds for Group By, PIVOTBY (so GROUPBY with totals) and Cube Rollup, which share one aggregate helper; Group By runs it on both engines. It diverges from Excel's MIN and MAX, which ignore text; the list MIN and MAX functions keep Excel's answer.

## Why

The author's ruling (2026-09-24, "alpha min/max couldn't hurt"): a text column's min and max came back blank, which carried no information, while the first and last name in alphabetical order is a useful answer. Code-unit order is the one order both engines produce identically.

## Consequences

- **Reopen if:** a blank result for text is wanted back for Excel parity, or a locale-aware order is adopted for data sorts (C59 reopens first).
- The window functions (group_min, rolling_min, cummin and their max twins) stay numeric; extending them is an addition under this leaf.
