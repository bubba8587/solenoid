## Decision

Min and max over a text column in Group By, PIVOTBY and Cube Rollup give the group's alphabetically first and last text, instead of a blank as Excel's MIN and MAX would give by ignoring text. The order is the one Sort uses ([[C59]] byteStringOrder), and the result column stays text. The list MIN and MAX functions keep Excel's answer.

## Why

The author's ruling ("alpha min/max couldn't hurt"): a text column's min and max came back blank, which carried no information, while the first and last name in alphabetical order is a useful answer. Sort's order is the one both engines produce identically.

## Consequences

- **Reopen if:** a blank result for text is wanted back for Excel parity, or a locale-aware order is adopted for data sorts (C59 reopens first).
- The window functions (group_min, rolling_min, cummin and their max twins) stay numeric; extending them is an addition under this leaf.
- How it's built: the frame-verbs spec (aggregates).
