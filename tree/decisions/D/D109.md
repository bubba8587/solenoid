## Decision

**Text given to an aggregate is an error, wherever it sits.** The aggregates below never skip text. Text is an error in all three places it can reach them:

1. typed into the formula: `SUM(2, "a")`;
2. coming from a name or a wired card: `SUM(2, x)` with `x` = `"a"`;
3. as an item inside a list, at any depth: `SUM(xs)` with `xs` = 2, `"a"`.

This holds for text that looks like a number or a logical too: `"2"` and `"TRUE"` are text, not numbers ([[C10]] socketLattice), so `SUM(2, "2")` is an error, not 4.

**Which error** follows the operator the function is built from ([[C134]] functionsFollowAlgebra):

- **`#VALUE!`, as `2 + "a"` gives**, for the functions built from arithmetic: SUM, PRODUCT, AVERAGE, SUMSQ, SUMPRODUCT, GEOMEAN, HARMEAN, AVEDEV, DEVSQ, SKEW, SKEW.P, KURT, and the STDEV and VAR families (STDEV, STDEV.S, STDEV.P, VAR, VAR.S, VAR.P).
- **`#TYPE!`, as `2 > "a"` gives**, for the functions built from ordering: MIN, MAX, MEDIAN, LARGE, SMALL, and the PERCENTILE and QUARTILE families (PERCENTILE, PERCENTILE.INC, PERCENTILE.EXC, QUARTILE, QUARTILE.INC, QUARTILE.EXC). For LARGE, SMALL, PERCENTILE and QUARTILE this is about the list of values; text in the position or fraction argument (the `k` in `LARGE(xs, k)`) stays `#VALUE!`, as it was.

Worked example, with `x` = `"a"` and `xs` = 2, `"a"`:

| Formula | Solenoid | Excel (a cell or range holding the same) |
|---|---|---|
| `SUM(2, "a")` | `#VALUE!` | `#VALUE!` |
| `SUM(2, x)` | `#VALUE!` | 2 (the text is skipped) |
| `SUM(xs)` | `#VALUE!` | 2 |
| `SUM(2, "2")` | `#VALUE!` | 4 |
| `AVERAGE(xs)` | `#VALUE!` | 2 |
| `PRODUCT(3, x)` | `#VALUE!` | 3 |
| `MAX(xs)` | `#TYPE!` | 2 |
| `MIN(2, "a")` | `#TYPE!` | `#VALUE!` |
| `MEDIAN(xs)` | `#TYPE!` | 2 |
| `LARGE(xs, 1)` | `#TYPE!` | 2 |
| `COUNT(xs)` | 1 | 1 (unchanged: COUNT counts numbers) |

**Cards and Frames follow:** a card or a Frame aggregation that is one of these functions answers text as the formula does, with the same error and message ([[C17]] shareImpl): the Aggregate card, the Rank & Percentile card's Large, Small, Percentile and Quartile, Group Lists, and a Frame's column aggregation in GroupBy, Pivot and Rollup. Text on such a card's input reaches the card instead of the input's own `#TYPE!`. A formula on a card (Expression, By Row/Column, Reduce) already follows. A text column's MIN and MAX in a Frame still give its first and last text in order, which no formula does.

**Unchanged by this leaf:**

- COUNT still skips text: counting the numbers is its job. COUNTA and COUNTBLANK are as before.
- The criteria family (SUMIFS, COUNTIFS, AVERAGEIFS, MINIFS, MAXIFS and the rest) is not decided here.
- AND, OR and XOR are not decided here; [[D110]] logicRefusesText decides them the same way, with `#VALUE!`.
- The paired functions SUMX2MY2, SUMX2PY2 and SUMXMY2 are not decided here.
- MODE.SNGL is not decided here: it compares for equality, and text equal to a number is just FALSE, not an error, so its algebra does not settle whether text is skipped.
- TRUE and FALSE still read as 1 and 0, and an error is still the answer.
- A blank, empty text (`""`) and NaN are not decided here; each aggregate keeps what it does with them today.

**Where this differs from Excel, on purpose:** Excel errors only for text typed straight into the formula, and even there it reads text that looks like a number as that number (`SUM(2, "2")` is 4). Text from a cell or inside a range it skips. Solenoid errors in all three places. Excel has no `#TYPE!`; where Solenoid gives `#TYPE!`, Excel gives `#VALUE!` or skips the text.

## Why

We want each named function to answer what its algebra answers ([[C134]] functionsFollowAlgebra), and `2 + "a"` is an error wherever the `"a"` came from, so `SUM` is too. Text in a list of numbers is almost always a mistake (a stray label, an unparsed import), and an error shows it where a skip hides it inside a plausible total.

## Consequences

- Text in a list stops being a quiet way to leave an item out. To leave text out on purpose, filter it first, or count only the numbers with COUNT.
- **Reopen if:** people need an aggregate that skips text inside a list (that would be a separate, named function, not a change to these), or Excel's own answer is wanted back.
