## Decision

**MUST:** a placed node is titled with the name of what the user clicked in the Add menu. For a node with an op dropdown, the title is the current op's name and follows it live: a placed ABS reads "ABS", never "Math", and switching XNPV's toggle to Periodic retitles it "NPV". A title the user types always wins. Every place that names a node (its header, the Navigator, the Inspector, popups, history) shows that same name.

An Add-menu name is therefore a title: no symbol in front ("+ Add"), no hint ("ROUND to N digits"), and a row named "X / Y" that only makes X is split in two.

**Exception, the hover hint (the author's call):** the small hint on the right of a node, shown on hover, gives the family name ("Series", "Math FX"), not the op that the header and dropdown already show.

**Exception, the Conduit (the author's call):** a Conduit's default title is "Conduit N", its number, not the bare catalog name, so every Conduit reads distinctly in the Navigator. A blank or bare "Conduit" title takes the numbered one, on placement and on load. **Removed by:** the Navigator telling same-named nodes apart on its own.

## Why

[[C19]] namingModel makes the node's name the one name every surface shows, so it has to say what the node computes. A node titled by its family ("Aggregate", "Arithmetic") or by a sibling op ("IRR" on a dated XIRR) misreports what it computes, and the Add menu then names things the canvas never shows. The hover hint states the kind of node once without repeating the op dropdown.
