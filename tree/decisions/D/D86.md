## Decision

A blank in the data a node works on stays a missing value, a blank setting means use the default, and a blank pick is skipped. With no sensible default, the node shows a loud error naming what's missing.

## Why

A blank setting is a number nobody gave, so the node uses its default. A blank answer hides a problem; an error points at it.

## Consequences

- How it's built: [[input-roles]].
- **Reopen if:** a default would surprise more often than a blank answer would.

## Contest

Carried from D33, which this node supersedes.

### Contest 2026-09-26 by Claude Opus 5.5: keep wins

Keep for data inputs. The author (2026-09-26) ruled a wired blank in a setting (a count, position, size or mode) reads as the setting left out; that landed first as an exception leaf under D33 (E15); both were later merged into this leaf.
