## Decision

What a blank means depends on what the input is for. In the data a node works on (the prices SUM adds up), a blank is a real missing value and stays blank. In a setting that says how the node works (how many rows TAKE keeps, how many places ROUND uses), a blank means "not given", so the node uses its default, and a plugged-in blank overrides a value typed on the card. In a pick that says which items to take (INDEX's positions), a blank pick is skipped. When a setting or pick has no sensible default, the node shows a loud #SYNTAX! error naming what is missing. Formulas follow the same rules, and the aim throughout is as few blank answers as possible.

## Why

A blank is a real value, not a zero ([[C24]] arraySemantics), and for data that matters. A blank setting is different: it's a number nobody gave, and "not given" already means use the default, as a skipped formula argument does ([[C80]] blankArgIsExcelBlank). A blank answer hides a problem; an error points at it.

## Consequences

- *Excel diverges:* Excel reads an empty cell in a size slot as 0, so TAKE(m, A1, 2) with A1 empty is #CALC! there; here it keeps every row ([[A6]] divergeByDesign).
- A half-built card shows #SYNTAX! until it is finished, and that is intended.
- The roles, the declaration every function subscribes to, the inputs not yet swept and the author's detailed rulings: [[input-roles]].
- **Reopen if:** a default would surprise more often than a blank answer would.
