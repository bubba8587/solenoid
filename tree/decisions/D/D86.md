## Decision

Every input on a node can be filled in two ways: by typing a value into the field on the card, or by plugging a cable into its socket. When a cable is plugged in, the cable always wins, and the typed value is ignored until the cable is removed. This leaf decides what happens when a cable is plugged in but carries a blank (an empty cell, or an upstream result that has nothing in it), and what happens when a formula gets a blank argument. The answer depends on what the input is for.

**Inputs that carry the data a node works on.** For example, the list of prices a SUM adds up, or the table a TAKE cuts rows from. A blank here is a real missing value. It stays blank and is passed along, so a missing price shows up as missing instead of quietly turning into 0. If a node has no data at all, its answer is blank, because there is nothing to work on.

**Inputs that tell a node how to do its work.** For example, how many rows TAKE should keep, how many decimal places ROUND should use, or how big EXPAND should make a table. These are called settings. A blank setting is treated as if nobody filled it in, so the node uses its normal default: TAKE keeps every row, ROUND rounds to whole numbers. This is true even when a value is typed on the card: a plugged-in blank overrides the typed value. When a setting arrives as a list with one value per item (a different number of decimal places for each price, say), a blank in that list uses the default for that one item only.

**Inputs that say which items to pick.** For example, the positions INDEX should pull out of a list, or the row numbers CHOOSEROWS should keep. A blank position is simply skipped, and the rest are picked as normal. If every position is blank, it is treated as if no positions were given at all.

**When there is nothing to fall back on.** Some settings and positions have no sensible default: CHOOSEROWS has no way to guess which rows you meant. Then the node shows a `#SYNTAX!` error that names what is missing, instead of quietly showing a blank. A card that is only half built will show that error until it is finished, and that is intended.

Formulas follow the same rules as cards. An argument left empty (`TAKE(m, , 2)`) and an argument whose value turns out blank are treated the same way.

The goal behind all of this is as few blank answers as possible. A blank answer hides a problem; an error points at it.

## Why

[[C24]] arraySemantics treats a blank as a real value rather than a zero, and for data that matters: if a missing price silently became 0, every total and average built on it would be a believable wrong number, with nothing on screen to show why.

A setting is different. A blank row count is not a mystery number; it is a number nobody gave. "Not given" already has a clear meaning, the same one it has when a formula argument is skipped ([[C80]] blankArgIsExcelBlank): use the default. The old behavior, blanking the whole answer, threw away the data that was plugged in and protected nothing. When there is truly no default, an error that names the missing input tells the user exactly what to fix, where a blank would leave them guessing. The card already hides its typed value while a cable is plugged in, so the override is visible rather than hidden.

## Consequences

- *Excel diverges:* Excel reads an empty cell in a size slot as 0, so `TAKE(m, A1, 2)` with `A1` empty is `#CALC!` there; here it keeps every row ([[A6]] divergeByDesign). The author: "that's a fine divergence and I think it's a strict upgrade on Excel behavior in this instance".
- *Swept 2026-09-26* on Claude's judgement at the author's word ("please use your own judgement and implement for now. can review later."): about 150 formula functions and their cards, and the filter conditions, which overturn [[C24]]'s blank-filter consequence ("I don't really care about C24, it's fine to override and make compliant with other changes"). The calls and the few inputs not swept yet (column references, an as-of tolerance, the Slider's bounds) are in `docs/settings-audit.md` for review.
- The roles, the declaration every function subscribes to, and how each is read: [[input-roles]].
- **Reopen if:** a default would surprise more often than a blank answer would.
