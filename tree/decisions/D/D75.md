## Decision

**MUST:** for each chart type, the Chart Builder's key list (`CHART_BUILDER_TARGETS` in `chartOptions.ts`) is exactly the set of options that type's renderer honors. An option the renderer reads is offered for that type, and an option offered for that type visibly changes its figure on every surface that draws it: the card, a Display, the popup and a Report embed.

## Why

The Chart Builder is how most people set options, so an option missing from it is invisible and an option that does nothing looks broken. A figure-level title that silently stopped drawing on nine figure types went unnoticed because nothing tied the offered keys to what the renderers read (the author, 2026-09-23).

## Consequences

- A renderer that learns an option adds it to that type's key list in the same change; one that drops an option removes it.
- A surface that draws a figure goes through `ChartFigure`, so no card or embed skips the options.
- *Unenforced:* whether a key visibly changes a figure needs a render, and component render tests stay out of the node-env suite. `chartTitles.test.ts` pins the title half; the rest is checked by eye when a key list or a renderer changes.
- **Reopen if:** the options move to structured per-type fields, which would make the key lists derived.
