## Decision

**MUST:** an Add-menu row's visible name carries only what a reader needs to recognize and pick it. Other spellings a user might type, Excel function names first, are search words that search reads and the menu never shows. They are never tacked onto the name to make the row findable.

## Why

Being findable and being readable are separate jobs. A search word counts as much as the name does, so moving a spelling out of the name costs nothing and can even rank the row higher. A stuffed name costs twice. It repeats a name already declared elsewhere ([[C8]] declareOnce), and because every row in the Add menu is as wide as the widest one, one long name widens the whole menu. When the Distribution rows each carried their full list of dotted Excel names, one row was almost seven times the usual width, and the menu tripled in width on the first keystroke.

## Consequences

- The search mechanism is in [[add-menu]].
- *Exception:* a parenthetical that tells apart two entries sharing a name stays in the label ("T.TEST (equal var)" and "T.TEST (Welch)", "TAKE (table)", "DATE (Build)"), and so does a bare acronym that is the name people know ("Growth Rate (CAGR)"). What is barred is an Excel function spelling: a dotted one, or several separated by slashes. **Removed by:** the menu gaining per-row truncation. The length pressure would then be gone, and only [[C8]] declareOnce would still argue against it.
