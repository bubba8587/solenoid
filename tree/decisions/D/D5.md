## Decision

**MUST:** an Add-menu row's visible name carries only what a reader needs to recognize and pick it. Other spellings a user might type, Excel function names first, are search words that search reads and the menu never shows; they are never tacked onto the name to make the row findable.

## Why

A node's one name shows on every surface, so it has to stay readable. Being findable and being readable are separate jobs, and a search word counts as much as the name does, so moving a spelling out of the name costs nothing.

## Consequences

- *Exception:* a short parenthetical that tells apart two entries sharing a name stays ("T.TEST (Welch)", "DATE (Build)"), and so does a bare acronym that is the name people know ("Growth Rate (CAGR)"). An Excel function spelling never does. **Removed by:** the menu gaining per-row truncation, which would remove the length pressure.
- One long name widens the whole menu: [[add-menu#Why one long label widens the whole menu]].
- **Reopen if:** search words stop ranking as high as the name.
