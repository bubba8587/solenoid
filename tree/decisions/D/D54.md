## Decision

`parseDate` refuses relative phrases (today, next friday, in 3 days, a bare weekday with no year) unless it is called with `{ relative: true }`. The only caller that passes it is the Date Input node, and only when Settings ▸ Data ▸ Relative dates is on (it's off by default). Such a Date Input re-resolves on every pass and raises a warning Alert when the day it resolves to changes between calculations. Text with a four-digit year is never relative: "Monday, 16 March 2026" is a fixed date.

## Why

A stored date should be a fixed calendar day. DATEVALUE, Cast, Frame and Table columns and every other date surface stay deterministic, so a document never changes its answers because the day changed, unless the user asked for exactly that. The alert makes the one exception visible when it moves.

## Consequences

- **Reopen if:** the author wants DATEVALUE or a Frame column to follow the setting. The opt-in would then move from the node to the parser's call sites, and the alert with it.
