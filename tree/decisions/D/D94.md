## Decision

Every surface that shows a number without a format the user picked shows it one way, the Format Controller's General (auto) style: an integer as it is, anything else to the "Decimal places" setting (2, 3, 4 or 6; 4 by default) with trailing zeros dropped, and scientific at 1e12 and above and below the smallest decimal shown. Value boxes, Frame and Table cards, the Table and Cube popups, complex numbers, unit suffixes, Alert messages and formula steps all use it.

## Why

[[C94]] formatFamilyGates gives decimal places one rule, and the same number read four ways by surface (0.2203 in a value box, 0.22 on a Frame card, 0.22033898305084745 in a Cube cell) makes a user doubt which is the value. General is already the named default a user can pick, so the default display is that choice. How many decimals suit depends on the person and the data, so it is a setting, not a constant; dropping trailing zeros keeps 1.5 from reading as 1.5000, and going scientific below the last shown decimal keeps a small value from reading as 0.

## Consequences

- The formatter is `formatScalar` (`components/format.ts`); the Format Controller's `auto` style is the same function, and `formatAnnotationStore` and `frameFormatStore` notify when the setting changes, so what is on screen redraws. A popup already open keeps its text until it is opened again.
- A number turned into text as data (Cast to text, a complex number in a text formula) is not a display and keeps its own rule.
- Displays that exist to show a constant's precision (the Constant and Physics Constant cards) and chart axis ticks keep theirs.
- **Reopen if:** one surface needs a different default than the rest; it then takes a Format Controller, never its own constant.
