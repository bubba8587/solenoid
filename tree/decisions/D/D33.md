## Decision

**MUST:** an input with nothing plugged in uses the value typed on the node. An input that is plugged in and receives a blank keeps the blank: it is a real missing value, it passes on downstream, and the typed value never replaces it.

## Why

[[C24]] arraySemantics makes a blank a real value. "Nothing is plugged in" and "the value is unknown" are different facts, and replacing a wired blank with the typed value makes the node answer with a number the user can't see anywhere on the node.

## Consequences

- How a node reads its inputs: [[value-semantics]].
- *Exception:* a blank wired into a setting (a count, position, size or mode) reads as the setting left out, overriding the typed value ([[E15]] settingBlankIsLeftOut). **Removed by:** nothing; a setting is not data.

## Contest

### Contest 2026-09-26 by Claude Opus 5.5: keep wins

Keep for data inputs. The author (2026-09-26) ruled a wired blank in a setting (a count, position, size or mode) reads as the setting left out; that lands as an exception leaf under D33 rather than a rewrite, since the data half stands as written.
