## Decision

The native engine stores an error cell only in a number or date column (a reserved NaN carrying the code and a reference back to the original error). A frame that holds an error cell in a string or logical column is not uploaded: PolarsBackend keeps it on the oracle, and a binary verb that meets such a frame collects its native partner into the oracle.

## Why

[[C16]] polarsEngine promises identical answers from both engines, and Polars' string and boolean columns have no bit pattern to spare for an error, so uploading one would turn the error into a blank. Routing only those frames keeps every answer exact and leaves the common case, errors from computed numeric columns and date parsing, on native Polars.

## Consequences

Such a frame runs at oracle speed. Reopen if: those frames get large enough that the oracle is too slow, or the engine gains a lossless error encoding for text and logical columns (a reserved string, or a side column of codes), which would remove this exception.
