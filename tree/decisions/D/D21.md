## Decision

**MUST:** a node's name (its title, its Add-menu row, its help and Function Reference entry, its socket docs) never reads as a core Excel function that does something else. A bare "Columns" reads as COLUMNS(), which counts columns, so the node that keeps or drops columns is named for what it does, "Keep Columns" or "Drop Columns", and its title follows the op.

## Why

Under [[C19]] namingModel a node's name is how it is named everywhere, and an Excel user reads that name as a claim about behavior ([[A5]] excelParity). A node that borrows a function's spelling for an unrelated job is a trap rather than a shortcut.
