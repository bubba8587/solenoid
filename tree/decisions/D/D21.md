## Decision

**MUST:** a node's user-facing name (card label, catalog leaf, help and Function Reference, socket docs) never reads as a core Excel function that does something else. A bare "Columns" reads as `COLUMNS()`, which counts columns, so the node that keeps or drops columns is named for its op, "Keep Columns" or "Drop Columns", and its card label follows the op.

## Why

Excel users are promised no learning curve ([[A5]] excelParity), so a name is a claim about behavior, and a node that borrows a function's spelling for an unrelated job is a trap rather than a shortcut. The ROWS and COLUMNS merge first shipped a bare "Columns" node, which is what prompted this rule.
