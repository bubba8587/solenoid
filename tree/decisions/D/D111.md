## Decision

A frame's Cards can follow a card layout the user writes, in the same grammar as the Form layout: the layout picks the fields and places them, and the data still decides how each field draws (stars, meters, chips). With no layout written, Cards stay inferred, and the Form view lays its fields out from the same reading of the data instead of stacking them; a Suggest button writes that layout out so it can be edited.

## Why

Some frames read best with the fields a person picks and places, and a form laid out from its data fills faster than one long stack. Inferred cards stay the default because most frames never need a hand-written layout.

## Consequences

- A card layout hides the columns it doesn't name, as a Form layout does.
- **Reopen if:** people want a card layout to restyle a field the plan reads differently (a meter shown as a plain number).
