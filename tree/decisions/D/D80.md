## Decision

A Cube column either declares an element type (Number, Text, Date, Boolean) or declares none. A declared type overrides every kind inside the column: a scalar cell reads as a Frame cell of that type does (what it can't read shows as NaN), each item of a list cell reads as a List Input item of that type does (what it can't read is blank), and a nested table reads with every column set to that type. With none, each cell keeps the kind it arrived with, so one column can mix numbers, text and lists. The text as typed is never rewritten.

## Why

[[C10]] socketLattice keeps kinds from mixing on their own, and a Frame column enforces that by having one type. A Cube is the container for data that doesn't flatten, so forcing a type on every column would refuse the vault notes and hand-typed records it exists to hold. Letting the column say which it is keeps both: a typed column is as trustworthy as a Frame column, and an untyped one says openly that it isn't. The source stays as typed ([[C58]] tableInputRawText), so a type is a reading, never a rewrite.

## Consequences

- Cube Input's column type button cycles None, Number, Text, Date, Boolean and Formula; a new column starts with none. The Solenoid Properties plugin's cube editor has the same button without Formula, and saves the picks as it saves a Frame's.
- A list mixing kinds in an untyped column claims no kind: it always shows its items as they are (its chip in the neutral gray, its popup as text), and a Cast converts it item by item.
- The editor shows each typed cell's reading, and the Source switch shows what was typed.
- An inferred type on a column nobody typed is a display hint only.
- How it's built: the frame-verbs spec (The Cube value) and the table-popup spec (Editing a Cube Input).
- **Reopen if:** nested levels of a Cube Input need their own column types.
