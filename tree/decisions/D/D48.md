## Decision

**MUST:** a number a calculation can't represent never leaves the node that computed it as a bare not-a-number or infinity. That node turns it into a named error: not-a-number becomes `#DOMAIN!`, and infinity from finite inputs becomes `#OVERFLOW!`. Infinity that came in as infinity passes, since the Constant node's ∞ is a real value. It is never left to flow on and be caught later, or not at all. A function with its own recorded answer for this case (a quiet blank, a specific error) has made the same call its own way, not skipped it.

## Why

[[C24]] arraySemantics keeps errors apart from numbers so a wrong answer never looks right. A bare not-a-number shows as an empty cell and computes onward as more not-a-number: a wrong answer that doesn't look like one, the least visible failure in the model. Only the node that produced it knows why, so it is the one that names it.

## Consequences

- An infinite or not-a-number value is a key of its own when rows are grouped, deduplicated or split into windows: plus infinity, minus infinity and not-a-number are three keys, not one. Sort already puts the infinities at opposite ends and totals read not-a-number as `#DOMAIN!`, so one shared bucket would merge values every other surface tells apart.
- Such a key never matches in a Join, not even another of its kind: not-a-number doesn't equal itself, and an infinity marks an overflow, so two rows that both overflowed are not the same thing.
- Which calculations run the check, and the functions with a convention of their own: [[error-values]].
