## Decision

A note whose properties say `knap: true` reads in Obsidian the way its Note card reads in Solenoid: the plugin renders the body as a Knap template from the note's own properties, and a bare `{{ name }}` on a property of a Solenoid type is that property's chip, which opens the same editor the properties panel does. Without the property the plugin leaves the body alone.

## Why

[[C68]] knapIsTheDocumentSyntax makes `{{ name }}` the one way a note refers to a value and has a bare tag show what the canvas shows, and Solenoid's Note already fills its tags from its own frontmatter; under [[C107]] obsidianPlugin the same note should read the same in Obsidian, so the syntax is Knap's and the object is the app's chip, not a second inline syntax. The switch is per note because a vault's template notes also hold `{{ }}` tags that are not meant to render.

## Consequences

- Reading view renders the whole body, so a loop or an `if` may span paragraphs. Live Preview renders it too, piece by piece: each tag, and each `if` or `for` block whole, shows its output until the cursor enters it, then its source, as Obsidian treats its own tables and callouts.
- A chip in the body edits the property itself; nothing in the body is ever written.
- How it is built: [[obsidian-plugin]] § Knap notes.
- **Reopen if:** Obsidian renders Knap in notes itself, or the app's Note card stops rendering its own frontmatter into its body.
