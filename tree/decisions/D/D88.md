## Decision

A frame's Table popup has a Cards view: every row drawn as a card in one narrow column, for reading a frame on a phone. Nobody writes a card layout. It is worked out from the columns (their order, types, names and what the cells hold), so the same frame always gets the same cards. On a phone-width screen a frame popup opens in Cards.

## Why

[[C63]] oneRecordNode puts every authored record view on the Record node and keeps data entry on the Form view, whose layout is written on the Frame Input. A grid of many columns is unreadable at phone width, and asking for a layout before you can read your own data on a phone is backwards, so this view is derived rather than authored. Deriving it the same way every time means a card never rearranges itself between opens.

## Consequences

- The Cards view reads; editing stays in Form, and on an editable popup each card jumps there.
- **Reopen if:** people want to author the card layout, which would make it a Record view on the Record node instead.
