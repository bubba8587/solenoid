## Decision

React Flow draws the canvas. The graph and the engine that computes it stay on the small rete core libraries underneath, rather than code of our own.

## Why

React Flow only draws; it knows nothing of typed sockets or values flowing. Rete supplies those, and writing our own would add code to maintain with nothing new for the user.

## Consequences

- How it's built: [[react-flow-surface-contract]].
- **Reopen if:** rete core stops being maintained in a way that hurts, or a library would let us delete code.

## Alternatives considered

### Contest 2026-09-15 by Claude Opus 5: keep wins

Rubric: [[A1]].
- keep: React Flow view, rete core + rete-engine headless. Cost: already landed; ~1,500 vendored lines to track.
- opposite: rete renders again. The port was done because the rete render stack could not carry the canvas the author wanted; re-porting back is the whole port's cost again.
- deletion: [[A1]] says visual node graph but not what draws or computes it; every canvas change would re-open the stack.
- variant: hand-rolled model and engine under React Flow. ~400 lines of ours for no functional gain, a new engine to trust.
Verdict: keep.
