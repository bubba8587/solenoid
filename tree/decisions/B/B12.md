## Decision

A saved document reopens exactly as it was left, and saving it again writes the same thing. When a save can't capture everything, it fails loudly rather than writing a file that looks fine but has lost something. Every save is written from one plain-text form of the document, so there is only one definition of what a document holds.

## Why

[[A1]] visualGraphCalculator is only usable if the work survives. A loss that happens quietly is the worst kind: the file looks fine, nothing marks the loss, and by the time a reload shows it the next save has written over the good copy. So a save that can't capture everything fails loudly rather than writing that file, and one text form means there is only one place a save can go wrong.

## Consequences

The save-path rules live in the specs: [[save-format#The capture is a fixed point, and plain JSON]], [[save-format#Every save passes through the text form]], [[per-doc-autosave-persistence#Change detection is object identity]], [[per-doc-autosave-persistence#Two slots per pair]], [[save-format#Saving binds the main graph]], [[save-format#The persisted type is the class name]], [[C35]] unknownViaPlaceholder, [[per-doc-autosave-persistence#Swapping documents]], [[save-format#Every field is persisted or deliberately transient]], [[react-flow-surface-contract#Node width and height]].

- The app opens exactly one save-format version. A file from a newer version is refused rather than opened with the parts it doesn't understand dropped, because the next autosave would write that loss over the good copy. An older one is refused because there is no upgrade path ([[B7]] preAlphaBreakFreely).
- A damaged file is refused before the open document is touched. If opening fails partway, the previous document comes back. If even that fails, autosave stays off, so the broken state never overwrites the last good copy.

## Alternatives considered

### Contest 2026-09-15 by Claude Opus 5: keep wins

Rubric: [[A1]].
- keep: saves are lossless and loud. Cost: the persistence fixed-point and field-classification sweeps, slot rotation, text-form completeness scan.
- opposite: best-effort saves; occasional loss accepted for speed of change. A calculator that loses a setting on reload is not usable for real work.
- deletion: [[A1]] alone does not name persistence; the save-path rules would hang on the engine or the view, neither of which is why they exist.
- variant: lossless only for values, settings may reset. The recorded bug (an as-of join direction resetting on reload) is this variant's cost.
Verdict: keep.
