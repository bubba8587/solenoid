## Decision

A build of Solenoid won't open a document saved by a newer build. It says the file needs a newer version, and whatever you had open stays on screen. It never opens just the parts it understands.

## Why

The only way an older build can open a newer file is by dropping what it doesn't recognize — and the moment that trimmed copy is open, autosave writes it over the good one. You'd never be told what went missing. Refusing is annoying, but it leaves the file intact for the build that can read it.

## Consequences

- A newer file just won't open on an older install, where another app would show you most of it. Updating is the fix.
- Older files are refused too, but that's [[B7]] preAlphaBreakFreely (no migrations), not this leaf.
- How it's built: [[save-format#The version gate]].
- **Reopen if:** other people's files start going around between versions, and opening a newer file read-only, with a list of what was skipped, becomes worth more than a flat refusal.

## Alternatives considered

- **Open what you can** (what Word and most apps do): load the parts this build knows, warn about the rest. It's friendlier, but autosave turns the warning into a permanent loss.
- **Open read-only:** show the newer file but block saving. That's safe, and it's the likely answer once there's more than one user. For a single user who controls which build they're running, it isn't worth building yet.

### Contest 2026-09-15 by Claude Opus 5: keep wins

Run against the leaf's earlier, wider wording ("a saved document reopens exactly as it was left"). Rubric: [[A1]].
- keep: saves are lossless and loud. Cost: the persistence fixed-point and field-classification sweeps, slot rotation, text-form completeness scan.
- opposite: best-effort saves; occasional loss accepted for speed of change. A calculator that loses a setting on reload is not usable for real work.
- deletion: [[A1]] alone does not name persistence; the save-path rules would hang on the engine or the view, neither of which is why they exist.
- variant: lossless only for values, settings may reset. The recorded bug (an as-of join direction resetting on reload) is this variant's cost.
Verdict: keep.
