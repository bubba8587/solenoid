## Decision

Type safety, units and shape are core to Solenoid. A value has a type family (number, text, date, logical), a shape (one value, a list, a table: a List is one row, and a Frame column read whole is a column), a unit and a format, or is a blank or an error. Solenoid keeps each of these and never blends, drops or reshapes them for convenience: text that looks like a number is still text, a number is not a date, 5 km is not 5, and a row is not a column. Changing any of them takes a node the user can see, or a calculation whose answer is by nature a different kind of thing.

## Why

A quiet conversion gives a plausible answer built on a wrong reading, and nothing on screen says it happened. Excel lets types slide to save a step; Solenoid is meant to be where what a value is can be trusted, so every conversion is a step the user chose and can see. A value that quietly loses its unit or its orientation is wrong in the same way as text read as a number.

## Consequences

- How it's built: [[value-semantics]] and [[socket-lattice]].
- It holds where Excel converts and where converting would be handier: the criteria functions never sum the text "10" or match it against the number 10.
- A typed column is not a conversion. A cell typed into a column the user declared as number, date or Boolean is how a value of that type gets written, so its text reads as that type: `1` in a Boolean column is TRUE, `0` is FALSE. What this leaf forbids is text crossing into another type where no one declared it, as when a criteria function sums a text column.
- **Reopen if:** Solenoid stops treating types and units as first-class.

## Contest

### Contest 2026-10-16 by Claude Opus 5.5: keep wins

Rubric: [[A6]].
- keep: types, units, blanks and errors stay distinct; every conversion is a visible node. Cost: explicit conversion nodes and typed-column readings.
- opposite: convert where convenient, as Excel does (sum numeric text, read dates from text). A6 names typed values as where Solenoid diverges from Excel's frustrations, so this undoes the parent.
- deletion: A6 already names typed values and units, but not that convenience never blends them; without this leaf each subsystem would re-decide coercion on its own.
- variant: typed values but lenient criteria functions (sum text that looks numeric). That is the recorded incident (criteria functions summed numeric text) that forced the 10-05 rewrite.
Verdict: keep.
