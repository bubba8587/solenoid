## Decision

Type safety is a core value of Solenoid. A value has a type family (number, text, date, logical), a shape, a unit and a format, or is a blank or an error, and Solenoid keeps each of these distinct and never blends them, even for convenience: text that looks like a number is still text, and a number is not a date. Changing any of them takes a node the user can see.

## Why

A quiet conversion gives a plausible answer built on a wrong reading, and nothing on screen says it happened. Excel lets types slide to save a step; Solenoid is meant to be where what a value is can be trusted, so every conversion is a step the user chose and can see.

## Consequences

- How it's built: [[value-semantics]] and [[socket-lattice]].
- It holds where Excel converts and where converting would be handier: the criteria functions never sum the text "10" or match it against the number 10.
- A typed column is not a conversion. A cell typed into a column the user declared as number, date or Boolean is how a value of that type gets written, so its text reads as that type: `1` in a Boolean column is TRUE, `0` is FALSE ([[D93]] oneTextReading). What this leaf forbids is text crossing into another type where no one declared it, as when a criteria function sums a text column.
- **Reopen if:** Solenoid stops treating types and units as first-class.
