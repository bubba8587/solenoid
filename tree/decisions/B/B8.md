## Decision

Solenoid's decisions and rules live only in this decision tree, one leaf per decision, never in a separate rules document. The code, tests and docs point at the leaf that explains them instead of restating it.

## Why

[[A1]] needs a product that stays maintainable while AI sessions change it daily, and the project's standing order is one home per fact: every copy of a rule is a place it can be contradicted. The tree records who made each decision, what it touches, what it rests on and whether the author has ratified it, which prose documents cannot.

Each leaf also has a short name beside its number, because code, tests and docs cite rules by name, and a bare number means nothing in a comment. That departs from DTE's own rules on one point: the name is a readable label on the leaf, not a second identity, and a test checks that every name used matches its number.

## Consequences

- A leaf says only what stands now: what was decided, why, and what follows from it. Finished work and build history stay out of it; git has them. History is a log, one line per event. The record of a contest is deleted once the author ratifies the leaf.
- A test guards the tree: every rule is enforced by a test or says why it can't be, the author's ratifications match a list the author keeps, and every name used matches its leaf. How that works: `docs/dte.md`.
- A doc that explains how something works, or how to build it, stays and points at the leaves it explains; a doc that only restates decisions is deleted.
- DTE's own rules are kept as a copy in `dte-rules/` and are never re-created as Solenoid leaves.

## Alternatives considered

### Contest 2026-09-15 by Claude Opus 5: keep wins

Rubric: [[A1]]. [[B8]] was written as the variant that won B4's contest (2026-09-15), so its alternatives are the same ones, costed there: keep-both-docs (every fact held twice, the contradiction class the reconcile rule fights); no DTE (loses provenance, blast radius, trace, ratification); no node (every session re-asks where rules live). A further variant scoped here: generate rules.md and decisions.md from the nodes as read-only indexes. Cost: a generator plus a staleness test, and a second rendering agents would still read instead of the tree; dte tree and find already index by ID and name. Verdict: keep.
