## Decision

Desktop is the full product, with a fast native table engine and real file access; the web build is for looking and trying. A feature that needs files degrades to a no-filesystem path on the web instead of being a dead end there.

A desktop-only feature is built without hesitation. "It won't work on the web" is never an objection, because the web build is look-and-try by design.

## Why

The web build has to demonstrate the product for real, so a file-backed feature needs some web story, even a reduced one; a visitor who hits a dead end sees a broken product, not a desktop feature. But the full product lives where native code and a real filesystem do, and holding desktop back to what a browser can do would cap the product at its demo. Table work shows the pattern: a native engine on desktop, and on the web a slower one that gives identical answers ([[C16]] polarsEngine).
