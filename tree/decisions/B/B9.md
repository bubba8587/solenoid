## Decision

Solenoid is developed by AI agent sessions directed by a single author. The rules that govern its code are therefore written down once, derived rather than transcribed, and enforced by tests, rather than held in anyone's memory, because no session carries memory of the last.

## Why

[[A1]] needs a product that stays correct while it changes daily. Every agent session starts cold, and the project's recorded structural risk is a single-author bus factor, so a rule held in anyone's memory is lost at the next session. The incidents in the leaves' Why sections record the cost: nearly every one is a rule someone was trusted to remember.

## Consequences

- The families under this leaf: derivation ([[C8]] declareOnce), enforcement ([[C9]] labelUnenforced), exceptions ([[C5]] exceptionsUnderRule), rules before code ([[C6]] specFirst), comments ([[C57]] commentMinimalism), provenance ([[C7]] authorRuled), parallel sessions ([[C83]] parallelAgents) and audits ([[C108]] auditDefaultsToFix).
- Standing risk: the single-author bus factor. Mitigation: the doc series, machine-checked seeds, and the reconcile rule.
- Standing risk: doc rot, the project's named failure mode. Mitigation: reconcile, don't append; the docs index; verify claims against code.

## Alternatives considered

### Contest 2026-09-15 by Claude Opus 5: keep wins

Rubric: [[A1]].
- keep: rules are written once, derived, and test-enforced because agents carry no memory. Cost: source-scan and sweep suites; the enforcement column on every rule.
- opposite: rules held by a human reviewer who reads every diff. One author cannot review every agent session's output, and the bus factor stays.
- deletion: [[A1]] alone does not explain why Solenoid's rules are test-enforced; sessions would relax the guards as ceremony.
- variant: enforcement by a review agent instead of tests. Non-deterministic, and the reviewer has the same cold start.
Verdict: keep.
