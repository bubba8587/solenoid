## Decision

One card, selectors for what varied: "these could be one node" means the MAXIMAL merge, never a pairwise or partial one. A variant is a mode/op selector on the existing card, never a sibling node.

## Why

A recurring author program, with [[C60]] oneRunningNode and [[C61]] oneDistributionNode as the models. [[A1]] wants a calculator that is learnable at scratchpad scale and still covers table work, and every sibling node is another name to find, learn and keep in parity with the formula surface. A distribution merge once stopped at pairwise when the intent was all fourteen.

## Consequences

Mechanics that were gotten wrong once and must not repeat:
- An op's formula name is `fx ?? despace(label)`: when the real name is an Excel spelling or the label went bare, declare `fx` (distribution `normal` → NORM.DIST; Running `SUM` → RUNNINGSUM). Never dodge a [[C18]] uniqueNameMap collision by reclassifying the family as an argument or inventing a parallel presentation flag: the selector that names the card is the `op` field, and the accent follows ([[C26]] opArgDistinct).
- Selector-driven socket swaps prune departing keys through `dropInputCables` before `removeInput` ([[D10]] onePrunePath), spec-table the per-op shape (the `DIST_SPECS` pattern), and carry state across switches by meaning (PDF↔PMF, inverse variants → Inverse).
- Where the combinations are few, flat ops beat a second picker: each op keeps its own hover description, and no new saved field is needed (Hypothesis Test's six tests, Rank & Percentile's INC and EXC forms).
- A merge keeps the old Add-menu leaf types, so `NODE_EXCEL` and the Function Reference are untouched; the merged cards are inventoried in `docs/node-coverage.md`.
- Old saves load as Placeholders ([[B7]] preAlphaBreakFreely).
- After a merge run `nodeOps.test.ts` + `formulaNodeCoverage.test.ts` beside the parity/catalog/seed suites.
- **Reopen if:** a family whose variants cannot share a spec table (a second x input, a non-numeric parameter); then a sibling is honest, and the reason is recorded.

## Alternatives considered

### Contest 2026-09-15 by Claude Opus 5: keep wins

Rubric: [[A1]].
- keep: maximal merges, variants as selectors. Cost: spec tables per family; socket-swap and prune mechanics on each merged card.
- opposite: one node per variant. The Add menu and Reference grow by every variant; each is another parity target and another name to learn.
- deletion: [[A1]] alone would not stop sibling nodes accreting one session at a time, the observed failure (a pairwise distribution merge).
- variant: merge only when the author asks, pairwise otherwise. The recorded stall at pairwise is exactly this variant's cost.
Verdict: keep.
