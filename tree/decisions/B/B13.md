## Decision

An AI assistant that edits the document is in scope. It never changes the document directly: it proposes an edit, the edit is checked the same way a loaded file is, and the user sees the change and approves it before it lands. The assistant uses Anthropic's models.

## Why

[[A1]] visualGraphCalculator is built by drawing a graph, and an assistant that can draw one for you shortens that; the document's plain-text form is something a model can write. The approval step keeps it caged: nothing the model writes reaches the document unchecked or unseen. The product's pitch stays the files and the canvas. AI is a capability, not the headline, and marketing says little about it.

## Consequences

- What the assistant knows about the nodes is generated from the same catalog the Add menu uses, never written by hand ([[C8]] declareOnce).
- The assistant ships switched off, the author's call, until its checking is finished. While it is off, every trace of it in the app is hidden.
- How it is built: the Command Palette spec, AI mode.
- **Reopen if:** the assistant can't be made trustworthy, or it pulls the product's focus on Excel users toward an AI-first pitch.

## Alternatives considered

### Contest 2026-09-15 by Claude Opus 5: keep wins

Rubric: [[A1]].
- keep: AI edits in scope, caged behind validation and approval. Cost: the AI service, the whole-document rewrite gate and diff.
- opposite: AI stays out. Forgoes AI-assisted graph building for a calculator whose canvas is already a text form an AI can write.
- deletion: [[A1]] alone does not decide whether an AI may edit the document; each AI feature would re-open the question.
- variant: AI as a separate assistant that never edits the document. Loses the edit loop; the cage already bounds the risk.
Verdict: keep.
