## Decision

Every visual, layout and copy choice in the app follows one design system, written in DESIGN.md: its rules on cards, color, chrome and voice bind UI work, strings included.

## Why

[[A1]] visualGraphCalculator's product is a visual canvas, so how it looks, lays itself out, reads and answers the hand is the product. Many agent sessions touch the UI; without one rulebook each makes locally reasonable choices that disagree, and the canvas reads as several apps.

## Consequences

Parent of the design calls lifted from DESIGN.md: palette and chrome ([[C62]] paletteAllOrNone), labels, selection, groups and layout, gestures, formatting controls, chart options and the Command Palette.

## Alternatives considered

### Contest 2026-09-15 by Claude Opus 5: keep wins

Rubric: [[A1]].
- keep: one design system in DESIGN.md. Cost: reading it before UI work; keeping it current.
- opposite: per-feature design judgment. Chrome drifts into inconsistency across sessions, the canvas reads as several apps.
- deletion: [[A1]] does not govern visual consistency; UI rules would have no parent to hang on.
- variant: adopt an external system (Material, Fluent). Fights the node-canvas identity and the author's own rules (no accent stripes, the voice).
Verdict: keep.
