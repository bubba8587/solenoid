## Decision

**MUST:** an error stays in its cell. An answer carries an error only when it reads the cell that holds it:

- **Element-wise** work (arithmetic, math functions, comparisons, Convert over a list) gives an error in the matching output cell only; the other cells compute normally.
- **Positional** reads (INDEX, XMATCH, a MAKEARRAY read) propagate only the error in the cell they actually read; an error elsewhere in the range doesn't touch the answer.
- **Aggregates** (SUM, AVERAGE, GROUPBY's function over a group) read the whole range, so an error anywhere in it makes the whole answer that error, as in Excel.

## Why

This is Excel's model ([[A5]] excelParity), and it is the per-cell error model of [[C24]] arraySemantics applied to each kind of op. Getting either direction wrong is silent: erroring a whole list or lookup hides good answers, and letting an aggregate skip an error hides a bad one. [[D35]] errorInErrorOut covers an input that *is* an error; this leaf covers a list or range that *holds* one.
