## Decision

**MUST:** an error stays in its cell. An answer carries an error only when it uses the cell that holds it:

- **Element-wise** work (arithmetic, math functions, comparisons, Convert over a list) gives an error in the matching output cell only; the other cells compute normally.
- **Positional** reads (INDEX, XMATCH) use only the cell they land on, so an error elsewhere in the range doesn't touch the answer.
- **Whole-range** work (SUM, AVERAGE, a group's total, FILTER's condition list) uses every cell, so an error anywhere in the range makes the whole answer that error.

## Why

This is how Excel usually behaves, and it is also why Excel feels aggressive about errors: one bad cell spoils every total that includes it, and each spoiled total spoils everything that reads it in turn. Excel isn't fully consistent, though. COUNT and COUNTIF skip error cells instead of failing, and AGGREGATE can be told to. Where a Solenoid function follows one of those exceptions, its function note says so.

Getting either direction wrong is silent: an error that spreads too far hides good answers, and a total that skips an error hides a bad one. [[D35]] errorInErrorOut covers an input that *is* an error; this leaf covers a list or range that *holds* one ([[C24]] arraySemantics).
