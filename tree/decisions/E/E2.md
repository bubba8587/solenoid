## Decision

**MUST:** the lattice refuses a Cube into a Frame socket. A verb that should accept a Cube declares a Cube-adoptive input (`cubeAdoptIn` plus `noWidenInputs`, the Add Column and Computed Column pattern) and flattens or refuses inside `data()`. A verb that adds a column keeps the Cube a Cube (an adoptive output, as Computed Column and Window do); a verb whose output is a Frame reads through `flatCubeToFrame` only the columns it uses. A nested cell in a column the verb reads is a loud `#SHAPE!` naming the column; nested columns it doesn't read never block it, so a vault table (whose tags and links are lists) still groups, windows and charts. The lattice is never widened to spare one node the work.

## Why

The author's words: "cube into frame socket is NOT acceptable. if you have to upgrade something, upgrade the sockets on each node, not vice versa." A Cube can hold nested tables that a Frame can't, so letting one into every Frame socket would make every Frame verb meet shapes it was never built for, while a per-node input keeps the flattening visible and deliberate.
