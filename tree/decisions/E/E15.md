## Decision

**MUST:** a setting is an input that tells a node how to work on its data: a count, a position, a size, a mode. A blank wired into a setting reads as the setting left out. It overrides the value typed on the card, and the node uses its own default (TAKE keeps the whole axis, INDEX takes the whole row or column, ROUND's digits are 0). A setting with no default answers `#SYNTAX!` naming it. A formula reads a blank value in a setting slot the same way it reads a slot left empty.

- A blank inside a list of settings stays at its spot: INDEX or CHOOSEROWS given `[3, blank]` answers row 3 and then a blank row.
- An error in a setting still passes on ([[D35]] errorInErrorOut).
- Data keeps [[D33]]'s rule: a blank value stays blank, and a node whose data is wholly blank answers blank. That is the only way a setting-driven node blanks its whole answer.

## Why

[[D33]] keeps a wired blank from turning into a number nobody can see, which protects data. A setting is not data: a blank count is not an unknown count, it is a count nobody gave, and "not given" already has a meaning, the one a skipped formula argument has ([[C80]] blankArgIsExcelBlank). Blanking the whole answer instead throws away the table that was wired in and protects nothing. The card already hides the typed value while a cable is plugged in, so the override is visible.

## Consequences

- *Excel diverges:* Excel reads an empty cell in a size slot as 0, so `TAKE(m, A1, 2)` with `A1` empty is `#CALC!` there; here it keeps every row. A deliberate improvement ([[A6]] divergeByDesign).
- *Where:* cards read a setting through `readSetting` or `requiredSetting` (`nodes/shared.ts`); formulas declare their setting slots in `BLANK_ARG_TYPES` (`excelFormula.ts`), with `required` for a setting that has no default.
- *Not yet swept:* only TAKE, DROP, EXPAND, INDEX, ROUND and CHOOSEROWS/COLS follow this so far; the rest of the catalog is a backlog item, Filter's value among them (which overturns [[C24]]'s blank-filter consequence when it lands).
- **Reopen if:** a setting's default would surprise more often than a blank answer would.
