## Decision

Every cell of a Cube Input's editor, at any level and inside a list, can be switched in place between a value, a list, a matrix and a table: every shape a Cube cell holds. A table reads as a Frame while its cells are flat and as a Cube once one of them holds a list, matrix or table. Switching keeps what it can: a value becomes the first item or cell; a list is a matrix's first row and a table's first column, and back; a table's rows become a matrix's and back, losing the column names; switching to a value keeps the first value found.

## Why

[[C28]] literalsIffEditable ties what a literal node saves to what its editor shows, and a Cube holds lists, matrices, Frames and Cubes in its cells ([[D90]] cubeTypesAtDepth), so an editor that can only type a value leaves most of what a Cube is for reachable only by pasting JSON. Keeping the old contents on a switch means a wrong pick is one more pick away from undone.

## Consequences

- Each editing cell has a small menu at its edge naming Value, List, Matrix and Table, with the cell's current kind marked; it shows on hover or focus, and always on a touch screen. A matrix's own cells are values, with no menu.
- A new list starts empty (or holding the value that was there); a new matrix or table starts as one cell, a table's named `Column 1`.
- A switch drops the column types declared for tables inside the cell ([[D90]] cubeTypesAtDepth).
- The Solenoid Properties plugin's cube editor gets the same menu, since it shares the editor.
- How it's built: the table-popup spec (Editing a Cube Input).
