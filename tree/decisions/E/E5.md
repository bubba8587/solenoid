## Decision

**MUST:**
- **As an input,** `anydata` accepts every family value of rank ≤ 2 (scalar, list, combo, matrix) and the lower wildcards (`any`, `anylist`, `anycombo`, `anytable`). It refuses Frames, Cubes and the object family (lambda, chart, document).
- **As an output,** it flows wherever `anycombo` flows: shaped at runtime, with the same accepted risk.
- Its edges are derived additions to `accepts()` under [[D14]] derivedSocketTypes, swept by the full lattice test.
- A formula surface's variable and side sockets are `anydata`: Expression variables, and Computed Column side inputs (a side value can be a whole list, as in `SUM(list)`, or a row-aligned list read with `@name`).
- The result socket keeps its family instead. The `resultAs` combo socket serves rank ≤ 1 results. When a result is a matrix, the node swaps its result socket to the same family's matrix rung and reconciles through `retypeOutputCables` ([[D16]] retypeReconciles), the machinery every in-place retype uses. Downstream Format Controllers keep their family, and the socket never lies about rank.

## Why

Any Matrix (`anytable`) can't do this job because of how it adopts: a scalar or list wired into it is lifted to a matrix of that family, so a formula variable would see `5` as a 1×1 matrix and every downstream type would change rank. A formula variable has to take a scalar, a list or a matrix and keep each one as it is. `anydata` is that rung: rank ≤ 2 in, the wired rank kept. [[C15]] matricesInFormulas stops at matrices. A `trueany` variable would let Frames and Cubes into formulas, which is permanently out of scope, and `anycombo` refuses the matrices C15 admits, so the lattice needed the one rung between them. The result socket isn't `anydata` because that would give up the family Format Controllers key on (`familyOf` is none) in exchange for a rank the matrix rungs already spell.
