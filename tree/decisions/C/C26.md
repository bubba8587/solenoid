## Decision

**MUST:** every choice on a node is either an operation or an argument, never something in between.

- **An operation** is a different function. It is picked at the top of the node in the accent color, has its own formula name and its own row in the Add menu.
- **An argument** is a setting of the node's one function. It is picked with a neutral control in its own row, and has no formula name and no Add-menu row. In a formula it is a parameter of the node's function: `SORT(list, index, order)`, `RUNNING(op, list, [window])`, `PADTEXT(text, width, [side])`.

**An aggregator is an argument when the node has a job it only parameterizes.** Group Lists, GROUPBY, Cube Rollup and Running each pick SUM, AVERAGE, MIN and so on, and none of them names a function per aggregator. Aggregate is the exception: there the aggregator is the whole node, so it is an operation.

## Why

[[B11]] maximalMerge folds a family's variants into one node, and each folded choice is either a different function or a setting of the same one. The two look alike on the node but behave differently everywhere else: an operation is searched for and called by name, an argument is not. A node that blurs them either hides a function from search or gives a setting names nobody would type. So the question is only what the choice changes, another function or a parameter of this one, and a per-choice formula name follows from the answer, never decides it.

## Consequences

- To classify a new picker, weigh the signals together instead of letting the last one win. Would the user pick it, or could it arrive computed? Does it have its own name? ([[formula-language#Derived names are unique]] can overrule: ops that would share a formula name can't be ops.) Would the user search for it? Is it meaningless without its host? Is it an Excel function? That last one only corroborates.
- Distribution's `.RT` forms have search rows because Distribution is an op family, not because arguments may be searchable.
- Gauge's Dial and Bar are an argument (`mode`, a SegToggle), not ops: nobody searches the Add menu for "dial" or "bar", and the card has no formula surface.
- Whether every op is callable from a formula is the parity program's business ([[C17]] shareImpl), not this rule's.
- The picker components and their layout are in `DESIGN.md` § Op pickers.
- **Reopen if:** users search for aggregator names and don't find them. The fix is then more `keywords` on the host leaf, not a search row per aggregator.
