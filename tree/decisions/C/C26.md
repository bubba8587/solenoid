## Decision

**MUST:** every choice on a node is either an operation or an argument, never something in between. An operation is a different function: it is picked at the top of the node in the accent color, and has its own formula name and its own row in the Add menu. An argument is a setting of the node's one function: it is picked in its own row with a plain control, and has no formula name and no menu row. An aggregator (SUM, AVERAGE and so on) is usually an argument, because the node has a job the aggregator only adjusts; on Aggregate, where it is the whole job, it is an operation.

## Why

We fold a family's variants into one node, and each folded choice is either a different function or a setting of the same one. An operation is something you search for and type by name, and a setting isn't, so a node that blurs the two either hides a function from search or gives a setting names nobody would type.

## Consequences

- How to classify a new picker, and the worked cases: [[node-classes#Formula registrations and op modules]].
- **Reopen if:** users search for aggregator names and don't find them.
