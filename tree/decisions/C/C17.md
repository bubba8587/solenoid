## Decision

**MUST:** a function you can use both as a node and in a formula is written once, and the node and the formula both run that same code, never a copy per surface.

Differing from Excel is a judgment call, recorded in the function's note in the Function Reference. The node and the formula disagreeing with each other is a defect and never ships.

## Why

[[B16]] oneFormulaSurface promises one answer on both surfaces. Two implementations of one function drift apart however carefully they are kept in step, and the two surfaces here drifted for as long as they were two. Running the same code is the only way the promise holds without anyone checking it.

## Consequences

- *Exception:* SHUFFLE's node and formula can't be tested for equal answers, because it is random and the two redraw at different moments on purpose. The node keeps its order until the next recalc, while a formula reshuffles every time it is evaluated. The shuffling itself is still written once, and the test checks for a real shuffle that varies. **Removed by:** nothing; that is what a random function means, and any future random function splits the same way.
- The node covers everything the formula reaches ([[D73]] nodeCoversFormula).
- The shared code doesn't depend on the graph engine ([[engineering#The formula path is rete-free]]), and the rules inside it are shared too ([[D51]] oneAnswerOneDivergence).
- Where the shared code lives: [[formula-language]], *Shared kernels*.
