## Decision

**MUST:** a function that is callable both as a node and as a formula has one implementation, in a rete-free module (`nodes/listOps.ts`, `textOps.ts`, `financeOps.ts`, `mathUtils.ts`, `dateSerial.ts`, `convertUnits.ts`, `nodes/matrixOps.ts`, `nodes/indexAccess.ts`, `cxValue.ts`), and both surfaces call it.

**MUST (capability parity, the author's standing order):** the node can do everything the formula can. Every argument, mode and result shape the formula reaches has a socket, op or control on the node.

- A node that dispatches through `resolveExcelFunction` passes the function's full argument list.
- A node with its own computation covers every mode the registration does, preferably by routing both surfaces through one shared kernel. The REGEX ops, for example, compose `regexApply`, `replaceNth` and `regexGroups` on both sides.

Diverging from Excel or Formula.js is a judgment call, recorded in the function's `nodeExcel` note. The node and the formula disagreeing with each other is a defect and never ships.

## Why

The two surfaces drifted apart for exactly as long as they were two implementations.

## Consequences

- *Exception:* `SHUFFLE`'s node and formula can't be tested for equal answers, because it is volatile and the two surfaces redraw on different clocks on purpose. The node keeps its sort keys until the next recalc, while a formula redraws on every evaluation. The permutation is still one implementation (`shuffleList` takes its keys as an argument), and the test checks for a real permutation that varies. **Removed by:** nothing; that is what volatile means, and any future volatile function splits the same way.
- A node may lack an argument when there's a recorded reason: the argument is a cell-grid concept, or the formula surface lacks it too.
- Shared modules stay rete-free ([[D19]] implReteFree), and the semantics inside them are shared too ([[D51]] oneAnswerOneDivergence).
