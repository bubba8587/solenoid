## Decision

Solenoid's own formula functions have plain names, with no `SOL.` prefix, and each is spelled exactly as the hint on the node's header shows it. A pack brings its own formula functions, and they are offered only while the pack is on.

## Why

[[B16]] oneFormulaSurface gives a function one name on both surfaces. A user reads a name off a node and types it, so the node's hint and the formula must agree on one spelling ([[C19]] namingModel), and a prefix is one more thing to learn with nothing gained.

## Consequences

- Retired Excel spellings are blocked, not kept as second names: [[C14]] currentExcelParity and [[formula-language#Blocked and wrong-surface names]].
- Every function has exactly one formula name, and no two share one ([[formula-language#Derived names are unique]]).
- A pack's functions keep resolving with the pack off, so a saved formula still computes; they are only hidden from autocomplete ([[C79]] packActivationIsPresentation).
- **Reopen if:** a future Excel release collides with a bare name. That is a case-by-case rename, not a namespace.
