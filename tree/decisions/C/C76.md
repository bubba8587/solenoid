## Decision

By default a pack node is a pre-set Expression: a formula plus its metadata (name, description, socket names and units, Excel mapping), compiled by the core and authored as pack data rather than new node code. A pack declares, per node, when it needs custom logic instead: a native compiled library, root-finding or iteration, interpolation over an embedded dataset, or a custom widget.

## Why

Formula nodes keep packs cheap and honest about units, because they run through the compiler the unit system already understands ([[B15]] leanCore). They also settle what happens when a pack is off: a pre-set formula is data the core can still evaluate, while a custom-logic node ships code that runs during calculation, makes isolation and third-party safety hard, and is usually desktop-only. That is why custom logic is the short list that gets scrutiny.

## Consequences

- A formula pack node saves as a core `ExpressionNode`, which is always registered, so a formula pack that is switched off reloads as a locked Expression and still computes. Its formula functions keep resolving with the pack off and are only left out of autocomplete (`formulaExtensions.test.ts`).
