## Decision

By default a pack node is a pre-set Expression: a formula plus its description (name, help text, input names and units, the matching Excel function), written as pack data rather than new program code. A pack says, node by node, when it needs custom logic instead: a native compiled library, solving or iterating, looking values up in a bundled dataset, or a custom control.

## Why

Formula nodes keep packs cheap and honest about units, because they run through the same formula engine the unit system already understands ([[B15]] leanCore). They also settle what happens when a pack is off: a pre-set formula is data the core can still work out, while a custom-logic node ships code that runs during calculation, is hard to keep safe when a third party writes it, and usually works only on desktop. That is why custom logic is the short list that gets scrutiny.

## Consequences

- A formula pack node saves as an ordinary Expression, so a document using a pack that is switched off reopens with a locked Expression that still computes. The pack's formula functions keep working with the pack off; they are only left out of autocomplete ([[C79]] packActivationIsPresentation).
