## Decision

In the Decision Matrix, each Breakdown column is a criterion's signed contribution (effective value × weight / Σ|weight|), so the columns sum to the Score. Ranking runs on the score rounded to 4 decimal places, so the display and the rank cannot disagree, and `round4` turns −0 into 0. Both decision nodes default normalization to ÷Max. On an exact tie, Sensitivity lists every rank-1 option in Winner ("A = B"), and Margin is 0 exactly when there is a tie. Sensitivity returns `#VALUE!` when no Scenarios column names a criterion.

## Why

Each default removes a plausible wrong reading ([[A6]] divergeByDesign). Bare normalized values read backwards under a negative weight: the priciest option showed Price 1.0 while taking the largest penalty. Raw values silently break down the moment criteria mix scales, which is the node's whole reason to exist. And with no matching Scenarios column every weight defaults to 1, so every scenario comes out identical, which is the trap a renamed criterion springs.

## Consequences

- **Reopen if:** a raw-values breakdown is wanted back (add it as a third detail mode rather than redefining this one), or a scenarios Frame legitimately needs to run with no matching columns.
