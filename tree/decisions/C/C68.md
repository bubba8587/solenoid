## Decision

Note and Report bodies use Knap (knap.md, the `knap` package) for references: the author types `{{ name }}`, and the old author-typed `` `=name` `` syntax is gone. A bare `{{ name }}` in a Report embeds the wired value according to its kind. Rendering rewrites each bare tag to the internal `` `=name` `` span, which the on-screen, Write to Obsidian and export paths resolve as before (`embedBareVariables`; node-coverage § Annotation). Anything beyond a bare tag reads the value's plain data form.

The Report's Template and Records (mail merge) inputs follow the same rule. A wired Note's raw `source` is the template text and its variables become the sockets, and a batch renders one page per row through the same engine.

## Why

The author wanted one syntax to type and one resolution path underneath. Notes and Reports are written to Obsidian ([[B1]] obsidianBet), so their body syntax should be a real template language rather than a mini-syntax only Solenoid understands.

## Consequences

- There is never a second template language for names or pages. The `{{date}}` tokens in Write to Obsidian's NAME field predate Knap and stay as a file-name mini-language.
- **Reopen if:** an author-typed reference grammar returns beside Knap (two syntaxes for one thing), or the bare-tag rule stops matching the on-canvas rendering. A bare `{{ frame }}` printing JSON instead of the grid is the relapse.
