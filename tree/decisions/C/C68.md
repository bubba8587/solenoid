## Decision

In a Note or a Report you refer to a value only by typing `{{ name }}`, in the Knap template language (knap.md); Solenoid has no reference syntax of its own. A plain `{{ name }}` in a Report shows the value as the canvas shows it (a table as a table, a chart as a chart), never as raw data. Anything more than a plain name (a filter, a loop, a path) works on the value's underlying data. A Report's mail merge uses the same syntax, never a second one.

## Why

The author wanted one syntax to type and one way it is read underneath. Notes and Reports are written to Obsidian ([[B1]] obsidianBet), so their text should use a real template language rather than a mini-syntax only Solenoid understands.

## Consequences

- There is never a second template language for names or pages. The `{{date}}` tokens in Write to Obsidian's file-name field are older than Knap and stay, as a small file-name language.
- How a reference is resolved on screen, in Obsidian and in exports: [[reports-and-notes]].
- **Reopen if:** a second reference syntax returns beside Knap (two syntaxes for one thing), or `{{ name }}` stops showing what the canvas shows. A `{{ frame }}` printing raw data instead of the table is the relapse.
