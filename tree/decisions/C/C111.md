## Decision

A node's color is its family's color (input, math, logic, text, date, complex, list, table, frame, chart, document and the rest), and a node placed in a family keeps that color. A node that no family lists falls back to math blue. But when such a node has exactly one output, and that output isn't a number or a slot that takes anything, the node wears its output's color instead. A node that makes a number stays math blue, since it is math in all but name.

## Why

[[B14]] oneDesignSystem uses a node's color to say what it makes. The math-blue fallback exists so every node has a color, not to say the node is math, and a text or date result on a blue node reads as a number when its output's color already says what it is. Families stay as they are because they were chosen, the author's call.

## Consequences

- Placing a node in a family is still the way to pick its color; this rule only reaches nodes nobody placed.
- A node whose one output takes any type keeps the math blue, since that output has no color of its own.
- How it's built: the palette-and-theme spec.
- **Reopen if:** the numeric fallbacks get a family of their own, or a node's color should follow its output as the output's type changes, as the nodes that change their own sockets (List Input, Table Input, Sets, the Format Controller) already do.
