## Decision

Tidy is an ELK layered layout, called directly, that only moves nodes. Ports sit symmetrically (the same offset for inputs and outputs) so two connected nodes line up. The result is anchored to the flow's leading edge and its cross-axis center, and no layout pass leaves a fixed inline size on a card. A global Tidy keeps each group as a rigid unit and never enters it; a group's own Tidy arranges exactly that group's members.

## Why

Each of the three failures this closes came from the opposite choice. rete-auto-arrange's `classic` preset put outputs at the top and inputs at the bottom, so every link staircased its target upward and the whole graph looked as if it floated high. Anchoring by the top-left corner dropped a flattened row to the top of the old footprint, the same "nodes float up" symptom from the other side. And its applier stamped an inline height on every card, which froze it: collapse could not shrink it, and a grown value clipped. Moving without resizing keeps cards content-driven, which [[C37]] observerOwnsSize already demands of everything else. Symmetric ports and leading-edge anchoring give the same answer in either direction, so Cleanup's cycle of Tidy then autofit is a fixed point: running it again changes nothing.

## Consequences

- The three knobs (direction, density and width cap), the rule that a flipped node counts as a predecessor, and the space reserved for a docked FC are mechanics in [[auto-arrange-tidy]], not decisions.
- **Reopen if:** ELK is replaced, or React Flow starts owning card sizes (then the guard that drops pinned sizes becomes the wrong tool).
