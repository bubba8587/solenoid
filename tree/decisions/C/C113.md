## Decision

Picking a different operation, mode or option on a node can change that node's inputs and outputs on the spot: change what type an input or output takes, or add and remove whole input rows, instead of each variant needing a node of its own. Cables plugged into an input that goes away are unplugged first, and whatever reads a changed output is updated to match ([[D10]] onePrunePath). This is separate from a socket that takes on the type of whatever is wired to it; that follows the wiring, not a pick on the node.

## Why

[[B11]] maximalMerge puts a family's variants on one node, so a picker that changes what the node computes has to be able to change its sockets. Without that, every variant would be a separate node. This is recorded because it has been wrongly reported as missing more than once.

## Consequences

- How it's built, and how to check whether a node already does it: the type-propagation spec (§ Control-driven socket swaps).
- **Reopen if:** never.

## Alternatives considered

### Contest 2026-09-16 by Claude Fable 5.1: keep wins

Judged by [[D16]] and [[D10]]. keep: a control-driven in-place swap with prune-first then reconcile is the one path both parents demand; cost = each swapping node calls the shared prune then retypeOutputCables. opposite (a control never swaps sockets): [[D16]] has nothing to reconcile and every variant becomes a sibling node, so the retype family loses its only in-place exemplar. deletion: [[D16]] and [[D10]] state the obligations but not that a mode toggle is a sanctioned trigger, which is the fact repeatedly reported absent. Acted under it: PendingCableLayer draws the Input Switch's dropped cables while the mode is wrong.
