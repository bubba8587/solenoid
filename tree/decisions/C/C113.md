## Decision

A node's `op`, `mode` or `arg` toggle can change an input socket, an output socket or both in place, and can add or remove whole input rows. The class exposes `setOp` / `setMode` (changing `this.inputs` / `this.outputs`) and `keysDroppedBySwitch`. The component prunes the departing sockets' cables first ([[D10]] onePrunePath), then calls it, then calls `retypeOutputCables` after an output swap, since the swap fires no connection event. This is separate from wildcard adoption (`trueAnyAdopt`), which the wiring drives and no field touches.

## Why

[[B11]] maximalMerge puts a family's variants on one card, so a selector that changes what the card computes has to be able to change its sockets. Without in-place swaps, every variant would be a separate node. This is recorded because it has been wrongly reported as missing more than once.

## Consequences

- Grep `setOp`, `setMode` and `keysDroppedBySwitch` before claiming a node can't retype on a mode.
- **Reopen if:** never.

## Alternatives considered

### Contest 2026-09-16 by Claude Fable 5.1: keep wins

Judged by [[D16]] and [[D10]]. keep: a control-driven in-place swap with prune-first then reconcile is the one path both parents demand; cost = each swapping node calls the shared prune then retypeOutputCables. opposite (a control never swaps sockets): [[D16]] has nothing to reconcile and every variant becomes a sibling node, so the retype family loses its only in-place exemplar. deletion: [[D16]] and [[D10]] state the obligations but not that a mode toggle is a sanctioned trigger, which is the fact repeatedly reported absent. Acted under it: PendingCableLayer draws the Input Switch's dropped cables while the mode is wrong.
