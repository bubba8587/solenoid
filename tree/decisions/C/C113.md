## Decision

Picking a different operation, mode or option on a node can change that node's own inputs and outputs on the spot: change the type an input or output takes, or add and remove input rows, instead of each variant needing a node of its own. This is separate from a socket that takes on the type of whatever is wired to it.

## Why

We put a family's variants on one node, so a picker that changes what the node computes has to be able to change its inputs and outputs. Otherwise every variant would need a node of its own.

## Consequences

- Cables plugged into an input that goes away are unplugged, and whatever reads a changed output is updated to match.
- How it's built: [[type-propagation-on-in-place-socket-retype#Control-driven socket swaps]].
- **Reopen if:** never.

## Alternatives considered

### Contest 2026-09-16 by Claude Fable 5.1: keep wins

Judged by D16 retypeReconciles (retired) and [[input-cable-pruning#The ordering rule]]. keep: a control-driven in-place swap with prune-first then reconcile is the one path both parents demand; cost = each swapping node calls the shared prune then retypeOutputCables. opposite (a control never swaps sockets): D16 retypeReconciles (retired) has nothing to reconcile and every variant becomes a sibling node, so the retype family loses its only in-place exemplar. deletion: D16 retypeReconciles (retired) and [[input-cable-pruning]] state the obligations but not that a mode toggle is a sanctioned trigger, which is the fact repeatedly reported absent. Acted under it: PendingCableLayer draws the Input Switch's dropped cables while the mode is wrong.
