## Decision

**MUST:** a text field's edit commits on Enter or clickaway, never per keystroke. The draft stays local while the user types, Escape reverts it, and one commit is one undo entry. `useDraftCommit` (`inlineInput.tsx`) is the mechanism, and nothing calls `processGraph()` from a text field's `onChange`. Discrete picks (dropdowns, checkboxes, sliders) apply immediately.

## Why

An Excel cell commits when you leave it, and that is the model users bring. Per-keystroke commits recompute the graph on every character, flood undo with partial values, and let a half-typed number flow downstream as a wrong value.

## Consequences

- The editable node title runs the same state machine (`useEditableLabel`): typing never writes `node.label`.
- A source sweep enforces it: a raw `<input>` (other than a checkbox, radio, range or color input) or `<textarea>` whose `onChange` calls `processGraph`, writes a field of the node (`data.x =`, `node.x =`) or calls `scheduleAutosave`, directly or through a local function up to two calls deep, fails, naming the file and line. The draft-commit fields (`InlineNumberField`, `QuotedTextInput`, `InlineCsvField` and the like) expose `onChange` as their commit callback, so a component that wires `processGraph` there is correct.
- A formula or script source is written once, when its field or popup closes. Its commit re-derives the card's input sockets, so a half-typed formula or parameter list would drop a variable mid-edit and prune the cables already wired to it.
- **Exception:** the formula popup's variable descriptions commit per keystroke. They are notes kept out of the formula string, display-only, and never trigger a recompute. It goes if a description ever feeds a computation.
- **Exception (the author's call):** the Slider's playback speed commits on each change. It drives only the play timer and never triggers a recompute. It goes if speed ever feeds a computation.
- An open draft is never lost to a document switch, a file save or the page closing: each flushes every open draft through `draftFlush.ts` before it captures. The idle autosave does not, since it would commit a field mid-typing.
- **Reopen if:** a live-preview field is wanted. It would then preview the draft, as the number scrub does, and still commit once.

## Contest

### Contest 2026-09-24 by Claude Opus 5.5: keep wins

Opposite (commit per keystroke) leaks half-typed values: the Image URL fetched per character and a first keystroke dropped the attached file; a Note body or Report template was read half-typed by any unrelated recompute and by the autosave. Deletion: B14 says nothing about commit timing, so the rule would go unenforced. No variant beats keep; the sweep now also flags onChange that writes the node or saves.
