## Decision

A typed edit takes effect when you press Enter or click away, never on each keystroke, and Escape throws the draft away. A pick made in one gesture, like a dropdown, applies at once.

## Why

That's the spreadsheet habit people bring, and committing every keystroke would send half-typed values downstream as wrong answers.

## Consequences

- *Exception:* the descriptions of a formula's variables save on each keystroke; they are notes and never cause a recalculation. **Removed by:** a description ever feeding a computation.
- *Exception (the author's call):* the Slider's playback speed applies on each change; it only drives the play timer. **Removed by:** speed ever feeding a computation.
- **Reopen if:** a live-preview field is wanted; it would preview the draft and still commit once.

## Contest

### Contest 2026-09-24 by Claude Opus 5.5: keep wins

Opposite (commit per keystroke) leaks half-typed values: the Image URL fetched per character and a first keystroke dropped the attached file; a Note body or Report template was read half-typed by any unrelated recompute and by the autosave. Deletion: B14 says nothing about commit timing, so the rule would go unenforced. No variant beats keep; the sweep now also flags onChange that writes the node or saves.
