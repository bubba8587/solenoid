## Decision

Parity is with the Excel people use today. Functions Excel itself has replaced (VLOOKUP, HLOOKUP, LOOKUP, MATCH, the old statistics names and their kind) have no node and no formula, rather than living on as second names beside their replacements. Typing one gets a short `#NAME?` naming the function to use instead.

## Why

We measure against current Excel, so what a user learns here should still be right in Excel. Keeping the old names doubles the surface and teaches the forms Excel itself moved away from.

## Consequences

- Which names are blocked, why each family is, and where each one points: [[formula-language#Blocked and wrong-surface names]].
- **Reopen if:** a real `.xlsx` import ships: auto-rewriting classic lookups then beats erroring.

## Contest

### Contest 2026-09-29 by Claude Opus 5.5: keep wins

Keep wins against B16 oneFormulaSurface: current-Excel parity on one surface is exactly what dropping superseded names delivers. Opposite (superseded names live on as second names) doubles the surface and teaches forms Excel replaced, against B16 directly. Deletion fails: B16 says what to measure against, not what a retired name answers, so the redirect rule needs a home. Separately, the ROW/COLUMN consequence was mis-filed: they are not superseded, they are cell-position functions, and inside a computed column ROW's job is done by the row builtin; that consequence is amended in place.
