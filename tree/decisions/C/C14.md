## Decision

Parity is with the Excel people use today. Functions Excel itself has superseded (VLOOKUP, HLOOKUP, LOOKUP, MATCH, the legacy CEILING sign rules and the pre-2010 statistics family) have no node and no formula, rather than living on as second names beside their replacements. Typing one gets a short `#NAME?` pointing at the replacement. INDEX stays, since it was never superseded.

## Why

[[B16]] oneFormulaSurface measures parity against current Excel, on every surface at once. Carrying superseded functions doubles the surface and teaches the forms Excel itself replaced, so what a user learns here would be out of date in Excel.

## Consequences

- A name is blocked only once its replacement already works, so a redirect never points at a name that fails.
- The D* database family (DSUM, DAVERAGE, DGET and the rest) is superseded by composition, a Frame Filter feeding an aggregate, the same way XLOOKUP supersedes VLOOKUP. It is blocked rather than left to the open-source function library the formula bar falls back on (Formula.js), whose versions are broken, and each name redirects to the aggregate it wraps; DGET, a unique-match lookup, redirects to XLOOKUP.
- CEILING.PRECISE, FLOOR.PRECISE and ISO.CEILING differ from the MATH forms only in ignoring the significance's sign, so they redirect to CEILING.MATH and FLOOR.MATH. SUBTOTAL and AGGREGATE pick their operation by a number code, and their hidden-row and ignore-errors options only mean something in a cell grid, so they redirect to SUM.
- COLUMN and ROW answer a cell reference's position, which the graph has no notion of, and the fallback library's versions do something unrelated. INDEX's whole-row and whole-column form replaces both, so both redirect to INDEX.
- AVERAGEA, MINA, MAXA, STDEVA, STDEVPA, VARA and VARPA differ from their plain forms only in reading the text and logicals a range's cells hold. The graph's lists are typed, so text never sits among numbers, and how an aggregate reads a logical is one question for every aggregate rather than a second name per function. So each redirects to its plain form: AVERAGE, MIN, MAX, STDEV.S, STDEV.P, VAR.S and VAR.P.
- SUMIF is covered by SUMIFS with one criteria pair, the node implements only the plural forms, and the fallback library's SUMIF concatenates a numeric-text sum range as text ("01030" for 4), a wrong answer rather than an error. So SUMIF redirects to SUMIFS.
- **Reopen if:** a real `.xlsx` import ships: auto-rewriting classic lookups then beats erroring.
