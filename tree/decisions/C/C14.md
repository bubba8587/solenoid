## Decision

VLOOKUP, HLOOKUP, LOOKUP, MATCH, the legacy CEILING sign rules and the pre-2010 stats family have no node and no formula; typing one gets a short `#NAME?` pointing at the replacement. INDEX stays, since it was never superseded.

## Why

[[A5]]'s on-ramp is the Excel users have today; carrying superseded functions doubles the surface and teaches the forms Excel itself replaced. VLOOKUP was once rebuilt because this ruling lived only in a parenthetical, which is why cross-surface rulings get their own record.

## Consequences

- A name is blocked only once its replacement already dispatches, so a redirect never points at a name that fails.
- The D* database family (DSUM, DAVERAGE, DGET and the rest) is superseded by composition, a Frame Filter feeding an aggregate, the same way XLOOKUP supersedes VLOOKUP. It is blocked rather than left as a broken Formula.js fallthrough, and each name redirects to the aggregate it wraps; DGET, a unique-match lookup, redirects to XLOOKUP.
- CEILING.PRECISE, FLOOR.PRECISE and ISO.CEILING differ from the MATH forms only in ignoring the significance's sign, so they redirect to CEILING.MATH and FLOOR.MATH. SUBTOTAL and AGGREGATE are function-code indirection whose hidden-row and ignore-errors options are cell-grid concepts, so they redirect to SUM.
- COLUMN and ROW answer a cell reference's position, which the graph has no notion of, and Formula.js's versions are unrelated array extractors. INDEX's whole-axis form is the accessor that replaces both, so both redirect to INDEX.
- SUMIF is covered by SUMIFS with one criteria pair, the node implements only the plural forms, and Formula.js's SUMIF concatenates a numeric-text sum range as text ("01030" for 4), a wrong answer rather than an error. So SUMIF redirects to SUMIFS.
- **Reopen if:** a real `.xlsx` import ships: auto-rewriting classic lookups then beats erroring.
