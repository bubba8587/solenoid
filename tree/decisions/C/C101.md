## Decision

A note's YAML frontmatter has one writer, `frontmatterPatch.ts`, and it patches the raw text line by line; it never parses and reserializes. Every byte the write did not target stays identical, and what it does write uses Obsidian's own block style. Write Properties and every other note write go through it.

## Why

The vault belongs to the user, not to Solenoid ([[B1]] obsidianBet). A writer that round-trips a note through a YAML library rewrites the spelling, order and quoting of every property on each save, and Obsidian users see that as churn in their own files and in git. A single patch path is also the only way to test "untouched bytes stay identical" as a property of the writer, instead of hoping each caller gets it right.

## Consequences

- `frontmatterPatch.test.ts` proves untouched bytes identical and a cube round-trip unchanged.
- Reading stays permissive: any spelling Obsidian or a person writes still parses (`noteFrontmatter.ts`).
- **Reopen if:** Obsidian's own Properties writer changes its block style, or a write needs to restructure a note beyond its frontmatter.
