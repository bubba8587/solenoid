## Decision

**MUST:** `node.width` and `node.height` mirror the node's measured size. NodeCard's ResizeObserver overwrites both with the rendered pixels on every layout, and the minimap silhouette and the cable geometry read them.
- Both persist for every node, but only the declared size-owner classes read `init.width` and `init.height` back on load. These are the surfaces the user sizes by dragging: the annotation frames, the composite card, groups and the overlay hosts. For every other class the saved values are inert, and the class default plus a fresh measure win.
- A class with a resize gesture must either read the init back or route its size through `nodeSizeStore`, as Display's grip does (its own persisted channel, `sn.size`).
- No other class may start reading the init.

## Why

A field with two jobs drifts silently, and this one can drift either way. A new resizable class that forgets to read the init back loses the user's drag on reload (the same kind of bug as `asofDirection`, [[save-format#Every field is persisted or deliberately transient]]). A compute class that starts reading it freezes an old measured size into its layout.
