## Decision

A palette either sets every neutral color of the app's chrome (the window, the canvas and its dots, the surfaces, borders and inks, in light and dark) or sets none of them and keeps the app's own; never a partial set. The other neutrals (panel and overlay fills, hover, shadows and the like) are mixed from that one set, never set one by one. A palette may recolor the workbench but not break its structure (listed under Consequences), and a tinted palette's neutrals follow the accent the user picked. The contrast requirement (WCAG AA, 4.5:1 for ink on a node and a field) binds two palettes only: Default and Colorblind-safe.

## Why

[[B14]] oneDesignSystem gives the chrome one set of rules. A partial set would leave the app wearing two looks at once, the palette's neutrals and the stylesheet's, and a palette that copied Default's would be two homes for one truth. Mixing the rest from one set means a palette author moves one set and the whole chrome follows, including on a palette nobody has checked by eye. Contrast binds Default because nobody chose it and Colorblind-safe because it exists to be legible; the other palettes are looks a user opts into, whose value is fidelity to that look.

## Consequences

- `appTheme` clears every chrome variable on each apply, because an inline property beats the stylesheet and a stale one would strand cream chrome under Default. The Custom palette's ramp is always complete, seeded from `DEFAULT_CHROME`, a hand-kept mirror of App.css.
- Structure holds for every ramp, the App.css baseline included (a rule that Default fails is a wrong rule): the canvas is darker than a card; the dot is legible on the canvas without shouting; the field is the brightest surface in light mode and a recess in dark mode; the hover fill steps toward the ink; the three border tiers step outward; the four ink tiers step down in contrast.
- Tinted ramps: Orchard and Blueprint declare a home accent (`CHROME_HOME`: green and blue). `appTheme` rotates the whole ramp in OKLCh by the hue difference to the selected accent, holding each key's chroma and its WCAG relative luminance, so at the home accent the authored ramp comes back byte-identical. Chroma may only drop in transit, never grow. This does not reopen the socket-sibling HSV rule (DESIGN.md §Tertiary), whose steps stay near their own hue. Each palette declares whether it adapts: Solarized, Colorblind-safe, Equinox, Muted and Custom do not rotate. An accent below the OKLCh chroma floor leaves the ramp as authored.
- A document's palette pin selects that palette's ramp too, because a pin exists so the document looks the same wherever it opens. A document's slot overrides never touch the ramp.
- **Reopen if:** chrome outgrows flat colors (a texture, a vignette, a per-document ramp), which would need its own model. If a palette other than these two ever becomes anyone's default, it joins `AA_PALETTES` (`palette.test.ts`) that day.
