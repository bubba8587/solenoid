## Decision

A standoff is a spacing the user declared, so no layout action may leave it broken: standoffs are settled after every other layout step (a drag, expand, collapse, autofit and Tidy), never before a step that could undo them. For the same reason, nodes tied together by standoffs move as one rigid block in every layout action. The solver is in [[standoffs]].

## Why

[[B14]] oneDesignSystem holds the layout to what the user set up, and a standoff is the one spacing the user declares outright. A constraint a layout step can silently break is not a constraint, so the standoffs settle last. Treating the cluster as one block is the same idea from the other side: a Tidy that pulled a pair apart and then let the standoffs snap it back would visibly fight itself.

## Consequences

- The band semantics, the anchors and the 45° lock are in [[standoffs]].
- The no-overlap pass ([[C112]] noOverlapsEver) runs after the solver and moves each cluster as one unit, so it never breaks a band.
- A live drag applies the bands only (never `forceLock`), so an unlocked slant survives a drag. Every layout operation forces the lock for its single solve without touching the saved flag.
- Seeds follow the author's rule: groups liberally, standoffs sparingly. A seed standoff only pins an unwired explanatory Note to what it explains, and a data node never has a standoff to its consumer.
- The known gaps of the first version (dormant endpoints inside collapsed groups, no undo entries) are listed in [[standoffs]].
- **Reopen if:** standoffs should become ELK constraints, or need to bind group members and conduits.

## Contest

### Contest 2026-09-24 by Claude Opus 5.5: keep wins

Opposite (bands as soft hints any pass may break) makes a declared constraint meaningless; deletion leaves nothing saying clusters move rigidly. Keep. The no-overlap pass that now follows the solver moves each cluster as one unit, so it never breaks a band and the rule holds.
