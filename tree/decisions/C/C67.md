## Decision

Solenoid respects a folder's mdbase schema when it has one, and goes no further. Vault Folder takes a column's type from the schema before anything else, and Write Properties refuses a row that breaks the schema's rules. A folder with no schema, or one Solenoid can't read, works as if it had none. Solenoid writes no schema files and runs no mdbase queries.

## Why

mdbase is an optional extra beside a folder of notes, and Obsidian and TaskNotes work fine without it. It's worth honoring when someone has written one, but not worth building on while it may still change before 1.0.

## Consequences

- One schema can serve both Solenoid and TaskNotes today.
- Which files and rules are read: `docs/node-coverage.md` § Vault Folder and Write Properties.
- **Reopen if:** mdbase reaches 1.0, or users arrive with schemas and ask for more.
