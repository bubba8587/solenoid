## Decision

A kind of value (number, text, true/false, date, complex) never turns into another kind on its own: that takes a Cast node, and the one exception is true/false to number and back (TRUE is 1, FALSE is 0). A value can always go where a bigger shape is expected: a single value into a list, a list into a matrix, a matrix into a Frame, a Frame into a Cube. It never goes the other way on its own: getting a smaller shape out of a bigger one takes a node that picks what to keep. Which connections the canvas allows follows from those two rules, never from a list of allowed pairs kept by hand.

## Why

[[B17]] typedValueModel makes a value's kind and shape part of its meaning, so the canvas refuses any connection that would change either silently. Going up a shape loses nothing, while going down would have to drop or pick values, so only going up is automatic. Working every connection out from two rules keeps them all consistent; a hand-kept list of pairs drifts.

## Consequences

- **Reopen if:** a new kind of value, or a second automatic crossing between kinds. Then every connection is worked out again from the rules; one pair is never edited by hand.
- How it's built: [[socket-lattice]].
