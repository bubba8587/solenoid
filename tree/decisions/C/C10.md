## Decision

A kind of value (number, text, true/false, date, complex) never turns into another kind on its own: that takes a Cast node. The one exception is true/false and numbers, where TRUE is 1 and FALSE is 0. A value can always go where a bigger shape is expected: a single value into a list, a list into a matrix, a matrix into a Frame, a Frame into a Cube. It never goes the other way on its own: getting a smaller shape out of a bigger one takes a node that picks what to keep.

## Why

A value's kind and shape are part of what it means ([[B17]] typedValueModel), so the canvas refuses a connection that would change either quietly. Going up a shape loses nothing, while going down has to drop or pick values, so only going up happens on its own.

## Consequences

- How it's built, with every allowed connection worked out from these two rules: [[socket-lattice]].
- **Reopen if:** a new kind of value, or a second automatic crossing between kinds.

## Contest

### Contest 2026-09-26 by claude: keep wins

keep: kinds never mix and shapes widen only upward is B17 applied to connections; both rules are cheap and derivable. opposite (automatic kind crossings, or narrowing) converts behind the user's back, which B17 forbids. deletion leaves every connection pair to be hand-listed, which B17's 'nothing converted silently' cannot decide pair by pair. Keep.
