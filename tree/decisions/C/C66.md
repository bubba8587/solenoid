## Decision

Script is the one node that runs code you write. You write a JavaScript function, such as `(a, b) => a * b`, and each of its parameters becomes an input on the node. Whatever goes in or comes out is an ordinary Solenoid value with an honest type.

**The result says its own type; you never declare one.** A number comes out as a number, text as text, true or false as a logical, and a JavaScript date (or a number marked as a date with `Solenoid.date`) as a date. The node's output changes to match. A list or table that mixes types (numbers beside text) is `#AMBIGUOUS!`, because no list in Solenoid mixes types. Anything else the node can't read as a Solenoid value is an error.

**Tables go both ways.** A script that returns a list of rows, each a set of named values, gives a Frame, typed column by column; rows with lists or tables inside them give a Cube. A Frame or Cube wired in arrives in the same shape, in full, so what one script returns another can read. LAMBDAs, charts and documents can't be passed to a script, and say so before it runs. Script ignores units: a number with a unit arrives as the plain number.

## Why

The author asked for a code node whose outputs are limited to the app's existing value types, replacing the blanket "no code node" line in `out-of-scope.md` §4 with this bounded form. [[A6]] sets the bound: whatever runs inside, only honestly typed values come out. And if it's going to be a script, the script's own values should say what type they are. Expression needs its Number / Text / Date / Auto switch because a formula doesn't say what it returns; a script's return value does.

Mixed lists are an error because the app has no mixed lists anywhere; the one naturally mixed case, a table row, is a Frame, where each column has its own type ([[D43]] unitByGranularity). Frames and Cubes are allowed in on the author's call. Expression keeps them out ([[C15]] matricesInFormulas) to hold an Excel-shaped surface to Excel's complexity; Script is the advanced surface, with no good reason for the same limit.

## Consequences

- A script runs apart from the app and is stopped after a short time limit, because a runaway loop would otherwise freeze the app, and freeze it again every time the autosaved document reopens. How it runs, and every shape and error: [[script-sandbox]].
- It's named Script, not Code, because CODE is an Excel function ([[D21]] noExcelNameClash).
- **Reopen if:** a script needs I/O, state between runs, or a second language. Each of those is the creep §4 guards against, not a feature request.
