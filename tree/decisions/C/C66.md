## Decision

Script is the one node that runs arbitrary code. Its source is a JavaScript function expression, `(a, b) => …`, and its parameters become inputs, worked out again on commit the way Expression's are (`applyScriptChange`). What crosses the boundary in either direction is an honestly typed Solenoid value.

**The result types itself; there is no declared result type.** `coerceScriptResult` reads the returned value:

- numbers, text and Booleans are their own families; a returned `Date`, or `Solenoid.date(serial)` (the one global a script can use), is a date;
- the result socket reconciles its family and rank to the computed value (`reconcileResultRank`: number, text and date sockets, with logical and complex on the wildcard);
- a list, table or Frame column that mixes families is `#AMBIGUOUS!`, because every container is single-typed;
- anything else that can't be resolved errors: `#TYPE!` for an unsupported value, `#DOMAIN!` for NaN, `#SHAPE!` beyond the accepted shapes (ragged rows pad with null).

**Frames and Cubes flow both ways.** An array of `{name: value}` rows, or one such object, builds a Frame, with columns in first-appearance order and typed per column; rows whose cells hold nested rows or lists build a Cube. Inputs mirror that exactly (`scriptArgToJs`): parameters are `trueany`, and a wired Frame (collected in full, never silently truncated to a preview) or Cube arrives as the same array of row objects, so what one script emits another can read. LAMBDAs, charts and documents have no script form and error before the run. Script is unit-blind: a Cube's unit cells unwrap to plain numbers.

## Why

The author asked for a code node whose outputs are limited to the app's existing value types, overriding the blanket "no code node" line in `out-of-scope.md` §4, which now states the bounded form. [[A6]] sets the bound: whatever runs inside, only honestly typed values come out. And if it's going to be a script, the script's own values should say what type they are. Expression needs its Number / Text / Date / Auto toggle because a formula's variables don't say what it returns; a script's return value does.

Mixed containers error because the app has no mixed lists anywhere; the one legitimately mixed case, a Frame row, is handled by Frames' per-column types ([[D43]] unitByGranularity). Frames and Cubes are allowed in on the author's call. Expression keeps them out ([[C15]] matricesInFormulas) to hold an Excel-shaped surface to Excel's complexity; Script is the advanced surface, with no principled reason for the same limit.

## Consequences

- Scripts run in the sandbox worker ([[script-sandbox]]) under `SCRIPT_TIMEOUT_MS`, and the Tauri content security policy carries `'unsafe-eval'` for it.
- It's named Script, not Code, because CODE is an Excel function ([[D21]] noExcelNameClash).
- **Reopen if:** a script needs I/O, state between runs, or a second language. Each of those is the creep §4 guards against, not a feature request.
