## Decision

When several agents work on this repo at once:
- Only one `tsc` or `vitest` run happens at a time, arbitrated by the file `.dev/test-lock` in the main checkout. Read it: if it says `free`, write your session name, run, then write `free` back; if it holds someone else's name, do other work and retry.
- Claims are one line each in `docs/agent-coordination.md`, deleted when the work lands. Agents message each other directly for live coordination.
- Agent 1 is the Lead. Peers commit on their worktree branches and send the Lead a commit hash once it is green; the Lead merges into `develop`, and nobody else pushes.

In a solo session all of this is dormant: claim nothing.

## Why

A second test run at the same time crashes the author's machine, and an agent that joins late or restarts has no memory of who holds what, so the protocol has to work without anyone remembering it ([[B9]] rulesWithoutMemory). Direct messages carry the live state; the board holds only what must survive a restart.

## Consequences

- **Reopen if:** the test lock stops being a machine constraint, or the branch model changes ([[C41]] branchModel).
