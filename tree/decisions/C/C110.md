## Decision

Range includes its Stop value, rather than stopping just before it as numpy's `arange` and Python's `range` do: Start 1, Stop 5, Step 1 gives 1, 2, 3, 4, 5. This holds for the Range op on the Series node and the RANGE formula alike. The last value lands exactly on Stop when the steps reach it, so 0 to 1 by 0.1 ends on 1.

## Why

[[B16]] oneFormulaSurface measures against Excel, but RANGE has no Excel counterpart, so no parity rule picks the convention. Including Stop reads more naturally ("1 to 5" means 1 through 5) and matches LinSpace, whose End is inclusive, so the two Series ops that take an endpoint treat it the same way. The author's call.

## Consequences

- numpy's `arange` and Python's `range` stop before Stop; the Range description says so, so a user porting code knows to adjust.
- **Would reopen it:** Excel shipping a RANGE-style function with an exclusive stop, since current-Excel parity ([[C14]] currentExcelParity) would then outrank the house convention.
