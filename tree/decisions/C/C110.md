## Decision

The Range op (list Series, and the RANGE formula through the same kernel) is inclusive of Stop: Start 1, Stop 5, Step 1 gives 1, 2, 3, 4, 5. The last value lands exactly on Stop when the steps reach it, so 0 to 1 by 0.1 ends on 1.

## Why

RANGE is not an Excel function, so no parity rule picks the convention. Including Stop reads more naturally ("1 to 5" means 1 through 5) and matches LinSpace, whose End is inclusive, so the two Series ops that take an endpoint treat it the same way (the author, 2026-09-23).

## Consequences

- numpy's `arange` and Python's `range` stop before Stop; the Range description says so, so a user porting code knows to adjust.
- **Would reopen it:** Excel shipping a RANGE-style function with an exclusive stop, since current-Excel parity ([[C14]] currentExcelParity) would then outrank the house convention.
