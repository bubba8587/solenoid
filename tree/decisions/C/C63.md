## Decision

Every record-shaped view (Card, Gallery, Board, List, and any future one) is an op on the one Record node, never a sibling node. Each view is an op in `NODE_OPS` with its own Add-menu row ("Record: Gallery"), picked on the card the way a chart type is.

Record-at-a-time entry is the Table popup's Form view on frame-source editors: the same record look made editable, placed by the same layout text, and authored on the Frame Input card (never in the popup). Entry widgets follow the column type: a logical column gets a checkbox with an indeterminate state for blank, and a date column gets the native date input, which writes ISO text.

## Why

The author's call ([[B11]] maximalMerge): a view is a way of presenting one figure, so it belongs on the one card. Each view is still an op, like a chart type, because people search for a drawing by name, and typing "gallery" has to land on a row that says Gallery.

## Consequences

- The views have no formula names; a figure node registers none.
- The card itself never draws the figure, which would be squashed at card width. The hero chip stands in for it, and the drawn figure appears wherever the chart output goes (Display, popup, Report embed). Record boxes touch and are square.
- **Reopen if:** a record view needs behavior an op cannot express, or the formula surface ever needs a record-view name.
