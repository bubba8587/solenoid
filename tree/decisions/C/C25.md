## Decision

A unit is part of a value: 5 m and 5 km are different values, so relabeling a unit is overwriting the number. A Format Controller after a value with a unit shows that unit and can't change it; only Convert, or a calculation whose result is a different kind of quantity, changes a unit. Joining tables on values with units compares the actual quantities, so 5 km matches 5000 m, and a currency is identified by its code, so $5 never matches 5€.

## Why

[[B17]] typedValueModel makes a unit belong to its number, and [[A6]] divergeByDesign names first-class units as a headline divergence from Excel. A unit that a dropdown could relabel would make every number with a unit untrustworthy.

## Consequences

- A unit the user types in (say, "widgets") is its own kind of quantity, never a plain number: treated as a plain number, widgets per second would read as Hz. Two typed names that differ only in case are the same unit.
- A Convert further along fills in a Format Controller's unit only when the Format Controller has none. A unit the user set stands, and a real clash surfaces as the Convert's error rather than a silent rewrite.
- **Reopen if:** nothing. This is value-model integrity, in the same class as [[C24]] arraySemantics.
