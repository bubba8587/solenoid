## Decision

Desktop runs table operations on Polars. The web runs Solenoid's own Rust core compiled to WebAssembly, and that core also runs pivots and computed-column formulas on both platforms. The TypeScript implementation is the reference answer every engine matches, and it answers whatever the core can't. DuckDB is not used.

## Why

A big table shouldn't be slow because it's open in a browser, and one reference answer keeps a cell the same whichever engine computed it.

## Consequences

- How it's built: [[frame-verbs]] and [[rust-core]].
- Settings → Rust engine turns the core off on the web, leaving the TypeScript; it is on by default.
- **Reopen if:** Polars ships a production WebAssembly build, which could take the core's place on the web.

## Contest

### Contest 2026-09-24 by Claude Opus 5.5: keep wins

Judged by B2. Keep: web stays instant and filesystem-free on the oracle, desktop gets native speed; the cost is parity upkeep, which D29's corpus and fuzzer make mechanical (8 divergences found and closed 2026-09-24). Opposite (DuckDB on both, wasm on web) adds a multi-megabyte web download against B2's look-and-try web and SQL semantics that differ from the Excel-parity oracle. Deletion (the JS oracle everywhere) forfeits the desktop full product's scale. Variant (Polars-WASM) has no production path yet, which is already this node's reopen trigger.
