## Decision

Everything that computes runs on Solenoid's own Rust core: formulas, functions and Frame verbs, and the graph itself (which nodes and cables exist, the calculation pass that runs them, and what reruns when something changes), built on Ruggine, Solenoid's Rust port of rete, kept as its own library. Only the UI stays TypeScript: React components, the canvas and gestures. The core is compiled to WebAssembly and runs in the browser and the desktop app alike. There is no second engine: the desktop runs the same build the web does, and the core is the reference answer. Neither Polars nor DuckDB is used. The desktop shell adds only what a browser can't do, such as reading a Parquet file.

## Why

A big Frame shouldn't be slow because it's open in a browser, and one implementation of everything that computes keeps an answer the same wherever it is computed, with nothing to keep in step. rete was an outside library, so it was ported as one rather than inside Solenoid.

## Consequences

- How it's built: [[frame-verbs]] and [[rust-core]].
- A Frame chain of a million rows runs in well under a second in wasm (the figures in [[rust-core]] § Where it runs).
- **Reopen if:** a Frame people open is too slow in wasm; the first step is linking the same core natively in the desktop shell behind the same commands, not a second engine.

## Contest

Carried from C16, which this node supersedes.

### Contest 2026-09-24 by Claude Opus 5.5: keep wins

Judged by B2. Keep: web stays instant and filesystem-free on the oracle, desktop gets native speed; the cost is parity upkeep, which D29's corpus and fuzzer make mechanical (8 divergences found and closed 2026-09-24). Opposite (DuckDB on both, wasm on web) adds a multi-megabyte web download against B2's look-and-try web and SQL semantics that differ from the Excel-parity oracle. Deletion (the JS oracle everywhere) forfeits the desktop full product's scale. Variant (Polars-WASM) has no production path yet, which is already this node's reopen trigger.

Carried from D102, which this node supersedes.

### Contest 2026-10-24 by Claude Opus 5.5: keep wins

keep: C130 rustCore puts computation on one Rust core, and the graph's pass, its walks and the card bodies it calls are computation, so the graph moving there follows from the parent. opposite (the graph stays in TypeScript) leaves a second implementation of what computes, which C130 rules out, and keeps a JS hop between every card on the core. deletion: C130 alone says formulas compute on the core but not that the graph does, or that rete is ported as its own library; D102 carries that. No variant beat keep.
