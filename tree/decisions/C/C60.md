## Decision

Running is one node: an aggregate computed for each element over a window ending at that element. The Window input is always present. A Window of 0, the default, is cumulative, running from the start through the element; a Window of N (1 or more) slides over the last N elements and runs short at the start. A wired blank Window leaves the result unknown, and a negative or non-finite one is `#DOMAIN!`. One aggregator set, picked as the `agg` argument, serves both behaviors. On the formula surface it is one function, `RUNNING(op, list, [window])`, with the aggregator as a string argument ([[C26]] opArgDistinct), and an omitted window means cumulative.

## Why

The author's call: Cumulative and Rolling were too alike to stay separate ([[B11]] maximalMerge). A mode toggle on the card was dropped too, so the card matches the formula, where the window is simply optional. Only an explicit 0 means cumulative, never a blank, because a wired blank means unknown (`docs/value-semantics.md`).

## Consequences

- There is no per-op `RUNNING*` family.
- **Reopen if:** the cumulative and sliding edge policies need to diverge further than the per-window reducer policy can express.
