## Decision

Running is one node, never separate Cumulative and Rolling nodes, and it has no switch between the two: its Window input decides. A Window of 0, the default, runs from the start of the list; a Window of N covers the last N items. Only an explicit 0 means "from the start"; a blank wired into Window leaves the answer unknown. In a formula it is one function, `RUNNING(op, list, [window])`, with the kind of total (SUM, AVERAGE and so on) typed as text ([[C26]] opArgDistinct), never a separate function per kind.

## Why

[[B11]] maximalMerge: a running total from the start and one over a window are one job with one setting, so they are one node. A switch between the two would be a second way of saying what the Window already says, and the formula has no such switch, where the window is simply optional. Only an explicit 0 means "from the start", never a blank, because a wired blank means unknown ([[value-semantics]]).

## Consequences

- The exact window rules (short windows at the start, a negative window, blanks): [[formula-language]], `running`.
- **Reopen if:** the running-total and last-N kinds need to treat the start of the list differently in ways one rule can't cover.
