## Decision

The scheduling engine and the Gantt figure live in three npm workspaces, `packages/schedule-engine`, `packages/gantt-layout` and `packages/gantt-react`, each with its own `package.json` and LICENSE. The app consumes them through `tsconfig.json` paths, the Vite alias and the vitest alias, so no install step changes and `npm ci` and the desktop build are untouched. No GPL, EPL or commercial code enters them, and each package's README records what was studied while building it.

## Why

Scheduling serves the task data that [[B1]] obsidianBet brings in from TaskNotes, and no permissively licensed project has a real engine to adopt (`docs/v2.0/25-gantt.md` § 0), so the engine is built here. Keeping it in separate packages holds its license boundary and leaves a future publish open without changing how the app builds.

## Consequences

- **Reopen if:** a second consumer appears (then publish them), or the source-scan tests and the shared fixture directory stop reaching them.
