## Decision

**A logical is the number 0 or 1.** FALSE *is* 0 and TRUE *is* 1. Everything Solenoid computes with a logical follows from that; how one is shown and how one is typed are separate from what it is.

**Shown many ways, one value.** A logical can be drawn as TRUE/FALSE, 1/0, Yes/No or a check mark (the Format Controller's and Value Input's logical style). The style changes only the drawing; the value underneath is still 0 or 1.

**Typed or wired in many ways, coerced to 0 or 1.** Where a logical is asked for (a logical socket, a logical column, a Boolean Value Input, Cast to Boolean), what arrives becomes 0 or 1:

- a logical stays itself;
- a number: 0 becomes FALSE (0), any other number TRUE (1), and NaN becomes blank (an unknown truth value);
- text becomes a logical only where a typed input or Cast asks for it, never inside a formula ([[C10]]).

**Computation is downstream of 0 and 1.** Because a logical is a number, it computes as one wherever numbers are computed with:

- arithmetic: `TRUE + 1` is 2, `TRUE * 5` is 5;
- every aggregate counts it, typed straight in or inside a list: `SUM(x > 5)` is the number of matches;
- comparisons between a logical and a number compare 0 or 1 with that number: `TRUE = 1` is TRUE and `TRUE > 0` is TRUE.

What keeps it a logical rather than a plain number is its type: a logical socket, column or Value Input still says "logical", the logic functions (AND, OR, NOT, IF) read it as true or false, and it is drawn in a logical style. The type governs the drawing and which cards accept it; the value is 0 or 1.

## Why

One definition settles every question a logical raises, instead of a rule per function: whether an aggregate counts it, what `TRUE + 1` is, what a Yes/No column sums to. Spreadsheets and data tools already treat true and false as 1 and 0 in arithmetic (Excel's `TRUE + 1`, pandas' and R's `sum(mask)`), so counting the matches with `SUM(x > 5)` is what people expect. Keeping the style separate from the value lets a column read Yes/No without changing a single answer computed from it.

## Consequences

- C10's crossing "between true/false and numbers" is this leaf: it is not a conversion between two kinds but one value with two faces.
- Where this parts from Excel: Excel agrees in arithmetic (`TRUE + 1` is 2) and for a logical typed straight into a function. It differs in two places, on purpose: inside a range Excel skips logicals, where Solenoid counts them, and Excel compares a logical with a number by type, ranking every logical above every number (its `TRUE = 1` is FALSE and `TRUE > 1000` is TRUE), where Solenoid compares 0 or 1.
- How it's built: the bridge in [[value-semantics]] § Boundaries and bridges, and `to_num` (`excel_functions.rs`), which reads a logical as 1 or 0.
- **Reopen if:** a logical ever needs a third state that is not blank, or a value that is not 0 or 1.
