## Decision

Every data comparison and data sort orders strings with JavaScript's `<` and `>` on the raw string (UTF-16 code units), never by locale. The order is case- and accent-sensitive. It differs from UTF-8 byte order only for astral-plane characters (such as emoji), a gap deliberately left alone. Lists in the UI keep their locale or natural sort.

## Why

A locale sort depends on the host's ICU data, so the same document would sort differently from machine to machine. [[B2]] webTryDesktopFull also needs its two engines to sort identically, and Polars compares strings by byte order, which code-unit order matches.

## Consequences

- **Reopen if:** users ask for locale-aware data sorts. That needs a locale pinned per document, recorded as a new decision.
