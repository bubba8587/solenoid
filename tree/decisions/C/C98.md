## Decision

The Command Palette is the menubar in searchable form. Every menubar action is a command, so the two cannot drift apart, and the palette adds the canvas and selection operations that have no menu home. Node types stay out: the Add menu is the one place to browse the catalog. A setting that Settings greys out on this device cannot be reached from the palette either.

## Why

[[B14]] oneDesignSystem gives each thing one home. Two lists of the same actions drift, so the palette is derived from the menu, and each new menu item is a palette command automatically. Keeping nodes out keeps one catalog surface ([[D22]] oneNamePerCard), and a palette that could flip a setting disabled on this device would be a back door around that gate.

## Consequences

- Labels name the end effect, not the axis: "Center vertically" stacks nodes in a column.
- Graph shortcuts route through the canvas keydown handler and are never duplicated in the palette.
- **Reopen if:** the Add menu and the palette merge into one launcher.
