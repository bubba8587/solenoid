## Decision

A blank and an error are values in their own right, in a single value and in every cell of a list or table, and an error in one cell leaves the other cells alone. A blank is missing: a total over a range skips it, cell-by-cell work passes it on, a true/false test on it answers unknown (TRUE OR blank is TRUE, FALSE OR blank is blank), and nothing turns it into zero. An error passes on unchanged through every node it reaches, which doesn't compute on it; a node that can't produce an answer, a number out of range included, answers a named error (#DOMAIN!, #OVERFLOW!), never a bare not-a-number. A result that is undefined while nothing is wrong, such as too few points for a statistic, is a quiet blank, and only a wrong input is an error.

## Why

A missing value, an error and a zero are three different facts, and a calculator that mixes them up answers with believable wrong numbers. A total over a column with gaps should still total, but one unknown cell added in gives an unknown answer, not a guess. An error carries its cause, and only the node that hit the problem knows it. Not enough data yet is the normal state of a growing Frame, so it mustn't hide the one cell that's actually wrong.

## Consequences

- *Exception:* nodes that exist to look at errors receive them: the ones that catch or test errors, carry separate lanes, show or draw whatever arrives, and composites, which hand the error to the nodes inside. **Removed by:** nothing; a node that catches errors has to see them.
- *Exception:* Fill exists to turn a blank into something on purpose. **Removed by:** nothing; that is the node's whole job.
- An infinity that came in as one passes on; only a node that produces one turns it into a named error.
- In GROUPBY, PIVOTBY and Cube Rollup, the min and max of a text column give its first and last text in sort order, where Excel gives a blank, since a blank should mean a missing value ([[frame-verbs#groupBy]]).
- Range totals skipping blanks follows Excel's range functions; the split follows the kind of work, never the surface (formula or node).
- How it's built: [[value-semantics#Propagation, by context]], [[error-values]] (the per-cell contract and the non-finite guard), [[compute-pass#The error guard]], [[formula-language#Range functions]], with each difference from Excel in [[formulajs-divergences]].
- **Reopen if:** Solenoid has to treat a blank as zero the way Excel does; Excel's range functions stop skipping blanks; someone needs Excel's exact error on short data (an IFERROR guard that must fire); or a blank min or max of text is wanted back for Excel parity.
