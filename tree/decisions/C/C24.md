## Decision

Lists and Frames can hold a real blank, meaning a missing value that totals and averages skip, and an error in a single cell, which spreads to whatever uses that cell. True/false is its own kind of value with three-valued logic: a blank in a test answers "unknown" rather than false.

## Why

[[B17]] typedValueModel makes a blank and an error values in their own right. A missing value, an error and a zero are three different facts, and a calculator that confuses them answers with believable wrong numbers. Every value rule under this leaf refines that model.

## Consequences

- A filter value that cannot be read for the column's type (a blank, or text that is not a number for a number column) matches no rows, on desktop and on the web alike. The answer is always the same and looks misconfigured, rather than silently keeping or dropping everything.
