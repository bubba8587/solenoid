## Decision

Lists and Frames carry a first-class `null`, meaning a missing value that aggregators skip, and per-cell errors (`SolError`) that propagate. Logical is its own family, with Kleene three-valued logic, so a null operand answers "unknown" rather than false.

## Why

[[A6]]: a missing value, an error and a zero are three different facts, and a calculator that confuses them answers with believable wrong numbers. Every value rule under this leaf refines that model.

## Consequences

- A filter value that cannot be read for the column's type (a blank, or text that is not a number for a number column) matches no rows, on both engines. The answer is deterministic and looks misconfigured, rather than silently keeping or dropping everything.
