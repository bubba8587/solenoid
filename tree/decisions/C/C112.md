## Decision

Every layout operation (expand, collapse, Tidy, autofit, grouping) ends with one no-overlap pass, separateAll in groupPushCore.ts, over every top-level box: loose cards and groups. The pass is never gated or exempted: an overlap that existed before the op is separated like any other. Only a position-locked group holds still unconditionally; what the op just placed holds still when its partner can yield, and a standoff cluster moves as one unit.

## Why

Overlapping cards read as broken, and no overlap is intentional. Two escape hatches each silently broke the guarantee: a baseline that exempted overlaps present before the op, and a gate that skipped the pass whenever a standoff existed.

## Consequences

- Separation only moves right or down, so the pass always terminates.
- Two locked groups that overlap are left alone, since neither may move ([[D63]] lockedGroupIsObstacle).
- A standoff cluster moves rigidly, so the pass never breaks a band ([[C89]] standoffsSolveLast).
- Manual gestures are not layout ops: a drag, Align and paste place cards where the user put them.
- The groupPush setting ("Auto-arrange groups on expand") still turns off the expand push and its pass; whether the pass should run anyway is open with the author.
- **Reopen if:** the author wants a class of overlap kept, such as a Note deliberately laid over a card.

## Contest

### Contest 2026-09-24 by Claude Opus 5.5: keep wins

Opposite (overlaps allowed, or best-effort) is what B14 oneDesignSystem rules out: an overlap reads as a broken canvas. Deletion leaves no node owning the final pass, which is how two exemptions crept back in. Variant (exempt overlaps the user made before the op) was tried and broke the guarantee twice. Keep.
