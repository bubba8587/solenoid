## Decision

Every layout action (expanding or collapsing a group, Tidy, autofit, grouping) finishes by pulling apart anything that overlaps, across every node and group on the canvas. Nothing is exempt: an overlap that was there before the action is pulled apart like any other. Only a group whose position is locked never moves. What the action just placed stays put when the other box can move instead, and nodes tied together by standoffs move as one.

## Why

[[B14]] oneDesignSystem holds the canvas to legibility, and overlapping nodes read as broken; no overlap is intentional. The guarantee holds only if nothing is exempt: exempting overlaps that were already there, or skipping the step when standoffs exist, would each leave overlaps the user never made and nothing fixes.

## Consequences

- Things only move right or down to make room, so the step always finishes.
- Two locked groups that overlap are left alone, since neither may move ([[D63]] lockedGroupIsObstacle).
- Nodes tied by standoffs move together, so the step never breaks a standoff ([[C89]] standoffsSolveLast).
- The user's own moves are not layout actions: a drag, Align and paste put nodes where the user put them.
- A node growing is not a layout action either: one that grows with its live content, or whose body is expanded, can cover a neighbor until the next layout action. Whether growth should push is open with the author (inbox card-growth-pushes).
- The "Auto-arrange groups on expand" setting still turns off the push on expand, and this step with it; whether the step should run anyway is open with the author.
- How it's built: the group-expand-push spec.
- **Reopen if:** the author wants a kind of overlap kept, such as a Note deliberately laid over a node.

## Contest

### Contest 2026-09-24 by Claude Opus 5.5: keep wins

Opposite (overlaps allowed, or best-effort) is what B14 oneDesignSystem rules out: an overlap reads as a broken canvas. Deletion leaves no node owning the final pass, which is how two exemptions crept back in. Variant (exempt overlaps the user made before the op) was tried and broke the guarantee twice. Keep.
