## Decision

A new subsystem, a new naming law, a new declaration format, or a sweep that touches many files writes its rule down before the code lands: the spec for how it works, and a leaf only for a choice a person could make about it. Ordinary work (a new node, a bug fix, a one-line change) follows the existing rules and needs neither.

## Why

When a mechanism is built before its rule is written, the next agent has to infer the rule from the code, and inferred rules drift into folklore ([[B9]] rulesWithoutMemory). This is the agents' working default rather than an author ruling, so it may be tightened freely.
