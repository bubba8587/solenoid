## Decision

A formula never turns text into a date, number or logical on its own, even when the text looks like one. Text becomes another type only in a typed input, where the type shows on screen (a column's type, a socket's color, a Date field), or when the formula asks for it with a converter: DATEVALUE, TIMEVALUE, NUMBERVALUE or VALUE. Both read text the same way.

## Why

A guess you can't see is a wrong answer you can't see. A formula that quietly turned "3/1/2024" into a date would hold a type nobody chose. This is a deliberate break from Excel, which reads `="5"+1` as 6: there the guess is invisible, and here a type always shows where it was set.

## Consequences

- Arithmetic on text is `#VALUE!`, and `5 = "5"` is FALSE ([[formula-language]]).
- A function reading a range or list takes text as text: it doesn't read `"5"` as 5, and an aggregate that skips non-numbers skips it rather than reading it.
- *Exception:* IMSUM, IMABS and the rest of the complex-number functions read text such as "3+4i", since text is how Excel writes a complex number. **Removed by:** a typed complex input that people use in its place.
- *Unenforced:* a criterion string (COUNTIFS, SUMIFS and kin) still reads a date out of its text as Excel's criteria do. Excel's criterion syntax is its own small language, and a confusing one; replacing it is in the backlog (`docs/backlog.md` § Leaves the code breaks), and until then it keeps working as it does.
- **Reopen if:** a typed input can't express a value people need to type into a formula.
