## Decision

The app ships a small read-only demo vault of real notes, tasks and CSV tables, so the Obsidian nodes and Local File have something real to read before the user sets their own folder, on the web too, instead of showing a mockup or nothing. Nothing is ever written to it.

## Why

[[B1]] obsidianBet needs the vault integration to be something a newcomer can try before pointing it at a vault of their own, and [[B2]] webTryDesktopFull needs that to work on the web, where there is no vault to point at. Real notes, rather than a mockup or an empty node, show the vault nodes doing their real job. Read-only keeps the demo the same for everyone.

## Consequences

- Which vault a node reads (the one a marketing page forces, a configured one, or the demo) is [[D62]] demoVaultResolution. Local File's data folder follows the same order.
- Parquet files still need the desktop app and a real folder; the demo holds CSV only.
- How it's built: the live-connections spec, *The demo vault*.
