## Decision

A chart is a value, like a number: it travels along a cable, saves with the document and shows anywhere a value can, and it keeps its controls wherever it's drawn: a Display showing it gets every control that belongs to the figure, such as paging through records or rotating a 3-D surface.

## Why

A chart that lives only on the node that drew it can't go into a Report or a Display; as a value it goes wherever a number goes. If its controls stayed behind on that node, the same figure would work in one place and be dead in another.

## Consequences

- Controls on a node's card that work with no chart drawn stay on the card.
- How it's built: [[chart-figures]] and [[chart-figures#Display]].
- **Reopen if:** charts need to write edits back into their data, or a figure's controls start changing more than the figure itself, so that driving them from a Display surprises people.

## Contest

### Contest 2026-09-26 by claude: keep wins

keep: a chart that is a value can be shown, embedded and formatted anywhere (B17 counts it as a value). opposite (chart as the node's private drawing) breaks Reports and Displays downstream. deletion leaves B17's 'a chart is a value' unimplemented. Keep.
