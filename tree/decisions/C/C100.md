## Decision

A chart is a value, not a picture that belongs to the node that made it. A chart node's output is a complete description of the figure (what kind of chart, its data and its options), so it travels along a cable like a number does, saves with the document, and can be drawn anywhere a value can be shown: a Display, a Report, a popup.

## Why

[[B17]] typedValueModel counts a chart as a value like any other. If the chart were only the node's own drawing, nothing downstream could show, embed or format it, and a Report couldn't carry a chart the way it carries a number. A chart that flows is what lets a Format Controller style a chart ([[C94]] formatFamilyGates), a Report embed one, and one node draw a chart from another's output (Gantt from Schedule) with no special wiring.

## Consequences

- The chart describes its data, not its pixels, so the same figure can be drawn at any size: a small chip, a Display, a popup, a Report.
- How each kind of figure is drawn is in the chart-figures spec.
- The chart's options travel with it as text ([[C96]] chartOptionsAreMatplotlib).
- **Reopen if:** figures need to write edits back into their data. They would then need an identity, not just a value ([[C71]] noBarEditing).
