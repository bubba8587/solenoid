## Decision

The chrome envelopes are two measured CSS variables: `--chrome-top`, published by `Header.tsx`, and `--chrome-bottom`, published by `chromeBottom.ts` as the height of the tallest visible bottom bar, safe-area inset included. Every floating overlay derives its anchor from them with `calc(var(--chrome-*) + gap)`, and no overlay hard-codes a bar height.

## Why

The recurring bug was a floating overlay covering a bar. The offsets were magic numbers scattered across many CSS files, all tracing back to the same few bar heights, so moving one bar meant finding every dependent by hand. Measuring the envelope once means a bar that appears, hides or grows carries every overlay with it.

## Consequences

- Still hard-coded, by choice: the bars' own row heights, the gutters, each overlay's gap and mobile's top overrides. [[layout-chrome]] maps what each number means.
- Citations in that map are file plus selector, never line numbers.
- **Reopen if:** the header and footer become part of the layout rather than floating, so the canvas is simply the remaining flex box.
