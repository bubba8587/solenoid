## Decision

Table Input saves exactly the text you typed, blank lines included, and works the table out from it each time; in Obsidian the plugin's Save writes each cell as typed too, so picking a column type changes how cells show, never what the note holds. Wherever text becomes a value of a declared type, it is read one way, as a Frame Input cell reads it: a number in the US form only, `.` the decimal point and `,` grouping thousands, with a European form such as `1.234,5` refused rather than reread as a different number. Text the type can't read is NaN, never a silent blank.

## Why

What you typed is the truth. If the saved text were rebuilt from the table, anything the reading step dropped would quietly vanish from the document too, and picking a type would cost data. One reader means one rule to learn and the same text is the same number on every machine; a refusal is visible where a misreading or a blank is not.

## Consequences

- A cell keeps the NaN; a computation that needs the type turns it into `#TYPE!` naming the value ([[frame-verbs#Type inference]]).
- *Exception:* in Obsidian a Complex property has no editor of its own, so it refuses text it can't read and writes nothing. **Removed by:** a Complex control in the app, which the plugin would then bundle.
- How it's built: [[literal-input-editors]], [[save-format]], [[obsidian-plugin#Requirements]], and number parsing in [[formulajs-divergences]] (*Text and number parsing*) and [[value-semantics]].
- **Reopen if:** a note can store an error value for a cell; Frame Input's cell reading changes (every reader follows it); or users outside the US need their own number form, as a per-document setting.

## Contest

### Contest 2026-09-26 by claude: keep wins

keep: saving the typed text and deriving the table each time is the only way no edit loses input (B12). opposite (save the derived table) drops whatever reading rejects. deletion leaves each literal editor to decide. Keep.
