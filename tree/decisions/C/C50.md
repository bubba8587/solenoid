## Decision

When a LAMBDA is wired into MAP, BYROW, BYCOL, REDUCE, SCAN or MAKEARRAY, its parameters are matched to that function's values by name, in any order, not by position as in Excel. A parameter name the function doesn't offer is `#VALUE!`. A name in the LAMBDA's body that matches one of the node's variables, but isn't a parameter, is flagged on the node as a likely missing input. Any other value the LAMBDA uses stays an input you can see and wire.

## Why

[[B17]] typedValueModel: nothing changes meaning behind the user's back. On a canvas the order of the wiring is invisible, so matching by position would silently swap arguments; matching by name turns a mismatch into a loud `#VALUE!`. This is a deliberate break from Excel ([[A6]] divergeByDesign), and the function's note says so.

## Consequences

- *Rejected:* filling reserved names in automatically, ignoring what is wired. It leaves inputs that do nothing and silently ignores cables.
