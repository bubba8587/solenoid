## Decision

**MUST:** in a computed column's formula, a bare name or `[Name]` is the whole column, a one-column table as an Excel table column is, and `@name`, `@[Name]` or `[@Name]` is this row's cell, the same as Excel's table references. A whole column where one value is needed is a `#SHAPE!` on that row pointing at `@`, never a silent read of this row's cell.

## Why

[[B16]] oneFormulaSurface measures against current Excel, and this is how Excel's table references read. Any other rule fails with a believable number instead of an error: if bare names read this row's cell, `revenue / SUM(revenue)` gives 1.0 on every row, because `SUM(revenue)` sums a single cell, and nothing looks wrong. Formulas that mix both readings, like `SUMIFS(amt, cat, @cat)`, can't be written at all if one spelling has to mean both.

## Consequences

- `ROW()` is this row's number and `ROWS(price)` the row count, as in an Excel table. A function call can't collide with a column's name, so a column may be called `row` or `rows` like any other.
- When names collide, a column wins, then a LAMBDA's captured values, then an input wired into the node.
- A LAMBDA's parameters are bound to the row. Any other name in its body, bare or `@`, becomes a captured input.
- Because a parameter is this row's value whether written `x` or `@x`, a LAMBDA whose body writes one parameter both ways is flagged on its card, pointing at `[x]` for the whole column or at leaving `x` off the parameter list. A bare `x` in such a body is almost always meant as the column, and the answer it gives is believable, so it must not pass silently.
- Brackets spell names that have spaces or other characters a plain name can't hold: `[Unit Price]`, `@[Unit Price]`.
- How it's built: [[computed-columns]].
- **Reopen if:** nothing. This is the Excel model the surface exists to mirror.
