## Decision

**MUST:** in a computed column's formula, a bare name or `[Name]` is the whole column, and `@name`, `@[Name]` or `[@Name]` is this row's cell, the same as Excel's table references. A whole column where one value is needed is an error on that row pointing at `@`, never a silent read of this row's cell.

## Why

This is how Excel's table references read. Any other rule fails with a believable number instead of an error: if bare names read this row's cell, `revenue / SUM(revenue)` gives 1.0 on every row and nothing looks wrong. And formulas that need both readings, like `SUMIFS(amt, cat, @cat)`, couldn't be written at all.

## Consequences

- A LAMBDA body that writes one parameter both bare and `@` is flagged on its card, since the bare one is almost always meant as the whole column.
- How names resolve, `ROW()`, `ROWS(price)` and the rest: [[computed-columns]].
- **Reopen if:** Excel changes how its table references read.

## Contest

### Contest 2026-09-26 by claude: keep wins

keep: Excel's table references read bare as whole column and @ as this row, which B16 measures against; any single spelling for both makes SUMIFS(amt, cat, @cat) unwritable. opposite (bare = this row) silently gives believable wrong answers like share = 1.0. deletion leaves B16 to be applied per surface. Keep.
