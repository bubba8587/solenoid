## Decision

A Format Controller shows only the controls that fit the kind of value it formats (number, date, text and so on). A control that doesn't fit is hidden, never shown greyed out, and never applied behind the user's back. Decimal places work the same way in every number style. Any number style can carry a unit, and no other kind of value takes one.

## Why

Before this, each style had its own hand-written rules, decimal places were handled separately in each, and the popup decided what to show with its own scattered checks. Every new style was another place for what the popup shows and what the value looks like to disagree. Controls are hidden rather than greyed out, because a control that can't apply tells the user nothing. The one greyed-out control is the unit menu when an upstream Convert sets the unit: there the value does have a unit, and the control shows where it comes from ([[C25]] firstClassUnits).

## Consequences

- Which controls each kind of value gets is in [[format-model]].
- A table (Frame) gets no controls here: each column carries its own unit and format instead ([[D43]] unitByGranularity).
- A Format Controller keeps the user's style choice when the kind of value arriving changes; a choice that doesn't fit just has no effect until a fitting value returns. A value whose kind is only known once it computes, such as a Script's output, changes kind a few times on the way, and resetting the choice each time used to wipe a saved date style.
- **Reopen if:** a control needs to be shown greyed out for a reason other than a Convert setting the unit, or one kind of value needs two rules for decimal places.
