## Decision

Artifacts cite nodes as `[[ID]]`, optionally followed by the name (`[[ID]] name`), and the link fields `parents`, `supersedes`, `superseded_by` and `conflicts_with` hold quoted wikilinks (`["[[B7]]"]`). The `links = wikilink` setting in `dte.cfg` makes the vendored tool write that form; the tool still reads the upstream `dte:ID` token.

## Why

Obsidian resolves `[[ID]]` by file name across a vault, so with the repo opened as a vault, every node's parents, supersessions and citing docs become followable links, backlinks and graph-view edges with no plugin ([[B1]] obsidianBet). [[B8]] treeIsTheHome makes the tree the one home for rules, so it has to be readable where the author reads. The upstream `dte:ID` token means nothing to Obsidian, and once the tool reads both forms a wikilink costs it nothing.

## Consequences

- The tool patch (`cited_ids`, `LINK_RE`, `fm_id`, `fm_ids`, `cite_text` and the `links` config key) can go upstream as it is, since DTE's own tree keeps `links = token`. It is logged in DTE's FEEDBACK.md.
- Titles are double-quoted on write (`fm_str`), because a title may contain a colon and Obsidian rejects an invalid frontmatter block entirely.
- `dte-rules/` stays the verbatim upstream copy and still describes the token form; `docs/dte.md` carries the Solenoid difference.
- The vault is `tree/`, holding `decisions/` and `specs/` side by side, so a spec and the nodes it serves link to each other in one graph. Specs are Obsidian notes too: a front matter with the spec's title as an alias and a `spec` tag, wikilinks to other specs by file name. The author's call.
- **Reopen if:** upstream DTE adopts a different link syntax, or the repo stops being read from Obsidian.
