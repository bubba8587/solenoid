## Decision

Each filter node has one job, never two. List Filter tests a list's items on their own values only; it never filters one list by the values of another. Filtering a table is only the Frame Filter's job, and totalling or counting the rows that match is only the job of SUMIFS and its siblings (COUNTIFS, AVERAGEIFS, MINIFS, MAXIFS), never a filter's.

## Why

[[B11]] maximalMerge folds variants of one job into one node, but a second job is not a variant. A List Filter that could also filter by a second, parallel list would leave nobody able to tell from the node which of the two it was doing. With one job per filter node, what each does is plain to see, and "total the rows that match" already has its Excel-shaped home in SUMIFS.

## Consequences

- **Reopen if:** filtering one list by another, without totalling, turns out to be common enough to be worth the confusion. Filtering a 2-D grid cell by cell stays out regardless; the way to do it is TOCOL followed by Filter.
