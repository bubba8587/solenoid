## Decision

While a big graph pans or zooms, an optional layer may draw snapshots of the nodes in place of the live nodes, and at rest the live nodes are back. The live nodes are the default and the only resting state; the layer is a setting, offered only in browsers that support it. The canvas has exactly two ways of being drawn, the live nodes and this layer, never a third.

## Why

[[B10]] reactFlowView gives the canvas one way of being drawn, and on a big graph that one way can stutter while panning. The layer smooths panning without becoming a second canvas: it only draws pictures of the real nodes. It rests on an experimental browser feature, so the live nodes stay the default and the layer is an extra, never a requirement. A third way of drawing would be another renderer to keep in step with every node, for no gain a user would see. Keeping the layer is the author's call.

## Consequences

- The pipeline and every knob (the size gate, the zoom settle, the hold zoom, capture resolution, the atlas, the camera sync, clone positioning) are [[html-in-canvas]]. They are tuning, changed with a measurement, not decisions.
- Standing risk: the flag could stall or change. If it does, the DOM stays default and nothing breaks.
- Static export (the viewport PNG and chart SVGs in `canvasCapture.ts`) never uses the layer's API: `drawElementImage` needs a browser flag the recipient of an exported file won't have.
- **Reopen if:** the API ships unflagged and the DOM path becomes the one that costs more to keep.
