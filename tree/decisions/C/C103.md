## Decision

Content that crosses the app's boundary is guarded at the one seam it crosses:

- A table cell that a spreadsheet would run as a formula when pasted or opened is made harmless on every export, whether it leaves through the Table popup's Copy or Export or through the Write File node.
- An SVG image that a user pastes, uploads or fetches is cleaned of anything that could run or phone home before it is shown or saved.
- A link inside a Note or Report opens in the system browser and never replaces the app itself.
- A document that was not made on this machine fetches nothing over the network until the user allows it, once per document; the user's own documents fetch on open as usual. Every node that fetches (Connection nodes, data feeds, the SVG Picker's web address) asks this one question.

## Why

[[B18]] safeToShare says opening someone else's document never acts, leaks or reaches out on its own. A Note carries whatever its author's vault put in it, an exported cell can run as a formula in a spreadsheet, an SVG can phone home, and a shared file could contact any web address the moment it opens. Each guard is one rule in one place rather than a check in every feature, so a new way to export or a new place that shows markdown gets the guard for free instead of forgetting it.

## Consequences

- A new way for text, an image, a link or a fetch to leave or enter the app goes through the existing guard and does not grow its own check or prompt.
- Opening a file link asks first when the file would run a program or the link came with someone else's document, since a shared file can point anywhere.
- How each guard is built: the reports-and-notes spec (§ What is sanitized, and where), the table-popup spec and the live-connections spec.
- **Reopen if:** a surface needs to run untrusted script on purpose (a sandbox is then the seam, [[C66]] scriptNode), or documents carry a provenance the app can trust (a signed origin), which would let the network gate choose its default per source.
