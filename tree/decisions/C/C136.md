## Decision

Before a calculation, an output whose type the wiring can't tell (a lookup's picked column, the branch an IF will take, a Cube cell) shows as untyped. Once the calculation has run, nothing is unknown: the output takes the type of the value it actually carried, so a date that leaves a lookup or a branch is still a date. When the data changes, the type follows it.

## Why

A value's type is part of what it is ([[B17]] typedValueModel). Guessing ahead of time is a limit of looking at the wiring, not of the value, and after the calculation the value is in hand. A date shown as its serial number is the value losing its type for no reason the user can see.

## Consequences

- A branch card whose branches differ shows the taken branch's type, and an output's type can change when the data does.
- How it's built: the Type Settle's run-time facts, [[socket-lattice]] req. 9.
- **Reopen if:** an output's type flipping with the data breaks something downstream that can't follow it.
