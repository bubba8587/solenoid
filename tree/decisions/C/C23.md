## Decision

Answers recalculate on their own after every edit, touching only what the edit affects, with a manual mode (F9) for heavy documents. However much is recalculated, the answers match a full, clean recalculation. A node that draws random numbers keeps its draw until you recalculate (F9 or its equivalents), and a composite in a heavy run mode, any mode with a Solve button, sits blank until you press Solve or Refresh; a composite in Single mode stays fully live.

## Why

We keep Excel's habit of answers that update themselves, and a shortcut is only fine if nobody can tell it was taken. F9 is how you ask for a new draw, so an unrelated edit shouldn't change random numbers, and a Monte Carlo built on them stays reproducible. People expect a heavy composite to wait for Solve, so they can watch it compute.

## Consequences

- *Exception:* Sketch mode, the user's own pick, works on a sample of very large Frames and marks its answers approximate; F9 always computes exactly. **Removed by:** exact answers on any Frame being fast enough.
- *Exception:* a random function inside a formula draws again each time that formula recalculates. **Removed by:** formulas holding their draws until F9 the way nodes do.
- A Script whose code draws random numbers or reads the clock holds its result until F9 too, and like every random node it has a Recalculate button for a new draw. *Unenforced:* a volatile Script runs again on every recalculation today, though it already shows the button (`docs/backlog.md` § Leaves the code breaks).
- How it's built: [[compute-pass]] (its volatile nodes and the recalc generation) and [[composite-nodes#The heavy-mode hold]].
- **Reopen if:** a document grows too big for a recalculation that matches a full one to keep up, or people want a heavy mode to compute on load again.
