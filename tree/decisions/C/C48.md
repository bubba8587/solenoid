## Decision

There is one append node per shape, never one per kind of value, and each takes any number of inputs holding any kind of value: Concat Lists for lists, the Stack node (VSTACK and HSTACK) for matrices, where an uneven edge pads with `#N/A` cells as in Excel, and Append for Frames, where columns match by name and a missing column fills with blanks. Each grows a new input row as you connect one.

## Why

[[B11]] maximalMerge: appending lists of numbers and lists of text is one job with different values, so a node per kind of value would be the sibling nodes it forbids. The shape does change the job (lists join end to end, matrices stack on an edge, tables match columns by name), so the line falls at shape. Uneven matrix stacking pads the way Excel does ([[A5]] excelParity).

## Consequences

- **Deliberately not merged, so no one merges them later:** Interleave, Pad, Repeat, Add Column, and Build Frame versus Frame from Lists. "Add one row" is Get Row followed by Append; a plain list connected to Append, which matches columns by name, is refused as a trap.
- **Reopen if:** a single input that accepts several cables exists; it would replace the growing input rows.
