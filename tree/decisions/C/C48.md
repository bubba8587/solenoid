## Decision

There is one append node per shape, never one per kind of value, and each takes any number of inputs holding any kind of value: Concat Lists for lists, Stack for grids and Append for tables. Each grows a new input row as you connect one.

## Why

We want one node per job. Appending numbers and appending text is the same job, so it is one node; joining lists end to end, stacking grids and matching table columns by name are different jobs, so the line falls at shape.

## Consequences

- **Deliberately not merged, so no one merges them later:** Interleave, Pad, Repeat, Add Column, and Build Frame versus Frame from Lists. A plain list connected to Append is refused, because Append matches columns by name.
- How they stack and pad: [[formula-language]] (the append ladder) and [[frame-verbs#append]].
- **Reopen if:** a single input that accepts several cables exists; it would replace the growing input rows.
