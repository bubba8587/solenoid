## Decision

Solenoid ships an Obsidian plugin, Solenoid Properties (`obsidian-plugin/`). It adds every Solenoid object type that YAML can hold to Obsidian's properties: each shows as the app's own chip and opens the app's own popup editor, and the note keeps plain YAML.

Three things are decided here; the mechanics, the type table and every divergence from the full app are [[obsidian-plugin]], and the code is built to that spec.

- The chips and popups are the real components ([[B3]]), bundled by a plugin-only build behind a fixed list of module shims. Nothing is redrawn or forked; a need the component lacks becomes a prop on the component.
- They render inside Shadow DOM, styled by the app's own tokens, and the plugin never writes to Obsidian's document or variables.
- A property is plain YAML in the shape Solenoid's note reader already reads, and a type id is `solenoid-` plus the socket variant, so `.obsidian/types.json` names a socket by identity. What needs a graph (computed columns, λ, units, pins, persisted formats) is left out instead of faked.

This reverses the "no Obsidian plugin" line in `docs/v2.0/24-obsidian-vault.md`, at the author's ask. The file, HTTP and URI touchpoints stand unchanged; the plugin adds the one thing they cannot give, which is Solenoid's objects shown and edited inside a note.

## Why

A property that is a table or a nested cube reads as raw YAML in Obsidian, so the values Solenoid writes back are the ones a reader cannot see. Bundling the real components keeps the note and the canvas identical by construction, where a redraw would drift with every card change.

## Consequences

- The author's rulings on the plugin's surface, each specified in [[obsidian-plugin]]: a chip is always `sm`, because `md` overpowers a property row; the settings page shows no sample chips, because a chip over made-up data is bogus; a list property opens a one-column raw grid with Save, a fine workaround while the app has no list editor; every popup wears its value type's socket color, since no node launches it; a frame column's picked type is kept and Solenoid reads it, because the pick is what stops the guessing games, and a column nobody has typed takes its first guess from the YAML values' own types, never their text, because re-inferring from the text on every open made the type selector a lie and let a Save turn a Text `"0012"` into 12.
- **Reopen if:** a component in the bundle needs a shim that changes what it draws (the component then gets a real seam instead), or Obsidian drops `metadataTypeManager.registeredTypeWidgets` (undocumented; read from the 1.13.7 source).
