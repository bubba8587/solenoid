## Decision

One concept, an aggregate per element over its window, with a mode toggle: "Cumulative" grows the window, "Last N" slides it (Window size input exists only there). One op set across both modes. On the formula surface it is one function, `RUNNING(op, list, [window])`; the aggregator is a string argument per [[C56]] aggregatorsAreArguments (window omitted = cumulative, window given = Last N).

## Why

The author's call: Cumulative and Rolling were too similar to stay separate ([[B11]] maximalMerge). A blank or 0 wired window as an "unbounded" sentinel was rejected, because a wired blank means unknown (`docs/value-semantics.md`), so the mode is structural, not in-band.

## Consequences

- There is no per-op `RUNNING*` family.
- **Reopen if:** the grow/slide edge policies need to diverge further than the per-window reducer policy can express.
