## Decision

Query = the same `CompositeNode`, pre-seeded Table→Result, `runMode: "manual"` (arm-and-run; Solve relabelled Refresh). The drill-in canvas IS the steps view; the frame verbs are the steps. No new persistence shape.

## Why

maximalMerge: a query is a composite that runs on demand, so it is a mode of the existing card rather than a sibling class with its own persistence.
