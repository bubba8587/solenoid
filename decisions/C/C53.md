## Decision

Query, the Power Query analogue, is the same `CompositeNode` in a preset form: pre-seeded with a Table input and a Result output, set to `runMode: "manual"` so it arms and runs on demand, with its Solve button relabeled Refresh. The drill-in canvas is the steps view, and the frame verbs are the steps. It adds no new save format.

## Why

[[B11]] maximalMerge: a query is a composite that runs on demand, so it is a mode of the existing card rather than a sibling class with its own persistence.

## Consequences

- **Reopen if:** a real need arises for per-step preview or caching, or for something that adopting boundary typing can't express.
