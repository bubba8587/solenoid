## Decision

Deletion is the default outcome for a comment under review; a survivor states a line-granular constraint invisible in code, types, tests, specs, and commits. History → commits; rulings → decision nodes; investigations → dev-notes. Test files exempt for now.

## Why

[[B9]]: a comment is a copy of knowledge that has a better home, and copies drift. A WHY that governs code belongs in a node the code cites ([[B8]]), where it is found by trace and blast rather than by reading the file.

## Consequences

- **Where knowledge lives, strongest home first; a comment is home five:** (1) the code, names and types (rename before commenting); (2) a machine check (a "do NOT do X" a test can enforce becomes a test: a comment-guard is a plea, a test is a wall); (3) the decision node or the spec ([[B8]] treeIsTheHome; routed by the README table); (4) the commit message (all revision history); (5) a comment, only for a line-granular constraint invisible at every level above AND likely to be violated by an editor of that exact line. Both conditions.
- **The cut rules.** Revision history ("the old code…", "previously…") → the commit message; a present-tense constraint fused with it survives alone. A dated ruling in a comment is a decision misfiled → node, then delete. Investigations, measurements and negative results have ONE home (dev-notes or the spec); a routed file carries zero prose residue beyond its `[[ID]]` line, and content that exists only in a comment is promoted before it is cut. Module headers state scope and hard constraints only, cite the spec, never excerpt it (max 2 lines; zero scope prose on a routed file). Doc comments carry what the signature cannot (ordering, null meaning, units, side effects); a JSDoc that restates the name goes. Never translate code into English. TODOs → `backlog.md`; commented-out code → deleted.
- **The blast-radius test** (comment vs node/spec): a constraint earns a comment only when its blast radius is one edit site, no doc is on the path to the mistake, and no stronger home is available. Prose that governs a module's architecture flips the other way and is promoted.
- **Compression:** a survivor is one sentence stating the constraint (enumerated contracts and truth tables excepted); section banners only in ~400+ line files; no Excel-equivalent or duplicate annotations the catalog or a spec already carries. Test files (`*.test.ts[x]`) are exempt for now.
- A file's `[[ID]]` citation line is the machine-checked link to its governing nodes, the one line a routed file must carry; a rationale comment migrates into its node's Why and collapses to that citation. DTE's own B38 commentsMigrate is the same split (WHY → node, HOW → spec, WHAT stays).
- **Reopen if:** repeated regressions a comment would have prevented; fix routing first, comment copies are the last resort.
