## Decision

A note's YAML frontmatter has ONE writer, and it patches LINE-LEVEL over the raw text: never parse-and-reserialize. Every byte the write did not target stays identical, and what it does write renders in Obsidian's own block style.

## Why

The vault is the user's, not Solenoid's ([[B1]] obsidianBet): a writer that round-trips a note through a YAML library rewrites every property's spelling, ordering and quoting on each save, which Obsidian users notice as churn in their own files and in git. One patch path is also the only way "untouched bytes identical" can be tested as a property rather than hoped for per caller.

## Consequences

- `frontmatterPatch.ts` is that writer; Write Properties and every other note write go through it, and `frontmatterPatch.test.ts` proves untouched bytes identical and a cube round-trip unchanged.
- Reading stays permissive: any spelling Obsidian or a person emits parses (`noteFrontmatter.ts`).
- **Reopen if:** Obsidian's own Properties writer changes its block style, or a write needs to restructure a note beyond its frontmatter.
