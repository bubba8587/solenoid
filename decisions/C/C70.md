## Decision

The schedule is always recomputed from the table; a gap is a lag on the link; a typed Start holds a task no earlier, a typed Finish caps its late finish and shows as negative float, a Deadline flags and never moves, Manual pins and still drives successors. No constraint-type columns, no per-task mode, no project-wide shift switch.

## Why

The user sweep's top complaint about scheduling tools is dates moving from hidden state; four visible columns with one rule each leave nothing hidden (2026-09-12).

## Consequences

- A structural failure (a cycle, an unknown predecessor name, a duplicate name) aborts the whole run with ONE error naming a member; per-row faults (a bad duration, an unparseable date) stay per-row. No member of a loop has a defined start, so nothing downstream does either.
- **Reopen if:** an imported file needs a constraint the four columns cannot express (ALAP, must-finish-on); then it is a named `unsupported` at the MSPDI border, not a fifth column.
