## Decision

**MUST:** a text field's edit commits on Enter or clickaway, never per keystroke. The draft stays local while typing, Escape reverts, and one commit is one undo entry. `useDraftCommit` (`inlineInput.tsx`) is the mechanism; nothing calls `processGraph()` from a text field's `onChange`. Discrete picks (dropdowns, checkboxes, sliders) apply immediately.

## Why

An Excel cell commits when you leave it, and that is the model users bring. Per-keystroke commits recompute the graph on every character, flood undo with partial values, and let a half-typed number flow downstream as a wrong value.

## Consequences

- The editable node title is the same state machine (`useEditableTitle`): typing never writes `node.label`.
- Enforced by a source sweep: a raw `<input>` (other than checkbox / radio / range / color) or `<textarea>` whose `onChange` calls `processGraph` fails by file and line. The draft-commit fields (`InlineNumberField`, `QuotedTextInput`, `InlineCsvField`…) expose `onChange` as the COMMIT callback, so a component wiring `processGraph` there is correct.
- **Reopen if:** a live-preview field is wanted (then it previews the draft, as the number scrub does, and still commits once).
