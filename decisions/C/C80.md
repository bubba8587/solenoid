## Decision

**MUST:** a formula argument slot left BLANK (`SUM(a,,b)`, parsed to `null`) reads as Excel's blank for the parameter's type: 0 for a number, FALSE for a logical, "" for text. An OMITTED trailing argument (`undefined`) takes the function's default. One typed table (`BLANK_ARG_TYPES` in `excelFormula.ts`) applies the mapping at the dispatch boundary for every declared parameter; a `registerInternal` override reads `undefined` as the default and never treats `null` as omitted.

## Why

[[B5]] says a formula returns Excel's answer. Excel distinguishes a blank slot from an omitted argument: `TEXTJOIN(",",,"a","","b")` keeps the empty (blank = FALSE) while `MATCH(x, r,)` is an exact match (blank = 0). The evaluator carried the opposite "blank = omitted" convention on the lookup family and Formula.js answers an error object to a null MATCH type, so the same formula gave a different answer here. A table at one boundary makes the mapping declarative and audited; the parameter types outside the table are left to the function, so unlisted blanks keep propagating as missing.

## Consequences

*Enforced by:* `blankArgIsExcelBlank.test.ts` → "TEXTJOIN: a blank ignore_empty is FALSE and keeps the empties", "XMATCH / XLOOKUP: a blank match_mode is 0 (exact, the default); a blank search_mode is 0, which Excel rejects", "an undeclared blank still propagates as missing, never a fabricated 0"; the table's names resolve ("every declared function exists").
*Where:* `BLANK_ARG_TYPES` + `excelBlanks` in `excelFormula.ts` (the one boundary); `xMatchModeArg` / `xSearchModeArg` in `excelFunctions.ts` default only on `undefined`.
*Not in the table:* MATCH / VLOOKUP / HLOOKUP are blocked spellings (currentExcelParity), so Formula.js's null handling on them is unreachable. XLOOKUP's blank `if_not_found` is left as missing (Excel's answer there is unverified).
*Reopen if:* a formula needs a blank that the table can't type, or the Expression grammar stops parsing an empty slot as `blank`.
