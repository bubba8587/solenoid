## Decision

When several agents work this repo at once: exactly ONE `tsc` / `vitest` run at a time, arbitrated by the file `.dev/test-lock` in the main checkout (read it; `free` → write your session name, run, write `free` back; someone else's name → do other work and retry). Claims are one line each in `docs/agent-coordination.md`, deleted on land; agents message each other directly for live coordination. Agent 1 is Lead: peers commit on their worktree branches, message the Lead a hash when green, the Lead merges into `develop`; nobody else pushes. Dormant in a solo session: claim nothing.

## Why

A second concurrent test run crashes the author's machine, and a late-joining or restarted agent has no memory of who holds what; the rules must hold without anyone remembering them. Direct messages carry the live state; the board carries only what must survive a restart.

## Consequences

- **Reopen if:** the test lock stops being a machine constraint, or the branch model changes ([[C41]] branchModel).
