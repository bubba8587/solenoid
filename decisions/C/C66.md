## Decision

The source is a JavaScript function expression (`(a, b) => …`). Its parameters are `anydata` inputs, worked out again on commit (Expression's mechanism, `applyScriptChange`). The return value passes through `coerceScriptResult`, and **the value types itself; there is no declared result type**. Numbers, text and Booleans carry their own families; a returned `Date`, or `Solenoid.date(serial)` (the one in-script global, closed over by `compileScript`), is a date; and the result socket reconciles family as well as rank from the computed value (`reconcileResultRank`: number, text and date sockets, with logical and complex on the wildcard). **Containers are single-typed, uniformly:** a list, table or Frame column that mixes families is `#AMBIGUOUS!`. Other outputs that can't be resolved error: `#TYPE!` for unsupported values, `#DOMAIN!` for NaN, `#SHAPE!` beyond the accepted shapes (ragged rows pad with null).

**Frames and Cubes flow both ways.** Rows of `{name: value}` objects, or one such object, build a `FrameValue`, with columns keyed in first-appearance order and typed per column; rows whose cells nest rows or lists build a `CubeValue`. The input side mirrors it exactly (`scriptArgToJs`): parameters are `trueany`, and a wired Frame (lazy handles and head-N previews collected in full, never silently truncated) or Cube arrives as the same rows of objects, so what one script emits another can read. LAMBDAs, charts and documents have no script form and error before the run. Script stays unit-blind: Cube `UnitCell` cells unwrap to magnitudes.

## Why

The author asked for a code node whose outputs are restricted to the existing value types, overriding `out-of-scope.md` §4's blanket no; §4 now states the bounded form. [[A6]] is what bounds it: whatever runs inside, only honestly typed values leave. If it's going to be a script, script it, so the value types itself. The app has no mixed lists; the one legitimately mixed case in [[D43]] unitByGranularity is a Frame row. Frames and Cubes flow both ways on the author's call: Expression's Frame ban is about the complexity budget of an Excel-shaped surface, while Script is the more advanced surface and follows its own rule, with no principled blocker. Expression keeps its Number / Text / Date / Auto toggle because a formula's variables don't say what it returns; a script's values do.

## Consequences

- Evaluation runs in the sandbox worker (`specs/script-sandbox.md`) under `SCRIPT_TIMEOUT_MS`; the Tauri CSP carries `'unsafe-eval'` for it.
- Named Script, not Code ([[D21]] noExcelNameClash: CODE is an Excel function node).
- **Reopen if:** a script needs I/O, state between runs, or a second language. Each is §4's creep, not a feature request.
