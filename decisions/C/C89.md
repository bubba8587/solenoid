## Decision

A standoff is a constraint the user declared, so no layout pass may leave it violated: the pure solver runs LAST after every layout-affecting pass (drag chain-pull, expand push, collapse, autofit, Tidy). For the same reason a standoff-connected cluster is one rigid block to every layout op: Tidy lays it out as a single super-node, a push moves every member by the cluster's largest displacement.

## Why

A constraint a layout pass can silently violate is not a constraint; running the solver last is what makes "declared" mean something. Treating the cluster as a block is the same idea from the other side: a Tidy that pulled the pair apart and then let the solver snap it back would visibly fight itself.

## Consequences

- The band semantics, anchors and the 45° lock are `specs/standoffs.md`.
- Live drag is band-only (never forceLock) so an unlocked slant survives a drag; every layout op forces the lock for its single solve without touching the saved flag.
- Seeds (author's rule, 2026-09-04): groups liberally, standoffs sparingly. A seed standoff only pins an unwired explanatory Note to what it explains; a data node never standoffs to its consumer.
- Known v1 edges (dormant endpoints in collapsed groups, no undo entries) are listed in `specs/standoffs.md`.
- **Reopen if:** standoffs should become ELK constraints, or need to bind group members and conduits.
