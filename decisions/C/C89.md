## Decision

A standoff is a constraint the user declared, so no layout pass may leave it violated. The pure solver runs last, after every pass that affects layout (the drag chain-pull, expand push, collapse, autofit and Tidy). For the same reason, a cluster joined by standoffs is one rigid block to every layout operation: Tidy lays it out as a single super-node, and a push moves every member by the cluster's largest displacement.

## Why

A constraint that a layout pass can silently break is not a constraint, and running the solver last is what gives "declared" its meaning. Treating the cluster as a block is the same idea from the other side: a Tidy that pulled a pair apart and then let the solver snap it back would visibly fight itself.

## Consequences

- The band semantics, the anchors and the 45° lock are in `specs/standoffs.md`.
- A live drag applies the bands only (never `forceLock`), so an unlocked slant survives a drag. Every layout operation forces the lock for its single solve without touching the saved flag.
- Seeds follow the author's rule: groups liberally, standoffs sparingly. A seed standoff only pins an unwired explanatory Note to what it explains, and a data node never has a standoff to its consumer.
- The known gaps of the first version (dormant endpoints inside collapsed groups, no undo entries) are listed in `specs/standoffs.md`.
- **Reopen if:** standoffs should become ELK constraints, or need to bind group members and conduits.
