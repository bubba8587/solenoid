## Decision

The Command Palette is the menubar in searchable form: every menubar action is a command, so the two surfaces cannot drift, plus canvas and selection ops that have no menu home. Node types stay out; the Add menu is the one place to browse the catalog. A setting Settings greys out on this device is unreachable from the palette too.

## Why

Two lists of the same actions drift; deriving the palette from the menu model means a new menu item is a palette command by construction. Keeping nodes out keeps one catalog surface ([[D22]] oneNamePerCard names it), and a palette that could flip a device-disabled setting would be a back door around the gate.

## Consequences

- Labels name the end effect, not the axis ("Center vertically" stacks nodes in a column).
- Graph-domain shortcuts route through the canvas keydown handler and are never duplicated in the palette.
- **Reopen if:** the Add menu and the palette merge into one launcher.
