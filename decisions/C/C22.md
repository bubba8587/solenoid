## Decision

**MUST:** in a computed column's formula, a bare name or `[Name]` is the whole column as a list, and `@name`, `@[Name]` or `[@Name]` is this row's cell, the same as Excel's table references (tableRefSemantics). A whole column where one value is needed is a `#SHAPE!` on that row pointing at `@`, never a silent read of this row's cell.

## Why

Any other rule fails with a believable number instead of an error. When bare names read this row's cell, `revenue / SUM(revenue)` returned 1.0 on every row, because `SUM(revenue)` summed a single cell, and nothing looked wrong. Formulas that mix both readings, like `SUMIFS(amt, cat, @cat)`, can't be written at all if one spelling has to mean both.

## Consequences

- Names resolve in a fixed order: column, then the `row` and `rows` builtins, then the LAMBDA's captures, then the side value.
- A LAMBDA's parameters are bound to the row. Any other name in its body, bare or `@`, becomes a captured input.
- Brackets spell names that aren't valid identifiers: `[Unit Price]`, `@[Unit Price]`.
- **Where:** `computedColumnCore.ts`.
- **Reopen if:** nothing. This is the Excel model the surface exists to mirror.
