## Decision

The default pack node is a pre-set Expression: a formula plus its metadata (name, description, socket names and units, Excel mapping), compiled by the core, authored as pack data rather than new node code. A pack declares, per node, when it needs custom logic instead: a native compiled library, root-finding or iteration, interpolation over an embedded dataset, or a custom widget.

## Why

Formula nodes keep packs cheap and honest about units, since they run through the compiler the unit system already understands. They also decide dormancy: a pre-set formula is data the core can still evaluate with its pack off, while a custom-logic node ships code that runs during calculation, makes isolation and third-party safety hard, and is usually desktop-only, so custom logic is the short list that gets scrutiny.

## Consequences

- A formula pack node serializes as a core `ExpressionNode` (always registered), so a dormant formula pack reloads as a locked Expression and still computes; its formula functions keep RESOLVING with the pack off and are only un-advertised (`formulaExtensions.test.ts`).
- **Where:** `formulaExtensions.ts`; the declared custom-logic exceptions `nodes/fluids.ts` (Colebrook root-finding) and `nodes/electrical.ts`.
