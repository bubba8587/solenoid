## Decision

Solenoid ships an Obsidian plugin, Solenoid Properties (`obsidian-plugin/`). It registers property types for the container values (list and matrix of each element family, frame, cube), shows each property as the app's own `sm` chip, and opens the app's own popup editors on it: the raw-text grid for a list or matrix, Frame Input's literal-source editor for a frame, the Cube Input editor for a cube. Its settings page switches the palette.

- The chips and popups are the real components ([[B3]]), bundled by a plugin-only Vite build. Nothing in them is redrawn or forked. The build swaps the app modules that reach the graph for the shims in `obsidian-plugin/src/shims/`; the `SHIMMED` map in `obsidian-plugin/vite.config.ts` is the whole seam, and `PLUGIN_REPORT=1` lists what the bundle pulled in.
- Every chip and the popup layer render inside a Shadow DOM root, because Obsidian and its themes style bare `button`, `input` and `select`. The build rewrites `:root` selectors to `:host`; the tokens and socket colors come from `palette.ts` and follow Obsidian's light or dark mode. The plugin never touches `<html>` or Obsidian's own variables.
- A property holds plain YAML: a list is a sequence of scalars, a matrix a sequence of sequences, a frame a sequence of maps, a cube a sequence of maps whose values may be lists or rows. Dates are ISO text in the note and serials inside the components. What the plugin writes, `noteFrontmatter.ts` reads (`tests/obsidianPlugin/yamlValue.test.ts`); the one gap is a matrix, which the reader does not type yet (`docs/backlog.md`).
- A type id is `solenoid-` plus the socket variant (`solenoid-strlist`, `solenoid-frame`), so `.obsidian/types.json` names the socket by identity.
- Excluded in Obsidian, since they need a graph: pin and go-to-source, computed (Fx) columns and λ options (`noFormulaColumns` on the popup state), unit tagging, persisted format picks (a pick there is display-only for the open popup).

This reverses the 2026-09-06 "no Obsidian plugin" line in `docs/v2.0/24-obsidian-vault.md`, on the author's ask of 2026-09-20. The file, HTTP and URI touchpoints stand unchanged; the plugin adds the one thing they cannot give, which is Solenoid's objects shown and edited inside a note.

Would reopen it: a component in the bundle needing a shim that changes what it draws (then the component gets a real seam instead), or Obsidian dropping `metadataTypeManager.registeredTypeWidgets` (undocumented; read from the 1.13.7 source).

## Why

A property that is a table or a nested cube reads as raw YAML in Obsidian, so the values Solenoid writes back are the ones a reader cannot see. Bundling the real components keeps the note and the canvas identical by construction, where a redraw would drift with every card change.
