## Decision

Artifacts cite nodes as `[[ID]]` (optionally `[[ID]] name`), and the link fields parents, supersedes, superseded_by and conflicts_with hold quoted wikilinks (`["[[B7]]"]`). `links = wikilink` in dte.cfg makes the vendored tool write that form; it reads the upstream `dte:ID` token too.

## Why

[[B1]] puts the project inside Obsidian's world, and Obsidian resolves `[[ID]]` by filename across a vault: with the repo opened as a vault, every node's parents, supersessions and citing docs become followable links, backlinks and graph-view edges with no plugin. [[B8]] makes the tree the one home for rules, so the home has to be readable where the author reads. The upstream spec's `dte:ID` token is opaque to Obsidian; a wikilink costs nothing to the tool once it reads both forms.

## Consequences

- The tool patch (`cited_ids`, `LINK_RE`, `fm_id`/`fm_ids`/`cite_text`, the `links` config key) is upstreamable as-is: DTE's own tree keeps `links = token`. Logged in DTE's FEEDBACK.md.
- Titles are double-quoted on write (`fm_str`): the `name: summary` convention puts a colon in them and Obsidian rejects an invalid frontmatter wholesale.
- `dte-rules/` stays the verbatim upstream copy and still describes the token form; docs/dte.md carries the Solenoid difference.
- *Enforced by:* `python tools/dte.py validate` (both forms resolve) and `rules.test.ts` → "a `[[ID]] name` citation names the node it points at".
- **Reopen if:** upstream DTE adopts a different link syntax, or the repo stops being read from Obsidian.
