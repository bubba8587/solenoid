## Decision

The chrome envelopes are two MEASURED CSS variables: `--chrome-top` (published by `Header.tsx`) and `--chrome-bottom` (by `chromeBottom.ts`, the max of the visible bottom bars' heights, safe-area inset included). Every floating overlay derives its anchor from them with `calc(var(--chrome-*) + gap)`; no overlay hand-keys a bar height.

## Why

The recurring bug class was a floating overlay covering a bar: the offsets were magic numbers scattered across many CSS files that all traced back to the same few bar heights, so moving one bar meant finding every dependent by hand. Measuring the envelope once makes a bar that appears, hides or grows carry every overlay with it.

## Consequences

- Still hand-keyed, by choice: the bars' own row heights, the gutters, per-overlay gaps and mobile's top overrides; `docs/layout-chrome.md` is the map of what each number means.
- Citations in that map are file + selector, never line numbers.
- **Reopen if:** the header and footer become layout (not floating) so the canvas is simply the remaining flex box.
