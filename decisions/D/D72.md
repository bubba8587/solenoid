## Decision

A Solenoid Properties editor's Save writes each cell's SOURCE TEXT to the note, never a value pushed through a type. An unchanged cell keeps the scalar it came in with; an edited cell is what was typed, as YAML reads a plain scalar (`parseCellText`: a number, true/false, blank → missing, else text). A type is a lens: a frame column's picked type lives in the plugin's data and the property's family shows through the chip, and neither touches the note. So a type switch keeps every cell's scalar and only reshapes, and `validate` checks shape alone inside a list or matrix, because a cell the family cannot read is the chip's to show as unreadable, never Obsidian's to refuse. One exception, and what makes it one: the Complex field is a scalar with no editor of its own, so it refuses text it cannot read and writes nothing; it never writes a coerced value either.

## Why

The author's ruling of 2026-09-22: switching a frame's date column to Number showed NaN, as it should, and the Save wiped the dates from the note. [[C58]] tableInputRawText is the app's rule for the same boundary (the raw text is the stored truth, editors never coerce it), and [[C107]] obsidianPlugin bundles the same editors, so the note must be treated as the app treats its literal source. Writing a coerced value would make the type a destructive act; a lens cannot lose data.

## Consequences

- `yamlValue.ts` (`frameSourceToYaml`, `listToYaml`, `matrixToYaml`, `coerceYaml`, `validateYaml`) and `PropertyChip.tsx`, which hands every Save the rows the editor opened on; `tests/obsidianPlugin/yamlValue.test.ts` pins it.
- Obsidian's own YAML writer may restyle a list (flow to block); the values are what was in the note.
- Solenoid reads what the plugin wrote as the same type (`pluginColumnTypes.ts`), through the app's own value boundary with the source text kept: a picked type that cannot read a cell shows NaN over the text in Solenoid too, never a silent blank; the note is untouched either way.
- **Reopen if:** a plugin editor gains a cell-level error value that can live in YAML (then a cell it cannot read could carry that instead of its text), or the app's literal editors stop keeping raw text ([[C58]]).
