## Decision

**MUST:** a node's user-facing name (card label, catalog leaf, help and Reference, socket docs) never reads as a core Excel function that does something else. A bare "Columns" reads as `COLUMNS()`, the count, so the keep and drop relational node is named for its op, "Keep Columns" or "Drop Columns", and its card label follows the op.

## Why

No learning curve from Excel means a name is a claim about behavior. A node that borrows a function's spelling for an unrelated operation is a trap, not a shortcut. The ROWS and COLUMNS merge first shipped a bare "Columns" node, which is what prompted this rule.
