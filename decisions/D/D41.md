## Decision

**MUST:** the FORMAT half of an annotation (style, precision, grouping, negatives,
scale, text attributes, logical show-as) flows DOWNSTREAM through a transform, but ONLY
where the transform DECLARES that its current op PRESERVES the value's meaning
(`formatCarry`, formatCarryPerOp) — a style says what a value MEANS, so it survives only
an op that keeps that meaning. A transform with no declaration for an output carries
NOTHING: `makeAnnotationResolver.compute` reads `formatCarry()` (duck-typed like
`passthrough()`, its per-op mapping living in the node's op table) and, among the
declared inputs, carries the first wired, annotated, same-element-family one; absent a
declaration it returns undefined. So add / subtract carry (5% + 3% is a percent, a
date + days is a date), a mean / min / max / stdev / moving-window / EWMA carries, abs /
round / mround / clamp carries, EDATE / WORKDAY keep a date; but multiply / divide /
power / mod, count / variance / product, a z-score / correlation, every finance output
(NPV, a rate, CAGR, Sharpe), and a wildcard Expression carry nothing — and two
date-styled operands are a SPAN (date − date, NETWORKDAYS), not a date, so they carry
nothing either. A passthrough (Sort, Reverse, Slice, Filter, INDEX, TRANSPOSE) still
forwards the format UNCHANGED — it is not a transform. The carried copy has
`unit: "none"`: the unit is VALUE-level and locked (unitOnValue), riding its `UnitCell`
or breaking at the transform on its own, and an annotation never re-states it — so a
multiply of $10 keeps the $ on the value while dropping the 2-decimal format. A family
change (number → text) carries nothing. A nearer FC OVERRIDES
what it inherits, so a format is always overridable from any point down the chain — but
a docked FC can also DECLINE to override: its style dropdown's leading `—` pick
(`inheritFormat`) carries the upstream display format through unchanged and authors the
FC's unit alone (`FormatControllerNode.resolveAnnotation`), so a second FC docked only
for a unit no longer resets the style to Auto.
**Convert is the one transform that still DROPS** — it authors a new unit and rescales
the magnitude, so the precision chosen for the old unit no longer describes the number.
The UPSTREAM direction (`downstreamAnnotation`, a box reading a trailing FC) stays
bounded by transforms: a format chosen AFTER a transform says nothing about the value
before it. A FRAME's per-column format obeys the same rule through a different carrier:
it rides `FrameColumn.format` on the VALUE (like the column's unit), stamped onto every
emitted frame from the producing node's own `frameFormatStore` picks by the coercion
wrapper's output step, with the nearer node's pick overriding. It is derived per compute
and NEVER serialized — the store stays the one persisted home.

## Why

*Why (author, 2026-09-04):* "Generally, we want formatting to carry down the stream if
possible, but it's always possible to override. Units are LOCKED in contrast." *(author,
2026-09-13, formatCarryPerOp):* "if possible" means a MEANING-preserving op — a percent's
NPV is not a percent, an integer 7 ÷ 2 is not 4 — so a transform now carries per its
declared op, not through everything.

The blanket "first annotated input, any transform, same family" carry was wrong: NPV of a 5% rate showed `123,456.00%`, integer `7 ÷ 2` showed `4`, `date − date` showed a date (formatCarryPerOp, 2026-09-13).

## Consequences

*Enforced by:* `formatCarryReadability.test.ts` — the readability table (every
numeric/date transform in the app, each row "inputs → op → shows"; it also writes
`.dev/format-carry-report.txt` for the author's eyeball pass); `unitFlowAnnotation.test.ts`
→ "the FORMAT carries through a transform, the unit does not" (its mock declares a carry),
"two annotated operands: the first input's format wins; agreeing formats pass as one", "a
family change drops the format (number → text)", "an FC downstream of a transform
overrides the inherited format", "Convert still DROPS the format — it authors a new unit
and rescales the magnitude", the upstream bound "the lock STOPS at a transform between the
Display and the FC", and the `—` inherit pick "FC inherit (`—` style pick) — carries the
upstream format, keeps its own unit"; `unitFlowSeed.test.ts` → "C · a × carries the
value's UNIT, but NOT the format — a multiply is a new value"; `frameColumnFormat.test.ts`
for the frame-column carrier (survives Sort → Columns, the nearer pick wins, derived
columns follow the unit rule, nothing serializes).

From the formatFlowsDownstream and formatCarryPerOp decisions (author rulings 2026-09-04 and 2026-09-13): **Where:** `unitFlow.ts` `carriedFormat` + each node's `formatCarry`; `tests/graph/formatCarryReadability.test.ts` (the table + `.dev/format-carry-report.txt`). **Reopen if:** the author wants a specific op regraded (e.g. currency × a scalar keeping its 2-decimal format): flip that op's `carry` in its op table and add a row.
