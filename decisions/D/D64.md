## Decision

**MUST:** every movement-stack size read (align, autofit, Tidy, expand push, standoffs, splice, focus, fly-to) routes through `measuredBox()` in `nodeSize.ts`: React Flow's measure, else the live rendered size, else the ResizeObserver mirror, else a collapse-aware non-zero default. No feature reads `offsetWidth || node.width || 100` on its own.

## Why

The ad-hoc variants disagreed exactly where it mattered: pre-paint (an unpainted member reads 0 and collapses the bounding box to its corner) and on collapsed groups (the stored size is the taller expanded one; OutlinePanel's reversed read once centred the camera on a collapsed group's expanded box). One read, one fallback ladder, so every feature agrees.

## Consequences

- Enforced by a source sweep: a direct `offsetWidth`/`offsetHeight` read in a movement-stack module outside `nodeSize.ts` fails unless the line above carries `[[D64]] exception:` and its reason ([[C5]] exceptionsUnderRule). Four stand today, each the same ladder with a different last tier: the expand push reads an expanding group at its stored size and a collapsed card's layout formula; group containment falls back to the stored box; a docked FC's caller supplies the fallback. Each goes when `measuredBox` grows a caller-supplied fallback.
- **Reopen if:** React Flow's measure becomes reliable before first paint, which would collapse the ladder to one tier.
