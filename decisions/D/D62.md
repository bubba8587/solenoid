## Decision

One resolver (`getVaultRoot()` in `demoVault.ts`, `isDemoTaskNotes()` in `demoTaskNotes.ts`) decides which vault or TaskNotes source a reader sees, in this order:

1. **Forced.** A non-persisted `forceDemoVault(on)` / `forceDemoTaskNotes(on)` pins every reader (and Local File's data folder) to the bundled demo. The marketing pages turn it on during render and off on unmount, never touching the user's settings.
2. **Configured.** A non-blank `obsidianVault` or `taskNotesUrl` always wins over the demo.
3. **Demo fallback.** With one blank and the `useDemoVault` setting on (the default, and the web app's only path), the reader reads the bundled demo.
4. **None.** With the setting off and nothing configured, the readers say to set the folder.

The setting never overrides a real setup; only the force does. An Obsidian seed therefore carries no snapshot input beside its live reader.

Ruled by the author 2026-09-16: the vault folder is the first setting in the Obsidian group, the demo switch second, and the switch is a fallback ("Enable the demo vault for usage on the web app and when no other vault is selected"), not an override beside a real vault. The force switch (formerly D1) is folded in as step 1.

## Why

B2 says the web is look-and-try and readers must work with no filesystem; C1 gave them a demo vault behind a setting nobody new had found. Every Obsidian seed shipped a snapshot Frame/Cube Input next to its live node so it would compute somewhere, which doubled the nodes and told the reader the live one was optional. With the demo as the unconfigured default, the seeds wire the live node only, the first open of the app shows real notes and tasks, and configuring a vault or a URL replaces the demo the moment it is set. The scenes (C2) must read the demo regardless of the visitor's saved setting, and a persisted setting flip would leak into their real app, so the force is a separate, non-persisted step above the settings; one switch keeps the vault root and data folder in lockstep.

## Consequences

*Enforced by:* `demoVault.test.ts` → "the force wins over the settings and pins both root and data folder", "a configured folder always wins; the demo is the fallback only while the setting allows it (dte:D62 demoVaultResolution)"; `obsidian.test.ts` → "armed but off-desktop → the desktop-only guard; with no vault set, the demo's read-only guard (dte:D62 demoVaultResolution)".
*Where:* `getVaultRoot()` / `forceDemoVault()` in `demoVault.ts`, `isDemoTaskNotes()` / `forceDemoTaskNotes()` in `demoTaskNotes.ts`, `ObsidianPage.tsx` (the force), the Obsidian group in `settingsStore.ts` (`useDemoVault` defaults on).
*Reopen if:* the web app gains a real filesystem, or a second demo source appears that the one switch can't cover.
