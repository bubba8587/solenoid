## Decision

While gesturing, the React Flow viewport's transform is steered to the camera the canvas actually presented (`holderSyncTransform`), derived from the WICG API when the build exposes it (`camFromDrawMatrix`: for a capture box drawn at world anchor at natural size the matrix is `translate(k·anchor + t) scale(k)`, so `k = a` and `t = (e,f) − k·anchor`). A native-derived camera is trusted only within tolerance of our own bookkeeping (`plausibleNativeCam`, defaults 2% of scale / 4 CSS px); anything further is treated as a misparse and the bookkeeping wins. On exit the layer hands the transform back by re-serializing the live camera (`holderTransform`).

## Why

During a gesture the canvas draws the graph while DOM-only content (conduits, their cables, the standoff svg) stays live DOM: two presentation pipelines that can skew by a frame or more (the "conduit trails the pan" complaint), because the canvas presents the camera it PAINTED with while the viewport composites the freshest CSS transform. The WICG surface is experimental, so a build could hand back backing-store px or an unexpected origin.

## Consequences

- Pure math, no DOM. React Flow's next viewport commit overwrites the handed-back transform with its own equivalent.
