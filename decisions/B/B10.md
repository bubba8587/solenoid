## Decision

The view is React Flow (`@xyflow/react`): it renders every card, cable, the minimap and the viewport in the app's ONE React tree. `rete` core and `rete-engine` stay as the headless graph model and dataflow engine.

## Why

View (author, 2026-08-26: "going all out on React Flow, no rete"). Model + engine author-ratified 2026-08-27, after the port's C0 scoping was surfaced as never agreed to.

The rete surface used is small and already minimal: `ClassicPreset.Node / Input / Output / Socket / Connection` (plain data classes; every node class extends `Node`), `NodeEditor` (add/remove/get nodes + connections, `addPipe` for the `nodecreated`/`connectioncreated`/`noderemoved` events that `coerceInputs`, the error guards, FC reconcile and the RF topology sync hang off), and `DataflowEngine` (`fetch`/`reset`/`cache`, the pull-with-cache that calls `data(inputs)`, whose public `cache` is pre-seeded for `#CIRC!`). ~1,500 lines of vendored ESM, one dep, MIT. React Flow is only a renderer: it has no graph model, typed ports or engine, and no third-party alternative fits better (graphology has no ports/dataflow; Flume/nodl bundle renderers; baklava core is the same shape under another name); hand-rolling would replace ~1,500 maintained lines with ~400 of ours for no functional gain across 151 files. Dependence here is fine.

## Consequences

- Every rete RENDER package (area/react/connection/render-utils/minimap/history/auto-arrange) and `styled-components` are deleted; Tidy calls elkjs directly; undo is the snapshot history (`flow/flowHistory.ts`). The module-singleton stores (`storeKit.ts`) stay as app-wide state; the save format was already rete-independent (saveViaTextForm).
- Components may import rete TYPES (`import type`) and construct `ClassicPreset.Connection` when they wire a cable: that is the app's own model type, not a render coupling.
- Do not rebuild a third render path (htmlInCanvasRenderer).
- **Where:** `architecture.md` § Stack, `subsystem-invariants.md` § React Flow surface contract, `flow/flowModel.ts` (the model/RF projection seam), `process.ts`. Merged to `develop` 2026-08-27; build record in `archive/react-port-plan.md`.
- **Reopen if:** rete core goes unmaintained in a way that bites (a React/TS major it can't follow), or a genuinely headless typed-dataflow library appears that would delete code rather than rename it.

## Alternatives considered

### Contest 2026-09-15 by Claude Opus 5: keep wins

Rubric: [[A1]].
- keep: React Flow view, rete core + rete-engine headless. Cost: already landed; ~1,500 vendored lines to track.
- opposite: rete renders again. The port was done because the rete render stack could not carry the canvas the author wanted; re-porting back is the whole port's cost again.
- deletion: [[A1]] says visual node graph but not what draws or computes it; every canvas change would re-open the stack.
- variant: hand-rolled model and engine under React Flow. ~400 lines of ours for no functional gain, a new engine to trust.
Verdict: keep.
