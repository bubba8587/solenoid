## Decision

Solenoid's decisions, normative rules and their provenance live in one home: DTE nodes under `decisions/`, cited from artifacts as `[[ID]]`.

## Why

[[A1]] needs a product that stays maintainable while AI sessions change it daily, and the project's standing order is one home per fact: every duplicated restatement is a place a spec can be contradicted. DTE gives each decision provenance, blast radius, trace and owner ratification, which prose documents cannot.

Names survive as a property because code, tests and docs have cited rules by name for months, and a bare ID is unreadable in a comment. That overrides DTE's no-alias rule on one point: the name is a readable handle bound to the node, not a second identity, and a test holds each `[[ID]] name` pair to the node's `name`.

## Consequences

- A node states present governance only: what stands, why, what it makes true. Finished work, migrations and build history are not kept in the body; git has them.
- `rules.test.ts` guards the nodes: every MUST labels its enforcement, cited suites exist, quoted test names appear in them, owner ratifications match an owner-kept list, and `[[ID]] name` pairs match the node's `name`.
- A doc that explains mechanics or guides authoring stays and cites the nodes it explains; a doc that only restates decisions is deleted.
- DTE's own rules stay vendored in dte-rules/ and are never re-created as Solenoid nodes.
