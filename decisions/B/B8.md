## Decision

Solenoid's decisions, normative rules and their provenance live in one home: DTE nodes under `decisions/`, cited from artifacts as `[[ID]]`. Every rule in docs/rules.md and every decision in docs/decisions.md moves into a node, and the two documents are deleted once empty. A node lifted from a named rule carries the name in its `name` property (`name: shareImpl`; the title is the description alone, and the tool prints `ID name: title`), and a citation may carry that name after its link.

## Why

[[A1]] needs a product that stays maintainable while AI sessions change it daily, and the project's standing order is one home per fact: every duplicated restatement is a place a spec can be contradicted. Keeping rules.md and decisions.md authoritative beside the tree would hold every fact twice. DTE adds what the prose documents lacked: provenance per decision, blast radius, trace, and owner ratification.

Names survive as a property because code, tests and docs have cited rules by name for months, and a bare ID is unreadable in a comment. That overrides DTE's no-alias rule on one point: the name is a readable handle bound to the node, not a second identity, and a test holds each `[[ID]] name` pair to the node's `name`.

## Consequences

- Mapping from rules.md: MUST becomes Decision; Why and Origin become Why; Enforced by, Exceptions and Removed by become Consequences.
- Mapping from decisions.md: what stands becomes Decision; the reasoning becomes Why; Where, Reopen if and relapse guards become Consequences.
- Provenance grades map onto DTE: ARR is `ratified_by` the owner; an INFERRED rule keeps its Origin in Why; a DEFAULT rule (no forcing incident) is confidence medium.
- rules.test.ts's guards move onto the nodes: every MUST labels its enforcement, cited suites exist, quoted test names appear in them, owner ratifications match an owner-kept list, and `[[ID]] name` pairs match titles.
- A doc whose content is settled decisions (a "settled policies" or relapse-guard doc) is lifted the same way and deleted; a doc that explains mechanics or guides authoring stays, citing the nodes it explains.
- DTE's own rules stay vendored in dte-rules/ and are never re-created as Solenoid nodes.
- Lifting an existing rule or decision into a node is not acting under it, so the import runs no contest (overriding DTE's B28 for this one migration). A lifted node gets its one contest when later work first builds on it.

### Contest 2026-09-15 by Claude Opus 5: variant wins

Rubric: [[A1]], read with the project's standing order of one home per fact.
- keep: adopt DTE, but rules.md and decisions.md stay authoritative and the tree cites them. Cost: ~150 rules and decisions held twice, each a place the two can contradict; the reconcile duty doubles.
- opposite: no DTE; stay on the prose documents. Loses per-decision provenance, blast radius, trace and ratification, which the prose documents cannot give.
- deletion: no node; [[A1]] alone does not say where Solenoid's rules live, so every session re-asks.
- variant: adopt DTE and make the nodes the ONE home: each rule and decision moves into a node and the two documents retire. Cost: one migration plus rewriting rules.test.ts onto the nodes and re-pointing citations.
Verdict: variant. Written as a new node that supersedes B4.

### Contest 2026-09-15 by Claude Opus 5: keep wins

Rubric: [[A1]]. [[B8]] was written as the variant that won B4's contest (2026-09-15), so its alternatives are the same ones, costed there: keep-both-docs (every fact held twice, the contradiction class the reconcile rule fights); no DTE (loses provenance, blast radius, trace, ratification); no node (every session re-asks where rules live). A further variant scoped here: generate rules.md and decisions.md from the nodes as read-only indexes.
